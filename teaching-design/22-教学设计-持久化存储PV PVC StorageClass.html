课程：Docker云容器与管理技术 ｜ 课次：第 22 次课 ｜ 文档：教学设计

课程名称：Docker云容器与管理技术 模块：M8 K8s进阶——存储与配置 课次：第22次课（共2学时，90分钟） 贯穿项目：CTTS多服务（Vue3 + SpringBoot + MySQL）部署到K8s

一、教学目标

1. 知识目标

  • 理解K8s持久化存储的必要性，能复述Pod销毁数据丢失的根本原因。
  • 阐述K8s存储体系总览：Volume、PV、PVC、StorageClass四层抽象的职责与关系。
  • 掌握PersistentVolume（PV）的定义、YAML关键字段（capacity、accessModes、persistentVolumeReclaimPolicy）及生命周期四态（Available / Bound / Released / Failed）。
  • 掌握PersistentVolumeClaim（PVC）的YAML定义、与PV的绑定机制及生命周期。
  • 理解StorageClass动态供给原理，能说明provisioner、reclaimPolicy、volumeBindingMode字段语义。
  • 掌握在Pod中通过volumes挂载PVC，以及在StatefulSet中使用volumeClaimTemplates的方法。

2. 能力目标

  • 能够独立编写PV、PVC、StorageClass的YAML并通过kubectl部署。
  • 能够完成"创建PV → 创建PVC → 验证绑定 → Pod挂载 → 写入数据 → 删除Pod → 数据持久化验证"全链路操作。
  • 能够为CTTS项目的MySQL服务设计并实现持久化存储方案。
  • 能够排查PV/PVC常见报错（Pending、Failed、无法绑定等）。

3. 素质目标（思政元素）

  • 数据安全意识：持久化存储是数据保障的最后一道防线，培养学生对生产数据负责的工程师品格。
  • 抽象分层思维：通过PV/PVC/StorageClass三层解耦，体会"资源与使用解耦"的工程哲学。
  • 协作沟通能力：通过两人一组讲解PV/PVC绑定流程，锻炼技术表达与团队协作。

二、教学内容与重难点

教学内容

  1. 存储需求与K8s存储体系总览
  2. PersistentVolume（PV）——定义、字段、类型、生命周期
  3. PersistentVolumeClaim（PVC）——定义、绑定机制、生命周期
  4. StorageClass——动态供给、provisioner、Minikube示例
  5. 在Pod中使用PVC——volumes挂载、StatefulSet volumeClaimTemplates
  6. CTTS项目实战：MySQL数据持久化完整示例

教学重点

  • PV与PVC的绑定机制（accessModes匹配、容量匹配、selector选择）
  • StorageClass动态供给流程
  • MySQL数据持久化的完整YAML实现

教学难点

  • PV生命周期中Released状态与Reclaim策略的联动理解
  • StorageClass动态供给与静态供给的区别
  • StatefulSet中volumeClaimTemplates的自动化逻辑

三、学情分析

  • 学生已掌握K8s基础概念（Pod、Deployment、Service）、ConfigMap与Secret（第21次课），具备基本YAML编写与kubectl操作能力。
  • 学生对"存储"的认知停留在Docker Volume层面，对K8s分层存储抽象较陌生。
  • 学生容易混淆PV（资源）与PVC（申请）的角色定位，需要通过类比与图示强化。
  • 实操环节对NFS/hostPath环境差异敏感，需提前在Minikube中验证。

四、教学方法

  • 讲授法：核心概念与YAML字段讲解。
  • 类比法：PV≈机房机柜，PVC≈租户申请工单，StorageClass≈自动派工系统。
  • 演示法：Minikube现场演示MySQL持久化全流程。
  • 小组讨论：两人一组讲解PV/PVC绑定流程，互相提问。
  • 任务驱动：以CTTS MySQL持久化为贯穿任务，边学边做。
  • 对比法：静态供给 vs 动态供给、hostPath vs NFS vs CSI。

五、教学环境与资源

  • 硬件：教师机1台、学生机若干（每生1台），每台至少8GB内存。
  • 软件：VirtualBox/WSL2、Minikube 1.30+、kubectl 1.28+、Docker Desktop。
  • 集群：每生独立Minikube单节点集群（minikube start --addons=storage-provisioner）。
  • 素材：教学PPT、YAML模板、生命周期流程图、绑定流程图、CTTS项目仓库。
  • 平台：课程Git仓库（含本课YAML）、在线考核系统。

六、教学策略与过程设计

采用"问题驱动 → 概念建构 → 实操验证 → 项目应用 → 总结提升"五段式教学。

1. 问题驱动（5分钟）

通过演示"Pod销毁后MySQL数据丢失"现象，引发存储需求思考。

2. 概念建构（40分钟）

按"Volume → PV → PVC → StorageClass → Pod使用PVC"顺序递进讲解，每讲完一个抽象层立即用图示强化。

3. 实操验证（25分钟）

学生跟随教师完成PV/PVC/Pod全链路操作，验证数据持久化。

4. 项目应用（15分钟）

将所学应用到CTTS MySQL服务，输出项目交付物。

5. 总结提升（5分钟）

梳理四层抽象关系，强调数据安全思政点。

八、教学评价设计

1. 过程性评价（60%）

  • 课堂参与度（提问回答、小组讨论）：10%
  • 实操环节完成度（PV/PVC/Pod全链路）：25%
  • 项目任务交付（CTTS MySQL持久化YAML）：25%

2. 终结性评价（40%）

  • 课后题库练习（78题）：30%
  • 思政反思短文（数据安全与工程师责任）：10%

附：思政融入设计

思政主题：数据安全——持久化存储是数据保障

融入节点

  1. 导入环节：Pod销毁数据丢失的真实事故案例（如某公司未配置持久化导致用户数据丢失），引出数据安全责任。
  2. PV生命周期：讲解Released状态时强调"删除PVC不等于数据安全"，需关注Reclaim策略，培养严谨态度。
  3. 项目实战：CTTS MySQL持久化是用户数据保障的核心，强调工程师对用户数据负责的伦理。
  4. 总结提升：联系国家《数据安全法》，强调数据安全是国家安全的重要组成部分，工程师应具备数据安全底线意识。

思政目标

  • 培养学生"数据为王、安全至上"的工程伦理。
  • 引导学生理解技术背后的社会责任。
  • 强化"预防胜于补救"的运维哲学。
