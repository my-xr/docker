课程：Docker云容器与管理技术 ｜ 课次：第 24 次课 ｜ 文档：教学设计

课程名称：Docker云容器与管理技术 模块归属：M8 综合项目实践模块 课次：第24次课（课程收官课） 学时：2学时（90分钟） 课型：实践课 + 项目答辩 贯穿项目：CTTS（云原生运维训练平台）多服务部署到K8s

一、教学目标

1.1 知识目标

  • 掌握K8s集群5大典型故障的现象识别、根因分析与排查方法（CrashLoopBackOff、NotReady、Service无端点、ImagePullBackOff、OOMKilled）
  • 理解滚动更新、回滚、扩缩容的底层原理与生产级运维操作流程
  • 系统回顾24次课八大模块知识体系，构建Docker+K8s完整技术图谱
  • 掌握云原生岗位能力要求与后续学习路线

1.2 能力目标

  • 能够独立完成K8s集群故障模拟、定位、修复的全流程操作
  • 能够使用kubectl set image/rollout undo/scale/logs/describe等命令完成生产级运维
  • 能够基于CTTS项目产出完整K8s交付物（YAML清单、部署文档、运维手册、项目报告）
  • 能够进行清晰的项目答辩，展示技术决策与工程落地能力

1.3 素质目标（课程思政）

  • 完整交付意识：能部署、能运维、能排障才是合格交付，培养工程闭环思维
  • 责任担当：生产环境无小事，运维操作要谨慎、可追溯、可回滚
  • 系统思维：从单容器到多服务到集群运维，构建云原生全栈视角
  • 协作精神：项目答辩强调团队协作，师生共同评审，培养沟通表达能力

二、教学重点与难点

2.1 教学重点

  • 5大故障场景的排查命令链与解决方案
  • 滚动更新与回滚的实战操作
  • CTTS项目答辩流程与交付物规范
  • 课程知识体系总结与岗位能力映射

2.2 教学难点

  • 故障现象到根因的快速定位（需综合运用kubectl describe/logs/events/get多命令）
  • 滚动更新过程中的版本管理与回滚策略选择
  • 项目答辩中技术决策的表达与问答应对

2.3 重点难点突破策略

  • 故障排查采用"现象→原因→命令→方案"四步法，配合实机演示
  • 运维操作采用"演示-模仿-实战"三段式训练
  • 答辩采用"分组演示+师生提问+集体评议"模式，提前1周下发答辩要求

三、学情分析

  • 知识基础：学生已完成23次课学习，掌握Docker全部内容（镜像/容器/网络/存储/Compose/Dockerfile）与K8s核心内容（Pod/Deployment/Service/ConfigMap/Secret/Ingress/存储/HPA/Job/CronJob/安全/网络策略/Helm）
  • 实践能力：已完成CTTS项目Docker化部署与K8s基础部署，具备单服务部署能力
  • 薄弱环节：故障排查经验不足、生产级运维命令不熟练、项目表达与文档化能力弱
  • 学习动机：课程收官课，学生期望通过项目答辩验证学习成果，对就业相关内容（岗位能力、学习路线）关注度高

四、教学方法

  • 任务驱动法：以5大故障排查任务为驱动，边做边学
  • 案例教学法：每个故障场景配真实生产案例
  • 演示模仿法：教师演示运维操作，学生模仿实战
  • 答辩评审法：分组答辩，师生共同评审
  • 思维导图法：课程总结环节使用思维导图回顾全课程

五、教学环境与资源

类别 内容
硬件环境 教师机1台 + 学生机40台（每台≥8GB内存），K8s集群（1 master + 2 worker，或单节点minikube/kind）
软件环境 Docker 24+、K8s 1.28+、kubectl、Helm 3、Git、VS Code
项目资源 CTTS项目代码仓库、K8s YAML清单模板、故障模拟脚本
教学资源 故障排查指南、运维操作手册、答辩评分表、课程知识图谱
网络环境 教室局域网 + 互联网（拉取镜像、查文档）

六、教学过程设计（90分钟时间分配）

阶段一：课程回顾与任务导入（10分钟）

时间 环节 教师活动 学生活动 设计意图
0-5min 课程回顾 用思维导图回顾24次课八大模块、Docker+K8s技术图谱 跟随回顾，对照笔记 唤醒先验知识，为综合实践奠基
5-10min 任务导入 宣布本课三大任务：故障排查实战、运维操作演练、项目答辩；强调"能部署+能运维+能排障=合格交付"的工程闭环理念 明确任务与交付要求 课程思政融入，明确收官目标

阶段二：故障排查实战（30分钟）

时间 环节 教师活动 学生活动 设计意图
10-15min 故障1演示 演示CrashLoopBackOff：制造容器启动失败，用kubectl describe/logs定位，修复应用启动命令 观察、记录命令 掌握Pod级故障排查四步法
15-20min 故障2演示 演示NotReady：模拟节点失联（停止kubelet/网络隔离），用kubectl get nodes定位 观察、记录命令 掌握节点级故障排查
20-25min 故障3演示 演示Service无端点：制造标签不匹配，用kubectl get endpoints定位 观察、记录命令 掌握服务发现故障排查
25-30min 故障4+5演示 演示ImagePullBackOff（错误镜像名）与OOMKilled（resources限制过低），定位与修复 观察、记录命令 掌握镜像与资源故障排查
30-40min 学生实战 下发故障模拟脚本，学生在自己集群复现3个故障并修复 动手实战，填写排查记录表 实操能力训练

阶段三：运维操作演练（15分钟）

时间 环节 教师活动 学生活动 设计意图
40-47min 滚动更新与回滚 演示kubectl set image触发滚动更新，kubectl rollout status查看进度，kubectl rollout undo回滚 跟随操作 掌握生产级发布能力
47-52min 扩缩容与HPA 演示kubectl scale手动扩缩容，配置HPA基于CPU自动扩缩容 跟随操作 掌握弹性伸缩能力
52-55min 日志与排障 演示kubectl logs -f/--previous、kubectl describe pod排障技巧 跟随操作 掌握日常排障能力

阶段四：项目答辩（25分钟）

时间 环节 教师活动 学生活动 设计意图
55-58min 答辩规则说明 宣布答辩流程、演示要点、评分标准、提问规则 明确答辩要求 规范答辩流程
58-78min 分组答辩 5组依次答辩（每组4分钟演示+1分钟提问），师生共同评审 分组演示、回答提问 综合能力展示
78-80min 集体评议 师生集体评议各组表现，宣布答辩成绩 互评、反思 强化反馈

阶段五：课程总结与展望（10分钟）

时间 环节 教师活动 学生活动 设计意图
80-85min 课程总结 回顾24次课八大模块、Docker+K8s技术图谱、云原生岗位能力图谱 跟随回顾 系统化知识体系
85-90min 后续展望 介绍后续学习路线（Service Mesh/Serverless/GitOps/可观测性）、推荐认证（CKA/CKAD/CKS）、推荐社区 记录学习路线 延伸学习，职业发展引导

七、答辩流程与评分标准

7.1 答辩流程

  1. 答辩准备（课前1周下发）：每组提交答辩PPT（≤10页）+ 演示视频（≤3分钟）+ 交付物压缩包
  2. 现场演示（4分钟/组）：
    • 项目架构与K8s部署拓扑介绍（1分钟）
    • 核心YAML清单讲解（1分钟）
    • 故障排查与运维操作演示（1分钟）
    • 亮点与难点总结（1分钟）
  3. 师生提问（1分钟/组）：教师1问 + 学生互问1问
  4. 集体评议（2分钟）：师生共同打分

7.2 评分标准（100分制）

维度 权重 评分细则
功能完整度 20% CTTS多服务全部成功部署到K8s并能访问（20分）；部分服务部署（10-15分）；未完成（0-10分）
Dockerfile与YAML质量 20% 镜像分层合理、多阶段构建、YAML规范、使用ConfigMap/Secret/资源限制（20分）；基本规范（12-18分）；不规范（0-12分）
运维能力 20% 能完成5大故障排查与滚动更新/回滚/扩缩容（20分）；能完成3项以上（12-18分）；能完成1-2项（0-12分）
文档与部署 20% 4类交付物齐全规范、可复现部署（20分）；文档基本完整（12-18分）；文档缺失（0-12分）
答辩表现 20% 表达清晰、技术决策合理、问答应对得当（20分）；表达基本清晰（12-18分）；表达不清（0-12分）

序号 交付物 要求 提交形式

九、教学评价设计

9.1 过程性评价（60%）

  • 故障排查实战记录表（20%）
  • 运维操作演练完成度（20%）
  • 课堂参与与互动（20%）

9.2 终结性评价（40%）

  • 项目答辩成绩（40%）

9.3 评价方式

  • 教师评价（60%）+ 学生互评（20%）+ 自我评价（20%）

十、教学反思与改进

10.1 预期反思点

  • 故障排查实战时间是否充足（30分钟可能偏紧，考虑课前预下发故障脚本）
  • 答辩分组数与时间是否合理（5组×5分钟=25分钟，若组数多需调整）
  • 课程总结是否覆盖到位（10分钟较紧，可提前下发知识图谱供课后细化）

10.2 改进方向

  • 可将故障模拟脚本提前1周下发，让学生课前预习，课堂重点演示与答疑
  • 答辩可引入"最佳项目""最佳运维""最佳文档"等单项奖，激发积极性
  • 课程总结可制作一页纸"云原生学习路线图"作为课程纪念
