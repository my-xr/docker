二、教学目标

知识目标

  1. 理解容器可写层的问题，明确数据持久化的必要性与典型场景。
  2. 掌握数据卷（Volume）的概念、存储位置与挂载方式（-v / --mount）。
  3. 掌握绑定挂载（Bind Mount）的概念、路径映射与适用场景。
  4. 理解 Volume 与 Bind Mount 的差异，能够根据场景选择合适的持久化方案。
  5. 掌握数据卷管理命令（docker volume create/ls/inspect/rm/prune），区分命名卷与匿名卷。
  6. 掌握数据卷共享（--volumes-from）与数据备份、恢复的完整方案。
  7. 掌握 MySQL 容器数据持久化配置方法，能够验证数据持久化的有效性。

能力目标

  1. 能够用准确的语言说明"为什么不能把数据存容器里"，并描述持久化的必要性。
  2. 能够为 MySQL、Nginx 等常见服务配置数据卷，实现数据持久化。
  3. 能够使用 docker volume 系列命令管理数据卷生命周期。
  4. 能够使用绑定挂载将宿主目录映射到容器，实现开发环境的热加载。
  5. 能够使用临时容器对数据卷进行备份与恢复操作。
  6. 能够通过"删除容器→重建容器→验证数据还在"的流程验证持久化配置是否生效。

素质目标（课程思政）

  1. 树立"数据安全"意识——持久化是数据安全的底线，无持久化无生产。
  2. 培养"工程规范"意识——数据与计算分离是云原生架构的基本原则。
  3. 建立"故障思维"——设计时要预想容器删除、迁移、升级场景下的数据保障。

四、项目任务或案例任务

贯穿项目任务：MySQL 容器数据持久化配置（CTTS 项目数据库持久化）

本次课任务：

  1. 教师提出问题场景：CTTS 项目的 MySQL 容器昨天运行得好好的，今天 docker rm 重建后，数据库里的用户表、课程表全没了——为什么会这样？
  2. 学生分析问题根因：数据写在了容器的可写层，容器删除后可写层随之消失。
  3. 教师引出解决方案：使用数据卷把 MySQL 数据目录 /var/lib/mysql 持久化到 Docker 管理的卷中。
  4. 学生完成 MySQL 持久化配置：创建命名卷 mysql_data → 启动 MySQL 容器挂载卷 → 写入测试数据 → 删除容器 → 重建容器挂载同一卷 → 验证数据还在。
  5. 教师演示数据备份方案：用临时容器挂载 mysql_data 卷，打包成 tar 文件备份到宿主机。

项目背景概述（详见 教学资料.md 综合示例）：

  • 项目名称：多服务容器化部署项目
  • 本次任务定位：为 CTTS 项目的 MySQL 服务配置数据持久化，确保容器重建、升级、迁移时数据库不丢失。
  • 与后续课程衔接：本次课的 mysql_data 卷将在第 11 次课 Compose 编排中通过 volumes: 声明，在第 22 次课 K8s 中通过 PV/PVC 演进为集群级持久化存储。

📌 本节课是 CTTS 项目数据库走向"生产可用"的关键一步——没有持久化的数据库不能上生产。

五、课堂互动设计

互动 1：开场问题导入（课前 5 分钟）

项目 内容
互动问题 "小明同学昨天用 docker run mysql:8.0 跑了一个 MySQL 容器，往里录入了 100 条用户数据。今天他发现容器配置不对，docker rm 删掉容器后用同样的命令重新跑了一个，结果发现数据库空空如也——100 条数据全没了。请问数据去哪了？为什么？"
组织方式 自由发言，教师板书关键词，不评判对错
预期学生输出 提到"数据在容器里""容器删了数据也删了""数据没保存""应该存到别的地方""要挂载磁盘"等关键词
教师点评要点 肯定合理认知，引出"容器可写层"概念——容器运行时所有写入都存在可写层，容器删除可写层随之消失。这正是数据持久化的必要性，引出 K10-1

互动 2：代码找错——数据未持久化导致丢失的反例（讲解 K10-2 后）

项目 内容
互动问题 给出一段有问题的部署脚本，让学生找出持久化方面的错误：
docker run -d --name ctts-mysql -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0
问：这条命令在生产环境运行会有什么风险？如何修复？
组织方式 两人一组讨论 3 分钟 → 每组派代表指出问题并给出修复命令 → 教师汇总
预期学生输出 能指出"没有挂载数据卷""数据写在容器里，容器删了就没了"；修复命令应包含 -v mysql_data:/var/lib/mysql 或 --mount type=volume,source=mysql_data,target=/var/lib/mysql
教师点评要点 强调生产环境 MySQL 必须配置持久化；进一步引导思考：除了 /var/lib/mysql 数据目录，MySQL 还有哪些路径需要持久化（如 /etc/mysql/conf.d 配置目录）？为 K10-3 绑定挂载埋伏笔

互动 3：Volume vs Bind Mount 辨析（讲解 K10-3 后）

项目 内容
互动问题 给出 4 个场景（① 生产环境 MySQL 数据持久化 ② 开发环境 Vue3 代码热更新 ③ 团队共享配置文件 ④ CI/CD 流水线构建产物输出），判断哪些更适合用 Volume、哪些更适合用 Bind Mount
组织方式 全班举手投票，少数派陈述理由
预期学生输出 能区分"生产数据用 Volume（Docker 管理、可移植）""开发热加载用 Bind Mount（直接映射宿主目录）"；对部分场景可能有分歧
教师点评要点 强调选择原则：生产环境优先 Volume（可移植、可备份、Docker 管理）；开发环境需要热加载时用 Bind Mount；不要在生产环境用 Bind Mount 暴露宿主路径，有安全风险

互动 4：数据备份方案设计（讲解 K10-5 后）

项目 内容
互动任务 提出问题："mysql_data 卷里的数据很重要，要做异地备份。但卷是 Docker 管理的，存在 /var/lib/docker/volumes/ 下，普通用户没法直接访问。怎么把卷里的数据备份出来？"让学生设计备份方案
组织方式 个人思考 2 分钟 → 同桌讨论 2 分钟 → 教师投影标准方案讲解
预期学生输出 能想到"用一个临时容器挂载这个卷，再打包拷出来"；具体命令可能写不全
教师点评要点 肯定思路，给出标准命令：docker run --rm -v mysql_data:/data -v $(pwd):/backup alpine tar cvf /backup/mysql_data.tar /data。强调"临时容器+卷挂载+打包"是数据卷备份的经典模式，可迁移到任何卷备份场景

六、课程思政融入点

项目 内容
融入点 数据安全——持久化是数据安全的底线
技术关联 容器可写层随容器删除而消失，生产环境数据库、配置、日志等必须持久化；数据卷是 Docker 提供的持久化机制，是数据安全的第一道防线；后续 K8s 的 PV/PVC、企业级备份方案都是在此基础上的演进
引导问题 "如果一个电商平台的所有订单数据都存在容器可写层里，容器重启后数据全丢，会造成什么后果？作为工程师，我们怎么从架构上保证数据不丢？"
预期价值目标 树立数据安全意识，理解"持久化是数据安全的底线"；培养工程责任意识——一行 -v 参数的缺失可能导致生产事故；建立"数据与计算分离"的云原生架构思维

思政自然融入，不空喊口号。通过"容器删除数据丢失"的真实反例让学生体会持久化的必要性。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. 容器的可写层在容器删除后仍然保留。（✗）
  2. 数据卷由 Docker 管理，存储在 /var/lib/docker/volumes 目录下。（✓）
  3. 绑定挂载需要使用宿主机的绝对路径。（✓）
  4. --volumes-from 可以实现容器之间共享数据卷。（✓）
  5. 生产环境推荐使用绑定挂载来持久化 MySQL 数据。（✗）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 Volume vs Bind Mount 的对比、数据卷管理命令、数据备份方案。
  2. 实操：在本地 Docker 环境完成 MySQL 数据持久化配置全流程（创建卷→启动容器→写入数据→删除容器→重建容器→验证数据），截图下次课提交。
  3. 思考：用 200 字描述"Volume 和 Bind Mount 的区别及各自适用场景"，下次课抽查。
  4. 项目准备：为 CTTS 项目的 MySQL 服务编写一份持久化配置说明（1 页），包含卷名、挂载路径、备份命令、恢复命令，为第 11 次课 Compose 编排做准备。
  5. 拓展练习（选做）：尝试用 --volumes-from 实现两个容器共享同一个数据卷，并验证写入的数据在两个容器中都能读到。
  6. 拓展阅读：阅读 Docker 官方文档关于 tmpfs 挂载的内容（docs.docker.com/storage/tmpfs/），了解第三种挂载方式，对比三种挂载的差异。
