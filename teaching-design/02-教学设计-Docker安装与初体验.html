二、教学目标

知识目标

  1. 掌握 Linux（Ubuntu 22.04）环境下 Docker 安装的前置条件与系统要求。
  2. 掌握通过 apt 官方源安装 Docker 引擎的完整流程（卸载旧版本、配置 apt 源、安装、验证）。
  3. 掌握 Docker 服务管理命令（systemctl start/stop/restart/enable/status）与开机自启配置。
  4. 理解镜像加速器的作用，掌握 /etc/docker/daemon.json 的完整配置方法。
  5. 理解 docker run hello-world 的执行流程与 pull 原理。
  6. 掌握 docker version 与 docker info 关键字段的含义。

能力目标

  1. 能够在 Ubuntu 22.04 上独立完成 Docker 引擎的安装与验证。
  2. 能够配置国内镜像加速器并使其生效。
  3. 能够运行首个容器 hello-world 并解读输出含义。
  4. 能够使用 systemctl 管理 Docker 服务，并查看服务状态。
  5. 能够通过 docker version / docker info 排查安装问题。

素质目标（课程思政）

  1. 培养"工程规范"意识——环境标准化是团队协作的基础，统一安装步骤、统一镜像源、统一配置文件是工程化的起点。
  2. 树立"自主可控"意识——国内镜像加速器既是为了速度，也是降低对境外网络依赖的工程实践。
  3. 培养"运维责任"意识——服务管理、开机自启是保障系统稳定运行的基本功。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

K2-6 Docker 基本信息查看 docker version 客户端/服务端字段；docker info 关键字段含义

四、项目任务或案例任务

贯穿项目阶段 1：Docker 环境准备第一步

本次课任务：

  1. 教师演示：在 Ubuntu 22.04 上从零安装 Docker 引擎，配置镜像加速器，运行首个容器。
  2. 学生同步操作：在自己的虚拟机/云主机上完成同样的安装流程。
  3. 完成验证：学生执行 docker run hello-world 看到成功输出，标志 CTTS 项目环境准备第一步完成。
  4. 教师引出：后续 CTTS 三服务（前端/后端/MySQL）都将跑在这套 Docker 环境上，环境标准化是团队协作的基础。

项目背景衔接：

  • 上次课明确了 CTTS 多服务容器化部署项目的整体目标。
  • 本次课是项目阶段 1（M1）的实操起点——先有 Docker 环境，才能后续拉取镜像、构建镜像、编排部署。
  • 每位同学把 Docker 装好，是后续所有课程实操的前提。

📌 本次课以"装好 Docker + 跑通 hello-world"为实操目标，命令必须完整可执行。学生若课堂未完成，课后必须补齐，否则无法跟进第 3 次课。

五、课堂互动设计

互动 1：课前 5 分钟回顾（开场导入）

项目 内容
互动问题 "上次课我们了解了容器化思想，请回忆：Docker 是什么架构？客户端命令最终由谁执行？今天我们要把 Docker 装到自己机器上，你觉得安装前需要准备什么？"
组织方式 自由发言，教师板书关键词
预期学生输出 提到"C/S 架构""守护进程执行""需要 Linux 系统""需要联网""需要管理员权限"等关键词
教师点评要点 肯定学生对 C/S 架构的回忆，引出 K2-1 环境准备；强调"装 Docker 不是下一步下一步，要按规范流程"

互动 2：实操演示——学生同步安装 Docker（核心互动）

项目 内容
互动任务 教师投影演示 Docker 安装全流程，学生同步在自己虚拟机上操作，分阶段验证
组织方式 教师演示一段 → 学生跟做一段 → 验证输出 → 进入下一段。分四段：①卸载旧版本+配 apt 源 ②apt 安装 ③配置镜像加速器 ④运行 hello-world
预期学生输出 每段都有明确的预期输出：①apt 源配置成功无报错 ②docker --version 显示版本号 ③docker info 显示镜像源 ④hello-world 输出 "Hello from Docker!"
教师点评要点 巡视学生操作，重点检查：apt 源是否配对、GPG 密钥是否添加、daemon.json 格式是否正确、是否忘记 restart。对常见报错（权限拒绝、源不对、JSON 格式错）集中讲解

互动 3：镜像加速器辨析（讲解 K2-4 后）

项目 内容
互动问题 "为什么从 Docker Hub 拉镜像很慢甚至超时？镜像加速器是怎么加速的？配置后不重启会生效吗？"
组织方式 同桌讨论 2 分钟 → 教师提问 2 位同学
预期学生输出 提到"Docker Hub 在国外""国内镜像源是镜像副本""配置文件要重启 dockerd 才生效"
教师点评要点 强调镜像加速器是"国内镜像站点缓存"，配置后必须 systemctl restart docker 才生效；引出"环境标准化"——团队统一用同一组镜像源

互动 4：hello-world 输出解读（讲解 K2-5 时）

项目 内容
互动任务 教师投影 hello-world 的完整输出，请学生逐段解释每段输出的含义
组织方式 全班齐答 + 个别提问
预期学生输出 能识别"Unable to find image locally → pull → Pull complete → Hello from Docker"的流程
教师点评要点 强调 docker run 的 pull 原理：本地没有镜像就自动去仓库拉取；这次拉取后下次运行 hello-world 不再 pull（本地已有）。为第 3 次课镜像管理埋伏笔

六、课程思政融入点

项目 内容
融入点 工程规范——环境标准化是协作基础
技术关联 Docker 安装有标准流程（卸载旧版→配源→安装→验证）；镜像加速器配置有标准文件（daemon.json）；服务管理有标准命令（systemctl）。这些"标准"让团队每个人的环境一致，是协作的基础
引导问题 "如果团队 5 个人各自用不同方式装 Docker、用不同镜像源、有人开机自启有人不开，部署 CTTS 时会出什么问题？为什么企业要统一环境？"
预期价值目标 培养工程规范意识——环境标准化不是"多此一举"，而是团队协作与生产稳定的基础；同时国内镜像加速器也体现"自主可控"——降低对境外网络依赖

思政自然融入，不空喊口号。通过"为什么企业要统一环境"的真实视角让学生体会工程规范的价值。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. 安装 Docker 前应该先卸载系统自带的旧版本 docker.io。（✓）
  2. 配置镜像加速器后，需要重启 Docker 服务才能生效。（✓）
  3. docker run hello-world 第二次运行时仍会从仓库拉取镜像。（✗）
  4. systemctl enable docker 是配置 Docker 开机自启的命令。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 复习：通读同文件夹 教学资料.md，重点掌握 Docker 安装全流程、daemon.json 配置、hello-world 输出解读。
  2. 实操补全：课堂未完成安装的同学，课后必须在自己的 Ubuntu 22.04 环境上完成 Docker 安装、镜像加速配置、运行 hello-world，截图提交。这是后续所有课程实操的前提。
  3. 思考：用 200 字描述"Docker 安装的完整步骤"，下次课抽查。
  4. 对比：查阅资料，对比 Ubuntu（apt）与 CentOS（yum）安装 Docker 的命令差异，写一份对照表（选做，为后续多环境部署打基础）。
  5. 排错练习：若安装过程中遇到报错，记录报错信息与解决办法，下次课分享（培养运维排错意识）。
  6. 拓展阅读：访问 Docker 官方文档 docs.docker.com/engine/install/，对比官方安装步骤与课堂步骤（选做）。
