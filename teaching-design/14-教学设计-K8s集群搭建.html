二、教学目标

知识目标

  1. 理解 K8s 集群搭建的常见方案（Minikube / kubeadm / Kind / 云托管 K8s），能根据场景选择合适方案。
  2. 掌握 Minikube 的安装前提条件、安装命令、启动停止命令，理解单机学习集群的特点与局限。
  3. 掌握 kubectl 的安装方法、kubeconfig 配置文件结构与作用，能通过 kubectl 连接并验证集群。
  4. 掌握 kubeadm 多节点集群的搭建流程（1 master + N worker）：前置条件配置、kubeadm init、kubeadm join、kubectl 配置。
  5. 掌握集群验证与基本操作命令：kubectl get nodes/pods/services、kubectl cluster-info、kubectl describe node、minikube dashboard。
  6. 明确 CTTS 项目 K8s 部署的集群环境准备：资源规划、镜像准备与推送策略。

能力目标

  1. 能够在自己的机器上独立搭建一套可用的 Minikube 单机 K8s 集群。
  2. 能够安装配置 kubectl，并通过 kubeconfig 连接到 K8s 集群。
  3. 能够使用 kubectl get / cluster-info / describe 等命令验证集群状态、排查节点异常。
  4. 能够梳理 kubeadm 多节点集群搭建的完整步骤，理解每一步的作用。
  5. 能够为 CTTS 三服务 K8s 部署规划集群资源与镜像准备清单。

素质目标（课程思政）

  1. 树立"实践出真知"意识——亲手搭建集群才能真正理解 K8s 架构，纸上谈兵学不会云原生。
  2. 培养"工程规范"意识——集群搭建每一步都有标准流程，环境配置不规范的集群迟早出问题。
  3. 建立"系统思维"——从单机 Minikube 到多节点 kubeadm，从学习到生产的演进视角。

四、项目任务或案例任务

贯穿项目阶段 4：K8s 集群搭建

本次课任务：

  1. 教师演示 Minikube 单机集群的完整搭建流程（安装→启动→验证→dashboard）。
  2. 学生同步在自己的机器上搭建一套可用的 Minikube 集群。
  3. 每位学生通过 kubectl 验证集群就绪状态，并提交 kubectl get nodes 截图。
  4. 教师演示 kubeadm 多节点集群的关键步骤（init/join），学生梳理流程图（不强求实操，多节点需要多台机器）。
  5. 师生共同梳理 CTTS 三服务 K8s 部署的集群资源规划与镜像准备清单。

项目背景衔接（详见 教学资料.md 综合示例）：

  • 项目名称：多服务容器化部署项目（CTTS）
  • 项目阶段：阶段 5（M5 模块）—— 搭建 K8s 集群
  • 当前状态：前 12 次课已完成 CTTS 三服务的 Docker 化与 Compose 编排，第 13 次课已建立 K8s 架构认知
  • 本次目标：让 CTTS 拥有一套可用的 K8s 集群环境，为第 15~23 次课部署 Pod/Deployment/Service 做好底座
  • 后续衔接：第 15 次课在本次搭建的集群上编写 Pod YAML 部署 CTTS 后端

📌 本节课是 K8s 部分从"认知"到"实操"的转折点。第 13 次课讲架构，本节课动手搭集群，第 15 次课开始部署应用。集群不搭好，后续 10 次课都没法练。

五、课堂互动设计

互动 1：课前 5 分钟讨论（开场导入）

项目 内容
互动问题 "上节课我们学了 K8s 的架构——Master 四大组件、Node 三大组件。但理论再清楚，没搭过集群就像没摸过方向盘。你觉得搭建一套 K8s 集群，最大的难点会在哪里？"
组织方式 自由发言，教师板书关键词，不评判对错
预期学生输出 提到"组件多""命令复杂""网络配置""前置条件""多机器准备""镜像拉取慢""版本兼容"等关键词
教师点评要点 肯定合理认知，引出"实践出真知"——本节课就动手搭一套。难点确实存在，但分步骤来并不难：先搭单机 Minikube（学习用），再了解 kubeadm 多节点（生产用）。引出 K14-1

互动 2：实操演示——学生同步搭建集群（讲解 K14-2、K14-3 后）

项目 内容
互动任务 教师在投影上逐步演示 Minikube 安装与启动，学生在自己机器上同步操作，最终每人都跑起一套 Minikube 集群
组织方式 教师演示一步 → 学生跟做一步 → 等待确认大部分成功 → 进入下一步。分 5 步：①检查 Docker/虚拟化 ②安装 Minikube ③minikube start ④安装 kubectl ⑤kubectl get nodes 验证
预期学生输出 学生机器上 kubectl get nodes 输出 Ready 节点；minikube status 显示 host/kubelet/apiserver Running
教师点评要点 巡视辅导常见问题：Minikube 启动卡在拉镜像（建议配 --image-mirror-country=cn）、kubectl 找不到 kubeconfig（检查 ~/.kube/config）、节点 NotReady（等组件启动）。强调"集群搭起来"是后续 10 次课的基础

互动 3：kubeadm 流程梳理（讲解 K14-4 后）

项目 内容
互动任务 教师讲解 kubeadm 多节点搭建流程后，请学生在纸上画出 kubeadm init/join 的流程图，标出 master 与 worker 节点各自的命令与产出
组织方式 个人独立完成 3 分钟 → 同桌互查 1 分钟 → 教师投影标准流程图讲解
预期学生输出 能画出"前置条件 → master:kubeadm init 生成 join 命令 → worker:kubeadm join 加入 → kubectl 配置"主流程；可能漏掉前置条件（关 swap/防火墙/SELinux）
教师点评要点 纠正常见错误（如把 join 命令在 master 上执行、忘记拷贝 kubeconfig）；强调前置条件是"踩坑重灾区"，生产环境 80% 的搭建失败都源于前置条件没配好

互动 4：CTTS 集群资源规划讨论（讲解 K14-6 时）

项目 内容
互动任务 分组讨论：把 CTTS 三服务（前端 2 副本 + 后端 3 副本 + MySQL 1 副本）部署到 K8s，需要规划多少集群资源？镜像要怎么准备？
组织方式 小组讨论 5 分钟 → 每组派代表发言 1 分钟 → 教师汇总
预期学生输出 资源：6 个 Pod，按每 Pod 0.5 核 512MB 估，至少 3 核 3G；镜像：MySQL 用官方，前后端用第 8 次课构建的镜像推到仓库；MySQL 需要持久化存储
教师点评要点 引导发现：Minikube 单机够学习用，但生产要 kubeadm 多节点；镜像准备要考虑仓库（Docker Hub/内网 Harbor）；MySQL 数据持久化要用 PV/PVC（第 22 次课）。为后续课程埋伏笔

六、课程思政融入点

项目 内容
融入点 实践出真知——亲手搭建才能理解架构
技术关联 K8s 架构（第 13 次课）讲得再清楚，不亲手搭一套集群，就无法体会"API Server 是入口""etcd 存状态""kubelet 调容器"这些抽象概念的真实含义。Minikube 让单机学习成为可能，kubeadm 让生产搭建有标准路径
引导问题 "看再多架构图，不如自己跑一遍 minikube start。云原生是工程实践性极强的领域，企业招聘 DevOps 工程师，面试官更看重你'搭过几套集群''踩过哪些坑'，而不是你能背多少组件名。这次课每人必须把集群跑起来。"
预期价值目标 树立实践出真知意识，破除对 K8s 的"理论畏惧"，养成动手验证的学习习惯；理解工程规范的价值——按标准流程搭建才能产出可靠集群

思政自然融入，不空喊口号。通过"亲手搭一套"的真实体验让学生体会"纸上得来终觉浅，绝知此事要躬行"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. Minikube 适合生产环境部署，可以承载真实业务流量。（✗）
  2. kubectl get nodes 显示节点状态为 Ready，表示该节点可以接受调度 Pod。（✓）
  3. 使用 kubeadm 搭建多节点集群时，必须先关闭 swap 分区。（✓）
  4. kubeadm join 命令需要在 master 节点上执行，让 master 加入 worker。（✗）
  5. kubeconfig 文件包含了集群连接信息和认证信息，kubectl 通过它连接集群。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 实操巩固：在自己的机器上重新搭建一套 Minikube 集群（不参考课件），记录每步命令与输出，下次课抽查。
  2. 验证练习：完成下列 kubectl 命令练习并截图：kubectl get nodes -o wide、kubectl cluster-info、kubectl describe node minikube、kubectl get pods -A、kubectl get services -A。
  3. 流程梳理：手绘 kubeadm 多节点集群搭建流程图（含前置条件、init、join、kubectl 配置），下次课带到课堂。
  4. 项目准备：为 CTTS 三服务 K8s 部署写一份《集群环境准备清单》（1 页），包含：集群资源规划（CPU/内存/节点数）、镜像准备清单（镜像名+版本+来源）、镜像仓库选型（Docker Hub / Harbor）。
  5. 拓展阅读（选做）：访问 Minikube 官方文档（minikube.sigs.k8s.io）了解 minikube addons list 可启用的插件，尝试启用 metrics-server 插件。
  6. 思考题：Minikube、kubeadm、Kind 三种方案各自的适用场景是什么？如果你要为公司搭建一套测试环境 K8s，会选哪种？为什么？
