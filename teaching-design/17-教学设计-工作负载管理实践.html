二、教学目标

知识目标

  1. 掌握 CTTS 三服务（MySQL + 后端 + 前端）Deployment 部署的总体规划方法（副本数、资源限制、标签、Namespace）。
  2. 掌握 MySQL Deployment YAML 编写要点：数据卷挂载、root 密码环境变量、资源限制、副本数选择。
  3. 掌握后端 Deployment YAML 编写要点：3 副本、连接 MySQL 的环境变量、requests/limits 资源限制。
  4. 掌握前端 Deployment YAML 编写要点：2 副本、Nginx 静态服务、资源限制。
  5. 掌握滚动更新与回滚的完整操作流程（kubectl set image / rollout status / rollout undo / rollout history）。
  6. 掌握 K8s 部署常见问题排查方法：CrashLoopBackOff、ImagePullBackOff、资源不足、标签不匹配。

能力目标

  1. 能够独立规划 CTTS 三服务 Deployment 部署方案（含副本数、资源、标签、Namespace）。
  2. 能够编写 MySQL、后端、前端三个 Deployment YAML 并成功部署到 Minikube 集群。
  3. 能够使用 kubectl 验证 Deployment 运行状态（get / describe / logs）。
  4. 能够执行滚动更新（v1→v2）并使用 kubectl rollout status 观察过程，必要时回滚。
  5. 能够根据 Pod 状态（CrashLoopBackOff / ImagePullBackOff / Pending）定位并修复部署问题。

素质目标（课程思政）

  1. 培养运维能力——声明式部署是云原生核心，运维从"操作机器"升级为"描述期望状态"。
  2. 培养工程规范意识——YAML 清单即基础设施代码（IaC），可版本化、可复现、可审计。
  3. 培养排障思维——遇到问题先看 kubectl describe 与 kubectl logs，定位根因再修复，不盲目重试。

四、项目任务或案例任务

贯穿项目阶段 6：CTTS 工作负载部署

本次课任务：

  1. 在第 14 次课搭好的 Minikube 集群上，规划 CTTS 三服务（MySQL + 后端 + 前端）的 Deployment 部署方案。
  2. 编写并部署 MySQL Deployment（1 副本 + 数据卷挂载，环境变量配置 root 密码）。
  3. 编写并部署 CTTS 后端 Deployment（3 副本，环境变量连接 MySQL，资源限制 requests/limits）。
  4. 编写并部署 CTTS 前端 Deployment（2 副本，Nginx 静态服务，资源限制）。
  5. 对后端 Deployment 执行滚动更新（v1→v2），用 kubectl rollout status 观察，验证后执行 kubectl rollout undo 回滚。
  6. 排查部署过程中出现的常见问题（CrashLoopBackOff / ImagePullBackOff / 资源不足 / 标签不匹配）。

项目背景概述（详见 教学资料.md 综合示例）：

  • 项目名称：多服务容器化部署项目（阶段 6 — 工作负载部署）
  • 项目架构：CTTS 前端（Vue3+Nginx）+ CTTS 后端（SpringBoot）+ MySQL 三服务
  • 本次成果：三个 Deployment 全部 Running，副本数满足规划，滚动更新与回滚验证通过

📌 本节课是 K8s 部分第 1 次实践课，重点是把第 16 次课学的 Deployment 理论综合应用到 CTTS 三服务，并完成滚动更新与回滚实操。Service 与外部访问在第 18 次课解决，本节课用 kubectl port-forward 临时调试。

五、课堂互动设计

互动 1：实践启动 — 部署规划讨论（开场）

项目 内容
互动问题 "CTTS 要部署 MySQL + 后端 + 前端三个 Deployment，请分组讨论：① 各服务副本数设多少？② 资源限制怎么设？③ 用什么标签区分？④ 部署顺序是什么？"
组织方式 4~5 人一组讨论 5 分钟 → 每组派代表发言 1 分钟 → 教师板书各组方案
预期学生输出 副本数：MySQL 1 副本（数据一致性）、后端 3 副本（高可用）、前端 2 副本；资源：MySQL 大、后端中、前端小；标签：app=ctts-mysql/backend/frontend；部署顺序：MySQL→后端→前端
教师点评要点 肯定合理规划，纠正典型错误（如 MySQL 3 副本会导致数据冲突，需用 StatefulSet，本课用 1 副本简化）；强调"部署顺序：数据库→后端→前端"是依赖关系决定

互动 2：滚动更新过程观察（K17-5 讲解时）

项目 内容
互动任务 教师演示后端 v1→v2 滚动更新，学生在另一个终端执行 kubectl get pods -w -l app=ctts-backend 持续观察，记录"新 Pod 创建→旧 Pod 终止"的节奏
组织方式 教师演示 + 学生同步观察，5 分钟；观察后请 2~3 位学生描述看到的 Pod 状态变化
预期学生输出 看到 Pod 数先变 4（3 旧+1 新），再变 3（2 旧+1 新），再变 4（2 旧+2 新）……直到 3 个全是 v2；理解 maxSurge/maxUnavailable 的实际效果
教师点评要点 强调"先启新再停旧"是滚动更新的核心；指出默认 maxSurge=25%/maxUnavailable=25% 在 3 副本下表现为"每次替换 1 个 Pod"；引出回滚场景

互动 3：项目任务复盘 — K8s 部署踩坑（K17-6 讲解时）

项目 内容
互动问题 "你在部署 CTTS 三个 Deployment 时遇到了哪些坑？是怎么解决的？请用'现象→排查命令→根因→解决方案'四步法描述"
组织方式 小组讨论 5 分钟收集踩坑 → 每组派代表分享 1 个典型问题 → 教师归类板书
预期学生输出 常见踩坑：① Pod CrashLoopBackOff（应用连不上 MySQL / 配置错）；② ImagePullBackOff（镜像名错 / imagePullPolicy 错）；③ Pending（资源不足）；④ Deployment READY 0/3（selector 与 template.labels 不匹配）；⑤ MySQL 数据未持久化
教师点评要点 肯定"先 describe 再 logs"的排障习惯；强调 90% 的 K8s 部署问题都能用 kubectl describe pod + kubectl logs pod 定位；引出 K17-6 的四大常见问题排查清单

互动 4：面试题快问快答（实践结束前）

项目 内容
互动任务 教师抛出 4 个面试题，学生举手抢答："① Deployment 滚动更新时服务会中断吗？为什么？② kubectl rollout undo 能回滚到任意版本吗？③ MySQL 适合用 Deployment 多副本吗？为什么？④ Pod 一直 CrashLoopBackOff 怎么排查？"
组织方式 抢答制，每题 1 分钟，答对加分
预期学生输出 ① 不会中断（默认 RollingUpdate 先启新再停旧，maxUnavailable 控制最少可用数）；② 能，用 --to-revision=N；③ 不适合（MySQL 有状态，多副本数据冲突，应用 StatefulSet，本课用 1 副本 Deployment 简化）；④ describe 看 Events、logs 看应用日志、检查依赖/配置/资源
教师点评要点 强化面试高频考点；指出"有状态应用用 StatefulSet"是延伸知识点（第 22 次课 PV/PVC 后再深化）

六、课程思政融入点

项目 内容
融入点 运维能力 — 声明式部署是云原生核心
技术关联 Deployment YAML 是"声明式基础设施代码"（IaC），描述"期望状态"而非"操作动作"；这是云原生运维与传统运维的根本区别；国内华为云 CCE、阿里云 ACK、腾讯云 TKE 都基于 K8s 声明式 API
引导问题 "传统运维是'敲命令操作机器'，云原生运维是'写 YAML 描述期望状态'。这种转变意味着什么？为什么说声明式运维是未来的方向？"
预期价值目标 让学生理解声明式部署是云原生核心能力，YAML 即代码（IaC）带来可版本化、可复现、可审计的运维新范式；培养"描述期望状态而非操作动作"的工程思维

思政自然融入，不空喊口号。通过"声明式 YAML 即代码"的真实视角让学生体会云原生运维的能力跃迁。

七、课堂练习或随堂测验

随堂练习（5 分钟，实践结束前进行）

操作题（限时完成）：

  1. 将 CTTS 后端 Deployment 扩容到 5 副本，再缩回 3 副本，记录命令与输出。
  2. 对后端 Deployment 执行一次镜像更新（v1→v2），用 kubectl rollout status 观察，再执行 kubectl rollout undo 回滚，记录全过程。

详细题目与解析见 题库.md。此处仅作课堂快速实操，不计分。

八、课后任务

  1. 复习：通读同文件夹 教学资料.md，重点理解三服务 Deployment YAML 编写、滚动更新与回滚流程、四大常见问题排查。
  2. 完善项目：在课堂三服务 Deployment 基础上，为每个 Deployment 补充 livenessProbe 与 readinessProbe（提示：参考 K8s 官方文档），下次课抽查。
  3. 排障练习：故意把后端 Deployment 的 selector.matchLabels 改成与 template.metadata.labels 不匹配，观察现象，用 kubectl describe 排查，记录排查过程（200 字）。
  4. 思考：MySQL 用 1 副本 Deployment 部署有什么风险？为什么生产环境用 StatefulSet？为第 22 次课 PV/PVC 做铺垫。
  5. 项目准备：整理三服务 Deployment YAML（含完整资源限制、环境变量、标签），提交到项目 Git 仓库，作为阶段 6 交付物。
  6. 拓展阅读：阅读 K8s 官方文档"Deployment Strategies"，了解 Blue-Green、Canary 等高级发布策略（选做）。
