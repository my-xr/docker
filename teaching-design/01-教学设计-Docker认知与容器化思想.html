二、教学目标

知识目标

  1. 理解"开发环境一致性"问题，明确容器化技术要解决的核心痛点。
  2. 理解 Docker 是什么、容器化思想的基本内涵。
  3. 掌握容器与虚拟机的区别（架构、启动速度、资源占用、隔离机制）。
  4. 理解 Docker 引擎的 C/S 架构（Client / Server / 守护进程）。
  5. 掌握镜像（Image）、容器（Container）、仓库（Registry）三大核心概念及其关系。
  6. 了解云原生生态（CNCF、Kubernetes）及容器技术在其中的定位。
  7. 明确本课程贯穿项目"多服务容器化部署项目"的整体目标。

能力目标

  1. 能够用自己的语言准确描述"什么是容器""容器与虚拟机的区别"。
  2. 能够识别一个应用交付场景中是否适合使用容器化技术。
  3. 能够画出 Docker 的 C/S 架构图并说明各组件职责。
  4. 能够理清镜像、容器、仓库三者之间的关系。

素质目标（课程思政）

  1. 树立"自主可控"意识——云原生基础设施是国之重器，理解国产化替代的意义。
  2. 培养"工程规范"意识——环境标准化是团队协作的基础。
  3. 建立"系统思维"——从单机到集群、从开发到运维的全局视角。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K1-1 为什么需要容器化 "在我电脑上能跑"问题；环境一致性；交付物不可复现；传统部署痛点
K1-2 什么是 Docker 与容器化思想 Docker 定义；容器化思想；一次构建、到处运行
K1-3 容器 vs 虚拟机 架构对比（Guest OS vs 共享内核）；启动速度；资源占用；隔离机制
K1-4 Docker 引擎架构 C/S 架构；docker CLI 客户端；dockerd 守护进程；REST API；containerd/runC
K1-5 镜像、容器与仓库 镜像=只读模板；容器=运行实例；仓库=镜像存储分发；Docker Hub
K1-6 云原生生态与课程项目导入 CNCF；云原生定义；K8s 定位；CTTS 多服务容器化部署项目八阶段

四、项目任务或案例任务

贯穿项目导入：多服务容器化部署项目

本次课任务：

  1. 教师介绍贯穿项目"多服务容器化部署项目"的业务背景与整体目标。
  2. 学生分组（每组 4~5 人），讨论并认领项目视角（前端 / 后端 / 数据库 / 运维）。
  3. 每组用 5 分钟讨论：从你认领的视角看，"把 CTTS 这个应用部署到生产环境"会面临哪些问题？
  4. 教师引出容器化是解决"环境一致性 + 一键部署 + 多服务编排"的关键技术。

项目背景概述（详见 教学资料.md 综合示例）：

  • 项目名称：多服务容器化部署项目
  • 项目架构：CTTS 前端（Vue3）+ CTTS 后端（SpringBoot）+ MySQL 三服务
  • 课程八阶段构建：Docker 环境与容器操作 → Dockerfile 镜像构建 → Compose 编排 → K8s 集群 → 工作负载 → Service/Ingress → ConfigMap/Secret/存储 → 综合部署运维
  • 与 JavaWeb 课程、Vue3 课程联动：将前两门课程的 CTTS 成果容器化并部署到 K8s

📌 本节课不敲命令，重点是建立容器化认知、导入贯穿项目。命令操作从第 2 次课（Docker 安装）开始。

五、课堂互动设计

互动 1：课前 5 分钟讨论（开场导入）

项目 内容
互动问题 "你有没有遇到过这样的场景：代码在我电脑上能跑，到了别人电脑/服务器上就报错？你觉得问题出在哪？"
组织方式 自由发言，教师板书关键词，不评判对错
预期学生输出 提到"系统不同""依赖版本不一样""环境配置不同""Java 版本""MySQL 版本""路径不一样"等关键词
教师点评要点 肯定合理认知，引出"环境一致性问题"是软件交付的头号痛点；这正是 Docker 要解决的核心问题，引出 K1-1

互动 2：容器 vs 虚拟机辨析（讲解 K1-3 后）

项目 内容
互动问题 给出 4 个场景（个人电脑跑多个不同版本 MySQL、银行核心系统强隔离、微服务快速弹性扩容、教学实验环境秒级启动），判断哪些更适合用容器、哪些更适合用虚拟机
组织方式 全班举手投票，少数派陈述理由
预期学生输出 能区分"强隔离需求用虚拟机""快速弹性用容器"；对部分场景可能有分歧
教师点评要点 强调容器不是要取代虚拟机，二者常常并存（虚拟机做基础设施隔离，容器做应用交付）；引出"选择技术要看场景"的工程思维

互动 3：架构图画图（讲解 K1-4 后）

项目 内容
互动任务 请学生在纸上画出 Docker 的 C/S 架构图：客户端、守护进程、REST API、镜像、容器、仓库，并标出一次"docker run"的流程
组织方式 个人独立完成 3 分钟 → 同桌互查 1 分钟 → 教师投影标准图讲解
预期学生输出 能画出 CLI → dockerd → 镜像 → 容器 的主流程；仓库位置可能画错
教师点评要点 纠正常见错误（如把仓库画成本地、漏掉 REST API 层）；强调 C/S 架构是后续所有命令操作的基础

互动 4：项目视角认领（讲解 K1-6 时）

项目 内容
互动任务 分组认领项目视角（前端 / 后端 / 数据库 / 运维），讨论"把 CTTS 部署到生产环境，你负责的部分会遇到什么问题"
组织方式 小组讨论 5 分钟 → 每组派代表发言 1 分钟
预期学生输出 前端：构建产物如何部署；后端：Java 运行环境一致性；数据库：数据持久化；运维：多服务如何一起管理
教师点评要点 引导发现"多服务 + 环境一致性 + 一键部署"正是容器化要解决的，为后续 Dockerfile / Compose / K8s 埋伏笔

六、课程思政融入点

项目 内容
融入点 自主可控——云原生基础设施的国产化
技术关联 Docker / Kubernetes 是云原生时代的"操作系统"，属于关键基础设施技术；国内有_containerd、KubeSphere、华为云 CCE、阿里云 ACK 等自主产品
引导问题 "如果整个国家的互联网应用都跑在国外厂商掌控的容器平台上，会有什么风险？我们为什么要关注自主可控的云原生技术？"
预期价值目标 树立自主可控意识，理解国产化替代的意义，激发学习云原生技术的责任感与使命感

思政自然融入，不空喊口号。通过"基础设施 = 国之重器"的真实视角让学生体会"为什么要学容器技术"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. 容器和虚拟机一样，都需要为每个实例运行一个完整的客户机操作系统。（✗）
  2. Docker 采用 C/S 架构，客户端命令通过 REST API 与守护进程通信。（✓）
  3. 镜像是只读的，容器是镜像运行起来的可写实例。（✓）
  4. 容器化技术可以完全取代虚拟机，所有场景都应该用容器。（✗）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解容器 vs 虚拟机、Docker 架构、镜像/容器/仓库三大概念。
  2. 思考：用 200 字描述"容器与虚拟机的区别"，下次课抽查。
  3. 画图：手绘 Docker 的 C/S 架构图，标出一次 docker run 的完整流程，下次课带到课堂。
  4. 项目准备：每组讨论并提交一份《CTTS 容器化部署初步设想》（1 页），列出前端/后端/数据库三服务各自容器化可能遇到的问题（至少各 3 条）。
  5. 环境准备（可选预习）：了解自己电脑操作系统，准备一台 Linux 虚拟机或使用云主机（Ubuntu 22.04 推荐），为第 2 次课安装 Docker 做准备。
  6. 拓展阅读：访问 CNCF 官网（cncf.io）了解云原生生态全景图（选做）。
