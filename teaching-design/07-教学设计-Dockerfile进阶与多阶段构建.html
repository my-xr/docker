二、教学目标

知识目标

  1. 掌握 ENV 与 ARG 指令的作用、用法及其区别（环境变量持久化 vs 构建时参数）。
  2. 理解 EXPOSE 与 VOLUME 声明性指令的作用，明确"声明"与"实际映射"的差异。
  3. 掌握 CMD 指令的语义与两种形式（shell 形式 / exec 形式），理解 CMD 可被 docker run 参数覆盖。
  4. 掌握 ENTRYPOINT 指令的语义，理解 ENTRYPOINT 与 CMD 的组合模式及"不被覆盖"特性。
  5. 掌握多阶段构建（FROM ... AS、COPY --from=）的写法与价值。
  6. 掌握镜像优化策略：层缓存顺序、合并 RUN、精简基础镜像（alpine/slim）、.dockerignore 完整配置。

能力目标

  1. 能够准确区分 ENV 与 ARG 的使用场景，编写可参数化的 Dockerfile。
  2. 能够在 Dockerfile 中合理使用 CMD/ENTRYPOINT 组合实现"固定入口 + 可变参数"的镜像。
  3. 能够编写 Java/Maven 多阶段构建 Dockerfile，把镜像从几百 MB 优化到一百多 MB。
  4. 能够编写 .dockerignore 文件并优化 Dockerfile 指令顺序以提升构建缓存命中率。

素质目标（课程思政）

  1. 培养"性能优化"意识——小镜像更安全、传输更快、攻击面更小。
  2. 建立"工程精益"思维——每一行 Dockerfile 都要经得起推敲。
  3. 强化"成本意识"——镜像体积直接影响带宽、存储和启动速度，是工程责任的体现。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K7-1 ENV 与 ARG 指令 ENV 设置环境变量并持久化到运行时；ARG 仅在构建阶段生效；ENV vs ARG 区别与协作
K7-2 EXPOSE 与 VOLUME 指令 EXPOSE 声明端口（文档化，不真正映射）；VOLUME 声明数据卷（声明性指令的作用与运行时挂载）
K7-3 CMD 指令 容器启动默认命令；shell 形式 vs exec 形式；CMD 被 docker run 参数覆盖
K7-4 ENTRYPOINT 指令 入口点；与 CMD 配合使用；entrypoint+cmd 组合模式；ENTRYPOINT 不被覆盖
K7-5 多阶段构建 FROM ... AS 多阶段；COPY --from=阶段名；减小镜像体积；Java/Maven 多阶段构建示例
K7-6 镜像优化与 .dockerignore 层缓存优化顺序；合并 RUN 减少层数；选择精简基础镜像（alpine/slim）；.dockerignore 完整配置

四、项目任务或案例任务

贯穿项目任务：用多阶段构建优化 CTTS 后端镜像

本次课任务：

  1. 教师演示"未优化的 CTTS 后端 Dockerfile"（单阶段，基于 maven:3.8 镜像直接打包运行），构建后镜像体积约 680MB。
  2. 教师带领学生分析镜像过大的根因：把 Maven、JDK、源码都打进了运行镜像，而运行时只需要 JRE + jar。
  3. 教师演示"多阶段构建优化版"：第一阶段用 maven:3.8-openjdk-17 编译打包；第二阶段只 COPY --from=builder 拿到 jar，基于 eclipse-temurin:17-jre-alpine 运行，镜像体积优化到 约 180MB。
  4. 学生分组讨论：还有哪些优化手段能进一步减小体积？（提示：alpine 基础镜像、合并 RUN、.dockerignore）。
  5. 教师引出 K7-6 镜像优化的完整方法论。

项目背景概述（详见 教学资料.md 综合示例）：

  • 项目名称：CTTS 多服务容器化部署项目
  • 本次课聚焦：后端 SpringBoot 服务的镜像优化
  • 优化目标：镜像体积从 ~680MB 优化到 ~180MB（减少 70%+），提升构建、推送、启动速度

📌 本节课是理论课，命令以教师演示 + 学生跟读为主，实操在第 8 次课（Dockerfile 构建实践）进行。

五、课堂互动设计

互动 1：课前 5 分钟回顾导入

项目 内容
互动问题 "上节课我们学了 Dockerfile 的基础指令（FROM/RUN/COPY/ADD/WORKDIR），写出了一个能跑的 CTTS 后端镜像。但运维同学反馈：镜像 680MB，每次 push/pull 都很慢，启动也慢。问题出在哪？怎么优化？"
组织方式 自由发言，教师板书关键词
预期学生输出 提到"基础镜像太大""Maven 也打进去了""源码没删""层数太多""没用 alpine"等关键词
教师点评要点 肯定合理认知，引出本节课的主线：进阶指令 → CMD/ENTRYPOINT → 多阶段构建 → 镜像优化，正是为了解决"镜像太大、不够灵活、不够规范"的问题

互动 2：面试题导入——"CMD 和 ENTRYPOINT 的区别"（核心互动）

项目 内容
互动问题 "这是 Docker 面试的高频题：CMD 和 ENTRYPOINT 的区别？请从形式、是否被覆盖、组合使用三个角度回答。"
组织方式 1. 教师先抛问题，给学生 1 分钟思考；2. 抽 2~3 位学生口述答案；3. 教师不立刻评判，先把答案写在黑板上；4. 讲完 K7-3、K7-4 后回看黑板答案，全班一起验证对错。
预期学生输出 学生可能回答："CMD 是默认命令""ENTRYPOINT 是入口点""ENTRYPOINT 不会被覆盖""两个可以一起用"——但多数对"shell 形式 vs exec 形式""组合模式的参数传递"理解不到位
教师点评要点 强调三个关键差异：①CMD 可被 docker run 后参数覆盖，ENTRYPOINT 不会；②都各有 shell 形式和 exec 形式，exec 形式才能正确接收信号；③ENTRYPOINT + CMD 组合模式：ENTRYPOINT 固定可执行程序，CMD 给默认参数，参数可被覆盖，是生产镜像的推荐写法。这道题答不全很正常，是后面两个知识点的引子。

互动 3：多阶段构建体积对比演示

项目 内容
互动任务 教师演示构建两个版本的 CTTS 后端镜像（单阶段 vs 多阶段），学生观察 docker images 输出的 SIZE 列差异
组织方式 教师投影命令 + 输出，学生跟读并记录两个镜像体积
预期学生输出 单阶段约 680MB，多阶段约 180MB，体积减少约 73%
教师点评要点 强调多阶段构建的本质：运行镜像只保留"运行所需"，把"构建所需"留在构建阶段丢弃。这是云原生镜像优化的核心手段，也是企业 CI/CD 的标配写法。

互动 4：.dockerignore 找错

项目 内容
互动任务 给出一份"漏写 .dockerignore"的 Dockerfile 构建场景：构建上下文目录包含 .git（50MB）、target（80MB 旧编译产物）、node_modules（200MB 前端依赖）、IDE 配置文件。问：构建会发生什么？怎么修复？
组织方式 小组讨论 3 分钟 → 每组派代表发言 1 分钟
预期学生输出 1) 构建上下文会非常大，docker build 第一步"Sending build context to Docker daemon"会传输几百 MB；2) 构建慢、缓存失效；3) 应该写 .dockerignore 排除 .git/target/node_modules/IDE 配置
教师点评要点 引出 K7-6 的 .dockerignore 完整配置；强调 .dockerignore 是镜像优化的"第一道防线"，但常被新手忽略。

六、课程思政融入点

项目 内容
融入点 性能优化——小镜像更安全、更高效
技术关联 镜像体积直接影响：①拉取/推送带宽成本；②存储成本；③容器启动速度；④攻击面（包含的工具越少，漏洞越少）。多阶段构建 + alpine/slim 基础镜像 + .dockerignore 是镜像优化的"三板斧"。
引导问题 "假设我们公司有 1000 个微服务镜像，每个镜像多 100MB，一年下来会增加多少存储和带宽成本？如果每个镜像都包含完整的 Maven、Git、调试工具，又会带来哪些安全隐患？"
预期价值目标 树立"性能与安全并重"的工程意识，理解"精益"——每一行 Dockerfile 都关乎资源与安全，是工程师的责任与担当。

思政自然融入，不空喊口号。通过"1000 个微服务镜像 × 100MB"的真实算账，让学生体会"小镜像 = 省钱 + 安全"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. ENV 设置的环境变量在容器运行时仍然可用，ARG 设置的变量在容器运行时不可用。（✓）
  2. EXPOSE 8080 指令会自动把容器的 8080 端口映射到宿主机。（✗）
  3. CMD ["java","-jar","app.jar"] 是 exec 形式，能正确接收 SIGTERM 信号。（✓）
  4. 多阶段构建中，前序阶段的镜像层不会进入最终镜像。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 ENV vs ARG、CMD vs ENTRYPOINT 对比表、多阶段构建示例、镜像优化三板斧。
  2. 背诵：CMD 与 ENTRYPOINT 对比表（形式、是否被覆盖、组合模式），下次课抽查。
  3. 编写：为 CTTS 后端编写一份多阶段构建 Dockerfile（Maven 编译 → JRE 运行），并写一份 .dockerignore 文件。下次实践课带过来。
  4. 思考：为什么 CMD ["java","-jar","app.jar"] 比 CMD java -jar app.jar 更推荐？（提示：信号传递、PID 1 问题）。
  5. 拓展阅读（选做）：访问 Docker 官方文档，阅读"Best practices for writing Dockerfiles"，整理 3 条最佳实践带到下次课分享。
