二、教学目标

知识目标

  1. 掌握 Java 后端应用多阶段构建 Dockerfile 的编写方法（Maven 构建阶段 + JRE 运行阶段）。
  2. 掌握 Vue3 前端应用多阶段构建 Dockerfile 的编写方法（Node 构建阶段 + Nginx 部署阶段）。
  3. 理解镜像构建标签管理规范（docker build -t、docker tag、命名规范）。
  4. 掌握构建日志的解读方法与常见构建失败的排查思路。
  5. 理解镜像构建优化实践（层缓存利用、.dockerignore 配置、镜像大小分析）。
  6. 掌握前后端容器联调验证的完整流程（容器运行、端口映射、访问测试）。

能力目标

  1. 能独立编写 CTTS 后端多阶段 Dockerfile（Maven 打包 → JRE 运行）。
  2. 能独立编写 CTTS 前端多阶段 Dockerfile（Node 构建 → Nginx 部署）。
  3. 能执行 docker build 构建镜像，并依据构建日志判断构建是否成功。
  4. 能运行前后端容器并通过浏览器/curl 验证服务可用性，完成联调测试。
  5. 能排查构建过程中的常见问题（COPY 路径错误、依赖下载失败、端口不通、前端 API 跨域等）。
  6. 能利用层缓存和 .dockerignore 优化构建速度与镜像体积。

素质目标（课程思政）

  1. 培养"质量意识"——镜像构建是一次性交付物，构建质量直接决定运行稳定性。
  2. 培养"工匠精神"——Dockerfile 每条指令都要经得起推敲，不能"能跑就行"。
  3. 建立"工程规范"意识——Dockerfile 命名、标签、注释要符合团队规范，便于协作。
  4. 培养"问题排查"思维——构建失败不慌张，按日志 → 定位 → 修复的流程冷静分析。

四、项目任务或案例任务

贯穿项目阶段 3 收尾：构建 CTTS 前后端镜像

本次课任务（实践课，全程实操）：

  1. 任务一：编写并构建 CTTS 后端镜像（K8-1、K8-3）

    • 学生在 ctts-backend/ 目录下编写多阶段 Dockerfile（Maven 构建 + JRE 运行）
    • 执行 docker build -t ctts-backend:v1 . 构建镜像
    • 解读构建日志，确认构建成功

  2. 任务二：编写并构建 CTTS 前端镜像（K8-2、K8-3）

    • 学生在 ctts-frontend/ 目录下编写多阶段 Dockerfile（Node 构建 + Nginx 部署）
    • 执行 docker build -t ctts-frontend:v1 . 构建镜像
    • 解读构建日志，确认构建成功

  3. 任务三：运行容器并验证（K8-4）

    • 运行后端容器：docker run -d -p 8080:8080 --name ctts-api ctts-backend:v1
    • 运行前端容器：docker run -d -p 80:80 --name ctts-web ctts-frontend:v1
    • 访问验证：curl http://localhost:8080/actuator/health、浏览器访问 http://localhost
    • 前后端联调：浏览器访问前端页面，验证能调通后端 API

  4. 任务四：构建优化与对比（K8-5）

    • 配置 .dockerignore 排除 node_modules、target、.git 等
    • 对比优化前后镜像大小：docker image ls
    • 分析层缓存：修改源码后重新构建，观察哪些层被缓存、哪些被重建

  5. 任务五：复盘与问题排查（K8-6）

    • 各组整理构建过程中遇到的踩坑问题
    • 教师汇总典型问题并演示排查思路

项目背景回顾：

  • 项目名称：多服务容器化部署项目
  • 项目架构：CTTS 前端（Vue3）+ CTTS 后端（SpringBoot）+ MySQL 三服务
  • 本次课是模块 3（Dockerfile 与镜像构建）的收尾实践课，承接第 6、7 次课的 Dockerfile 理论
  • 本次课产出的两个镜像（ctts-backend:v1、ctts-frontend:v1）将在第 12 次课（Compose 编排）中复用

📌 本节课全程实操，教师演示 + 学生同步操作 + 问题排查。MySQL 镜像使用官方 mysql:8.0，无需自建 Dockerfile。

五、课堂互动设计

互动 1：课前 5 分钟回顾（开场导入）

项目 内容
互动问题 "上节课学的多阶段构建，谁能用一句话说出它的核心好处？为什么要分两个阶段？"
组织方式 随机抽 2~3 名学生口头回答
预期学生输出 "减小镜像体积""把构建工具和运行环境分离""构建阶段用 Maven/Node，运行阶段只用 JRE/Nginx"
教师点评要点 肯定正确表述，强调"多阶段构建 = 构建阶段产物 + 运行阶段最小化"，引出本节课的实战任务

互动 2：构建日志解读（K8-3 讲解中）

项目 内容
互动问题 教师故意演示一次构建失败（如 COPY 路径错误），让学生观察构建日志，找出失败原因
组织方式 全班观察日志 → 小组讨论 2 分钟 → 派代表指出失败行和原因
预期学生输出 能从日志中找到 "COPY failed: file not found" 等错误信息，定位到具体指令
教师点评要点 强调"构建日志是排查的第一手资料"，教学生按 "Step → 错误行 → 错误信息" 的顺序阅读日志

互动 3：踩坑复盘（K8-6 实践后）

项目 内容
互动任务 各组整理本次构建过程中遇到的 1~2 个踩坑问题，描述"现象 → 原因 → 解决方案"，派代表分享
组织方式 小组讨论 5 分钟 → 每组代表发言 1~2 分钟 → 教师汇总典型问题
预期学生输出 典型问题：COPY 路径写错、npm install 慢/失败、端口被占用、前端调后端跨域、构建上下文太大导致构建慢
教师点评要点 将每组问题归类为"路径类/网络类/端口类/跨域类/缓存类"，给出通用排查思路；强调踩坑是实践课的最大价值

六、课程思政融入点

项目 内容
融入点 质量意识——镜像构建是一次性交付物
技术关联 镜像一旦构建完成推送到仓库，就会被多个环境（测试/预发/生产）拉取运行。如果构建质量有问题（如 COPY 错文件、依赖版本不对、没做 .dockerignore 导致敏感信息被打包），问题会在所有环境爆发。镜像 = 交付物 = 质量载体。
引导问题 "如果构建时把数据库密码硬编码进镜像，再推到仓库，会发生什么？镜像这个交付物和源代码相比，有什么特殊的质量要求？"
预期价值目标 树立"镜像即交付物"的质量意识，理解构建规范（不打包敏感信息、用明确标签、最小化镜像）的重要性，培养对生产环境负责的工程态度。

思政自然融入，不空喊口号。通过"镜像一旦推送就无法收回"的真实视角让学生体会"构建质量 = 生产质量"。

七、课堂练习或随堂测验

随堂练习（5 分钟，实践操作过程中穿插）

任务型快速作答：

  1. 在后端 Dockerfile 中，构建阶段用 FROM maven:3.9-eclipse-temurin-17 AS builder，运行阶段应该如何引用构建阶段的产物？请写出关键的 COPY 指令。

  2. 前端 Dockerfile 中，npm run build 产出的 dist 目录应该 COPY 到 Nginx 镜像的哪个路径？

  3. 构建镜像时，构建上下文过大（如包含 node_modules）会导致什么问题？如何解决？

  4. 运行前端容器后，浏览器访问 http://localhost 能看到页面，但调用后端 API 报跨域错误，可能的原因有哪些？

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 完善镜像：根据课堂踩坑复盘，优化自己的 CTTS 前后端 Dockerfile，确保构建成功且镜像体积合理（后端 < 300MB，前端 < 50MB）。
  2. 推送镜像（选做）：在 Docker Hub 注册账号，将自己构建的 ctts-backend:v1 和 ctts-frontend:v1 推送到自己的仓库（docker push <用户名>/ctts-backend:v1）。
  3. 思考题：对比"单阶段构建"和"多阶段构建"两种 Dockerfile，写出镜像大小差异和构建时间差异，下次课抽查。
  4. 预习准备：阅读课程总览中模块 4（Compose 与网络存储）的部分，思考"如何让前端容器和后端容器通过容器名通信"。
  5. 拓展实践（选做）：尝试为后端镜像添加健康检查（HEALTHCHECK 指令），让容器自动检测应用是否健康。
  6. 资料复习：通读同文件夹 教学资料.md，重点理解多阶段构建的层缓存机制和 .dockerignore 的作用。
