二、教学目标

知识目标

  1. 理解 Deployment 的概念与作用，明确 Deployment vs Pod 的区别及为什么需要 Deployment（自愈、扩缩容、滚动更新、声明式管理）。
  2. 理解 ReplicaSet 的副本控制机制，掌握 Deployment 管理 ReplicaSet 的层级关系。
  3. 掌握 Deployment YAML 结构（apiVersion: apps/v1, kind: Deployment, spec.replicas/selector/template，selector.matchLabels，template 与 Pod 模板）。
  4. 掌握滚动更新与回滚的完整流程（kubectl set image / rollout status / undo / history），理解 RollingUpdate 策略的 maxSurge 与 maxUnavailable 参数。
  5. 掌握扩缩容（kubectl scale）与标签管理（labels / selectors / kubectl label），理解 matchLabels 与 matchExpressions 的区别。
  6. 综合运用上述知识完成 CTTS 后端 Deployment（3 副本）部署，验证高可用、扩缩容与滚动更新。

能力目标

  1. 能够编写完整的 Deployment YAML（含 replicas/selector/template，3 副本），并部署到 K8s 集群。
  2. 能够使用 kubectl scale 命令对 Deployment 进行扩缩容，并验证副本数变化。
  3. 能够使用 kubectl set image 触发滚动更新，使用 rollout status/undo/history 管理更新与回滚。
  4. 能够使用 kubectl label 为 Pod 打标签，使用 selectors 筛选 Pod。
  5. 能够排查 Deployment 部署与更新过程中的常见问题（如副本不足、镜像拉取失败、回滚失败）。

素质目标（课程思政）

  1. 树立"高可用"意识——多副本是系统稳定性的保障，理解生产环境为什么不用裸 Pod。
  2. 培养"声明式思维"——Deployment 描述"期望状态"，K8s 让实际状态趋近期望状态。
  3. 建立"工程规范"——滚动更新与回滚是安全生产的底线能力。

四、项目任务或案例任务

贯穿项目任务：部署 CTTS 后端 Deployment（3 副本）

本次课任务：

  1. 教师回顾第 15 次课部署的 CTTS 后端裸 Pod，引出"Pod 挂了怎么办？怎么扩容？怎么更新？"三个问题。
  2. 学生跟随教师编写 CTTS 后端 Deployment YAML（3 副本），部署到 ctts namespace。
  3. 验证高可用：手动删除某个 Pod，观察 Deployment 自动重建。
  4. 扩缩容演示：kubectl scale 从 3 副本扩到 5 副本，再缩回 3 副本。
  5. 滚动更新演示：kubectl set image 把 ctts-backend:v1 更新到 v2，观察滚动更新过程，再 rollout undo 回滚。

项目背景概述（详见 教学资料.md 综合示例）：

  • 第 15 次课部署的 CTTS 后端是裸 Pod，无自愈、无扩缩容、无滚动更新能力。
  • 本节课用 Deployment 管理 CTTS 后端 Pod，实现：3 副本高可用、手动扩缩容、滚动更新与回滚。
  • 后续第 17 次课（实践）将部署 CTTS 前后端 + MySQL 全部工作负载。
  • 后续第 18 次课将为 Deployment 创建 Service 供访问。

📌 本节课聚焦 Deployment 概念与命令操作，把 CTTS 后端从"裸 Pod"升级到"Deployment 管理的多副本工作负载"。

五、课堂互动设计

互动 1：开场导入——裸 Pod 的三个痛点（讲解 K16-1 前）

项目 内容
互动问题 "上节课我们部署了 CTTS 后端 Pod。现在请思考三个问题：① 如果 Pod 所在节点宕机，Pod 会怎样？② 如果双十一流量激增，单个 Pod 扛不住怎么办？③ 如果要升级到 v2 版本，怎么不停机更新？"
组织方式 全班举手抢答，教师板书三个痛点关键词
预期学生输出 ① Pod 会消失/挂掉；② 要多开几个；③ 要先停旧再启新或一边停一边启
教师点评要点 肯定学生直觉，引出"裸 Pod 是临时性的，无自愈、无扩缩容、无滚动更新能力"，这正是 Deployment 要解决的三大问题，引出 K16-1

互动 2：面试题快问快答——Deployment 滚动更新原理（讲解 K16-4 后）

项目 内容
互动问题 "面试官问：请说一下 Deployment 滚动更新的原理。你会怎么回答？附加题：maxSurge=25%、maxUnavailable=25% 是什么意思？滚动更新时最多有多少个 Pod？"
组织方式 两人一组讨论 2 分钟 → 抽 2~3 名学生口述回答 → 教师点评并给出标准答案
预期学生输出 能答出"先启新 Pod 再停旧 Pod"或"边启边停"；能提到 ReplicaSet 的新旧更替；maxSurge/maxUnavailable 解释可能不准
教师点评要点 标准答案要点：① Deployment 更新模板后创建新 ReplicaSet，逐步增加新 Pod；② 旧 ReplicaSet 逐步减少旧 Pod；③ maxSurge 是超出期望副本数的最大值（向上浮动），maxUnavailable 是低于期望副本数的最大值（向下浮动）；④ 默认 25%/25% 时，3 副本最多 4 个（3+1）最少 2 个（3-1）同时存在。强调这是面试高频题，要答清"新旧 ReplicaSet 协作 + 参数控制速率"。

互动 3：YAML 找错——Deployment 常见错误（讲解 K16-3 后）

项目 内容
互动任务 给出一份有 3 处错误的 Deployment YAML（apiVersion 写 v1、selector 与 template labels 不匹配、replicas 写成 1.5），学生找出错误
组织方式 个人独立找错 2 分钟 → 同桌互查 1 分钟 → 教师投影标准答案讲解
预期学生输出 能找出 apiVersion 应为 apps/v1；能发现 selector 与 labels 不匹配；replicas 必须是整数
教师点评要点 强调 Deployment YAML 三大易错点：① apiVersion 是 apps/v1 不是 v1；② selector.matchLabels 必须与 template.metadata.labels 完全匹配（否则 Deployment 找不到自己创建的 Pod）；③ replicas 必须是整数。

互动 4：滚动更新实操观察（讲解 K16-6 时）

项目 内容
互动任务 教师演示 kubectl set image deployment/ctts-backend backend=ctts-backend:v2，学生在另一终端持续观察 kubectl get pods -w 的输出，描述看到的现象
组织方式 教师演示 → 学生观察并描述 → 教师讲解背后原理
预期学生输出 能看到新 Pod 逐渐创建、旧 Pod 逐渐终止；能看到 READY 状态变化
教师点评要点 把"滚动更新"从抽象概念变成可视化现象，强调"先启新再停旧"的渐进式过程，对应 K16-4 的原理。

六、课程思政融入点

项目 内容
融入点 高可用——多副本是稳定性的保障
技术关联 Deployment 通过 replicas 维持多个 Pod 副本，单 Pod 故障不影响整体服务；滚动更新保证更新期间服务不中断；这是生产环境"365 天不宕机"的基础能力
引导问题 "如果支付宝只有一个实例，宕机 10 分钟会怎样？为什么大型互联网应用都要部署多副本？多副本带来高可用的同时，又带来了哪些复杂性？"
预期价值目标 树立高可用意识，理解多副本是系统稳定性的保障；同时认识到多副本带来数据一致性、负载均衡等复杂性（为后续 Service/StatefulSet 埋伏笔）；培养"为失败而设计"的工程思维

思政自然融入，不空喊口号。通过"多副本 = 高可用"的真实视角让学生体会"为什么生产环境不用裸 Pod"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. Deployment 是 K8s 中能创建和部署的最小单元，类似于 Pod。（✗）
  2. Deployment 通过 ReplicaSet 管理 Pod 副本，保证副本数符合期望。（✓）
  3. kubectl set image 会立即删除所有旧 Pod，再创建新 Pod。（✗）
  4. RollingUpdate 策略中，maxSurge=0 且 maxUnavailable=1 时，滚动更新会变成"先停旧再启新"。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 Deployment vs Pod vs ReplicaSet 三者关系、Deployment YAML 结构、滚动更新原理与 maxSurge/maxUnavailable 参数。
  2. 画图：手绘 Deployment → ReplicaSet → Pod 三层管理关系图，并标出滚动更新时新旧 ReplicaSet 的协作过程，下次课带到课堂。
  3. 实践：在自己的 Minikube 集群上完成 CTTS 后端 Deployment 部署（3 副本），执行扩缩容（scale 到 5 再缩回 3）和滚动更新（set image v1→v2，再 undo 回滚），记录每步命令与输出。
  4. 思考：用 200 字描述"为什么生产环境不用裸 Pod 而用 Deployment"，下次课抽查。
  5. YAML 编写：编写一份 CTTS 前端 Deployment YAML（参考后端，前端用 nginx 镜像，端口 80，3 副本），下次课带到课堂。
  6. 拓展阅读：阅读 K8s 官方文档 Deployment 章节，了解 Deployment 的其他策略（如 Recreate）和 Pause/Resume 机制（选做）。
