二、教学目标

知识目标

  1. 理解容器生命周期的完整流程：创建 → 运行 → 暂停 → 停止 → 启动 → 重启 → 删除，能画出状态流转图。
  2. 掌握 docker run 核心参数：-d（后台运行）、--name（命名）、-p（端口映射）、-e（环境变量）、-v（数据卷简介）、--rm（自动清理）。
  3. 掌握容器查看与管理命令：docker ps、docker ps -a、docker stats、docker top。
  4. 掌握容器日志与进入命令：docker logs -f/--tail、docker exec -it、docker attach，理解 exec 与 attach 的区别。
  5. 掌握容器详情查看与端口映射原理：docker inspect、-p hostPort:containerPort 原理、-P 随机端口。
  6. 掌握运行 MySQL 容器的完整实践：CTTS 项目数据库容器化，含密码、端口、数据卷的完整 docker run 命令。

能力目标

  1. 能够独立完成容器的创建、启动、停止、重启、删除全生命周期管理。
  2. 能够根据应用需求正确组合 docker run 参数（端口、环境变量、命名、后台）。
  3. 能够使用 docker logs 排查容器启动问题，使用 docker exec 进入容器调试。
  4. 能够使用 docker inspect 查看容器详情与端口映射状态。
  5. 能够运行 MySQL 容器并通过客户端连接验证。

素质目标（课程思政）

  1. 培养"运维责任"意识——容器管理是系统稳定的基础，一条命令的疏忽可能导致线上事故。
  2. 培养"工匠精神"——每个 docker run 参数都要理解其含义，不能复制粘贴。
  3. 建立"安全意识"——端口映射暴露服务、环境变量传入密码等都涉及安全考量。

四、项目任务或案例任务

贯穿项目任务：运行 MySQL 容器并连接验证

本次课任务：

  1. 教师演示：用一条完整的 docker run 命令启动 MySQL 容器，包含密码、端口映射、命名、数据卷、后台运行所有要素。
  2. 学生实操：每位同学在自己的 Docker 环境中运行 MySQL 容器（镜像 mysql:8.0，第 3 次课已拉取）。

  4. 进阶探索：使用 docker exec -it 进入容器，查看 MySQL 进程；用 docker logs 查看 MySQL 启动日志。

项目背景对接（详见 教学资料.md 综合示例）：

  • 项目名称：多服务容器化部署项目

  • 后续衔接：第 5 次课综合实践会进一步配置 MySQL 数据持久化、网络通信；第 11 次课 Compose 编排将 MySQL 与前后端一起启动

📌 本节课是 CTTS 项目"数据库容器化"的关键一步， MySQL 容器运行成功意味着项目的数据层已就绪。

五、课堂互动设计

互动 1：课前 5 分钟复习提问（开场导入）

项目 内容
互动问题 "上节课我们学了镜像管理。请回答：① docker pull mysql:8.0 之后，镜像是只读的还是可写的？② 镜像怎么变成一个运行中的容器？③ 用过 Linux 进程管理命令（如 ps、kill）的同学请举手。"
组织方式 自由抢答，教师板书关键词
预期学生输出 提到"镜像是只读模板""容器是镜像运行的实例""docker run 可以启动容器"；对 Linux 进程命令有基础认知
教师点评要点 复习镜像→容器的关系，引出"今天学习如何管理容器（运行/停止/日志/进入）"，类比对进程的管理

互动 2：编程小测验——docker run 参数含义（讲解 K4-2 后）

项目 内容
互动问题 教师给出 5 条 docker run 命令，学生独立写出每条命令中各参数的含义（5 分钟限时）：
① docker run hello-world
② docker run -d --name web nginx
③ docker run -p 8080:80 nginx
④ docker run -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0
⑤ docker run --rm alpine echo hello
组织方式 个人独立作答 5 分钟 → 同桌互改 2 分钟 → 教师公布答案
预期学生输出 能正确解释 -d（后台）、--name（命名）、-p（端口映射 hostPort:containerPort）、-e（环境变量）、--rm（退出自动清理）；对参数顺序、大小写可能有混淆
教师点评要点 强调参数顺序无关但建议规范；-p 是 宿主端口:容器端口 的方向；-e 用于向容器内传配置（如密码）；--rm 适合临时任务容器

互动 3：exec vs attach 辨析（讲解 K4-4 后）

项目 内容
互动问题 "小王启动了一个 nginx 容器：docker run -d --name web nginx，现在他想进入容器查看进程。他用 docker attach web 后发现：①终端卡住没反应；②按 Ctrl+C 后容器竟然停止了！请帮他分析原因，并给出正确的进入方式。"
组织方式 小组讨论 3 分钟 → 每组派代表发言 1 分钟
预期学生输出 能说出"attach 共享主进程的 stdin/stdout，nginx 主进程没有交互终端所以卡住；Ctrl+c 会发信号给主进程导致容器停止"；正确方式是用 docker exec -it web bash 开一个新终端
教师点评要点 强调 attach 与 exec 的本质区别：attach 是"附着到主进程"，exec 是"新开一个进程"；生产中进入容器调试几乎都用 exec

互动 4：端口映射原理图（讲解 K4-5 后）

项目 内容
互动任务 请学生在纸上画出 -p 8080:80 的端口映射流程图：宿主机、Docker 进程、容器、客户端访问路径
组织方式 个人独立完成 3 分钟 → 同桌互查 1 分钟 → 教师投影标准图讲解
预期学生输出 能画出"客户端访问 宿主机IP:8080 → Docker 进程监听 8080 → 转发到容器内 80 端口 → nginx 响应"的链路
教师点评要点 纠正常见错误（如把 8080 画成容器端口、漏掉 Docker 进程的监听）；强调端口映射是"宿主机端口映射到容器端口"的方向

六、课程思政融入点

项目 内容
融入点 运维责任——容器管理是系统稳定的基础
技术关联 容器管理命令直接控制服务的运行状态：docker stop 一条命令可能让线上服务停止；-e MYSQL_ROOT_PASSWORD=123456 弱密码可能被破解；docker rm -f 误删容器可能导致数据丢失
引导问题 "如果你是某公司的运维工程师，凌晨 3 点被告知线上服务挂了，你怎么用容器命令排查？一条 docker rm -f 误删生产容器会发生什么？容器管理与系统稳定、与用户利益是什么关系？"
预期价值目标 树立运维责任意识，理解"每一条命令都关乎稳定"，培养敬畏生产环境、谨慎执行命令的工程素养

思政自然融入，不空喊口号。通过"一条命令可能让线上挂掉"的真实视角让学生体会运维责任的份量。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. docker run 默认以前台方式运行容器，加 -d 参数后容器在后台运行。（✓）
  2. docker ps 只显示运行中的容器，docker ps -a 显示包括已停止的所有容器。（✓）
  3. docker exec -it web bash 与 docker attach web 是等价的，都是进入容器。（✗）
  4. -p 8080:80 表示将容器的 8080 端口映射到宿主机的 80 端口。（✗）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解容器生命周期状态流转、docker run 各参数、exec 与 attach 的区别。
  2. 实操：在自己的 Docker 环境中完成以下练习，截图下次课提交：
    • 运行一个 nginx 容器：docker run -d --name myweb -p 8080:80 nginx
    • 查看容器日志：docker logs myweb
    • 进入容器查看进程：docker exec -it myweb ps aux
    • 查看容器详情：docker inspect myweb
    • 停止、启动、删除容器
  3. 思考：用 200 字描述"docker exec 和 docker attach 的区别及各自适用场景"，下次课抽查。
  4. 项目任务：运行 MySQL 容器并使用客户端连接验证（详见 教学资料.md 综合示例），记录遇到的问题与解决方法。
  5. 拓展阅读：阅读 Docker 官方文档 docker run 命令参考（docs.docker.com/engine/reference/commandline/run/），了解其他常用参数（如 --restart、-w、--network）。
  6. 预习：第 5 次课为综合实践课，将综合运用镜像与容器命令完成 CTTS 各服务容器操作，请提前复习第 3、4 次课内容。
