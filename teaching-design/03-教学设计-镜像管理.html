二、教学目标

知识目标

  1. 理解 Docker 镜像的概念、组成与不可变（immutable）特性。
  2. 掌握 docker pull 完整用法，能从 Docker Hub 拉取指定版本镜像。
  3. 掌握 docker images / docker image ls 列出镜像并理解 REPOSITORY / TAG / IMAGE ID / CREATED / SIZE 字段含义。
  4. 理解镜像分层结构（Layer + UnionFS 联合文件系统），理解分层原理、层共享与层缓存。
  5. 掌握 docker history 查看镜像构建层；掌握 docker image inspect 查看镜像详情并解读关键字段。
  6. 掌握 docker tag 重命名镜像、理解标签含义与 :latest 陷阱。
  7. 掌握 docker rmi / docker image rm、-f 强制删除、docker image prune 与 docker image prune -a 清理策略。

能力目标

  1. 能够独立完成 CTTS 项目所需镜像（MySQL / Nginx / OpenJDK）的拉取与查看。
  2. 能够用 docker history 与 docker image inspect 分析一个镜像的分层结构与配置信息。
  3. 能够合理使用 docker tag 为镜像打标签，规避 :latest 陷阱。
  4. 能够安全地删除镜像并使用 docker image prune 清理无用镜像，做好磁盘资源管理。
  5. 能够用"分层 + 共享 + 缓存"原理解释为什么 docker pull 第二次很快、为什么镜像实际占用磁盘远小于 SIZE 字段之和。

素质目标（课程思政）

  1. 培养"资源管理"意识——及时清理无用镜像，避免磁盘浪费，是云原生运维的基本素养。
  2. 培养"工程规范"意识——镜像标签规范（不用 :latest、明确版本号）是团队协作的基础。
  3. 建立"底层思维"——从镜像分层结构理解 Docker 的存储与传输机制，建立对技术底层的认知。

四、项目任务或案例任务

贯穿项目阶段 2 任务：CTTS 三服务镜像准备

本次课任务：

  1. 教师演示从 Docker Hub 拉取 CTTS 项目所需镜像：
    • mysql:8.0（数据库服务）
    • nginx:1.25（前端静态资源服务）
    • openjdk:17-slim（后端 Java 运行时）
  2. 学生跟随操作，完成三个镜像的拉取，并用 docker images 查看本地镜像列表。
  3. 用 docker history mysql:8.0 与 docker image inspect mysql:8.0 分析 MySQL 镜像的分层结构与配置。
  4. 用 docker tag 为镜像打项目专用标签（如 mysql:8.0 → ctts-mysql:8.0），理解标签管理在生产环境的意义。
  5. 课后练习清理本地无用镜像（docker image prune），培养资源管理意识。

项目背景关联（详见 教学资料.md 综合示例）：

  • CTTS 三服务架构：前端 Vue3（Nginx 托管）+ 后端 SpringBoot（OpenJDK 运行）+ MySQL 数据库。
  • 本阶段先准备"基础镜像"——后续第 6~8 次课会基于这些基础镜像用 Dockerfile 构建出 CTTS 自己的应用镜像。
  • 第 4 次课将进入"容器管理"，用本次拉取的镜像启动容器实例。

📌 本节课核心是把"镜像"这个静态概念彻底搞清楚——它是什么、怎么来、怎么管、怎么删。所有命令都围绕"镜像"展开，不涉及启动容器（容器是第 4 次课内容）。

五、课堂互动设计

互动 1：课前 5 分钟讨论（开场导入）

项目 内容
互动问题 "上节课我们安装好了 Docker 并跑了 hello-world。请回忆：docker run hello-world 时，如果本地没有 hello-world 镜像，Docker 会做什么？这说明镜像和容器是什么关系？"
组织方式 自由发言，教师板书关键词
预期学生输出 提到"会自动从仓库下载"、"镜像先下来才能跑容器"、"镜像是模板、容器是实例"等关键词
教师点评要点 肯定学生回忆，引出本节课主题——"上节是体验，本节正式学镜像管理"。强调"镜像是 Docker 一切操作的基础，没有镜像就没有容器"，引出 K3-1

互动 2：镜像分层结构探究（讲解 K3-3 后）

项目 内容
互动问题 "假如你拉了 mysql:8.0 和 mysql:5.7 两个镜像，它们 SIZE 都显示 500MB+，是不是磁盘占用就是 1000MB+？为什么？"
组织方式 全班举手投票"是 / 不是"，少数派陈述理由
预期学生输出 部分学生认为"是"（直接相加），部分认为"不是"（共享底层）。讲不清原因
教师点评要点 引出"层共享"概念——两个 MySQL 镜像共享 Debian 基础层、共享部分依赖层，实际占用远小于 SIZE 之和。这正是分层结构的核心价值，引出 docker history 命令验证

互动 3：代码阅读——docker inspect 分析镜像分层（核心互动）

项目 内容
互动任务 教师投影 docker image inspect mysql:8.0 的完整 JSON 输出，分组让学生找出并解读以下字段：(1) 镜像 ID 在哪？(2) 镜像有几层？(3) 镜像创建时间？(4) 容器启动时默认执行什么命令？(5) 暴露了哪些端口？(6) 环境变量有哪些？
组织方式 小组讨论 5 分钟 → 每组派代表指认一个字段并解读 → 教师投影标准解读
预期学生输出 大多能找到 Id、Created、Config.Cmd、Config.ExposedPorts、Config.Env；RootFS.Layers 数层数时可能漏数；GraphDriver 字段可能看不懂
教师点评要点 逐字段解读（详见 教学资料.md K3-4），强调 inspect 是排查镜像问题的"X 光机"；引出"阅读官方镜像的 Dockerfile 与 inspect 是学习容器化的最佳途径"

互动 4：latest 陷阱辨析（讲解 K3-5 后）

项目 内容
互动问题 "小王在 Dockerfile 里写 FROM mysql:latest，今天构建的镜像和一个月后构建的镜像，是同一个镜像吗？生产环境这样做有什么风险？"
组织方式 同桌讨论 2 分钟 → 自由发言
预期学生输出 部分学生能意识到"latest 会变，所以两次构建可能基于不同版本"；部分学生认为"latest 就是最新的，肯定一样"
教师点评要点 强调 :latest 只是默认标签名，会随仓库更新而漂移，导致"今天能跑、明天就报错"的不可复现问题。生产环境必须指定明确版本号（如 mysql:8.0.35），这是工程规范

六、课程思政融入点

项目 内容
融入点 资源管理——及时清理无用镜像
技术关联 docker image prune 清理悬空镜像；docker image prune -a 清理全部未使用镜像；定期清理是云原生运维的基本素养。一台磁盘被无用镜像占满的服务器，会导致新镜像拉不下来、容器无法启动，进而引发生产事故
引导问题 "你有没有过'手机相册几千张照片不舍得删、最后存储满'的经历？服务器也一样——长期不清的悬空镜像、旧版本镜像会占满磁盘。如何养成定期清理的运维习惯？"
预期价值目标 培养"资源管理"意识，理解运维责任——良好的资源管理是系统稳定的保障；引申到生活中的"断舍离"与工程中的"零冗余"思维

思政自然融入，不空喊口号。通过"磁盘满了 → 服务挂了"的真实运维场景让学生体会"清理"不是小事。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. docker pull mysql 不写标签时，会拉取 mysql:latest 镜像。（✓）
  2. 一个镜像可以打多个标签，如 mysql:8.0 和 mysql:latest 可以指向同一个镜像。（✓）
  3. docker rmi 删除镜像时，如果镜像有对应容器存在（即使已停止），必须加 -f 才能强制删除。（✓）
  4. docker image prune 不带参数会清理所有未使用的镜像。（✗，只清理悬空镜像，加 -a 才清理所有未使用）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解镜像分层结构、docker image inspect 字段解读、latest 陷阱。
  2. 实操：在自己的 Docker 环境完成以下操作并截图提交：
    • 拉取 mysql:8.0、nginx:1.25、openjdk:17-slim 三个镜像
    • 用 docker images 查看本地镜像列表
    • 用 docker history mysql:8.0 查看 MySQL 镜像的构建层
    • 用 docker image inspect nginx:1.25 查看镜像详情，找出镜像 ID、层数、暴露端口
    • 用 docker tag nginx:1.25 ctts-nginx:v1 给镜像打项目标签
  3. 思考：用 200 字描述"为什么镜像要分层？分层带来了哪些好处？"，下次课抽查。
  4. 项目准备：CTTS 三服务的镜像已准备就绪，思考下节课（第 4 次课容器管理）如何用这些镜像启动容器实例，特别是 MySQL 容器需要哪些环境变量（提示：MYSQL_ROOT_PASSWORD）。
  5. 拓展实验（选做）：用 docker image prune -a 清理本地所有未使用镜像，观察磁盘释放情况（注意先确认没有正在使用的容器依赖这些镜像）。
  6. 拓展阅读：访问 Docker Hub（hub.docker.com）查看 mysql、nginx、openjdk 官方镜像页面，阅读其 Supported tags 与 Dockerfile（选做）。
