二、教学目标

知识目标

  1. 理解 Dockerfile 的概念与作用，明确"Dockerfile 是镜像的源代码"这一工程规范。
  2. 掌握 Dockerfile 的基本结构（指令 + 参数 + 注释 + 大小写规范）。
  3. 掌握 FROM 指令的作用与基础镜像选择原则（官方镜像、版本固定、scratch 场景）。
  4. 掌握 RUN 指令的两种形式（shell / exec）与"每条 RUN 生成一层"的分层原理，理解层缓存对构建优化的影响。
  5. 掌握 COPY 与 ADD 指令的差异（解压、URL）以及"优先用 COPY"的工程建议。
  6. 掌握 WORKDIR 与 USER 指令的作用，理解非 root 运行的安全最佳实践。
  7. 掌握 docker build -t name:tag . 命令、构建上下文（build context）概念以及 .dockerignore 的作用与编写。

能力目标

  1. 能独立编写一个最小可构建的 Dockerfile（FROM + COPY + WORKDIR）。
  2. 能用 docker build 命令构建镜像并通过 docker images 验证构建结果。
  3. 能识别并优化 Dockerfile 中的常见反模式（多条 RUN、绝对路径硬编码、用 ADD 复制本地文件）。
  4. 能为 CTTS 后端服务编写基础 Dockerfile（FROM openjdk → COPY jar → 设置 WORKDIR）。
  5. 能编写合理的 .dockerignore 文件减小构建上下文。

素质目标（课程思政）

  1. 树立"工程规范"意识——Dockerfile 是镜像的源代码，必须像写代码一样规范。
  2. 培养"安全意识"——非 root 运行、最小权限原则。
  3. 建立"性能意识"——合并 RUN、利用层缓存、减小构建上下文。

四、项目任务或案例任务

贯穿项目阶段 3：编写 CTTS 后端基础 Dockerfile

本次课任务：

  1. 教师讲解 Dockerfile 基础指令后，演示为 CTTS 后端编写一个"最小可用"的 Dockerfile。
  2. 学生跟随编写并构建 CTTS 后端基础镜像（FROM openjdk → COPY jar → 设置 WORKDIR）。
  3. 用 docker build 构建镜像，用 docker images 和 docker run 验证镜像可用。

CTTS 后端基础 Dockerfile（课堂演示版）：

# CTTS 后端基础镜像 Dockerfile（第 6 次课版本，进阶版在第 7 次课）
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY ctts-backend.jar /app/app.jar
CMD ["java", "-jar", "/app/app.jar"]

构建与验证命令：

# 切换到 jar 包所在目录
cd ~/ctts/backend

# 构建镜像
docker build -t ctts-backend:v0.6 .

# 验证镜像
docker images ctts-backend

# 运行容器验证（暂时不连数据库，只验证 java 进程能起来）
docker run --rm ctts-backend:v0.6 java -version

📌 第 6 次课只做"基础 Dockerfile"，重点是 FROM/COPY/WORKDIR 三件套。CMD/ENTRYPOINT、多阶段构建、镜像优化在第 7 次课讲。

五、课堂互动设计

互动 1：开场对比（5 分钟，讲解 K6-1 前）

项目 内容
互动问题 "上节课我们用 docker commit 把一个容器提交成镜像。如果让你把 CTTS 后端的环境（JDK17 + jar）做成镜像，你会怎么做？这种方式有什么问题？"
组织方式 自由发言，教师板书学生提出的步骤
预期学生输出 "启动一个 openjdk 容器 → docker cp 拷 jar 进去 → docker commit 提交成镜像"；可能说出"不可复现""步骤多易错""没办法版本管理"等问题
教师点评要点 肯定 docker commit 思路，但引出三大痛点：不可复现（没人知道你做了什么）、不可版本管理、不可审计。引出 Dockerfile——"用代码描述镜像构建过程"，对应 K6-1

互动 2：代码阅读——分析官方 nginx 镜像的 Dockerfile（讲解 K6-2 后）

项目 内容
互动任务 投影展示 nginx:alpine 官方镜像的 Dockerfile（精简版），学生分组阅读并回答：①FROM 用的什么基础镜像？②为什么选 alpine？③有几条 RUN？每条在做什么？④有没有 COPY/WORKDIR？
组织方式 4 人一组，5 分钟讨论 → 每组派代表发言 1 分钟
预期学生输出 能找出 FROM nginx:alpine；能识别 RUN 在装依赖；可能不理解为何用 alpine（轻量）；可能注意到没有显式 WORKDIR
教师点评要点 强调三点：①官方镜像选 alpine 是为减小体积；②RUN 用 && 合并命令减少层数；③WORKDIR 不写时默认 /，工程上应显式设置。引出"看官方 Dockerfile 是学习最佳实践的最快路径"

官方 nginx:alpine Dockerfile（精简版，用于课堂阅读）：

FROM alpine:3.18

RUN set -x \
    && addgroup -g 101 -S nginx \
    && adduser -S -D -H -u 101 -h /var/cache/nginx -s /sbin/nologin -G nginx -g nginx nginx \
    && apkArch="$(cat /etc/apk/arch)" \
    && apk add --no-cache nginx

COPY docker-entrypoint.sh /
COPY nginx.conf /etc/nginx/nginx.conf

WORKDIR /usr/share/nginx/html

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]

互动 3：找错游戏——找出 Dockerfile 中的反模式（讲解 K6-3、K6-4 后）

项目 内容
互动任务 投影一段"反面教材"Dockerfile，学生找出其中的问题（至少 4 处）
组织方式 个人独立找 2 分钟 → 同桌互相对照 1 分钟 → 教师点名回答
预期学生输出 能找出：①每条 RUN 单独写（层数过多）；②用 ADD 复制本地 jar（应该用 COPY）；③没有 WORKDIR（路径硬编码）；④没有指定基础镜像版本（用了 :latest）
教师点评要点 把"反面教材"改写成"正面示例"，让学生直观看到对比。强调工程规范："Dockerfile 不是写出来能跑就行，是要写给团队和未来的自己看的"

反面教材 Dockerfile：

FROM openjdk
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y vim
ADD ctts-backend.jar /app.jar
CMD java -jar /app.jar

互动 4：构建上下文实战体会（讲解 K6-6 时）

项目 内容
互动任务 教师故意在一个含 2GB 日志文件的目录执行 docker build，让学生观察构建开始的输出 sending build context to Docker daemon 2.1GB，问"为什么会传 2GB？怎么避免？"
组织方式 教师演示 → 全班观察输出 → 自由回答
预期学生输出 能说出"构建上下文是当前目录所有文件""日志文件被传过去了""应该用 .dockerignore 排除"
教师点评要点 引出 .dockerignore 的重要性：减小上下文 = 加快构建 = 减少泄漏。给出现实 .dockerignore 示例

六、课程思政融入点

项目 内容
融入点 工程规范——Dockerfile 是镜像的源代码
技术关联 Dockerfile 像代码一样：要版本管理（提交到 Git）、要 Code Review、要规范化（指令大写、合并 RUN、固定版本）、要可复现（任何人 build 出同样的镜像）
引导问题 "如果你的同事给你一个镜像说'就用这个'，你能知道里面装了什么、改了什么吗？但如果他给你一个 Dockerfile，是不是一目了然？这就是为什么我们说 Dockerfile 是镜像的源代码"
预期价值目标 让学生养成"Dockerfile 优先"的工程习惯，杜绝"docker commit 做镜像"的不规范做法；建立"代码即文档、代码即审计"的工程规范意识

思政自然融入：通过 docker commit 与 Dockerfile 的对比，让学生体会"工程规范不是教条，是协作的基础"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. docker commit 是制作镜像的推荐方式，因为它最直接。（✗）
  2. Dockerfile 中每条 RUN 指令都会生成一个新的镜像层。（✓）
  3. COPY 和 ADD 功能完全相同，可以互换使用。（✗）
  4. docker build 命令最后的 . 表示 Dockerfile 所在的位置。（✗，更准确说是构建上下文路径）
  5. 生产镜像应该用非 root 用户运行应用。（✓）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 FROM/RUN/COPY/ADD/WORKDIR/USER 六条指令与 docker build 命令。
  2. 动手：在自己的 Docker 环境中，按教学资料 K6-1~K6-6 的示例完整跑一遍构建流程，截图下次课抽查。
  3. 编写：为 CTTS 后端编写一个基础 Dockerfile（FROM eclipse-temurin:17-jre → COPY jar → WORKDIR /app），并构建镜像 ctts-backend:v0.6。
  4. 优化：编写一个 .dockerignore 文件，排除 target/、*.log、.git/ 等不该进镜像的文件。
  5. 阅读：访问 Docker Hub 查看 mysql:8.0 或 nginx:alpine 官方镜像的 Dockerfile，记录至少 3 条你认为是"最佳实践"的写法。
  6. 思考：为什么"Dockerfile 是镜像的源代码"？用 200 字表述，下次课抽查。
  7. 预习：第 7 次课将讲 CMD/ENTRYPOINT、多阶段构建、镜像优化，预习时思考"如何把第 6 次课的 CTTS 后端镜像做得更小"。
