二、教学目标

知识目标

  1. 理解"容器编排"概念，明确 Kubernetes 要解决的核心问题（多机调度、自愈、弹性、滚动更新）。
  2. 掌握 Docker Compose 的局限性（单机、无自愈、无弹性、无滚动更新），理解从 Compose 到 K8s 的演进动因。
  3. 能够对比 Docker Compose 与 Kubernetes，判断何时用 Compose、何时用 K8s。
  4. 掌握 K8s 的 Master-Node 整体架构（控制平面 Control Plane 与工作节点 Worker Node）。
  5. 掌握 Master 控制平面四大组件的职责（API Server、etcd、scheduler、controller-manager）。
  6. 掌握 Node 工作节点三大组件的职责（kubelet、kube-proxy、container-runtime）。
  7. 了解 K8s 核心概念总览（Pod/Deployment/Service/ConfigMap/Secret/PV/PVC/Ingress/Namespace），为后续 11 次课铺垫。

能力目标

  1. 能够用自己的语言准确描述"什么是容器编排""为什么需要 K8s"。
  2. 能够画出 K8s 的 Master-Node 架构图，标注各组件职责与数据流。
  3. 能够辨析 Docker Compose 与 Kubernetes 的适用场景。
  4. 能够识别一个应用部署场景中是否需要升级到 K8s。
  5. 能够说出 CTTS 三服务从 Docker 部署升级到 K8s 部署的目标与价值。

素质目标（课程思政）

  1. 树立"自主可控"意识——K8s 是云原生时代的"操作系统"，属于关键基础设施，理解国产化替代与自主可控的意义。
  2. 培养"系统思维"——从单机到集群、从手动到自动、从 Compose 到 K8s 的全局视角。
  3. 建立"演进思维"——技术选型要看场景与规模，没有银弹，合适的才是最好的。

三、主要知识点纲要

详细讲解内容见同文件夹 教学资料.md，此处为纲要。

编号 知识点 要点
K13-1 什么是 Kubernetes K8s 定义；容器编排概念；为什么要编排；Docker Compose 的局限性（单机、无自愈、无弹性、无滚动更新）
K13-2 K8s vs Docker Compose 对比 单机 vs 集群；手动编排 vs 自动调度；功能对比表；何时用 Compose 何时用 K8s
K13-3 K8s 整体架构 Master-Node 架构；控制平面 Control Plane vs 工作节点 Worker Node；集群数据流
K13-4 Master 控制平面组件 API Server：统一入口；etcd：键值存储；scheduler：调度器；controller-manager：控制器管理器
K13-5 Node 工作节点组件 kubelet：节点代理；kube-proxy：网络代理；容器运行时 container-runtime：containerd/Docker
K13-6 K8s 核心概念总览 Pod/Deployment/Service/ConfigMap/Secret/PV/PVC/Ingress/Namespace 概念简介，为后续课程铺垫

四、项目任务或案例任务

贯穿项目升级：CTTS 从 Docker 部署升级到 K8s 集群部署

本次课任务：

  1. 教师回顾前 12 次课的成果：CTTS 三服务（前端 Vue3 + 后端 SpringBoot + MySQL）已用 Docker 容器化，并通过 Docker Compose 实现一键编排部署。
  2. 教师抛出问题："如果 CTTS 用户量从 100 人涨到 10 万人，单机 Docker 部署还能扛住吗？如果某台机器宕机，服务还能用吗？"引导学生发现 Compose 的局限。
  3. 学生分组（沿用前 12 次课的 4~5 人小组），讨论："把 CTTS 从单机 Compose 部署升级到 K8s 集群部署，你期望解决什么问题？"
  4. 教师引出 K8s 的核心价值：多机调度、自愈、弹性扩缩容、滚动更新，并介绍后 12 次课的项目升级路线。

项目升级背景概述（详见 教学资料.md 综合示例）：

  • 项目名称：多服务容器化部署项目（K8s 升级阶段）
  • 已有成果（前 12 次课）：CTTS 三服务镜像 + docker-compose.yml 一键部署
  • 升级目标（后 12 次课）：将 CTTS 三服务部署到 K8s 集群，实现高可用、弹性扩缩容、滚动更新
  • 升级路线：K8s 集群搭建（M5）→ Pod 与工作负载（M6）→ Service 与网络（M7）→ 配置存储与综合实践（M8）

📌 本节课不敲命令，重点是建立 K8s 全局认知、理解架构与核心概念。命令操作从第 14 次课（K8s 集群搭建）开始。

五、课堂互动设计

互动 1：课前 5 分钟讨论（开场导入）

项目 内容
互动问题 "Docker Compose 能解决所有部署问题吗？哪些场景下 Compose 会力不从心？"
组织方式 自由发言，教师板书关键词，不评判对错
预期学生输出 提到"单机扛不住""机器挂了服务就没了""不能自动扩容""更新要停机""几台机器一起管太麻烦"等关键词
教师点评要点 肯定合理认知，引出 Compose 的四大局限（单机、无自愈、无弹性、无滚动更新）；这正是 K8s 要解决的核心问题，引出 K13-1

互动 2：K8s vs Compose 场景辨析（讲解 K13-2 后）

项目 内容
互动问题 给出 4 个场景（本地开发联调、个人博客部署、企业级电商大促、CI 流水线测试环境），判断哪些适合 Compose、哪些必须上 K8s
组织方式 全班举手投票，少数派陈述理由
预期学生输出 能区分"小规模/单机用 Compose""大规模/高可用用 K8s"；对部分场景可能有分歧
教师点评要点 强调"技术选型要看规模与场景"，没有银弹；本地开发用 Compose 足够，生产高可用必须 K8s；引出"演进思维"

互动 3：K8s 架构图画图（讲解 K13-4、K13-5 后）

项目 内容
互动任务 请学生在纸上画出 K8s 的 Master-Node 架构图：Master 上的 API Server/etcd/scheduler/controller-manager，Node 上的 kubelet/kube-proxy/container-runtime，并标出一次"kubectl create deployment"的数据流
组织方式 个人独立完成 3 分钟 → 同桌互查 1 分钟 → 教师投影标准图讲解
预期学生输出 能画出 Master 与 Node 两大区域及各自组件；数据流可能画错（如把 scheduler 画成直接操作容器）
教师点评要点 纠正常见错误（如把 etcd 当成数据库、把 scheduler 当成执行器）；强调"API Server 是唯一入口，所有组件都通过它通信"

互动 4：CTTS 升级目标认领（讲解 K13-6 时）

项目 内容
互动任务 分组讨论："把 CTTS 升级到 K8s，你负责的视角（前端/后端/数据库/运维）期望 K8s 帮你解决什么问题？"
组织方式 小组讨论 5 分钟 → 每组派代表发言 1 分钟
预期学生输出 前端：多副本负载均衡；后端：滚动更新不停机、自动扩缩容；数据库：数据持久化、故障迁移；运维：自愈、统一管理多节点
教师点评要点 引导发现"多副本 + 自愈 + 弹性 + 滚动更新 + 持久化"正是 K8s 的核心能力，为后续 Pod/Deployment/Service/存储课程埋伏笔

六、课程思政融入点

项目 内容
融入点 自主可控——K8s 是云原生时代的"操作系统"
技术关联 Kubernetes 是云原生基础设施的核心，被称"云原生操作系统"；CNCF 生态以 K8s 为底座构建；国内有华为云 CCE、阿里云 ACK、腾讯云 TKE、青云 KubeSphere 等自主产品，国产化替代正在推进
引导问题 "如果整个国家的互联网应用都跑在国外厂商掌控的容器编排平台上，会有什么风险？我们为什么要关注自主可控的云原生技术？"
预期价值目标 树立自主可控意识，理解 K8s 作为"云原生操作系统"的战略意义，激发学习云原生技术的责任感与使命感

思政自然融入，不空喊口号。通过"K8s = 云原生操作系统 = 国之重器"的真实视角让学生体会"为什么要学 K8s"。

七、课堂练习或随堂测验

随堂练习（5 分钟，讲解结束前进行）

判断题（口头快速作答）：

  1. Docker Compose 可以跨多台机器调度容器，实现集群编排。（✗）
  2. K8s 的 API Server 是集群的统一入口，所有组件都通过它通信。（✓）
  3. etcd 是 K8s 的键值存储数据库，保存集群的所有状态数据。（✓）
  4. kubelet 运行在 Master 上，负责调度 Pod 到合适的 Node。（✗）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 阅读：通读同文件夹 教学资料.md，重点理解 K8s 架构、控制平面与工作节点组件、核心概念总览。
  2. 思考：用 200 字描述"Docker Compose 与 Kubernetes 的区别与适用场景"，下次课抽查。
  3. 画图：手绘 K8s 的 Master-Node 架构图，标出 Master 四大组件、Node 三大组件，并标出一次 kubectl create deployment 的完整数据流，下次课带到课堂。
  4. 项目准备：每组讨论并提交一份《CTTS K8s 升级初步设想》（1 页），列出从 Compose 升级到 K8s 期望解决的问题（至少 5 条），并标注对应 K8s 的哪个能力。
  5. 环境准备（可选预习）：了解自己电脑是否支持安装 Minikube（需虚拟化支持），为第 14 次课搭建 K8s 集群做准备。
  6. 拓展阅读：访问 Kubernetes 官网（kubernetes.io/zh-cn）浏览"K8s 是什么"文档（选做）。
