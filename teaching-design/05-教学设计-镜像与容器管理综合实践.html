二、教学目标

知识目标

  1. 掌握 MySQL/Nginx/OpenJDK 三类官方镜像的拉取与标签管理策略。
  2. 掌握 MySQL 容器的完整运行命令、初始化数据库与执行 SQL 的方法。
  3. 掌握 Nginx 容器运行与静态页面挂载部署的方法。
  4. 掌握基于 OpenJDK 镜像运行简单 Java 应用的方法。
  5. 理解容器间通信的基本方式（--link 与容器互 ping），为第 9 次课网络专题埋下伏笔。
  6. 掌握容器无法启动、端口冲突、数据丢失等常见问题的排查与解决方法。

能力目标

  1. 能够独立完成 CTTS 三服务（MySQL/Nginx/Java）镜像准备与容器运行。
  2. 能够使用 docker exec 进入 MySQL 容器执行 SQL，初始化 CTTS 数据库表。
  3. 能够使用 -v 挂载静态页面到 Nginx 容器并验证访问。
  4. 能够使用 docker run 启动 Java 容器运行简单 jar 包。
  5. 能够使用 docker exec 在容器间进行网络连通性验证（ping）。
  6. 能够根据容器日志、状态、端口占用等信息排查常见容器故障。

素质目标（课程思政）

  1. 培养工匠精神——每一个 docker run 参数都要理解其含义，不能照抄照搬。
  2. 培养工程规范意识——命令可复现、操作可记录、结果可验证。
  3. 培养问题排查能力——遇到报错先看日志、查状态，而非盲目重装。

四、项目任务或案例任务

贯穿项目阶段任务：CTTS 三服务容器化操作（M2 模块阶段成果）

本次课任务：

  1. 镜像准备：拉取 mysql:8.0、nginx:stable、openjdk:17-jdk-slim 三个镜像，盘点本地镜像。
  2. MySQL 容器：运行 MySQL 容器，使用 docker exec 进入容器，创建 ctts 数据库并初始化业务表（用户表、试题表）。
  3. Nginx 容器：编写 CTTS 简易首页 index.html，挂载到 Nginx 容器，浏览器访问验证。
  4. Java 容器：使用 OpenJDK 镜像运行一个简单 jar 容器（或执行 java -version 验证环境）。
  5. 容器通信：使用 --link 让 Nginx 容器链接到 MySQL 容器，进入容器互 ping 验证。
  6. 复盘总结：记录操作中遇到的问题与解决方案，形成《CTTS 容器踩坑笔记》。

项目阶段定位：

  • 本次课对应项目阶段 2（M2 模块）：拉取 MySQL/Java/Nginx 镜像，运行容器。
  • 上承第 3~4 次课（镜像管理、容器管理的命令学习），下接第 6 次课（Dockerfile 构建自定义镜像）。
  • 完成本次课后，学生应具备"用官方镜像跑起来 CTTS 三服务"的能力，为后续 Dockerfile 构建自定义镜像打下基础。

📌 本次课是 M2 模块的综合实践课，重点是把前两次课学的命令"串起来用"，强调操作流程的完整性与可复现性。

五、课堂互动设计

互动 1：任务说明与镜像选型讨论（开场导入，10 min）

项目 内容
互动问题 "我们要把 CTTS 三服务（MySQL/Nginx/Java）容器化，每个服务应该选哪个官方镜像？标签怎么选？为什么不用 :latest？"
组织方式 全班自由发言，教师板书三服务镜像选型，对比 :latest 与固定版本
预期学生输出 MySQL 选 mysql:8.0；Nginx 选 nginx:stable 或 nginx:1.25；Java 选 openjdk:17-jdk-slim；不使用 :latest 因为不可控
教师点评要点 强调"镜像选型是工程第一步"，标签要明确版本号；引出 K5-1 镜像准备任务

互动 2：项目任务复盘——容器踩坑（K5-6 复盘阶段，10 min）

项目 内容
互动问题 "刚才操作中你遇到了哪些坑？是怎么解决的？请用一句话总结你的踩坑经验。"
组织方式 小组讨论 5 分钟 → 每组派代表分享 1 分钟 → 教师汇总板书"踩坑 Top 5"
预期学生输出 端口 3306/80 被占用、MySQL 密码忘记、容器起不来、Nginx 挂载路径错误、docker exec 进不去、中文乱码等
教师点评要点 强调"先看日志再行动"的排查思路；每个坑都对应一个工程经验；引出 K5-6 常见问题排查

互动 3：容器通信思考（K5-5 后，5 min）

项目 内容
互动问题 "--link 能让 Nginx 容器访问 MySQL 容器，但 Docker 官方说 --link 是 legacy，那现代做法是什么？我们第 9 次课会学什么？"
组织方式 自由发言，教师引导
预期学生输出 --link 已过时；现代做法是自定义网络（bridge network）；第 9 次课会学 Docker 网络
教师点评要点 肯定学生的预习意识；强调 --link 只是过渡方案，真正要做容器间通信要用自定义网络；为第 9 次课埋伏笔

六、课程思政融入点

项目 内容
融入点 工匠精神——每个命令参数都要理解
技术关联 docker run 命令有十几个常用参数（-d/-p/-e/--name/-v/--link/--restart 等），每个参数都对应一个工程需求；不理解参数照抄命令，遇到问题就抓瞎
引导问题 "为什么 MySQL 容器要加 -e MYSQL_ROOT_PASSWORD=123456？不加会怎样？为什么 Nginx 要 -p 80:80？为什么挂载用 -v /宿主路径:/容器路径？"
预期价值目标 培养学生"知其然更知其所以然"的工匠精神，每个参数都要搞懂含义、用途、不写的后果，养成严谨的工程素养

思政自然融入：通过"参数理解"这一具体行为，让学生体会工匠精神不是空泛口号，而是"每个细节都搞懂"的工程习惯。

七、课堂练习或随堂测验

随堂实操检查（实践课，以操作结果代测验，最后 10 min 进行）

检查清单（学生自检 + 教师抽查）：

  1. ✅ docker images 能看到 mysql:8.0、nginx:stable、openjdk:17-jdk-slim 三个镜像。
  2. ✅ docker ps 能看到 MySQL、Nginx 两个运行中的容器。
  3. ✅ docker exec -it <mysql容器> mysql -uroot -p123456 -e "SHOW DATABASES;" 能看到 ctts 数据库。
  4. ✅ 浏览器访问 http://localhost 能看到 CTTS 简易首页。
  5. ✅ docker logs <nginx容器> 无报错。

详细题目与解析见 题库.md。此处仅作课堂快速检查，不计分。

八、课后任务

  1. 完善：完善课堂未完成的操作，确保 CTTS 三服务容器全部跑通，记录完整命令到《CTTS 容器踩坑笔记》。
  2. 思考：本次课 MySQL 容器没有配置数据卷持久化，重启容器后数据会丢失吗？如何持久化？（为第 10 次课数据卷埋伏笔）
  3. 进阶：尝试用 --link 让 Java 容器链接 MySQL 容器，并用一段简单 JDBC 代码（或 mysql 客户端）验证 Java 容器能否访问 MySQL。
  4. 整理：整理本次课的"踩坑 Top 5"与解决方案，下次课开课抽查 1~2 组分享。
  5. 预习：阅读第 6 次课《Dockerfile 基础指令》教材内容，思考"如果要把 CTTS 后端 jar 包做成镜像，Dockerfile 该怎么写"。
  6. 拓展（选做）：访问 Docker Hub，查看 mysql:8.0 镜像的官方说明，了解 MYSQL_DATABASE、MYSQL_USER 等环境变量的作用。
