二、教学目标

知识目标

  1. 理解 CTTS 三服务（MySQL + Backend + Frontend）的完整容器化部署架构。
  2. 掌握 MySQL 容器化的完整方案：初始化 SQL 脚本、数据卷持久化、环境变量配置。
  3. 掌握后端服务多阶段 Dockerfile 编写（Maven 打包 → JRE 运行）。
  4. 掌握前端服务多阶段 Dockerfile 编写（Node 构建 Vue3 → Nginx 部署）及 nginx.conf 反向代理配置。
  5. 掌握 docker-compose.yml 完整编排：三服务 + 自定义网络 + 具名数据卷 + depends_on 依赖 + healthcheck 健康检查。
  6. 掌握一键部署全流程（docker compose up -d → 验证 → 访问 → API 联调）与常见问题排障方法。
  7. 系统回顾 Docker 部分（前 12 次课）的知识体系，明确向 K8s 部分过渡的衔接点。

能力目标

  1. 能够独立编写 CTTS 数据库初始化 SQL 脚本并完成 MySQL 容器化。
  2. 能够独立编写后端多阶段 Dockerfile，实现 Maven 打包与 JRE 运行分离。
  3. 能够独立编写前端多阶段 Dockerfile，并配置 Nginx 反向代理后端 API。
  4. 能够编写完整的 docker-compose.yml，使用 healthcheck + depends_on 实现可靠的启动依赖。
  5. 能够一键部署 CTTS 三服务，并通过浏览器、curl、容器内命令验证全链路。
  6. 能够定位并修复部署中的常见故障（数据库连不上、前端跨域、后端启动失败等）。

素质目标（课程思政）

  1. 树立"完整交付"意识——从代码到容器的全链路是工程师的核心能力。
  2. 培养"工程闭环"思维——能部署、能验证、能排障、能交付，才是合格交付。
  3. 强化"系统思维"——单服务容器化只是起点，多服务协同才是工程现实。
  4. 建立"质量与责任"意识——一键部署的可复现性是团队协作的基石。

四、项目任务或案例任务

贯穿项目阶段交付：CTTS 三服务 Docker 完整部署

本次课任务（对应课程项目阶段 4 的最终交付）：

  1. 在 ~/ctts/ 目录下建立完整项目结构（docker-compose.yml + init.sql + backend/ + frontend/）。
  2. 编写 init.sql：建立 CTTS 数据库核心表（用户表、课程表、选课表）并插入初始数据。
  3. 编写 backend/Dockerfile：多阶段构建，第一阶段用 maven:3.9-eclipse-temurin-17 打包，第二阶段用 eclipse-temurin:17-jre 运行。
  4. 编写 frontend/Dockerfile：多阶段构建，第一阶段用 node:20-alpine 构建 Vue3，第二阶段用 nginx:alpine 部署；配套 nginx.conf 反向代理 /api/ 到 backend:8080。
  5. 编写 docker-compose.yml：编排 mysql + backend + frontend 三服务，配置 ctts-net 自定义网络、ctts-mysql-data 具名数据卷、healthcheck + depends_on 依赖。
  6. 一键启动 docker compose up -d --build，验证：MySQL 数据初始化、后端 API 可访问、前端页面可访问、前后端联调成功。
  7. 排障演练：模拟"数据库连不上""前端跨域""后端启动失败"三类故障并定位修复。
  8. 项目演示：每组展示部署成果，说明架构、演示访问、回答教师提问。

项目背景概述（详见 教学资料.md K12-1）：

  • 项目名称：多服务容器化部署项目（CTTS）
  • 项目架构：CTTS 前端（Vue3 + Nginx）+ CTTS 后端（SpringBoot + JDK17）+ MySQL 8.0 三服务
  • 本节交付物：完整可运行的 Docker 部署方案（Dockerfile × 2 + docker-compose.yml + init.sql + nginx.conf）
  • 课程衔接：本节完成后，Docker 部分收官；第 13 次课进入 Kubernetes 部分

📌 本节课为实践课，以学生动手实操为主，教师演示为辅。所有文件必须完整可执行，学生在课堂上完成端到端部署。

五、课堂互动设计

互动 1：开场回顾——Docker 知识体系串联（讲解 K12-1 时）

项目 内容
互动问题 "前 11 次课我们学了 Docker 的哪些核心能力？请用一句话总结每个模块。如果让你现在独立部署 CTTS 三服务，你会按什么步骤来？"
组织方式 全班自由发言，教师在黑板/白板上画出"Docker 知识地图"思维导图，学生补充节点
预期学生输出 提到"装 Docker、管镜像、管容器、写 Dockerfile、配网络、挂数据卷、Compose 编排"等关键词；能大致说出"先 MySQL、再后端、最后前端"的部署顺序
教师点评要点 肯定学生的体系认知；指出"散点知识"必须通过"完整项目"才能转化为"工程能力"；引出本节课目标——把所有散点串成一条完整的部署链路

互动 2：项目演示——Docker 部署成果展示（讲解 K12-6 时）

项目 内容
互动任务 每组（4~5 人）上台演示本组 CTTS 部署成果：①展示项目结构 ②执行 docker compose up -d --build ③浏览器访问前端 ④curl 调用后端 API ⑤回答教师 1~2 个提问
组织方式 每组演示 5 分钟 + 教师提问 2 分钟，共约 30 分钟；其余组同步在台下观摩并记录问题
预期学生输出 能完整跑通部署流程；能讲清楚"为什么 backend 要等 mysql 健康检查通过""为什么前端 Nginx 要反代后端""多阶段构建的好处"等关键点
教师点评要点 重点评价三点：①部署是否一次成功（工程规范）②排障思路是否清晰（运维能力）③表达是否准确（技术沟通能力）。对典型问题做集中讲解，对优秀实践做推广

互动 3：故障排查——"为什么我的后端连不上数据库"（K12-6 排障环节）

项目 内容
互动问题 教师现场制造一个故障（如把 depends_on: condition: service_healthy 改成默认 service_started），让全班观察后端启动日志，分析原因
组织方式 全班观察 → 分组讨论 2 分钟 → 推代表回答 → 教师复盘
预期学生输出 能从日志中识别"Connection refused""HikariCP connection failed"等关键字；能定位到"MySQL 还没就绪，后端就启动了"；能给出"加 healthcheck + service_healthy"的解决方案
教师点评要点 强调"看日志是排障的第一步"；总结"启动顺序 ≠ 就绪顺序"是 Compose 工程的常见坑；引出 K8s 中类似问题的处理思路（liveness/readiness probe）

六、课程思政融入点

项目 内容
融入点 完整交付——从代码到容器的全链路
技术关联 单个 Dockerfile 只是"碎片化的容器化"，只有把 SQL/Dockerfile/Compose/网络/存储/反代串联起来，才能真正交付一个"用户能访问的应用"。这背后是"全链路工程"思维：开发→打包→编排→部署→验证→排障，缺一不可
引导问题 "如果一个工程师只会写 Dockerfile，但不会编排、不会排障，他能独立交付项目吗？企业真正需要的是什么样的人？"
预期价值目标 让学生理解"完整交付"是工程师的核心竞争力；鼓励学生从"会写命令"升级为"能独立交付项目"；培养系统思维与责任意识——交付的每一步都要对结果负责

思政自然融入，不空喊口号。通过"完整部署一个能跑的应用"的真实体验，让学生体会"工程闭环"的价值。

七、课堂练习或随堂测验

随堂练习（5 分钟，K12-5 讲解后进行）

判断题（口头快速作答）：

  1. docker compose up -d --build 中的 --build 表示启动前强制重新构建镜像。（✓）
  2. MySQL 容器的 healthcheck 用 mysqladmin ping 即可，不需要传用户名密码。（✗，需要 -uroot -p密码）
  3. 前端 Nginx 反向代理 /api/ 到 backend:8080，可以避免浏览器跨域问题。（✓）
  4. 多阶段构建的最大价值是把"构建工具"与"运行时"分离，减小镜像体积。（✓）
  5. docker compose down 默认会删除具名数据卷，数据库数据会丢失。（✗，默认保留，加 -v 才删）

详细题目与解析见 题库.md。此处仅作课堂快速互动，不计分。

八、课后任务

  1. 完善交付：把课堂上的 CTTS 部署方案完善（如增加 Redis 缓存服务、增加日志卷、优化 Dockerfile 缓存层），提交完整 ctts-deploy.zip（含所有文件 + README.md 部署说明）。
  2. 排障复盘：写一份《CTTS 部署排障记录》，记录至少 3 个实际遇到的问题及解决过程（含日志截图、原因分析、解决方案）。
  3. 思考题：对比"手工 docker run 部署"与"Compose 一键部署"，从效率、可复现性、可维护性、团队协作四个维度分析，写 300 字小结。
  4. 过渡预习：阅读课程总览中第 13 次课（Kubernetes 认知与架构）部分，思考"为什么 Compose 解决了单机部署，但生产环境仍需要 K8s？"。
  5. 拓展阅读：了解 kompose 工具（把 docker-compose.yml 转换为 K8s YAML），尝试把本节课的 compose 文件转换为 K8s 资源清单（选做，为第 13 次课做铺垫）。
  6. Docker 部分总复习：通读第 1~12 次课的 教学资料.md，重点复习 Dockerfile 多阶段构建、Compose 编排、网络与存储，准备 Docker 部分阶段性测验。
