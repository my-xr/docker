一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

09-选择-001（★ 知识点：K9-1 网络子系统职责） Docker 网络子系统不负责解决下列哪项问题？

  • A容器之间的网络隔离
  • B容器之间的相互通信
  • C容器内文件系统的分层存储
  • D外部用户访问容器内服务

答案：C 解析：Docker 网络子系统负责隔离、互通、外部访问三大职责。文件系统分层存储是镜像/容器存储子系统（UnionFS）的职责，与网络无关。A、B、D 都是网络子系统的职责。

09-选择-002（★ 知识点：K9-1 默认网络） Docker 安装完成后默认会自动创建几个网络？

  • A1 个
  • B2 个
  • C3 个
  • D5 个

答案：C 解析：Docker 安装后默认创建 3 个网络：bridge（默认驱动）、host、none。macvlan 和 ipvlan 需要用户手动创建。

09-选择-003（★ 知识点：K9-1 默认网络驱动） 不指定 --network 参数启动容器时，容器默认加入的网络驱动是？

  • Ahost
  • Bnone
  • Cbridge
  • Dmacvlan

答案：C 解析：不指定 --network 时，容器默认加入默认 bridge 网络（名为 bridge，对应网桥 docker0）。host 和 none 必须显式指定 --network host / --network none。

09-选择-004（★ 知识点：K9-2 docker0 网桥） 默认 bridge 网络对应的虚拟网桥设备名是？

  • Abr0
  • Beth0
  • Cdocker0
  • Dveth0

答案：C 解析：默认 bridge 网络在宿主机上对应的虚拟网桥设备名为 docker0，默认 IP 通常是 172.17.0.1/16。

09-选择-005（★ 知识点：K9-2 默认 bridge 局限） 关于默认 bridge 网络，下列说法正确的是？

  • A支持通过容器名互访
  • B内置 DNS 服务自动解析容器名
  • C只能通过 IP 进行容器间通信，无容器名 DNS 解析
  • D容器端口默认对宿主机外部开放

答案：C 解析：默认 bridge 没有 DNS 解析服务，同网络容器只能通过 IP 互访。A、B 错；D 错，容器端口默认只在 bridge 内可达，外部访问必须 -p 映射。

09-选择-006（★ 知识点：K9-2 bridge 互通） 在默认 bridge 网络中，两个容器之间如何通信？

  • A只能通过容器名通信
  • B只能通过容器 IP 通信
  • C通过宿主机端口映射通信
  • D无法通信

答案：B 解析：默认 bridge 没有内嵌 DNS，容器之间只能通过 IP 互访。由于容器 IP 是动态分配的（重启可能变），用 IP 不可靠，这正是默认 bridge 的局限。

09-选择-007（★ 知识点：K9-3 host 网络） 关于 host 网络模式，下列说法正确的是？

  • A容器有独立的网络命名空间
  • B容器直接共享宿主机的网络栈
  • C容器端口需要 -p 映射才能被外部访问
  • D容器之间可以通过容器名互访

答案：B 解析：host 模式下容器直接共享宿主机网络栈，没有独立网络命名空间。A 错；C 错，host 模式下容器端口即宿主机端口，-p 会被忽略；D 错，host 模式没有 Docker DNS。

09-选择-008（★ 知识点：K9-3 none 网络） none 网络模式下，容器拥有哪种网络接口？

  • A只有 eth0
  • B只有 lo（本地回环）
  • Ceth0 和 lo 都有
  • D没有任何网络接口

答案：B 解析：none 网络的容器拥有独立的网络命名空间，但只有 lo（回环接口，127.0.0.1），没有 eth0，无法访问任何外部地址，也无法被外部访问。

09-选择-009（★ 知识点：K9-3 host 适用场景） 下列场景中，最适合使用 host 网络模式的是？

  • A生产环境的 Web 服务对外提供服务
  • B数据库容器需要被多个应用访问
  • C网络调试工具需要抓取宿主机所有流量
  • D安全沙箱中运行不可信代码

答案：C 解析：host 模式共享宿主网络栈，适合网络调试、抓包或对性能极致敏感的场景。A、B 应该用 bridge；D 应该用 none（完全隔离）。

09-选择-010（★ 知识点：K9-3 none 适用场景） 下列场景中，最适合使用 none 网络模式的是？

  • A微服务快速弹性扩容
  • B分析不可信文件的安全沙箱
  • C前端 Web 服务对用户暴露
  • D数据库服务被后端按名访问

答案：B 解析：none 模式完全无网络（仅有 lo），适合安全沙箱、离线计算、断网测试等场景。A、C、D 都需要网络，应该用 bridge。

09-选择-011（★ 知识点：K9-4 自定义网络命令） 创建自定义 bridge 网络的命令是？

  • Adocker network add mynet
  • Bdocker network create mynet
  • Cdocker create network mynet
  • Ddocker bridge create mynet

答案：B 解析：创建自定义网络的命令是 docker network create <网络名>。不指定 --driver 时默认创建 bridge 驱动。

09-选择-012（★ 知识点：K9-4 自定义网络优势） 相对默认 bridge，自定义 bridge 网络的主要优势是？

  • A启动速度更快
  • B支持容器名 DNS 解析
  • C容器端口默认对外暴露
  • D不需要 -p 端口映射

答案：B 解析：自定义 bridge 内嵌 DNS 服务（127.0.0.11），支持容器名互访；同时可按业务创建多个网络实现隔离。A 错，启动速度与网络类型无关；C 错，自定义 bridge 端口也默认不对宿主机暴露；D 错，外部访问仍需 -p。

09-选择-013（★ 知识点：K9-4 指定网络） 启动容器时指定加入自定义网络的参数是？

  • A--net mynet
  • B--network mynet
  • C--custom-network mynet
  • D--bridge mynet

答案：B 解析：docker run --network <网络名> 指定容器初始加入的网络。--net 是 --network 的简写形式（也合法），但完整写法是 --network。

09-选择-014（★ 知识点：K9-4 内嵌 DNS） 自定义 bridge 网络中，Docker 内嵌 DNS 服务的 IP 地址是？

  • A127.0.0.1
  • B127.0.0.11
  • C172.17.0.1
  • D8.8.8.8

答案：B 解析：自定义 bridge 网络中 Docker 内嵌 DNS 服务监听在 127.0.0.11，自动为该网络内容器注册 <容器名> → IP 的解析记录。可通过 cat /etc/resolv.conf 查看。

09-选择-015（★ 知识点：K9-5 容器间通信） 同一自定义 bridge 网络内的两个容器，如何相互访问？

  • A必须用容器 IP
  • B必须用 -p 端口映射
  • C通过容器名直接访问
  • D通过宿主机 localhost

答案：C 解析：同一自定义 bridge 网络内的容器，通过 Docker 内嵌 DNS 用容器名互访。A 错，IP 不可靠；B 错，-p 只用于外部访问；D 错，跨容器不能用 localhost。

09-选择-016（★ 知识点：K9-5 跨网络通信） 把已运行的容器追加接入第二个网络的命令是？

  • Adocker network add
  • Bdocker network connect
  • Cdocker network attach
  • Ddocker container join

答案：B 解析：docker network connect <网络名> <容器名> 把容器追加接入到目标网络，容器会获得该网络中的一个 IP，并能按容器名访问该网络内的容器。

09-选择-017（★ 知识点：K9-5 跨网络隔离） 关于跨网络容器通信，下列说法正确的是？

  • A任何网络的容器都能通过容器名互访
  • B跨网络容器默认隔离，需 docker network connect 才能按名访问
  • C跨网络容器只要 IP 通就能用容器名互访
  • Dhost 网络的容器能访问所有自定义网络容器

答案：B 解析：Docker DNS 按网络隔离，每个网络有自己的 DNS 视图。跨网络默认隔离，必须用 docker network connect 把容器接入目标网络才能按容器名访问。A、C、D 都错。

09-选择-018（★ 知识点：K9-6 端口映射方向） docker run -p 8080:80 nginx 命令中端口映射的方向是？

  • A容器 8080 → 宿主机 80
  • B宿主机 8080 → 容器 80
  • C容器 80 → 宿主机 8080
  • D宿主机 80 → 容器 8080

答案：B 解析：-p 宿主机端口:容器端口，即把宿主机 8080 端口的流量转发到容器 80 端口。外部访问 http://宿主机IP:8080 实际访问的是容器内的 80 端口服务。

09-选择-019（★ 知识点：K9-6 同网络通信端口） 同一自定义 bridge 网络内的容器 A 访问容器 B 的 8080 端口，正确的访问方式是？

  • Acurl http://容器B的IP:8080（必须用 IP）
  • Bcurl http://宿主机IP:8080
  • Ccurl http://容器B名称:8080
  • Dcurl http://localhost:8080

答案：C 解析：同自定义网络内容器通过容器名 + 容器内端口直接访问，不需要 -p 映射，也不需要 IP。A 可行但不可靠（IP 会变）；B、D 错，跨容器不能用宿主机或 localhost。

09-选择-020（★ 知识点：K9-6 端口映射作用） -p 端口映射的主要作用是？

  • A让同网络容器互相通信
  • B让宿主机外部能访问容器内服务
  • C让容器访问外网
  • D加快容器启动速度

答案：B 解析：-p 把宿主机端口流量转发到容器端口，让宿主机外部用户能访问容器内服务。A 错，同网络通信不需要 -p；C 错，容器访问外网靠 iptables NAT 自动处理；D 错，与启动速度无关。

09-选择-021（★★ 知识点：K9-2 bridge 原理） bridge 网络中，容器与虚拟网桥之间连接使用的虚拟网络设备是？

  • Aveth pair（虚拟以太网卡对）
  • Btap 设备
  • Cvxlan 隧道
  • D物理网卡

答案：A 解析：bridge 网络通过 veth pair（一对虚拟以太网卡）连接容器与网桥：一端在容器内（eth0），另一端插到宿主机的 docker0 网桥上，两端通过内核连通。

09-选择-022（★★ 知识点：K9-2 容器访问外网） bridge 网络中的容器能访问外网，依靠的技术是？

  • ADocker 内嵌 DNS
  • Biptables MASQUERADE（源地址转换）
  • Cveth pair 虚拟网卡
  • D-p 端口映射

答案：B 解析：容器出向流量经过 iptables MASQUERADE 规则做源地址转换（容器 IP → 宿主机 IP），让容器能访问外网。DNS 只负责域名解析；veth pair 只负责容器到网桥的连接；-p 只用于外部访问容器。

09-选择-023（★★ 知识点：K9-3 host 端口冲突） 在 host 网络模式下启动两个容器都监听 80 端口，会发生什么？

  • A两个容器共享 80 端口
  • B第二个容器启动失败，端口被占用
  • CDocker 自动分配不同端口
  • D两个容器都正常工作

答案：B 解析：host 模式下容器直接用宿主机端口，两个容器都监听 80 会冲突，第二个启动失败报 bind: address already in use。这是 host 模式的主要局限之一。

09-选择-024（★★ 知识点：K9-3 host 模式 -p） 在 host 网络模式下使用 -p 80:80 参数，会发生什么？

  • A端口映射正常生效
  • B-p 被忽略并告警
  • C容器启动失败
  • D端口冲突

答案：B 解析：host 模式下容器端口已经是宿主机端口，-p 没有意义会被忽略，并提示 WARNING: Published ports are discarded when using host network mode。

09-选择-025（★★ 知识点：K9-4 自定义网络子网） 创建自定义网络时指定子网和网关的正确命令是？

  • Adocker network create --subnet 172.20.0.0/16 --gateway 172.20.0.1 mynet
  • Bdocker network create --ip 172.20.0.0/16 --gw 172.20.0.1 mynet
  • Cdocker network create --cidr 172.20.0.0/16 --router 172.20.0.1 mynet
  • Ddocker network create -subnet 172.20.0.0/16 -gateway 172.20.0.1 mynet

答案：A 解析：docker network create --subnet <CIDR> --gateway <IP> <网络名> 指定子网和网关。不指定时 Docker 自动分配。

09-选择-026（★★ 知识点：K9-4 删除网络） 删除自定义网络 mynet 的命令是？

  • Adocker network delete mynet
  • Bdocker network rm mynet
  • Cdocker network remove mynet
  • Ddocker rm network mynet

答案：B 解析：docker network rm <网络名> 删除自定义网络。注意：网络内若有活跃容器，删除会报错 network has active endpoints，需先断开或删除容器。

09-选择-027（★★ 知识点：K9-4 删除网络限制） 删除自定义网络时，若网络内仍有活跃容器，会发生什么？

  • A网络和容器一起被删除
  • B报错 network has active endpoints，删除失败
  • C容器被自动断开，网络被删除
  • D网络被强制删除，容器不受影响

答案：B 解析：Docker 不允许删除仍有活跃容器的网络，会报 network has active endpoints。必须先停止并删除容器，或用 docker network disconnect 断开所有容器，才能删除网络。

09-选择-028（★★ 知识点：K9-5 容器名解析） 自定义 bridge 网络内容器名 ctts-backend 被解析为容器 IP，解析过程由谁完成？

  • A宿主机 /etc/resolv.conf 中的 DNS
  • B公网 DNS 服务器
  • CDocker 内嵌 DNS 服务（127.0.0.11）
  • D容器内 /etc/hosts 文件

答案：C 解析：自定义 bridge 网络中 Docker 内嵌 DNS 服务（127.0.0.11）负责容器名→IP 的解析。容器内 /etc/resolv.conf 自动指向 127.0.0.11。A、B、D 都不是。

09-选择-029（★★ 知识点：K9-5 connect 影响） 执行 docker network connect net2 containerA 后，下列说法正确的是？

  • AcontainerA 与原网络断开，只接入 net2
  • BcontainerA 同时存在于原网络和 net2 中
  • CcontainerA 重启后才会接入 net2
  • DcontainerA 的 IP 地址被改变

答案：B 解析：docker network connect 是追加接入，不断开原网络。容器会同时存在于原网络和 net2 中，获得 net2 中的一个 IP，原有 IP 保持不变。

09-选择-030（★★ 知识点：K9-6 CTTS 网络设计） 在 CTTS 三服务网络方案中，MySQL 容器为什么不对宿主机暴露 3306 端口？

  • A因为后端无法通过容器名连接 MySQL
  • B因为 MySQL 不需要被后端访问
  • C遵循最小暴露面原则，避免数据库被公网爆破或漏洞利用
  • D因为 3306 端口被宿主机占用

答案：C 解析：MySQL 容器不对宿主机暴露 3306 是网络安全设计——最小暴露面原则。后端在同自定义网络内通过容器名 ctts-mysql 访问即可，无需 -p 映射。公网暴露 3306 会被扫描爆破，存在严重安全风险。A、B、D 都错。

1.2 多项选择题（10 题）

09-选择-031（★★ 知识点：K9-1 内置网络驱动） 下列属于 Docker 内置网络驱动的有？（多选）

  • Abridge
  • Bhost
  • Cnone
  • Dmacvlan E. vmware

答案：A、B、C、D 解析：Docker 内置网络驱动包括 bridge、host、none、macvlan、ipvlan（还有 Swarm 集群用的 overlay）。E 错，vmware 是虚拟机技术，不是 Docker 网络驱动。

09-选择-032（★★ 知识点：K9-1 网络子系统职责） Docker 网络子系统负责解决的核心问题包括？（多选）

  • A容器之间的网络隔离
  • B容器之间的相互通信
  • C外部用户访问容器内服务
  • D容器镜像的分层存储 E. 容器内进程的 CPU 调度

答案：A、B、C 解析：网络子系统三大职责：隔离、互通、外部访问。D 是存储子系统（UnionFS）的职责；E 是操作系统进程调度的职责。

09-选择-033（★★ 知识点：K9-2 默认 bridge 局限） 默认 bridge 网络的局限包括？（多选）

  • A没有容器名 DNS 解析
  • B所有容器在同一网络，无法按业务隔离
  • C容器 IP 动态变化，用 IP 互访不可靠
  • D容器无法访问外网 E. 不支持端口映射

答案：A、B、C 解析：默认 bridge 无 DNS（A）、隔离弱（B）、IP 动态（C）。D 错，bridge 容器能访问外网（iptables MASQUERADE）；E 错，默认 bridge 支持 -p 端口映射。

09-选择-034（★★ 知识点：K9-3 三种驱动对比） 下列关于 bridge、host、none 三种网络驱动的对比，正确的有？（多选）

  • Abridge 有独立网络命名空间，host 没有
  • Bnone 完全无网络接口（包括 lo 也没有）
  • Chost 性能最好但无隔离
  • Dbridge 支持端口映射，host 不需要 -p E. none 适合安全沙箱场景

09-判断-001（★ 知识点：K9-1 默认网络） Docker 安装后会自动创建 bridge、host、none 三个默认网络。

答案：正确（✓） 解析：Docker 安装完成后默认创建 3 个网络：bridge（默认驱动）、host、none。可用 docker network ls 查看。

09-判断-003（★ 知识点：K9-3 host 网络） host 网络模式下容器与宿主机共享网络栈，容器端口即宿主机端口。

答案：正确（✓） 解析：host 模式下容器直接使用宿主机的网络命名空间，没有独立网卡、IP、端口空间，容器端口就是宿主机端口。

09-判断-004（★ 知识点：K9-3 none 网络） none 网络模式下容器没有任何网络接口，连 lo 回环都没有。

答案：错误（✗） 解析：none 网络的容器有独立的网络命名空间，且有 lo（本地回环，127.0.0.1），只是没有 eth0，无法访问外部地址。说"没有任何网络接口"是错的。

09-判断-005（★ 知识点：K9-4 自定义网络优势） 自定义 bridge 网络相对默认 bridge 的主要优势之一是支持容器名 DNS 解析。

答案：正确（✓） 解析：自定义 bridge 内嵌 DNS 服务（127.0.0.11），自动注册容器名→IP 的解析记录，支持容器名互访，这是相对默认 bridge 的核心优势之一。

09-判断-006（★ 知识点：K9-4 自定义网络创建） 创建自定义 bridge 网络的命令是 docker network create <网络名>。

答案：正确（✓） 解析：docker network create <网络名> 创建自定义 bridge 网络（默认驱动为 bridge）。可用 --driver bridge 显式指定。

09-判断-007（★ 知识点：K9-5 同网络通信） 同一自定义 bridge 网络内的容器之间通信也需要使用 -p 端口映射。

答案：错误（✗） 解析：同自定义网络内容器通过容器名 + 容器内端口直接访问，不需要 -p 端口映射。-p 只用于宿主机外部访问容器。

09-判断-008（★ 知识点：K9-5 跨网络通信） 跨网络的容器默认隔离，需要使用 docker network connect 才能按容器名互访。

答案：正确（✓） 解析：Docker DNS 按网络隔离，跨网络默认无法按容器名互访。必须用 docker network connect <目标网络> <容器名> 把容器追加接入目标网络。

09-判断-009（★ 知识点：K9-6 端口映射方向） -p 8080:80 表示把容器的 8080 端口映射到宿主机的 80 端口。

答案：错误（✗） 解析：方向反了。-p 宿主机端口:容器端口，-p 8080:80 表示把宿主机 8080 端口的流量转发到容器 80 端口，即外部访问 宿主机:8080 实际访问容器内 80。

09-判断-010（★ 知识点：K9-6 CTTS 设计） 在 CTTS 三服务网络方案中，MySQL 容器应该用 -p 3306:3306 对外暴露端口，方便外部直接连接。

09-判断-011（★★ 知识点：K9-2 bridge IP 动态） 容器的 IP 地址在容器重启后可能发生变化，因此默认 bridge 用 IP 互访不可靠。

答案：正确（✓） 解析：容器 IP 由 Docker 动态分配，重启后可能变化。默认 bridge 只能用 IP 互访，所以不可靠——这是自定义 bridge + 容器名 DNS 的核心动机。

09-判断-012（★★ 知识点：K9-2 docker0） 默认 bridge 网络对应的虚拟网桥设备名是 docker0，默认 IP 通常是 172.17.0.1。

答案：错误（✗） 解析：host 模式失去网络隔离、端口冲突风险高，不适合生产大规模部署。仅用于调试、抓包或对性能极致敏感的小规模场景。生产推荐自定义 bridge。

09-判断-014（★★ 知识点：K9-4 删除网络） 可以直接删除仍有活跃容器的自定义网络，Docker 会自动断开容器。

答案：错误（✗） 解析：host 模式下容器端口已经是宿主机端口，-p 会被忽略并告警 WARNING: Published ports are discarded when using host network mode。

09-判断-020（★★ 知识点：K9-6 最小暴露面） 生产环境应遵循"最小暴露面"原则，只对外暴露必要端口（如前端 80），数据库等内部服务不应直接对公网暴露。

答案：正确（✓） 解析：最小暴露面是网络安全的基本原则——只暴露必须对外提供服务的端口（如前端 80/443），数据库、缓存等内部服务应仅在同网络内被应用按容器名访问，不对公网暴露，降低攻击面。

09-论述-001（★★ 知识点：K9-2/K9-3 三种网络对比，10 分） 请从网络隔离、容器 IP、端口冲突、外部访问、容器间通信、性能、典型场景七个方面，对比 bridge、host、none 三种网络驱动。

参考答案与评分标准（10 分，按要点给分）：

  1. 网络隔离（1.5 分）：bridge 有独立网络命名空间；host 共享宿主机网络栈，无独立命名空间；none 有独立命名空间但无网络接口（除 lo）。
  2. 容器 IP（1 分）：bridge 有自己的 IP（如 172.17.0.x）；host 用宿主机 IP；none 仅 127.0.0.1。
  3. 端口冲突（1 分）：bridge 不会冲突（容器端口独立）；host 会冲突（容器端口即宿主端口）；none 不会（无网络）。
  4. 外部访问（1.5 分）：bridge 需要 -p 端口映射；host 直接访问（容器端口即宿主端口）；none 无法访问。
  5. 容器间通信（1.5 分）：bridge 同网络内可通过 IP/容器名（自定义 bridge）互访；host 通过 localhost+端口；none 无法通信。
  6. 性能（1 分）：bridge 有 NAT 开销略低；host 无 NAT 性能最好；none N/A。
  7. 典型场景（2.5 分）：bridge 适合普通应用容器（Web、API、DB），自定义 bridge 是生产推荐；host 适合调试、抓包或性能极致场景；none 适合安全沙箱、离线计算。

09-论述-002（★★ 知识点：K9-2/K9-4 默认 vs 自定义 bridge，8 分） 请说明默认 bridge 网络与自定义 bridge 网络的主要区别，并解释为什么 Docker 官方推荐生产环境使用自定义 bridge。

参考答案与评分标准（8 分，按要点给分）：

  1. 默认 bridge 与自定义 bridge 的区别（5 分）：
    • 创建方式（1 分）：默认 bridge 由 Docker 安装时自动创建（名为 bridge，对应 docker0）；自定义 bridge 由用户用 docker network create 手动创建。
    • 容器名 DNS 解析（2 分）：默认 bridge 没有内嵌 DNS，容器只能用 IP 互访（IP 动态变化不可靠）；自定义 bridge 内嵌 DNS（127.0.0.11），支持容器名互访。
    • 网络隔离（1 分）：默认 bridge 所有容器在同一网络无法按业务隔离；自定义 bridge 可按业务创建多个网络实现隔离。

  2. 为什么推荐自定义 bridge（3 分）：

    • 可按业务创建多个网络实现网络隔离，安全性更好（1 分）。
    • 默认 bridge 是早期兼容性设计，自定义 bridge 是新设计，功能更完善（1 分）。

参考答案与评分标准（8 分，按要点给分）：

  1. 方式 1：同自定义网络按容器名通信（4 分）：
    • 原理（1.5 分）：同一自定义 bridge 网络内的容器，通过 Docker 内嵌 DNS（127.0.0.11）自动解析容器名→IP，直接用容器名互访。
    • 使用场景（1 分）：同一应用内的多个服务（如前端+后端+数据库）需要相互通信。
    • 命令示例（1.5 分）：docker network create ctts-net → docker run --name backend --network ctts-net ... → docker run --name frontend --network ctts-net ... → 前端用 curl http://backend:8080 访问后端。
  2. 方式 2：跨网络通信（docker network connect）（4 分）：
    • 原理（1.5 分）：把已运行的容器追加接入到目标网络，容器获得目标网络的 IP，并能按容器名访问该网络内的容器。
    • 使用场景（1 分）：容器需要访问另一个网络中的容器（如监控容器需要访问业务网络中的多个服务）。
    • 命令示例（1.5 分）：docker network connect ctts-net prometheus 把 prometheus 容器接入 ctts-net，之后 prometheus 能 ping 通 ctts-net 中的 backend、frontend 等容器。

评分要点：两种方式各自独立给分；原理、场景、命令示例三要素齐全即可满分。

09-论述-004（★★ 知识点：K9-6 CTTS 网络方案设计，10 分） 请为 CTTS 三服务（前端 Vue3+Nginx + 后端 SpringBoot + MySQL）设计完整的容器网络通信方案，要求说明：①使用哪种网络驱动及原因；②三个容器分别接入哪些网络；③哪些端口需要对外映射；④容器间如何互访；⑤从网络安全角度说明设计原则。

参考答案与评分标准（10 分，按要点给分）：

  1. 网络驱动选型（2 分）：选择自定义 bridge 网络（如 ctts-net）。原因：bridge 兼顾隔离与互通；自定义 bridge 内置 DNS 支持容器名互访，避免依赖动态 IP；可按业务隔离。host 失去隔离、none 无法通信都不适合。
  2. 三容器网络接入（2 分）：三个容器都接入同一自定义 bridge 网络 ctts-net。前端 ctts-frontend、后端 ctts-backend、MySQL ctts-mysql 都用 --network ctts-net 加入。
  3. 端口对外映射（2 分）：仅前端 -p 80:80 对外暴露 80 端口供用户访问；后端不 -p 暴露（前端通过容器名访问）；MySQL 不 -p 暴露（后端通过容器名访问）。
  4. 容器间互访方式（2 分）：前端通过 http://ctts-backend:8080 访问后端 API（Nginx 反向代理）；后端通过 jdbc:mysql://ctts-mysql:3306/ctts 连接 MySQL。均通过 Docker 内嵌 DNS 解析容器名。
  5. 网络安全设计原则（2 分）：遵循"最小暴露面"原则，只对外暴露必要端口（前端 80）；MySQL 不对公网暴露 3306（防止暴力破解、漏洞利用、数据泄露）；后端不对宿主机暴露 8080；通过自定义 bridge 实现"默认隔离、按需放通"。

评分要点：五个要点各自独立给分；方案合理即可，不要求与答案完全一致；技术选型合理替代同样给分。
