14-选择-001（★ 知识点：K14-1 方案选型） 下列 K8s 集群搭建方案中，适合本地学习与开发测试的是？

  • Akubeadm
  • BMinikube
  • C云托管 K8s（如阿里云 ACK）
  • D手动二进制部署

答案：B 解析：Minikube 是 K8s 官方维护的单机学习集群工具，适合本地学习与开发测试。kubeadm 适合生产自建多节点集群；云托管 K8s 适合公有云生产；手动二进制部署门槛极高，不推荐。

14-选择-002（★ 知识点：K14-1 方案选型） 生产环境自建机房搭建 K8s 集群，推荐使用的工具是？

  • AMinikube
  • BKind
  • Ckubeadm
  • DDocker Compose

答案：C 解析：kubeadm 是 K8s 官方推荐的生产级多节点集群搭建工具，适合自建机房。Minikube 单机学习用；Kind 是 CI 测试用；Docker Compose 不是 K8s 集群搭建工具。

14-选择-016（★ 知识点：K14-4 kubeadm 前置） 使用 kubeadm 搭建 K8s 集群时，必须关闭的系统功能是？

  • A防火墙
  • Bswap 分区
  • CSSH 服务
  • Dcron 定时任务

答案：B 解析：K8s 设计上禁止 swap，kubelet 启动时若发现 swap 开启会拒绝启动，必须 swapoff -a 并注释 /etc/fstab。防火墙学习时可关，但不是必须；SSH 和 cron 不影响。

14-选择-017（★ 知识点：K14-4 kubeadm 流程） kubeadm 初始化 master 控制平面的命令是？

  • Akubeadm create master
  • Bkubeadm init
  • Ckubeadm start
  • Dkubeadm bootstrap

答案：B 解析：kubeadm init 在 master 节点上初始化控制平面，拉起 etcd/API Server/scheduler/controller-manager 并生成 worker 加入命令。

14-选择-018（★ 知识点：K14-4 kubeadm 流程） worker 节点加入 K8s 集群使用的命令是？

  • Akubeadm add
  • Bkubeadm join
  • Ckubeadm connect
  • Dkubeadm register

答案：B 解析：kubeadm join <master-ip>:6443 --token ... --discovery-token-ca-cert-hash ... 让 worker 节点加入集群。

14-选择-019（★ 知识点：K14-4 kubeadm join 执行位置） kubeadm join 命令应该在哪个节点上执行？

  • Amaster 节点
  • B任意 worker 节点
  • Cmaster 和所有 worker 同时执行
  • D仅在 etcd 节点

答案：B 解析：kubeadm join 在每台 worker 节点上执行，让该 worker 向 master 注册。在 master 上执行是错误的。

14-选择-020（★ 知识点：K14-4 kubeadm init 产出） kubeadm init 执行成功后，会输出的关键信息是？

  • A集群登录密码
  • Bworker 节点加入命令（kubeadm join + token）
  • Cmaster 的 SSH 密钥
  • Detcd 的访问密钥

答案：B 解析：kubeadm init 成功后输出 kubeadm join ... --token ... --discovery-token-ca-cert-hash ... 命令，用于 worker 加入集群，必须妥善保存。

14-选择-021（★ 知识点：K14-4 CNI 网络插件） kubeadm init 完成后，节点状态仍为 NotReady 的常见原因是？

  • A没装 CNI 网络插件
  • Bkubectl 版本不对
  • Ckubeconfig 没配置
  • Dswap 没关

答案：A 解析：kubeadm init 后必须安装 CNI 网络插件（如 Calico、Flannel），否则节点间网络不通，kubelet 上报 NotReady。装完 CNI 后节点才会变 Ready。

14-选择-022（★ 知识点：K14-4 kubeconfig 配置） kubeadm init 后，配置 kubectl 需要拷贝的文件是？

  • A/etc/kubernetes/kubelet.conf

  • C/var/lib/kubelet/config.yaml
  • D/etc/cni/net.d/calico.conf

答案：B 解析：把 /etc/kubernetes/admin.conf 拷贝到 ~/.kube/config 并 chown 给当前用户，kubectl 即可连接集群。

14-选择-024（★ 知识点：K14-5 kubectl 命令） 查看某节点详细信息的命令是？

14-选择-025（★ 知识点：K14-5 节点状态） kubectl get nodes 输出中 STATUS 列为 Ready 表示？

  • A节点已就绪，可以接受调度 Pod
  • B节点正在重启
  • C节点已删除
  • D节点处于维护模式

答案：A 解析：Ready 表示节点健康，kubelet 正常上报，可以接受 Pod 调度。NotReady 表示节点异常或不满足调度条件。

14-选择-026（★ 知识点：K14-5 Pod 状态） kubectl get pods 输出中 READY 列 1/1 表示？

  • A该 Pod 有 1 个容器，1 个就绪
  • B该 Pod 有 1 个副本，1 个运行
  • C该 Pod 启动了 1 次
  • D该 Pod 使用 1 核 CPU

答案：A 解析：READY 列格式为 <就绪容器数>/<总容器数>，1/1 表示 Pod 内 1 个容器全部就绪。2/2 表示 2 个容器都就绪，0/1 表示 1 个容器中 0 个就绪。

14-选择-027（★ 知识点：K14-5 命令区别） kubectl get 与 kubectl describe 的区别是？

  • Aget 查看列表概要，describe 查看单个详情
  • Bget 只读，describe 可写
  • Cget 查看实时状态，describe 查看历史
  • D二者完全相同

答案：A 解析：get 输出资源列表概要（一行一个），describe 输出单个资源的详细信息（含 Events、配置、状态）。排查问题用 describe。

14-选择-028（★★ 知识点：K14-5 排查） 节点状态为 NotReady 时，排查的第一步通常是？

  • A重启该节点
  • B重装 K8s
  • Ckubectl describe node 查看 Conditions
  • D删除该节点重新加入

答案：C 解析：先 kubectl describe node <name> 看 Conditions 部分找异常原因（如 KubeletNotReady），再针对性排查。直接重启/重装/删除都是不查明原因的暴力操作。

14-选择-030（★ 知识点：K14-6 镜像准备） 在 Minikube 学习环境中，让自构建镜像直接被 Pod 使用的命令是？

答案：A、B、C、D 解析：四种方式都可行：Minikube Docker daemon 直接构建（学习用）、Docker Hub/ACR/Harbor 推送后拉取（生产做法）。K8s 集群本身不提供镜像构建能力，E 错误。

二、判断题（共 20 题，每题 1 分）

14-判断-001（★ 知识点：K14-1 Minikube 适用） Minikube 适合生产环境部署，可以承载真实业务流量。

答案：错误（✗） 解析：Minikube 是单机学习集群，无高可用、无多节点，仅适合学习开发测试，不能用于生产。

14-判断-002（★ 知识点：K14-1 kubeadm 定位） kubeadm 是 K8s 官方推荐的多节点集群搭建工具，至今仍是生产环境自建集群的主流方式。

答案：正确（✓） 解析：kubeadm 是官方推荐生产级搭建工具，至今主流，云托管 K8s 底层很多也基于 kubeadm 或类似工具。

14-判断-003（★ 知识点：K14-2 Minikube 前提） 使用 docker 驱动启动 Minikube 时，必须先安装 Docker。

答案：正确（✓） 解析：docker 驱动依赖 Docker 引擎，必须先装 Docker。其他驱动（virtualbox 等）则需对应虚拟化软件。

14-判断-004（★ 知识点：K14-2 镜像加速） 国内网络环境下启动 Minikube 必须加 --image-mirror-country=cn 参数，否则可能卡在拉镜像。

答案：正确（✓） 解析：国内拉 registry.k8s.io 镜像很慢或超时，加 --image-mirror-country=cn 使用国内镜像源。

14-判断-005（★ 知识点：K14-2 stop vs delete） minikube stop 会删除集群及其所有配置数据。

答案：错误（✗） 解析：stop 只停止集群运行，配置和数据保留，下次 minikube start 即可恢复。minikube delete 才是删除集群。

14-判断-006（★ 知识点：K14-3 kubectl 必要性） 只要安装了 kubectl，就能连接并管理任意 K8s 集群。

答案：错误（✗） 解析：kubectl 是客户端，还需要正确的 kubeconfig 文件（含 API Server 地址和认证信息）才能连接集群。仅有 kubectl 没有 kubeconfig 无法连接。

14-判断-007（★ 知识点：K14-3 kubeconfig 自动生成） Minikube 启动时会自动生成 kubeconfig 文件写入 ~/.kube/config。

答案：正确（✓） 解析：Minikube 启动时自动把集群连接信息写入 ~/.kube/config，kubectl 即可直接连接。

14-判断-008（★ 知识点：K14-3 kubectl 部署位置） kubectl 必须安装在 K8s 集群的节点上才能管理集群。

答案：错误（✗） 解析：kubectl 是客户端，可装在任何能访问 API Server 的机器上（笔记本、跳板机），通过 kubeconfig 远程连接集群。这是 C/S 架构的优势。

14-判断-009（★ 知识点：K14-4 swap 要求） 使用 kubeadm 搭建 K8s 集群时，必须先关闭所有节点的 swap 分区。

答案：正确（✓） 解析：K8s 设计上禁止 swap，kubelet 启动时若发现 swap 开启会拒绝启动，必须 swapoff -a 并注释 /etc/fstab。

14-判断-010（★ 知识点：K14-4 join 执行位置） kubeadm join 命令需要在 master 节点上执行，让 master 加入 worker。

答案：错误（✗） 解析：kubeadm join 在 worker 节点上执行，让 worker 加入 master。在 master 上执行是错误的。

14-判断-011（★ 知识点：K14-4 CNI 必要性） kubeadm init 完成后，节点状态会立即变 Ready，无需额外操作。

答案：错误（✗） 解析：kubeadm init 后节点状态为 NotReady，因为还没装 CNI 网络插件。必须 kubectl apply -f calico.yaml 安装 CNI 后节点才会变 Ready。

14-判断-012（★ 知识点：K14-4 token 有效期） kubeadm init 生成的 join token 默认永久有效。

答案：错误（✗） 解析：kubeadm join token 默认 24 小时有效。过期后可在 master 上用 kubeadm token create --print-join-command 重新生成。

14-判断-013（★ 知识点：K14-5 get vs describe） kubectl get nodes 输出节点列表概要，kubectl describe node <name> 输出节点详细信息。

答案：正确（✓） 解析：get 输出列表概要（一行一个），describe 输出单个资源详情（Conditions、Capacity、Events 等）。

14-判断-014（★ 知识点：K14-5 -A 参数） kubectl get pods 默认查看所有 namespace 下的 Pod。

答案：错误（✗） 解析：kubectl get pods 默认只查看 default namespace 下的 Pod。加 -A（--all-namespaces）才查看所有 namespace。

14-判断-015（★ 知识点：K14-5 READY 含义） kubectl get pods 输出中 READY 列 0/1 表示该 Pod 内 1 个容器，0 个就绪。

答案：正确（✓） 解析：READY 列格式 <就绪容器数>/<总容器数>，0/1 表示 1 个容器中 0 个就绪，可能是正在启动或异常。

14-判断-016（★ 知识点：K14-5 dashboard） Minikube dashboard 是 K8s 集群的必备组件，生产环境必须安装。

答案：错误（✗） 解析：dashboard 是 Minikube 的 addon，学习可视化用。生产环境通常不装 dashboard（用 kubectl 命令行更专业、更安全）。

14-判断-017（★ 知识点：K14-6 namespace 隔离） CTTS 项目应该把所有资源部署到 default namespace，避免创建多个 namespace 增加复杂度。

答案：错误（✗） 解析：建议创建独立 namespace（如 ctts）做资源隔离，便于管理、清理、权限控制。default namespace 通常留给系统默认资源。

14-判断-018（★ 知识点：K14-6 Minikube 资源） Minikube 默认 2 核 2G 足够跑下 CTTS 三服务（前端+后端+MySQL）。

答案：错误（✗） 解析：CTTS 三服务加系统组件约需 3.5 核 4G，Minikube 默认 2 核 2G 不够，启动时需指定 --cpus=4 --memory=6g。

14-判断-019（★★ 知识点：K14-4 kubeadm 高可用） 生产环境推荐使用 3 个 master 节点做高可用，单 master 挂了另外两个接管。

答案：正确（✓） 解析：生产环境用 3 个 master 节点 + 堆叠或外部 etcd 做高可用，单 master 挂了另外两个接管，避免单点故障。

14-判断-020（★ 知识点：K14-6 镜像拉取策略） 在 Minikube 中用 eval $(minikube docker-env) 构建的镜像，Pod YAML 应设置 imagePullPolicy: Never，否则会去仓库拉取导致失败。

答案：正确（✓） 解析：Minikube Docker daemon 构建的镜像只在节点本地，默认 imagePullPolicy 是 Always 会去仓库拉取（找不到）。设置 Never 让 K8s 只用本地镜像。

14-编程-001（★★ 知识点：K14-6 CTTS 集群准备，15 分） CTTS 集群环境准备脚本设计：请为 CTTS 三服务 K8s 部署设计一份集群环境准备 Shell 脚本，要求包含：

  1. 启动 4 核 6G 的 Minikube 集群（含国内镜像加速）（3 分）
  2. 创建 ctts namespace（2 分）
  3. 切换到 Minikube Docker daemon 并构建前后端镜像（4 分）
  4. 拉取 MySQL 官方镜像（2 分）
  5. 启用 ingress、metrics-server、dashboard 三个 addons（3 分）
  6. 输出集群就绪汇总信息（1 分）

参考答案与评分标准（15 分）：

#!/bin/bash
# CTTS K8s 集群环境准备脚本
# 作者：第 14 次课作业
# 用法：bash prepare-ctts-cluster.sh

set -e

echo "===== 步骤 1：启动 Minikube 集群（4 核 6G，国内镜像加速）====="
minikube start \
  --cpus=4 \
  --memory=6g \
  --driver=docker \
  --image-mirror-country=cn
# 验证
kubectl get nodes
echo "===== 步骤 2：创建 ctts namespace ====="
kubectl create namespace ctts --dry-run=client -o yaml | kubectl apply -f -
kubectl get namespaces

echo "===== 步骤 3：切换到 Minikube Docker daemon 并构建镜像 ====="
eval $(minikube docker-env)

# 构建后端镜像（假设 Dockerfile 在 ~/ctts/backend/）
cd ~/ctts/backend
docker build -t ctts-backend:v1 .

# 构建前端镜像（假设 Dockerfile 在 ~/ctts/frontend/）
cd ~/ctts/frontend
docker build -t ctts-frontend:v1 .

# 验证镜像
docker images | grep ctts

echo "===== 步骤 4：拉取 MySQL 官方镜像 ====="
docker pull mysql:8.0
docker images | grep mysql

echo "===== 步骤 5：启用 addons ====="
minikube addons enable dashboard
minikube addons enable metrics-server
minikube addons enable ingress
minikube addons list | grep -E "dashboard|metrics-server|ingress"

echo "===== 步骤 6：集群就绪汇总 ====="
echo "==============================================="
echo "  CTTS K8s 集群环境准备完成"
echo "==============================================="
echo "集群节点："
kubectl get nodes
echo ""
echo "Namespace：ctts 已创建"
echo "镜像：ctts-backend:v1 / ctts-frontend:v1 / mysql:8.0 已就绪"
echo "Addons：dashboard / metrics-server / ingress 已启用"
echo "状态：✅ 可进入第 15 次课 Pod 部署"
echo "==============================================="

评分要点：

  • 步骤 1（3 分）：启动命令正确（cpus/memory/driver/image-mirror-country 全）
  • 步骤 2（2 分）：创建 namespace 命令正确
  • 步骤 3（4 分）：eval 切换 + 两次 docker build + 验证
  • 步骤 4（2 分）：docker pull mysql:8.0
  • 步骤 5（3 分）：三个 addons enable 命令
  • 步骤 6（1 分）：输出汇总信息
  • 脚本结构合理、可执行、有注释额外加分；缺少 set -e 或注释不扣分。
