1.1 单项选择题（30 题）

05-选择-001（★ 知识点：K5-1 镜像选型） 本次课 CTTS 三服务容器化，MySQL 使用的官方镜像标签是？

  • Amysql:latest
  • Bmysql:8.0
  • Cmysql:8
  • Dmysql:stable

答案：B 解析：本次课统一使用 mysql:8.0，明确版本号便于复现。A 错，不使用 :latest 因为不可控；C 错，mysql:8 虽然也存在但不规范；D 错，MySQL 没有 :stable 标签。

05-选择-002（★ 知识点：K5-1 镜像选型） 关于 Nginx 官方镜像的 Web 根目录，正确的是？

  • A/var/www/html
  • B/usr/share/nginx/html
  • C/etc/nginx/html
  • D/home/nginx/html

答案：B 解析：Nginx 官方镜像默认 Web 根目录是 /usr/share/nginx/html，由 /etc/nginx/conf.d/default.conf 配置。A 是 Apache 的默认目录；C、D 不是 Nginx 的目录。

05-选择-003（★ 知识点：K5-1 镜像标签） 关于镜像标签，下列做法正确的是？

  • A学习阶段可以用 :latest，生产环境用明确版本
  • B无论学习还是生产，都应明确指定版本号
  • C:latest 一定指向最新最稳定版本
  • D不写标签时默认使用 :stable

答案：B 解析：无论学习还是生产都应明确版本号，保证可复现。:latest 不保证最新最稳定，可能指向任意版本；不写标签默认 :latest 而非 :stable。

05-选择-004（★ 知识点：K5-2 MySQL 容器） 运行 MySQL 容器时，必须设置的环境变量是？

  • AMYSQL_DATABASE
  • BMYSQL_USER
  • CMYSQL_ROOT_PASSWORD
  • DMYSQL_PORT

答案：C 解析：MYSQL_ROOT_PASSWORD 是 MySQL 官方镜像的必填环境变量，不设置容器启动会报错退出。A、B 是可选环境变量；D 不是 MySQL 镜像的环境变量（端口在镜像内已固定为 3306）。

05-选择-005（★ 知识点：K5-2 MySQL 容器） 运行 MySQL 容器的命令 docker run -d --name ctts-mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0 中，-p 3306:3306 的含义是？

  • A宿主机 3306 端口映射到容器 3306 端口
  • B容器 3306 端口映射到宿主机 3306 端口
  • C仅打开容器 3306 端口
  • D仅打开宿主机 3306 端口

答案：A 解析：-p 宿主端口:容器端口，前者是宿主机端口，后者是容器端口，表示把宿主机 3306 端口的流量转发到容器 3306 端口。B 顺序写反；C、D 不完整。

05-选择-006（★ 知识点：K5-2 docker exec） 进入 MySQL 容器执行交互式 SQL 命令，正确的命令是？

  • Adocker exec ctts-mysql mysql -uroot -p123456
  • Bdocker exec -it ctts-mysql mysql -uroot -p123456
  • Cdocker run -it ctts-mysql mysql -uroot -p123456
  • Ddocker attach ctts-mysql mysql -uroot -p123456

答案：B 解析：进入运行中的容器用 docker exec -it（-i 交互式，-t 分配伪终端）。A 缺少 -it，无法交互；C 用 docker run 会创建新容器；D docker attach 是连接到容器主进程，不能执行新命令。

05-选择-007（★★ 知识点：K5-2 SQL 初始化） 将宿主机的 ctts-init.sql 文件内容传给 MySQL 容器执行，正确的命令是？

  • Adocker exec -it ctts-mysql mysql -uroot -p123456 < ctts-init.sql
  • Bdocker exec -i ctts-mysql mysql -uroot -p123456 < ctts-init.sql
  • Cdocker exec ctts-mysql mysql -uroot -p123456 < ctts-init.sql
  • Ddocker cp ctts-init.sql ctts-mysql:/tmp/ && docker exec ctts-mysql mysql -uroot -p123456

答案：B 解析：用 docker exec -i（仅 -i，不带 -t）配合 < 重定向，可将宿主机文件内容传给容器内命令。A 带 -t 会与重定向冲突报错；C 缺少 -i 无法接收标准输入；D 用 docker cp 也可行但更繁琐，且第二条命令仍需用 -e 执行 SQL 文件。

05-选择-008（★ 知识点：K5-3 Nginx 挂载） 将宿主机 ~/ctts/nginx-html 挂载到 Nginx 容器的 /usr/share/nginx/html，正确的参数是？

  • A-v /usr/share/nginx/html:~/ctts/nginx-html
  • B-v ~/ctts/nginx-html:/usr/share/nginx/html
  • C-mount ~/ctts/nginx-html:/usr/share/nginx/html
  • D-volume ~/ctts/nginx-html:/usr/share/nginx/html

答案：B 解析：-v 宿主路径:容器路径，前者是宿主机路径，后者是容器内路径。A 顺序反了；C、D 参数名错误，正确参数是 -v 或 --mount（--mount 语法不同，需 type=bind,source=...,target=...）。

05-选择-009（★ 知识点：K5-3 Nginx 验证） 运行 Nginx 容器后，在宿主机用命令行验证 HTTP 服务，可用的命令是？

  • Acurl http://localhost
  • Bping localhost
  • Ctelnet localhost 80
  • Dftp localhost

答案：A 解析：curl http://localhost 发 HTTP 请求并返回响应内容，是验证 Web 服务的常用命令。B ping 只能验证网络连通性，不能验证 HTTP 服务；C telnet 可验证端口但操作繁琐；D ftp 是文件传输协议，不适用于 HTTP 验证。

05-选择-010（★ 知识点：K5-4 Java 镜像） 关于 openjdk:17-jdk-slim 镜像，下列说法正确的是？

  • A只能运行 Java 程序，不能编译
  • B包含 JDK，既能编译也能运行 Java 程序
  • C体积比 openjdk:17 完整版大
  • D不能运行 jar 包

答案：B 解析：17-jdk-slim 是 JDK 的 slim 变体，包含 javac 编译器和 java 运行时，既能编译也能运行。A 错，JDK 包含 javac；C 错，slim 体积更小；D 错，java -jar 可以运行 jar 包。

05-选择-011（★ 知识点：K5-4 Java 运行） 用 OpenJDK 容器运行 jar 包，正确的命令形式是？

  • Adocker run -v app.jar:/app.jar openjdk:17-jdk-slim java -jar app.jar
  • Bdocker run -v ~/app.jar:/app/app.jar -w /app openjdk:17-jdk-slim java -jar app.jar
  • Cdocker run openjdk:17-jdk-slim -jar app.jar
  • Ddocker run openjdk:17-jdk-slim java app.jar

答案：B 解析：需要 -v 挂载 jar 到容器，-w 指定工作目录，再执行 java -jar app.jar。A 没指定工作目录且路径不规范；C 缺少 java 命令；D 缺少 -jar 参数。

05-选择-012（★★ 知识点：K5-4 JDK vs JRE） 运行一个已编译好的 SpringBoot jar 包，应该选择哪个镜像体积更小？

  • Aopenjdk:17-jdk-slim
  • Bopenjdk:17-jre-slim
  • Copenjdk:17
  • Dopenjdk:17-jdk

答案：B 解析：运行 jar 包只需 JRE（Java Runtime Environment），不需要 JDK 的编译工具（javac）。17-jre-slim 体积最小。A、C、D 都含 JDK，体积更大。

05-选择-013（★ 知识点：K5-5 --link） 关于 docker run --link，下列说法正确的是？

  • A--link 是双向通信机制
  • B--link 是单向通信机制，且已被官方标记为 legacy
  • C--link 是现代 Docker 推荐的容器通信方式
  • D--link 必须配合自定义网络使用

答案：B 解析：--link 是单向的（A link B，只有 A 能找 B），已被官方标记为 legacy（过时）。现代推荐做法是自定义网络（第 9 次课）。A 错，单向；C 错，已过时；D 错，--link 在默认 bridge 网络下即可用。

05-选择-014（★ 知识点：K5-5 --link 原理） --link 实现容器间通信的原理是？

  • A在容器内安装额外的网络驱动
  • B在新容器的 /etc/hosts 中添加目标容器的 IP 映射
  • C创建一个新的虚拟网卡
  • D通过环境变量传递 IP

答案：B 解析：--link 的原理是在新容器的 /etc/hosts 文件中添加一条记录，把目标容器的 IP 映射到指定别名。其他选项都不是 --link 的机制。

05-选择-015（★ 知识点：K5-6 故障排查） 容器启动后立即退出，排查问题的第一步应该是？

  • A直接删除容器重建
  • B重启 Docker 服务
  • C用 docker logs <容器名> 查看日志
  • D重装 Docker

答案：C 解析：容器故障排查的第一步是看日志，docker logs 能显示容器内应用的报错信息，据此定位原因。A、B、D 都是"盲目重装"的错误做法。

05-选择-016（★ 知识点：K5-6 端口冲突） 运行容器报错 Bind for 0.0.0.0:80 failed: port is already allocated，原因是？

  • A容器内 80 端口未开放
  • B宿主机 80 端口已被其他进程占用
  • C镜像不支持 80 端口
  • DDocker 服务未启动

答案：B 解析：该报错表示宿主机 80 端口已被占用（可能是宿主机的 Apache/Nginx 等）。解决方案是换一个宿主机端口，如 -p 8080:80。

05-选择-017（★ 知识点：K5-6 容器状态） 查看所有容器（包括已停止的），正确的命令是？

  • Adocker ps
  • Bdocker ps -a
  • Cdocker ps -l
  • Ddocker ps -q

答案：B 解析：docker ps 只显示运行中的容器；docker ps -a 显示所有容器（包括已停止的）；-l 显示最新创建的一个；-q 只显示容器 ID。

05-选择-018（★ 知识点：K5-6 数据丢失） 删除 MySQL 容器后重建，发现数据库表数据丢失，最可能的原因是？

  • AMySQL 版本不对
  • B容器未配置数据卷持久化 /var/lib/mysql
  • Croot 密码错误
  • D网络不通

答案：B 解析：未配置数据卷时，容器删除后 /var/lib/mysql 目录的数据随之丢失。需要用 -v ~/mysql-data:/var/lib/mysql 挂载数据卷持久化（第 10 次课详讲）。其他选项与数据丢失无关。

05-选择-019（★★ 知识点：K5-2 MySQL 启动） MySQL 容器刚启动时立即连接报 Can't connect to MySQL server，原因是？

  • AMySQL 镜像有问题
  • BMySQL 还在初始化数据库，尚未就绪
  • C端口映射错误
  • D容器名错误

答案：B 解析：MySQL 容器首次启动需 10~20 秒初始化数据库，看到日志 "ready for connections" 才能连接。立即连接会报连接失败。其他选项不是该报错的原因。

05-选择-020（★ 知识点：K5-2 环境变量） 设置 MySQL 容器自动创建 ctts 数据库的环境变量是？

  • AMYSQL_ROOT_PASSWORD=ctts
  • BMYSQL_DATABASE=ctts
  • CMYSQL_USER=ctts
  • DCREATE_DATABASE=ctts

答案：B 解析：MYSQL_DATABASE=ctts 让 MySQL 官方镜像在启动时自动创建 ctts 数据库。A 是设置 root 密码；C 是创建用户；D 不是 MySQL 镜像的环境变量。

05-选择-021（★ 知识点：K5-3 挂载特性） 修改宿主机的 index.html 后，Nginx 容器提供的页面立即更新，原因是？

  • ADocker 自动重启了 Nginx 容器
  • B-v 挂载是实时同步的，宿主机文件变化容器内立即可见
  • CNginx 自动检测文件变化
  • D浏览器自动刷新

答案：B 解析：-v 挂载是实时同步的，宿主机文件变化容器内立即可见，刷新浏览器即可看到新内容，无需重启容器。其他选项都不是原因。

05-选择-022（★★ 知识点：K5-5 --link 单向性） docker run --link ctts-mysql:mysql nginx:stable 后，下列说法正确的是？

  • Actts-mysql 容器能用 "nginx" 这个名字访问 nginx 容器
  • Bnginx 容器能用 "mysql" 这个名字访问 ctts-mysql 容器
  • C两个容器互相都能用名字访问
  • D两个容器都不能用名字访问

答案：B 解析：--link 是单向的，A link B 后只有 A（nginx）能用别名（mysql）访问 B（ctts-mysql），反向不行。这正是 --link 的局限之一。

05-选择-023（★ 知识点：K5-4 临时容器） 执行 docker run --rm openjdk:17-jdk-slim java -version，--rm 参数的作用是？

  • A删除镜像
  • B容器退出后自动删除该容器
  • C强制删除已有同名容器
  • D重启容器

答案：B 解析：--rm 表示容器退出后自动删除，适合一次性命令（如验证版本、编译等）。A 错，不删镜像；C 错，不强制删除已有容器；D 错，不重启。

05-选择-024（★ 知识点：K5-3 Nginx 端口） Nginx 官方镜像默认监听的端口是？

  • A8080
  • B80
  • C443
  • D3306

答案：B 解析：Nginx 官方镜像默认监听 80 端口（HTTP），由 /etc/nginx/conf.d/default.conf 配置。443 是 HTTPS 端口（需额外配置）；8080 是常用替代端口；3306 是 MySQL 端口。

05-选择-025（★ 知识点：K5-2 进入容器） docker exec -it ctts-mysql bash 命令中，-it 两个参数的含义分别是？

  • A-i 进入容器，-t 分配终端
  • B-i 保持标准输入打开，-t 分配伪终端
  • C-i 交互模式，-t 终端模式
  • D-i 忽略错误，-t 超时设置

答案：B 解析：-i（interactive）保持标准输入打开，-t（tty）分配伪终端，两者配合才能进入交互式 shell。A、C、D 都不准确。

05-选择-026（★★ 知识点：K5-6 排查流程） 容器故障排查的标准流程，顺序正确的是？

  • Adocker rm → docker run → docker logs
  • Bdocker ps -a → docker logs → docker inspect → docker exec
  • Cdocker logs → docker rm → docker run
  • Ddocker exec → docker logs → docker ps

答案：B 解析：标准流程是先看容器状态（docker ps -a），再看日志（docker logs），再看详细配置（docker inspect），最后进入容器手动排查（docker exec）。盲目 docker rm 重建是错误做法。

05-选择-027（★ 知识点：K5-1 镜像查看） 查看本地已拉取的镜像列表，命令是？

  • Adocker images
  • Bdocker ps
  • Cdocker list
  • Ddocker inspect

答案：A 解析：docker images（或 docker image ls）列出本地所有镜像。B docker ps 列出容器；C 不是有效命令；D docker inspect 查看详细信息。

05-选择-028（★★ 知识点：K5-2 MySQL 数据目录） MySQL 官方镜像中，数据存储的默认目录是？

  • A/etc/mysql
  • B/var/lib/mysql
  • C/usr/share/mysql
  • D/home/mysql

答案：B 解析：MySQL 官方镜像默认数据目录是 /var/lib/mysql，持久化数据需用 -v 挂载此目录。A 是配置文件目录；C、D 不是 MySQL 镜像的标准目录。

05-选择-029（★ 知识点：K5-3 Nginx 入口命令） Nginx 官方镜像的入口命令（CMD）是？

  • Anginx
  • Bnginx -g 'daemon off;'
  • Cservice nginx start
  • Dsystemctl start nginx

答案：B 解析：Nginx 官方镜像入口命令是 nginx -g 'daemon off;'，以前台模式运行 Nginx（容器需要前台进程才能保持运行）。A 会让 Nginx 后台运行导致容器立即退出；C、D 是宿主机的服务管理命令，不适用于容器。

05-选择-030（★★ 知识点：K5-6 综合排查） 某同学运行 Nginx 容器后访问 http://localhost 返回 403 Forbidden，最可能的原因是？

  • ANginx 镜像有问题
  • B挂载的宿主机目录为空或 HTML 文件不存在
  • C端口映射错误
  • DDocker 服务未启动

答案：B 解析：403 Forbidden 表示服务器拒绝请求，通常是因为目录为空或文件权限不足。Nginx 找不到 index.html 会返回 403。其他选项都不是 403 的原因。

1.2 多项选择题（10 题）

05-选择-031（★★ 知识点：K5-1 镜像选型） 本次课 CTTS 三服务容器化用到的官方镜像有？（多选）

  • Amysql:8.0
  • Bnginx:stable
  • Copenjdk:17-jdk-slim
  • Dubuntu:22.04 E. redis:7

答案：A、B、C 解析：本次课 CTTS 三服务分别用 mysql:8.0（MySQL）、nginx:stable（Nginx）、openjdk:17-jdk-slim（Java）。D、E 不在本次课三服务范围内。

05-选择-032（★★ 知识点：K5-2 docker run 参数） 运行 MySQL 容器的 docker run 命令中，用到的参数有？（多选）

  • A-d
  • B--name
  • C-p
  • D-e E. --link

答案：A、B、C、D 解析：运行 MySQL 容器用 -d（后台）、--name（命名）、-p（端口映射）、-e（环境变量）。--link 是 Nginx 容器 link MySQL 时用的，不是 MySQL 容器自身用的参数。

05-选择-033（★★ 知识点：K5-2 MySQL 环境变量） MySQL 官方镜像支持的环境变量包括？（多选）

  • AMYSQL_ROOT_PASSWORD
  • BMYSQL_DATABASE
  • CMYSQL_USER
  • DMYSQL_PASSWORD E. MYSQL_PORT

答案：A、B、C、D 解析：MySQL 官方镜像支持 MYSQL_ROOT_PASSWORD（root 密码，必填）、MYSQL_DATABASE（自动建库）、MYSQL_USER/MYSQL_PASSWORD（自动建用户）。E 错，MySQL 端口在镜像内固定为 3306，不能通过环境变量修改。

05-选择-034（★★ 知识点：K5-6 常见问题） 本次课实践中可能遇到的常见问题有？（多选）

  • A容器无法启动（环境变量缺失）
  • B端口冲突

    • 已过时：被官方标记为 legacy，不推荐生产使用（1 分）
    • 不稳定：重启容器后可能失效，不支持动态更新（1 分）

  3. 现代替代方案（1 分）：

    • 推荐用自定义网络（custom bridge network）（0.5 分）
    • 创建网络 docker network create ctts-net，把容器加入网络后即可用容器名双向通信（0.5 分）

  4. --link 单向性验证（1 分）：

    • 在 nginx 容器（A）--link ctts-mysql（B）后：
      • 在 nginx 容器内 getent hosts mysql 能解析（A 能找 B）（0.5 分）
      • 在 mysql 容器内 getent hosts nginx 不能解析（B 不能找 A）（0.5 分）

评分要点：四部分分别给分；原理要说到 /etc/hosts；局限性至少答出单向和过时；替代方案要提自定义网络。

docker run -d \

  • 必须包含 -d、--name、-p 80:80、-v 挂载到 /usr/share/nginx/html、--link ctts-mysql:mysql（每项 0.8 分，共 4 分）

docker run -d \
  --name ctts-backend \
  -p 8080:8080 \
  -v ~/ctts/java-app/ctts-backend.jar:/app/app.jar \
  -w /app \
  openjdk:17-jdk-slim \

  • 必须包含 -d、--name、-p 8080:8080、-v 挂载 jar、-w /app、java -jar app.jar（每项约 0.7 分，共 4 分）
