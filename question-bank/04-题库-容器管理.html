1.1 单项选择题（30 题）

04-选择-001（★ 知识点：K4-1 容器生命周期） 下列命令中，用于优雅停止一个运行中的容器的是？

  • Adocker kill
  • Bdocker stop
  • Cdocker rm
  • Ddocker pause

答案：B 解析：docker stop 先发 SIGTERM 信号让主进程优雅退出，超时后才发 SIGKILL，是生产推荐的停止方式。docker kill 直接发 SIGKILL 强制终止；docker rm 是删除容器；docker pause 是暂停容器（冻结进程）。

04-选择-002（★ 知识点：K4-1 容器生命周期） 容器被 docker stop 停止后，其状态变为？

  • Arunning
  • Bpaused
  • Cexited
  • Ddead

答案：C 解析：docker stop 让主进程退出，容器状态变为 exited（已退出但容器仍存在，可通过 docker ps -a 查看）。running 是运行中；paused 是冻结；dead 是异常状态。

04-选择-003（★ 知识点：K4-1 容器生命周期） 下列说法正确的是？

  • A容器 exited 后就自动删除了
  • B容器 exited 后仍存在，可通过 docker start 重新启动
  • C容器 exited 后无法重新启动
  • D容器 exited 后镜像也被删除

答案：B 解析：exited 只是主进程退出，容器本身（文件系统、配置等）仍存在。可以用 docker start 重新启动，或 docker rm 删除。镜像不受影响。

04-选择-004（★ 知识点：K4-2 docker run 参数） docker run -d nginx 中的 -d 参数表示？

  • A删除容器
  • B后台运行容器
  • C调试模式
  • D指定镜像版本

答案：B 解析：-d 即 --detach，让容器在后台运行，命令立即返回容器 ID。前台运行时不加 -d，终端会被容器日志占据。

04-选择-005（★ 知识点：K4-2 docker run 参数） docker run --name myweb nginx 中 --name 的作用是？

  • A设置镜像名
  • B给容器命名
  • C设置网络名
  • D设置主机名

答案：B 解析：--name 给容器指定一个可读的名字（如 myweb），便于后续管理。不指定则 Docker 自动生成随机名（如 nostalgic_einstein）。

04-选择-006（★ 知识点：K4-2 端口映射） docker run -p 8080:80 nginx 中端口映射的方向是？

  • A容器 8080 → 宿主机 80
  • B宿主机 8080 → 容器 80
  • C容器 80 → 宿主机 8080
  • D双向映射

答案：B 解析：-p hostPort:containerPort，方向是宿主机端口映射到容器端口（外→内）。访问宿主机 8080 端口的流量会被转发到容器内 80 端口。

04-选择-007（★ 知识点：K4-2 环境变量） 运行 MySQL 容器时设置 root 密码的参数是？

  • A--password=123456
  • B-e MYSQL_ROOT_PASSWORD=123456
  • C--root-password 123456
  • D--env-password 123456

答案：B 解析：-e（即 --env）用于设置环境变量。MySQL 官方镜像通过 MYSQL_ROOT_PASSWORD 环境变量接收 root 密码，是必填项。

04-选择-008（★ 知识点：K4-2 docker run 参数） docker run --rm alpine echo hello 中 --rm 的作用是？

  • A删除镜像
  • B容器退出后自动删除容器
  • C强制删除已有同名容器
  • D重启容器

答案：B 解析：--rm 让容器在退出（主进程结束）后自动删除，适合一次性任务容器（如运行测试、执行脚本）。echo hello 执行完容器立即退出并自动删除。

04-选择-009（★ 知识点：K4-3 容器查看） 查看所有容器（包括已停止的）的命令是？

  • Adocker ps
  • Bdocker ps -a
  • Cdocker ps -q
  • Ddocker ps -n 5

答案：B 解析：docker ps 只显示运行中的容器；docker ps -a 显示所有容器（包括 exited 状态的）；-q 只显示容器 ID；-n 5 显示最近 5 个容器。

04-选择-010（★ 知识点：K4-3 容器查看） docker stats 命令用于查看？

  • A容器列表
  • B容器资源占用（CPU/内存/网络/IO）
  • C容器内进程
  • D容器日志

答案：B 解析：docker stats 实时显示每个容器的 CPU、内存、网络 IO、磁盘 IO 占用情况，类似 Linux 的 top 命令。按 Ctrl+C 退出。

04-选择-011（★ 知识点：K4-3 容器查看） 查看容器内进程列表的命令是？

  • Adocker ps
  • Bdocker stats
  • Cdocker top <容器>
  • Ddocker logs <容器>

答案：C 解析：docker top <容器> 显示容器内的进程列表（UID/PID/PPID/CMD 等），PID 是宿主机视角的进程 ID。docker ps 是容器列表；docker stats 是资源监控；docker logs 是日志。

04-选择-012（★ 知识点：K4-4 容器日志） 实时跟踪容器日志的命令是？

  • Adocker logs <容器>
  • Bdocker logs -f <容器>
  • Cdocker logs --tail 10 <容器>
  • Ddocker logs -t <容器>

答案：B 解析：-f 即 --follow，实时跟踪日志输出（类似 tail -f），有新日志会持续显示，按 Ctrl+C 退出（容器继续运行）。

04-选择-013（★ 知识点：K4-4 容器进入） 进入运行中的容器开一个新 bash 终端的命令是？

  • Adocker attach <容器>
  • Bdocker exec -it <容器> bash
  • Cdocker enter <容器>
  • Ddocker shell <容器>

答案：B 解析：docker exec -it <容器> bash 在容器内新开一个 bash 进程，exit 后容器继续运行，是推荐的进入容器方式。docker attach 连接主进程，Ctrl+c 可能导致容器停止。

04-选择-014（★★ 知识点：K4-4 exec vs attach） 关于 docker exec 和 docker attach 的区别，下列说法正确的是？

  • A二者完全等价
  • Bexec 开新进程，attach 连接主进程
  • Cattach 比 exec 更安全
  • Dexec 会停止容器

答案：B 解析：exec 在容器内新开一个独立进程（如 bash），exit 不影响主进程；attach 直接连接到容器主进程的 stdin/stdout，Ctrl+c 会发信号给主进程可能导致容器停止。生产中推荐 exec。

04-选择-015（★ 知识点：K4-5 容器详情） 查看容器完整元数据（JSON 格式）的命令是？

  • Adocker info <容器>
  • Bdocker inspect <容器>
  • Cdocker show <容器>
  • Ddocker describe <容器>

答案：B 解析：docker inspect <容器> 输出容器的完整元数据，包括 ID、状态、网络、端口、挂载、配置等，JSON 格式。可用 -f 模板提取特定字段。

04-选择-016（★ 知识点：K4-5 端口映射） -P（大写）参数的作用是？

  • A删除所有端口映射
  • B随机映射镜像中 EXPOSE 的所有端口到宿主机高位端口
  • C映射所有端口到 80
  • D与 -p 等价

答案：B 解析：-P（大写）将镜像中 EXPOSE 声明的端口随机映射到宿主机 49000-49900 范围的高位端口。用 docker port <容器> 查看随机分配的端口。-p 是指定端口映射。

04-选择-017（★★ 知识点：K4-5 端口映射） 启动容器时报错 Bind for 0.0.0.0:8080 failed: port is already allocated，原因是？

  • A镜像不存在
  • B容器名冲突
  • C宿主机 8080 端口已被其他容器或进程占用
  • D容器内 80 端口未开放

答案：C 解析：报错说明宿主机的 8080 端口已被占用（可能被另一个容器的端口映射占用，或被宿主机其他进程占用）。解决方法是换一个宿主机端口（如 -p 8081:80）。

04-选择-018（★ 知识点：K4-6 MySQL 容器） 运行 MySQL 容器时必填的环境变量是？

  • AMYSQL_DATABASE
  • BMYSQL_USER
  • CMYSQL_ROOT_PASSWORD
  • DMYSQL_PORT

答案：C 解析：MYSQL_ROOT_PASSWORD 设置 root 密码，是 MySQL 官方镜像的必填项，不填会启动失败。其他变量（DATABASE/USER/PASSWORD）是可选的初始化配置。

04-选择-019（★ 知识点：K4-1 容器生命周期） docker run 命令等价于下列哪两个命令的组合？

  • Adocker create + docker start
  • Bdocker create + docker exec
  • Cdocker pull + docker start
  • Ddocker build + docker start

答案：A 解析：docker run = docker create（创建容器）+ docker start（启动容器）。run 是一步到位，create 只创建不启动，start 启动已存在的停止容器。

04-选择-020（★ 知识点：K4-1 容器生命周期） 要删除一个运行中的容器，正确做法是？

  • A直接 docker rm <容器>
  • B先 docker stop 再 docker rm
  • C先 docker kill 再 docker rmi
  • D用 docker delete <容器>

答案：B 解析：删除运行中的容器会报错，需先 docker stop 停止再 docker rm 删除。或用 docker rm -f（强制删除，等价于 kill+rm，生产慎用）。docker rmi 是删除镜像。

04-选择-021（★★ 知识点：K4-2 docker run 参数） 要让容器在宿主机重启后自动启动，应使用参数？

  • A--restart=always
  • B--autostart
  • C--boot=true
  • D--start-on-boot

答案：A 解析：--restart 设置重启策略，always 表示总是自动重启（包括宿主机重启后）。其他选项有 no（默认）、on-failure、unless-stopped（推荐，除非手动 stop 否则总是重启）。

04-选择-022（★ 知识点：K4-4 容器日志） 只查看容器最后 20 行日志的命令是？

  • Adocker logs --tail 20 <容器>
  • Bdocker logs --last 20 <容器>
  • Cdocker logs -n 20 <容器>
  • Ddocker logs -f 20 <容器>

答案：A 解析：--tail 20 只显示最后 20 行日志，类似 tail -n 20。-f 是实时跟踪；-n 和 --last 不是 docker logs 的有效参数。

04-选择-023（★ 知识点：K4-3 容器查看） docker ps -q 命令的作用是？

  • A静默模式，不输出
  • B只显示容器 ID
  • C显示队列信息
  • D退出所有容器

答案：B 解析：-q 即 --quiet，只显示容器 ID（每行一个），常用于脚本中批量操作，如 docker stop $(docker ps -q) 停止所有运行中的容器。

04-选择-024（★★ 知识点：K4-4 进入容器） 在 alpine 镜像容器中执行 docker exec -it <容器> bash 报错 bash: not found，原因是？

  • Adocker 命令错误

  • C容器未运行
  • D权限不足

答案：B 解析：alpine 是精简镜像，默认只装了 sh 和 busybox 工具，没有 bash。进入 alpine 容器应用 docker exec -it <容器> sh。

04-选择-025（★★ 知识点：K4-5 inspect 模板） 用 docker inspect 提取容器 IP 地址的命令是？

  • Adocker inspect <容器> | grep ip
  • Bdocker inspect -f '{{.NetworkSettings.IPAddress}}' <容器>
  • Cdocker inspect --ip <容器>

答案：B 解析：docker inspect -f 使用 Go 模板语法提取特定字段。.NetworkSettings.IPAddress 是容器的 IP 地址字段。直接 grep 也能找到但不够精确。

04-选择-026（★ 知识点：K4-2 数据卷） docker run -v /data/mysql:/var/lib/mysql mysql:8.0 中 -v 参数的作用是？

  • A设置环境变量
  • B挂载数据卷（宿主机目录挂载到容器目录）
  • C设置虚拟内存
  • D指定版本

答案：B 解析：-v hostPath:containerPath 将宿主机目录挂载到容器内目录，实现数据持久化。/data/mysql 是宿主机目录，/var/lib/mysql 是容器内 MySQL 数据目录。

04-选择-027（★★ 知识点：K4-1 stop vs kill） 关于 docker stop 和 docker kill 的区别，下列说法正确的是？

  • A二者完全等价
  • Bstop 优雅停止（先 SIGTERM），kill 强制终止（直接 SIGKILL）
  • Ckill 比 stop 更推荐
  • Dstop 会删除容器，kill 不会

答案：B 解析：docker stop 先发 SIGTERM 让主进程优雅退出（可保存数据），超时后才 SIGKILL；docker kill 直接发 SIGKILL 立即终止，可能丢数据。生产推荐 stop。两者都不删除容器。

04-选择-028（★★ 知识点：K4-4 attach 风险） 使用 docker attach 进入容器后按 Ctrl+c，会发生什么？

  • A仅退出 attach 会话，容器继续运行
  • B发送 SIGINT 给容器主进程，可能导致容器停止
  • C什么都不发生
  • D容器自动重启

答案：B 解析：attach 共享主进程的 stdin，Ctrl+c 会发送 SIGINT 信号给主进程，可能导致容器停止。要脱离 attach 但不停止容器，应按 Ctrl+p 然后 Ctrl+q（detach keys）。

04-选择-029（★★ 知识点：K4-2 端口映射） docker run -p 127.0.0.1:8080:80 nginx 的含义是？

  • A容器监听 127.0.0.1:8080
  • B仅允许本机访问宿主机 8080 端口，转发到容器 80
  • C容器内 127.0.0.1:8080 转发到宿主机 80
  • D监听所有网卡的 8080

答案：B 解析：-p 127.0.0.1:8080:80 表示绑定到宿主机的 127.0.0.1 网卡（仅本机回环），外部无法访问。常用于数据库等不希望对外的服务。默认 -p 8080:80 绑定 0.0.0.0（所有网卡）。

04-选择-030（★★ 知识点：K4-6 MySQL 容器） 运行 MySQL 容器后立即用客户端连接报错 "Can't connect"，最可能的原因是？

  • A镜像损坏
  • BMySQL 首次启动需 10~30 秒初始化，尚未就绪
  • C端口映射错误
  • D容器名错误

答案：B 解析：MySQL 首次启动要初始化数据目录、创建系统表、创建用户和数据库，通常需 10~30 秒。用 docker logs -f 看到 ready for connections 后再连接。立即连接会因 MySQL 未就绪而失败。

04-选择-032（★★ 知识点：K4-1 容器生命周期） 下列命令中，能让容器进入 running 状态的有？（多选）

  • Adocker run
  • Bdocker start
  • Cdocker restart
  • Ddocker create E. docker unpause

答案：A、B、C、E 解析：docker run 创建并启动（→running）；docker start 启动已停止的容器（→running）；docker restart 重启（→running）；docker unpause 恢复暂停的容器（→running）。docker create 只创建不启动（→created）。

04-选择-033（★★ 知识点：K4-3 容器查看） 关于 docker ps 命令，下列说法正确的有？（多选）

  • Adocker ps 显示运行中的容器
  • Bdocker ps -a 显示所有容器包括已停止的
  • Cdocker ps -q 只显示容器 ID
  • Ddocker ps 显示容器内的进程列表 E. docker ps -n 5 显示最近 5 个容器

答案：A、B、C、E 解析：A、B、C、E 都是 docker ps 的正确用法。D 错，docker ps 显示的是容器列表，不是容器内的进程；查看容器内进程用 docker top <容器>。

04-选择-034（★★ 知识点：K4-4 容器日志与进入） 关于 docker exec 命令，下列说法正确的有？（多选）

  • A在运行中的容器内执行新命令
  • B会新开一个进程，不影响主进程
  • Cexit 退出后容器继续运行
  • D可以同时开多个 exec 会话 E. 会停止容器

答案：A、B、C、D 解析：exec 在容器内新开进程（A），不影响主进程（B），exit 后容器继续运行（C），支持多个 exec 会话（D）。E 错，exec 不会停止容器；attach 才有停止容器的风险。

04-选择-035（★★ 知识点：K4-4 exec vs attach） docker exec -it 和 docker attach 的区别包括？（多选）

  • Aexec 开新进程，attach 连接主进程
  • Bexec 退出后容器继续运行，attach 的 Ctrl+c 可能停止容器
  • Cexec 支持多会话，attach 多个连接共享同一终端
  • Dexec 更安全，生产推荐 E. 二者完全等价

答案：A、B、C、D 解析：A、B、C、D 都正确描述了 exec 与 attach 的区别。E 错，二者本质不同：exec 开新进程（安全），attach 连接主进程（危险）。

04-选择-036（★★ 知识点：K4-5 端口映射） 关于 Docker 端口映射，下列说法正确的有？（多选）

  • A-p 8080:80 表示宿主机 8080 映射到容器 80
  • B-P（大写）随机映射所有 EXPOSE 的端口
  • C-p 127.0.0.1:8080:80 表示仅本机可访问
  • D一个容器可以映射多个端口 E. 端口映射方向是"容器:宿主"

答案：A、B、C、D 解析：A、B、C、D 都正确。E 错，端口映射方向是"宿主:容器"（host:container，外:内），不是"容器:宿主"。

04-选择-037（★★ 知识点：K4-6 MySQL 容器） 运行 MySQL 容器时，下列环境变量中属于 MySQL 官方镜像支持的有？（多选）

  • AMYSQL_ROOT_PASSWORD
  • BMYSQL_DATABASE
  • CMYSQL_USER
  • DMYSQL_PASSWORD E. MYSQL_PORT

答案：A、B、C、D 解析：A、B、C、D 都是 MySQL 官方镜像支持的环境变量。A 必填，B/C/D 可选用于初始化。E 错，MySQL 默认端口 3306 由镜像决定，无 MYSQL_PORT 环境变量。

04-选择-038（★★ 知识点：K4-1 容器状态） 下列属于 Docker 容器状态的有？（多选）

  • Acreated
  • Brunning

04-论述-002（★★ 知识点：K4-4 exec vs attach，8 分） 请详细说明 docker exec -it <容器> bash 和 docker attach <容器> 的区别，并解释为什么生产环境中几乎都用 exec 而不用 attach。

参考答案与评分标准（8 分，按要点给分）：

  1. 原理区别（4 分）：

    • docker exec -it：在容器命名空间内新开一个进程（如 bash），与主进程独立。exit 仅退出 exec 的进程，不影响主进程和容器。（2 分）
    • docker attach：直接连接到容器主进程的 stdin/stdout/stderr，不开新进程。多个 attach 会话共享同一终端。（2 分）

  2. 行为区别（2 分）：

    • exec 的 exit：仅退出 exec 进程，容器继续运行。
    • attach 的 exit 或 Ctrl+c：会发信号给主进程，可能导致容器停止。
    • attach 要脱离但不停止容器，需按 Ctrl+p 然后 Ctrl+q（detach keys）。

  3. 生产推荐 exec 的原因（2 分）：

    • exec 不影响主进程，操作安全（Ctrl+c/exit 不会停容器）。
    • exec 支持同时多个会话，便于多人协作排障。
    • attach 的 Ctrl+c 风险高，一不小心就停了线上容器。
    • 因此生产排障几乎都用 docker exec -it <容器> bash。

评分要点：原理区别是核心，要突出"开新进程 vs 连接主进程"；行为区别要提到 Ctrl+c 的不同效果。

    • 8080:80 表示宿主机的 8080 端口映射到容器内的 80 端口。

  2. 客户端访问链路（4 分）：

    • 客户端访问 http://宿主机IP:8080
    • Docker 在宿主机启动 docker-proxy 进程（或 iptables NAT 规则）监听 0.0.0.0:8080
    • docker-proxy / iptables 将流量转发到容器的 IP（如 172.17.0.2）的 80 端口

    • 端口映射是容器服务对外暴露的标准方式。

评分要点：方向、链路、原因三部分分别给分；链路要提到 docker-proxy 或 iptables NAT。

04-编程-001（★★ 知识点：K4-2/K4-3 容器管理综合，15 分） 容器管理综合操作题：请按顺序写出完成以下任务的 Docker 命令，并说明每条命令的预期作用：

  1. 启动一个 nginx 容器，要求：后台运行、命名为 web-test、宿主机 8080 端口映射到容器 80、退出后自动删除（3 分）
  2. 查看该容器是否在运行（2 分）
  3. 实时查看该容器的日志（2 分）
  4. 进入容器查看 /etc/nginx 目录内容（3 分）
  5. 查看该容器的 IP 地址（用 docker inspect -f 模板）（3 分）
  6. 查看该容器的资源占用（2 分）

参考答案与评分标准（15 分）：

1. 启动容器（3 分）：

docker run -d --name web-test -p 8080:80 --rm nginx
  • -d 后台运行（0.5 分）
  • --name web-test 命名（0.5 分）
  • -p 8080:80 端口映射（0.5 分）
  • --rm 退出自动删除（0.5 分）
  • nginx 镜像名（0.5 分）
  • 预期作用：后台启动一个 nginx 容器，访问 http://localhost:8080 可见 nginx 默认页面

2. 查看运行状态（2 分）：

docker ps | grep web-test
# 或 docker ps --filter "name=web-test"
  • 预期输出：容器列表中能看到 web-test，STATUS 为 Up
  • 命令正确 1 分，预期作用 1 分

3. 实时查看日志（2 分）：

docker logs -f web-test
  • 预期作用：实时显示 nginx 的访问日志，按 Ctrl+C 退出（容器继续运行）
  • 命令正确 1 分，预期作用 1 分

4. 进入容器查看目录（3 分）：

docker exec -it web-test ls /etc/nginx
# 或先 docker exec -it web-test bash 进入后 ls /etc/nginx
  • 预期输出：列出 nginx 配置文件（nginx.conf、conf.d 等）
  • 命令正确 2 分，预期作用 1 分

5. 查看容器 IP（3 分）：

docker inspect -f '{{.NetworkSettings.IPAddress}}' web-test
# 或 docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' web-test
  • 预期输出：容器 IP，如 172.17.0.2
  • 命令正确 2 分，预期作用 1 分

6. 查看资源占用（2 分）：

docker stats --no-stream web-test
# 或 docker stats web-test（实时，需 Ctrl+C 退出）
  • 预期输出：显示 CPU%、内存、网络 IO 等资源占用
  • 命令正确 1 分，预期作用 1 分

评分要点：每部分独立给分；命令正确即可，参数顺序不扣分；预期作用要说到关键点。

04-编程-002（★★★ 知识点：K4-6 综合应用，20 分） MySQL 容器化部署与排障：某团队要为 CTTS 项目部署 MySQL 容器，团队成员小王执行了以下命令序列，但遇到了问题。请回答问题：

# 命令 1
docker run -d --name ctts-db -p 3306:3306 mysql:8.0

# 命令 2（几秒后）
docker exec -it ctts-db mysql -uroot -proot -e "SELECT 1;"

执行后小王发现：

  • 命令 1 返回了容器 ID，但 docker ps 看不到 ctts-db 容器（docker ps -a 看到 STATUS 为 Exited）
  • 命令 2 报错 Error: No such container: ctts-db

问题：

  1. 命令 1 中漏掉了哪个必填的环境变量？请写出正确的命令（5 分）
  2. 为什么 docker ps 看不到容器，但 docker ps -a 能看到？（3 分）
  3. 为什么命令 2 报错 No such container？（3 分）
  4. 假设修正了命令 1，MySQL 容器正常启动。但小王立即执行命令 2 还是连接失败，最可能的原因是什么？如何确认？（4 分）
  5. 请为 CTTS 项目编写一个生产可用的 MySQL 容器启动命令，包含：数据持久化、自动创建数据库 ctts、自动重启、明确版本号（5 分）

参考答案与评分标准（20 分）：

1. 漏掉的环境变量与正确命令（5 分）：

  • 漏掉了 MYSQL_ROOT_PASSWORD（必填）（2 分）
  • 正确命令（3 分）： 
    docker run -d --name ctts-db -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0

2. docker ps 看不到但 -a 能看到的原因（3 分）：

  • 因为缺少必填的 MYSQL_ROOT_PASSWORD，MySQL 启动失败，主进程退出，容器状态变为 Exited（2 分）
  • docker ps 只显示运行中的容器（Up 状态），所以看不到；docker ps -a 显示所有容器包括已停止的，所以能看到 Exited 的 ctts-db（1 分）

3. 命令 2 报错 No such container 的原因（3 分）：

  • 因为命令 1 失败后小王可能已经 docker rm ctts-db 删除了失败的容器，或者命令 2 中的容器名与实际不符（2 分）
  • 也可能是容器虽然存在但已 Exited，docker exec 无法在已停止的容器上执行（1 分）
  • 注：实际上 docker exec 对 Exited 容器会报 No such container 或 is not running

4. 立即连接失败的原因与确认方法（4 分）：

  • 最可能原因：MySQL 首次启动需要 10~30 秒初始化（创建系统表、用户、数据库），立即连接时 MySQL 尚未就绪（2 分）
  • 确认方法：docker logs -f ctts-db 查看日志，看到 ready for connections 表示就绪；或 docker ps 看 STATUS 是否为 Up 一段时间（2 分）

5. 生产可用的 MySQL 容器启动命令（5 分）：

docker run -d \
  --name ctts-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=<强密码> \
  -e MYSQL_DATABASE=ctts \
  -e MYSQL_USER=ctts \
  -e MYSQL_PASSWORD=<强密码> \
  -v /data/ctts/mysql:/var/lib/mysql \
  --restart=unless-stopped \
  mysql:8.0
  • 数据持久化 -v（1 分）
  • 自动创建数据库 MYSQL_DATABASE=ctts（1 分）
  • 自动重启 --restart=unless-stopped（1 分）
  • 明确版本号 mysql:8.0（1 分）
  • 必填 root 密码 + 命名 + 端口映射（1 分）

评分要点：各小题独立给分；原因分析合理即可，不要求与答案完全一致；命令参数齐全即给分。
