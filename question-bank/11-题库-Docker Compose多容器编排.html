一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

11-选择-001（★ 知识点：K11-1 Compose 定位） Docker Compose 主要解决的问题是？

  • A单机单容器运行太慢
  • B单机多容器手工部署易错、不可复现
  • C跨多台机器的容器调度
  • D容器镜像构建体积过大

答案：B 解析：Compose 的核心定位是单机多容器编排，把"多条 docker run + 配网络 + 挂数据卷"的繁琐流程收敛为一份 YAML，一条命令启停。A 不是 Compose 解决的问题；C 是 K8s 的工作；D 是 Dockerfile 多阶段构建的问题。

11-选择-002（★ 知识点：K11-1 v1 vs v2） 关于 Compose v2 命令，下列写法正确的是？

  • Adocker-compose up -d
  • Bdocker compose up -d
  • Cdockercompose up -d
  • Ddocker:compose up -d

答案：B 解析：Compose v2 是 docker CLI 的子命令，用空格分隔：docker compose。v1 是独立二进制 docker-compose（连字符），已被废弃。其他写法都不合法。

11-选择-003（★ 知识点：K11-2 顶层结构） docker-compose.yml 中必需的顶层段是？

  • Aversion
  • Bservices
  • Cnetworks
  • Dvolumes

答案：B 解析：services 是必需的，定义所有服务。version 在 v2 中可省略；networks 和 volumes 是可选的，不写时 Compose 会自动创建默认网络。

11-选择-004（★ 知识点：K11-2 version 字段） 关于 Compose v2 中的 version 字段，下列说法正确的是？

  • A必须写 version: "3.8"
  • B必须写 version: "2"
  • C已不再必需，可省略
  • D必须写 version: "latest"

答案：C 解析：Compose v2 不再强制要求 version 字段，新版会自动识别文件格式，建议直接省略。

11-选择-005（★ 知识点：K11-3 image 配置） 关于 services 下 image 与 build 的关系，下列说法正确的是？

  • A二者必须同时使用
  • B二者互斥，不能同时出现
  • C可以同时使用，build 构建后打上 image 指定的标签
  • D只能使用 image，不能用 build

答案：C 解析：image 和 build 可以同时写。同时写时，build 构建 image 并打上 image 字段指定的标签，方便后续引用。只写 image 用现成镜像；只写 build 每次构建。

11-选择-006（★ 知识点：K11-3 ports 配置） 下列 ports 配置写法正确的是？

  • Aports: [8080:8080]
  • Bports: 8080:8080
  • Cports: ["8080:8080"]
  • Dports: 8080

答案：C 解析：端口映射 8080:8080 必须用引号包起来作为字符串，否则 YAML 会解析为时间。正确写法是 - "8080:8080" 或列表 ["8080:8080"]。A 没加引号会出错；B 不是列表；D 只写一个数字无意义。

11-选择-007（★★ 知识点：K11-3 depends_on） 关于 depends_on，下列说法正确的是？

  • A它能保证依赖服务真正就绪后再启动当前服务
  • B它只能控制启动顺序，不保证依赖服务就绪
  • C它会自动给依赖服务添加健康检查
  • D它会让当前服务在依赖服务停止时也停止

答案：B 解析：depends_on 只控制启动顺序——先启动依赖服务的容器，再启动当前服务。但容器启动 ≠ 服务就绪（如 MySQL 进程起来了但还没准备好接受连接）。要保证就绪必须配合 healthcheck + condition: service_healthy。

11-选择-008（★ 知识点：K11-3 container_name） 关于 container_name，下列说法正确的是？

  • A必须为每个服务指定 container_name
  • B不指定时默认容器名为 <项目名>-<服务名>-<序号>
  • C指定后仍可用 --scale 扩缩容
  • Dcontainer_name 必须用大写字母

答案：B 解析：不指定时默认容器名为 <项目名>-<服务名>-<序号>（如 ctts-mysql-1）。固定 container_name 后无法用 --scale 扩缩容（多容器会重名冲突）。建议用小写字母。

11-选择-009（★ 知识点：K11-3 environment） 下列 environment 写法中，错误的是？

  • A
    environment:
  MYSQL_ROOT_PASSWORD: "123456"
  • B
    environment:
  - MYSQL_ROOT_PASSWORD=123456
  • C
    environment:
  MYSQL_ROOT_PASSWORD: 123456
  • D
    environment:
  MYSQL_PASSWORD: "p@ssw0rd"
  MYSQL_USER: ctts

答案：C 解析：纯数字 123456 不加引号会被 YAML 解析为整数而非字符串，可能导致程序读到的不是预期值。密码建议统一加引号。A、B、D 写法都正确（A 字典、B 列表、D 含特殊字符加引号）。

11-选择-010（★ 知识点：K11-3 restart） 下列 restart 策略中，"除非手动 stop，否则总是重启"的是？

  • A
    no
  • B
    always
  • C
    on-failure
  • D
    unless-stopped

答案：D 解析：unless-stopped 表示除非手动停止，否则容器退出就自动重启，是生产推荐的策略。always 是总是重启（即使手动 stop 也会在 Docker 重启时拉起）；on-failure 只在非零退出码时重启；no 不重启。

11-选择-011（★ 知识点：K11-4 具名卷） 关于 Compose 中的具名卷，下列说法正确的是？

  • A在 services 下引用即可，无需在 volumes 顶层段声明
  • B必须在 volumes 顶层段声明，才能在 services 下引用
  • C具名卷不能用 docker volume ls 查看
  • D具名卷在 docker compose down 时默认被删除

答案：B 解析：具名卷（卷名:容器路径）必须在 volumes 顶层段声明，否则报错。具名卷由 Docker 管理，可用 docker volume ls 查看。docker compose down 默认保留卷，加 -v 才删除。

11-选择-012（★ 知识点：K11-4 绑定挂载） 下列挂载写法中，属于绑定挂载的是？

  • Amysql-data:/var/lib/mysql
  • B./init.sql:/docker-entrypoint-initdb.d/init.sql
  • Cctts-net:bridge
  • Dvolume-data:/data

答案：B 解析：绑定挂载用宿主机路径（相对或绝对）作为源，如 ./init.sql 或 /data/mysql。A、D 是具名卷；C 不是挂载语法。

11-选择-013（★ 知识点：K11-5 up 命令） docker compose up -d 中 -d 参数的作用是？

  • A删除已有容器再启动
  • B后台运行（detached 模式）
  • C强制重新构建镜像
  • D仅启动默认服务

答案：B 解析：-d 是 detached 模式，让容器在后台运行，不占用当前终端。强制重建用 --build；删除再启动不是 -d 的作用。

11-选择-014（★ 知识点：K11-5 down 命令） docker compose down 默认会执行的操作是？

  • A停止并删除容器、网络，保留具名卷
  • B停止并删除容器、网络、具名卷
  • C仅停止容器，不删除任何资源
  • D删除所有镜像

答案：A 解析：docker compose down 默认停止并删除容器和网络，但保留具名卷（保护数据）。要删卷加 -v；要删镜像加 --rmi。

11-选择-015（★ 知识点：K11-5 down 删卷） 要彻底清理 Compose 项目（包括数据卷），应使用命令？

  • Adocker compose down
  • Bdocker compose down -v
  • Cdocker compose stop
  • Ddocker compose rm

答案：B 解析：-v 参数会在 down 时同时删除具名卷。慎用，数据会丢。stop 只停止不删除；rm 删除已停止的容器但不删网络和卷。

11-选择-016（★★ 知识点：K11-5 up vs start） 修改了 docker-compose.yml 后，要让修改生效，应使用命令？

  • Adocker compose start
  • Bdocker compose up -d
  • Cdocker compose restart
  • Ddocker compose exec

答案：B 解析：start 只启动已存在的停止容器，不会应用 YAML 变更。up -d 是声明式对齐——让真实状态向 YAML 靠拢，会重建有变化的服务。restart 只是重启，不应用 YAML 变更。

11-选择-017（★ 知识点：K11-5 logs 命令） 实时跟随查看 backend 服务的日志，应使用命令？

  • Adocker compose logs backend
  • Bdocker compose logs -f backend
  • Cdocker compose logs --tail 100 backend
  • Ddocker compose logs -t backend

答案：B 解析：-f 是 follow，实时跟随日志输出。A 只输出当前日志不跟随；C 只看最后 100 行；D 带时间戳但不跟随。

11-选择-018（★ 知识点：K11-5 exec 命令） 进入运行中的 backend 容器的 sh 交互终端，应使用命令？

  • Adocker compose exec backend sh
  • Bdocker compose run backend sh
  • Cdocker compose attach backend
  • Ddocker compose shell backend

答案：A 解析：exec 在运行中的容器内执行命令，常用于进入交互终端。run 是启动一个新容器执行命令；attach 是连接到容器主进程（PID 1），不是开新 shell；shell 不是 compose 子命令。

11-选择-019（★★ 知识点：K11-5 --scale） 关于 docker compose up -d --scale backend=3，下列说法正确的是？

  • A会启动 3 个 backend 容器，并自动做负载均衡
  • B会启动 3 个 backend 容器，但 Compose 本身不做负载均衡
  • C只能扩展到 2 个实例
  • Dbackend 服务必须指定 container_name

答案：B 解析：--scale 启动多个实例，但 Compose 本身不做负载均衡，多实例需要外部反向代理。固定 container_name 会冲突报错。扩展数量无硬性上限（受资源约束）。

11-选择-020（★ 知识点：K11-5 -f 参数） 使用非默认文件名 docker-compose.prod.yml 启动，应使用命令？

  • Adocker compose up -d docker-compose.prod.yml
  • Bdocker compose -f docker-compose.prod.yml up -d
  • Cdocker compose --file docker-compose.prod.yml up -d
  • Ddocker compose up -d --file docker-compose.prod.yml

答案：B 解析：-f 参数指定 compose 文件，必须放在 up 之前。B 写法标准；C 用 --file 也对但更冗长；A、D 位置错误。

11-选择-021（★ 知识点：K11-5 项目名） 关于 Compose 项目名，下列说法正确的是？

  • A项目名固定为 docker-compose
  • B项目名默认是所在目录名（小写、特殊字符去除）
  • C项目名必须用 -p 显式指定
  • D项目名不影响容器命名

答案：B 解析：项目名默认是 docker-compose.yml 所在目录的名字（小写、特殊字符去除）。可用 -p 显式指定覆盖。项目名会影响容器/网络/卷的命名前缀，如 <项目名>-<服务名>-<序号>。

11-选择-022（★ 知识点：K11-5 stop vs down） 关于 docker compose stop 和 docker compose down 的区别，下列说法正确的是？

  • A二者完全等价
  • Bstop 只停止容器不删除，down 停止并删除容器和网络
  • Cstop 删除容器，down 删除容器和网络
  • Ddown 比 stop 更省资源，因为删除了容器

答案：B 解析：stop 只停止容器（保留容器与配置，下次 start 直接恢复）；down 停止并删除容器和网络（卷保留，下次 up 重新创建容器）。二者用途不同，不是简单的"谁更省"。

11-选择-023（★★ 知识点：K11-3 健康检查） 下列 healthcheck 配置中，start_period: 30s 的含义是？

  • A每 30 秒检查一次
  • B检查超时时间为 30 秒
  • C容器启动后 30 秒内健康检查失败不计入 retries
  • D重试 30 次后才判定不健康

答案：C 解析：start_period 是启动宽限期——容器启动后这段时间内健康检查失败不计入 retries，给应用预留启动时间。interval 是检查间隔；timeout 是单次检查超时；retries 是重试次数。

11-选择-024（★ 知识点：K11-4 自定义网络） 关于 Compose 中的自定义网络，下列说法正确的是？

  • A同一网络内的服务只能用 IP 互访
  • B同一网络内的服务可以用服务名互访（DNS 解析）
  • C自定义网络不支持 DNS
  • D一个服务只能接入一个网络

答案：B 解析：自定义 bridge 网络内置 DNS，同网络内的服务可以用服务名互访（这是相对默认 bridge 的关键优势）。一个服务可以接入多个网络。

11-选择-025（★ 知识点：K11-4 external） 关于 external: true 在 networks/volumes 中的含义，下列说法正确的是？

  • A让 Compose 创建一个新的外部网络
  • B引用 Docker 中已存在的网络/卷，不创建新的
  • C网络对外公开
  • D卷会被外部进程访问

答案：B 解析：external: true 告诉 Compose 这个网络/卷已经存在（在 Docker 中预先创建好），不要创建新的，直接引用。常用于多个 Compose 项目共享资源。

11-选择-026（★★ 知识点：K11-3 YAML 缩进） 关于 docker-compose.yml 的 YAML 语法，下列说法正确的是？

  • A缩进可以用 Tab 也可以用空格
  • B缩进必须用空格，不能混用 Tab
  • C缩进不影响解析
  • D一份文件可以混用 Tab 和空格

答案：B 解析：YAML 严格依赖缩进，必须用空格（建议 2 个），不能用 Tab，更不能混用。Tab 会导致解析错误。

11-选择-027（★ 知识点：K11-5 ps 命令） 查看 Compose 项目下所有服务状态（包括已停止的），应使用命令？

  • Adocker compose ps
  • Bdocker compose ps -a
  • Cdocker compose ls
  • Ddocker compose status

答案：B 解析：docker compose ps 默认只显示运行中的服务；-a 显示所有（包括已停止）。ls 是列出所有 Compose 项目（不是服务）；status 不是 compose 子命令。

11-选择-028（★★ 知识点：K11-6 依赖顺序） 在 CTTS 三服务编排中，正确的启动顺序应该是？

  • Afrontend → backend → mysql
  • Bbackend → mysql → frontend
  • Cmysql → backend → frontend
  • D同时启动

答案：C 解析：mysql 是基础（数据库要先就绪），backend 依赖 mysql（启动时要连接数据库），frontend 依赖 backend（调用后端 API）。所以顺序是 mysql → backend → frontend。

11-选择-029（★ 知识点：K11-1 Compose 与 K8s） 关于 Compose 与 Kubernetes 的区别，下列说法正确的是？

  • A二者功能完全相同
  • BCompose 用于单机多容器编排，K8s 用于集群容器编排
  • CCompose 可以替代 K8s
  • DK8s 可以替代 Compose，所以不用学 Compose

答案：B 解析：Compose 是单机多容器编排，K8s 是集群容器编排。二者定位不同，不是替代关系。Compose 适合开发/测试/小规模单机部署；K8s 适合生产级高可用、弹性扩缩容。

11-选择-030（★★ 知识点：K11-6 反向代理） 在 CTTS 编排中，frontend 的 Nginx 配置 proxy_pass http://backend:8080/; 中 backend 指的是？

  • Abackend 容器的 IP 地址
  • Bbackend 服务的服务名（DNS 解析）
  • Cbackend 容器的容器名
  • D宿主机的主机名

答案：B 解析：在 Compose 自定义网络中，服务名会作为 DNS 名被解析为对应容器的 IP。backend 是 services 下的服务名，Nginx 通过 DNS 解析到 backend 容器的 IP。

1.2 多项选择题（10 题）

11-选择-031（★★ 知识点：K11-1 Compose 价值） 使用 Docker Compose 带来的价值包括？（多选）

  • A多容器配置收敛为一份 YAML，可入 Git 版本管理
  • B一条命令启停多服务，避免手工命令易错
  • C自动跨多台机器调度容器
  • D声明式配置，便于 Code Review E. 配置可复现，迁移交付一致

答案：A、B、D、E 解析：A/B/D/E 都是 Compose 的真实价值。C 错，Compose 只能在单机上编排，跨机调度是 K8s 的工作。

11-选择-032（★★ 知识点：K11-2 顶层结构） docker-compose.yml 的顶层结构包括？（多选）

  • Aversion
  • Bservices
  • Cnetworks
  • Dvolumes E. containers

答案：A、B、C、D 解析：顶层结构有 version（v2 可省）、services（必需）、networks（可选）、volumes（可选）。E 错，没有 containers 顶层段，容器由 services 定义。

11-选择-033（★★ 知识点：K11-3 services 配置） 下列属于 services 下服务配置项的有？（多选）

  • Aimage
  • Bports
  • Cdepends_on
  • Dnetworks E. containers

答案：A、B、C、D 解析：image、ports、depends_on、networks 都是 services 下的配置项。E 错，没有 containers 配置项，服务本身就对应一个容器。

11-选择-034（★★ 知识点：K11-3 restart 策略） 下列属于 Compose 中合法 restart 策略的有？（多选）

  • Ano
  • Balways
  • Con-failure
  • Dunless-stopped E. never

答案：A、B、C、D 解析：合法策略有 no、always、on-failure、unless-stopped。E 错，没有 never，不重启用 no。

11-选择-035（★★ 知识点：K11-5 常用命令） 下列属于 docker compose 子命令的有？（多选）

  • Aup
  • Bdown
  • Clogs
  • Dexec E. run

答案：A、B、C、D、E 解析：up、down、logs、exec、run 都是 compose 子命令。其中 run 用于启动一个新容器执行一次性命令（不同于 exec 在运行中容器内执行）。

11-选择-036（★★ 知识点：K11-4 卷类型） 下列 volumes 写法中，属于具名卷的有？（多选）

  • Amysql-data:/var/lib/mysql
  • B./config:/etc/config
  • C/data/mysql:/var/lib/mysql
  • Dredis-data:/data E. ctts-net:bridge

答案：A、D 解析：具名卷以"卷名:容器路径"形式，卷名不带路径分隔符。A、D 是具名卷。B、C 是绑定挂载（带路径分隔符）。E 不是挂载语法。

参考答案与评分标准（10 分，按要点给分）：

  1. Compose 解决的问题（3 分）：

    • 单机多容器手工部署痛点：多条 docker run 命令、参数易错、启动顺序难记、不可复现、无法版本化管理（1.5 分）
    • Compose 把多服务配置收敛为一份 docker-compose.yml，一条命令启停，可入 Git 版本管理、可 Code Review、可一键复现（1.5 分）

  2. depends_on 的作用与局限（4 分）：

    • 作用：控制服务启动顺序——先启动依赖服务的容器，再启动当前服务（2 分）
    • 局限：只控制"容器启动顺序"，不保证"服务就绪"。例如 MySQL 容器启动了但还没初始化完，无法接受连接，此时 backend 启动会连不上数据库（2 分）

    • 当前服务的 depends_on 使用 condition: service_healthy，等待依赖服务健康检查通过后再启动（1.5 分）
    • 示例 YAML 片段（加分项，非必需）： 
      mysql:
  healthcheck:
    test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
    interval: 10s
    timeout: 5s
    retries: 5
    start_period: 30s
backend:
  depends_on:
    mysql:
      condition: service_healthy

11-论述-002（★★ 知识点：K11-5 命令对比，8 分） 请对比以下 docker compose 命令对的异同：(1) up -d 与 start；(2) stop 与 down；(3) down 与 down -v。

参考答案与评分标准（8 分，按要点给分）：

  1. up -d 与 start（3 分）：

    • up -d：声明式对齐——让真实状态向 YAML 描述的目标状态靠拢。会创建不存在的容器、应用 YAML 变更、重建有变化的服务（1.5 分）
    • start：只启动已存在的停止状态的容器，不会创建新容器，也不会应用 YAML 变更（1.5 分）
    • 结论：修改 YAML 后必须用 up -d，不能用 start

  2. stop 与 down（3 分）：

    • stop：只停止容器（保留容器、配置、网络），下次 start 直接恢复（1.5 分）
    • down：停止并删除容器和网络（卷保留），下次 up 重新创建容器（1.5 分）
    • 结论：stop 适合临时暂停；down 适合彻底清理

  3. down 与 down -v（2 分）：

    • down：删除容器和网络，保留具名数据卷（保护数据）（1 分）
    • down -v：删除容器、网络，同时删除具名数据卷（数据会丢，慎用）（1 分）
    • 结论：要保留数据用 down；要彻底清理用 down -v

评分要点：三组对比各自独立给分；要点清晰即可满分；只列命令不解释给一半分。
