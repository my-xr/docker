1.1 单项选择题（30 题）

03-选择-001（★ 知识点：K3-1 镜像概念） 关于 Docker 镜像，下列说法正确的是？

  • A镜像是可读写的运行实例
  • B镜像是只读的、分层的容器运行模板
  • C镜像就是容器
  • D镜像删除后容器一定不存在

答案：B 解析：镜像是只读的、分层的容器运行模板，包含应用运行所需的全部内容。A 错，可读写的是容器；C 错，镜像是模板、容器是运行实例；D 错，删除镜像前需先删容器，逻辑反了。

03-选择-002（★ 知识点：K3-1 镜像组成） 下列哪一项不属于 Docker 镜像包含的内容？

  • A应用代码
  • B运行时（如 JRE）
  • C宿主机的内核
  • D配置文件与环境变量

答案：C 解析：镜像包含应用代码、运行时、依赖库、配置文件、环境变量、元数据等，但不包含宿主机内核——容器共享宿主内核。这是容器与虚拟机的核心区别。

03-选择-003（★ 知识点：K3-1 不可变特性） 关于 Docker 镜像的不可变（Immutable）特性，下列说法正确的是？

  • A镜像构建后可以随时直接修改其中的文件
  • B镜像一旦构建完成，其内容不可修改，要改只能构建新镜像
  • C不可变特性导致镜像无法回滚
  • D不可变特性使镜像不可信任

答案：B 解析：镜像一旦构建完成，内容不可修改，要改只能基于它构建新镜像。不可变带来可复现、可回滚、可信任三大好处。A、C、D 都错。

03-选择-004（★ 知识点：K3-2 docker pull） docker pull mysql 命令（不写标签）实际拉取的镜像是？

  • Amysql:stable
  • Bmysql:latest
  • Cmysql:8.0
  • D报错，必须指定标签

答案：B 解析：docker 命令中不指定 tag 时默认 :latest。所以 docker pull mysql 等价于 docker pull mysql:latest。但生产环境不建议用 latest，应指定明确版本号。

03-选择-005（★ 知识点：K3-2 docker images 字段） docker images 命令输出中的 IMAGE ID 字段是？

  • A镜像的仓库名
  • B镜像的标签
  • C镜像唯一 ID（SHA256 前 12 位）
  • D镜像的创建者

答案：C 解析：IMAGE ID 是镜像完整 SHA256 摘要的前 12 位，是镜像的唯一标识。仓库名是 REPOSITORY，标签是 TAG。

03-选择-006（★ 知识点：K3-2 CREATED 字段） docker images 输出中的 CREATED 字段表示？

  • A镜像拉取到本地的时间
  • B镜像构建者构建镜像的时间
  • C镜像最后一次启动容器的时间
  • D镜像被修改的时间

答案：B 解析：CREATED 是镜像构建者构建这个镜像的时间（Dockerfile 构建完成时间），不是本地拉取时间。所以会看到 2 weeks ago、6 months ago 这种时间。

03-选择-007（★ 知识点：K3-2 命令等价） 下列哪两个命令是等价的？

  • Adocker pull 和 docker push
  • Bdocker images 和 docker image ls
  • Cdocker rmi 和 docker rm
  • Ddocker tag 和 docker build

答案：B 解析：docker images 是老语法，docker image ls 是新语法（Docker 1.13+），两者完全等价。A 是拉取和推送（相反操作）；C 是删镜像和删容器（不同）；D 是打标签和构建（不同）。

03-选择-008（★ 知识点：K3-3 分层结构） Docker 镜像采用分层结构，每一层是由什么生成的？

  • A一条 Dockerfile 指令
  • B一次 docker run 命令
  • C一次 docker pull 命令
  • D一次 docker tag 命令

答案：A 解析：每条 Dockerfile 指令生成一层（Layer）。如 FROM、RUN、COPY 等指令各自生成一层。docker run、pull、tag 命令不直接生成层。

03-选择-009（★ 知识点：K3-3 UnionFS） Docker 默认使用的联合文件系统（UnionFS）驱动是？

  • Aext4
  • Bxfs
  • Coverlay2（OverlayFS）
  • Dnfs

答案：C 解析：Docker 默认使用 overlay2 驱动（基于 OverlayFS）。ext4、xfs 是普通文件系统，nfs 是网络文件系统，都不是联合文件系统。

03-选择-010（★ 知识点：K3-3 层共享） 两个 MySQL 镜像（mysql:8.0 和 mysql:5.7）实际磁盘占用远小于两者 SIZE 字段之和，原因是？

  • ADocker 压缩了镜像
  • B镜像层共享，相同摘要的层只存一份
  • CSIZE 字段显示错误
  • DMySQL 镜像本身很小

答案：B 解析：镜像采用分层结构，相同 SHA256 摘要的层在多个镜像间共享，只存一份。所以两个 MySQL 镜像共享 Debian 基础层和部分依赖层，实际占用小于 SIZE 之和。

03-选择-011（★ 知识点：K3-3 docker history） 查看镜像构建层（每条 Dockerfile 指令生成的层）的命令是？

  • Adocker images
  • Bdocker image inspect
  • Cdocker history
  • Ddocker layers

答案：C 解析：docker history 镜像名:标签 查看镜像的构建层，显示每层的创建时间、生成命令、大小等。inspect 是详情，images 是列表，docker layers 不是有效命令。

03-选择-012（★★ 知识点：K3-3 history 输出） docker history mysql:8.0 输出中的 <missing> 表示？

  • A该层文件丢失，镜像损坏
  • B该层来自基础镜像，不在最外层镜像 ID 中显示
  • C该层是空的，没有内容
  • D该层是错误的，需要修复

答案：B 解析：<missing> 只表示该层来自基础镜像（被 FROM 引入），不在最外层镜像 ID 的"快照"中显示，并非真的缺失或损坏。

03-选择-013（★ 知识点：K3-4 docker image inspect） 查看镜像完整元数据（JSON 输出）的命令是？

  • Adocker image inspect
  • Bdocker image ls
  • Cdocker image info
  • Ddocker image show

答案：A 解析：docker image inspect 镜像名:标签 查看镜像完整元数据，输出 JSON。ls 是列表，info 和 show 不是有效命令。

03-选择-014（★ 知识点：K3-4 inspect 字段） docker image inspect 输出中，镜像的默认启动命令字段是？

  • A.Config.Cmd
  • B.Config.Env
  • C.Config.ExposedPorts
  • D.Config.WorkingDir

答案：A 解析：.Config.Cmd 是容器启动默认命令；.Config.Env 是环境变量；.Config.ExposedPorts 是暴露端口；.Config.WorkingDir 是工作目录。

03-选择-015（★★ 知识点：K3-4 ExposedPorts） 关于 docker image inspect 输出中的 Config.ExposedPorts，下列说法正确的是？

  • AExposedPorts 就是实际映射到宿主机的端口
  • BExposedPorts 只是声明，要外部访问仍需 docker run -p 端口映射
  • CExposedPorts 决定了容器一定能从外部访问
  • DExposedPorts 是镜像构建时自动生成的随机端口

答案：B 解析：EXPOSE 只是声明镜像"打算"暴露的端口，不等于实际映射。要外部访问仍需 docker run -p 宿主端口:容器端口 做端口映射。

03-选择-016（★ 知识点：K3-5 docker tag） docker tag mysql:8.0 ctts-mysql:v1 命令的作用是？

  • A删除 mysql:8.0 镜像
  • B创建一个新的镜像
  • C给 mysql:8.0 镜像打一个新标签 ctts-mysql:v1（加别名）
  • D拉取 ctts-mysql:v1 镜像

答案：C 解析：docker tag 给已有镜像打新标签（加别名），不创建新镜像，IMAGE ID 不变。两个标签指向同一个镜像 ID。

03-选择-017（★★ 知识点：K3-5 tag 本质） 关于 docker tag 命令，下列说法正确的是？

  • A会创建一个全新的镜像
  • B会复制镜像的所有层，占用额外磁盘
  • C只是元数据操作，给同一个镜像 ID 加别名，不创建新层
  • D必须指定完整的仓库地址

答案：C 解析：docker tag 只是元数据操作，给同一个镜像 ID 加一个别名，不创建新层，不占额外磁盘。一个镜像 ID 可以有多个标签。

03-选择-018（★★ 知识点：K3-5 latest 陷阱） 关于 :latest 标签，下列说法正确的是？

  • A:latest 一定指向最新最稳定的版本
  • B生产环境推荐使用 :latest 标签
  • C:latest 只是默认标签名，可能指向任意版本，生产环境应指定明确版本
  • D不写标签时镜像会报错

答案：C 解析：:latest 只是默认标签名，不保证最新最稳定，可能指向任意版本。生产环境应指定明确版本号（如 mysql:8.0.35）以保证可复现。A、B 错误；D 错，不写标签默认 latest 不报错。

03-选择-019（★ 知识点：K3-6 docker rmi） 删除本地镜像的命令是？

  • Adocker rm 镜像名
  • Bdocker rmi 镜像名
  • Cdocker delete 镜像名
  • Ddocker remove 镜像名

答案：B 解析：docker rmi 或 docker image rm 删除本地镜像。docker rm 是删除容器，不是镜像。delete 和 remove 不是有效命令。

03-选择-020（★ 知识点：K3-6 rmi vs rm） docker rmi 和 docker rm 的区别是？

  • A两者完全相同
  • Bdocker rmi 删除镜像，docker rm 删除容器
  • Cdocker rmi 删除容器，docker rm 删除镜像
  • D两者都是删除容器

答案：B 解析：docker rmi（image 的 i）删除镜像，docker rm 删除容器。两者操作对象不同，不能混用。

03-选择-021（★★ 知识点：K3-6 删除规则） 当镜像有对应容器存在（即使已停止）时，直接 docker rmi 会怎样？

  • A正常删除镜像
  • B报错，提示先删除依赖的容器
  • C自动删除容器和镜像
  • D删除镜像但保留容器

答案：B 解析：Docker 默认拒绝删除有容器依赖的镜像，会报错 image is being used by stopped container xxx。需先 docker rm 删除容器，或用 docker rmi -f 强制删除。

03-选择-022（★★ 知识点：K3-6 -f 强制删除） 关于 docker rmi -f 镜像 命令，下列说法正确的是？

  • A-f 表示友好删除，更安全
  • B-f 会先删除所有依赖此镜像的容器，再删镜像，可能误删运行中的容器
  • C-f 只删除镜像的标签，不删层
  • D-f 是 dry-run 模式，不实际删除

答案：B 解析：-f 是强制删除，会先删除所有依赖此镜像的容器（包括运行中的），再删镜像。生产环境慎用，可能误删运行中的容器。

03-选择-023（★ 知识点：K3-6 docker image prune） docker image prune 命令（不带参数）清理的是什么？

  • A所有未使用的镜像
  • B所有本地镜像
  • C悬空镜像（dangling，<none>:<none>）
  • D所有正在使用的镜像

答案：C 解析：docker image prune 不带参数只清理悬空镜像（dangling images，即 <none>:<none> 的镜像）。加 -a 才清理所有未被容器使用的镜像。

03-选择-024（★★ 知识点：K3-6 prune -a） docker image prune -a 与 docker image prune 的区别是？

  • A两者完全相同
  • B-a 清理所有未被容器使用的镜像，不带 -a 只清理悬空镜像
  • C-a 清理所有镜像包括正在使用的
  • D-a 是强制模式，不询问确认

答案：B 解析：docker image prune 默认只清理悬空镜像（<none>:<none>）；docker image prune -a 清理所有未被任何容器使用的镜像（含已打标签的）。-f 才是跳过确认。

03-选择-025（★★ 知识点：K3-6 悬空镜像） 下列哪种情况会产生悬空镜像（dangling image）？

  • A拉取新镜像
  • B用相同标签重新构建镜像，旧镜像失去标签
  • C删除容器
  • D启动容器

答案：B 解析：用相同标签重新构建镜像时，新镜像占用该标签，旧镜像失去标签变成 <none>:<none>，即悬空镜像。其他选项不会产生悬空镜像。

03-选择-026（★ 知识点：K3-3 层缓存） 为什么 docker pull 同一个镜像第二次通常很快？

  • A网络变快了
  • B镜像变小了
  • C分层 + 层缓存，本地已有的层不重复下载
  • DDocker 自动跳过下载

答案：C 解析：Docker 会校验每层的 SHA256 摘要，本地已有的层不重复下载（层缓存），只下载缺失或更新的层。所以第二次拉取很快。

03-选择-027（★ 知识点：K3-2 SIZE 字段） 关于 docker images 输出中的 SIZE 字段，下列说法正确的是？

  • ASIZE 是镜像实际占用磁盘的大小
  • BSIZE 是镜像所有层大小之和（逻辑大小），实际占用可能因层共享更小
  • CSIZE 是镜像被下载时占用的网络流量
  • DSIZE 是镜像构建时间

答案：B 解析：SIZE 是镜像所有层大小之和（逻辑大小），不是实际磁盘占用。实际占用因层共享可能更小，用 docker system df 查看真实占用。

03-选择-028（★★ 知识点：K3-4 Go 模板） 用 docker image inspect 提取镜像的完整 ID，正确的命令是？

  • Adocker image inspect -f '{{.Id}}' mysql:8.0
  • Bdocker image inspect -f '{{.ImageID}}' mysql:8.0
  • Cdocker image inspect -f '{{.ID}}' mysql:8.0
  • Ddocker image inspect -f '{{.RepoTags}}' mysql:8.0

答案：A 解析：{{.Id}} 是 Go 模板提取完整 SHA256 ID 的语法。{{.RepoTags}} 提取的是标签列表。其他两个不是有效字段。

03-选择-029（★★ 知识点：K3-4 提取层数） 用 docker image inspect 查看镜像有几层，正确的命令是？

  • Adocker image inspect -f '{{.Layers}}' mysql:8.0
  • Bdocker image inspect -f '{{len .RootFS.Layers}}' mysql:8.0
  • Cdocker image inspect -f '{{.RootFS}}' mysql:8.0
  • Ddocker image inspect -f '{{count .Layers}}' mysql:8.0

答案：B 解析：层信息在 .RootFS.Layers 字段，用 len 函数计算数组长度。{{len .RootFS.Layers}} 输出层数。

03-选择-030（★★★ 知识点：K3-6 综合清理） 某运维工程师发现 Docker 主机磁盘快满了，要安全清理无用镜像但保留正在运行容器使用的镜像，最合适的命令是？

  • Adocker rmi -f $(docker images -q)
  • Bdocker system prune -a --volumes
  • Cdocker image prune -a
  • Ddocker rmi $(docker images -q)

答案：C 解析：docker image prune -a 清理所有未被容器使用的镜像，正在运行容器使用的镜像不会被删，安全。A 和 D 会尝试删所有镜像，会因容器依赖报错或误删；B 会清理所有资源含卷，可能丢数据，过激。

1.2 多项选择题（10 题）

03-选择-031（★★ 知识点：K3-1 镜像组成） Docker 镜像包含下列哪些内容？（多选）

  • B运行时（如 JRE、Python 解释器）
  • C依赖库
  • D配置文件与环境变量 E. 宿主机内核

答案：A、B、C、D 解析：镜像包含应用代码、运行时、依赖库、配置文件、环境变量、元数据等。E 错，容器共享宿主内核，镜像不包含内核。

03-选择-032（★★ 知识点：K3-3 分层价值） Docker 镜像采用分层结构带来的价值包括？（多选）

  • C增量传输，push/pull 只传差异层
  • D让镜像变得可写 E. 层独立可复用

答案：A、B、C、E 解析：分层带来共享（A）、缓存（B）、增量传输（C）、层复用（E）。D 错，镜像层只读，容器才有可写层。

03-选择-033（★★ 知识点：K3-2 docker images） 关于 docker images 命令的输出字段，下列说法正确的有？（多选）

  • AREPOSITORY 是镜像仓库名
  • BTAG 是镜像标签
  • CIMAGE ID 是镜像唯一 ID（SHA256 前 12 位）
  • DCREATED 是镜像构建时间（不是拉取时间） E. SIZE 是镜像实际占用磁盘大小

答案：A、B、C、D 解析：A、B、C、D 都正确。E 错，SIZE 是逻辑大小（所有层之和），实际占用因层共享可能更小。

03-选择-034（★★ 知识点：K3-4 inspect 字段） docker image inspect 输出中属于 Config 字段的子字段有？（多选）

  • ACmd
  • BEntrypoint
  • CExposedPorts
  • DEnv E. RootFS

答案：A、B、C、D 解析：Cmd、Entrypoint、ExposedPorts、Env 都是 Config 的子字段。RootFS 是顶层字段（与 Config 同级），不在 Config 下。

03-选择-035（★★ 知识点：K3-5 latest 陷阱） 关于 :latest 标签，下列说法正确的有？（多选）

  • A:latest 只是默认标签名，不保证最新最稳定
  • B不写标签时 docker 命令默认使用 :latest
  • C:latest 可能随时指向不同版本，导致不可复现
  • D生产环境应指定明确版本号而非 :latest E. :latest 一定是最近推送的镜像

答案：A、B、C、D 解析：A、B、C、D 都正确。E 错，:latest 不一定是最近推送的，镜像维护者可以随时把 :latest 指向任何版本。

03-选择-036（★★ 知识点：K3-6 删除与清理） 下列关于镜像删除与清理的命令，说法正确的有？（多选）

  • Adocker rmi 镜像 删除指定镜像

03-论述-001（★★ 知识点：K3-3 分层结构，10 分） 请阐述 Docker 镜像分层结构的原理，并说明分层带来的核心价值。为什么两个 MySQL 镜像（mysql:8.0 和 mysql:5.7）的实际磁盘占用小于两者 SIZE 字段之和？

参考答案与评分标准（10 分，按要点给分）：

  1. 分层原理（3 分）：
    • Docker 镜像由多个只读层（Layer）叠加而成，每条 Dockerfile 指令生成一层（1 分）。
    • 多层通过联合文件系统（UnionFS，默认 OverlayFS）叠加成统一视图（1 分）。
    • 每层有 SHA256 摘要，相同摘要的层可共享；容器在镜像层之上加一层可写层，修改时用写时复制（CoW）（1 分）。
  2. 分层的核心价值（4 分，每点 1 分）：
    • 层共享：多个镜像共用同一基础层，节省磁盘和传输。
    • 层缓存：构建时未变化的层用缓存，加速构建；拉取时已有的层不重复下载。
    • 增量传输：push/pull 只传输差异层，大幅减少网络流量。
    • 可复用：一个基础镜像（如 openjdk:17）可被多个应用镜像复用。
  3. 为什么实际占用小于 SIZE 之和（3 分）：
    • docker images 显示的 SIZE 是镜像所有层大小之和（逻辑大小）（1 分）。
    • 两个 MySQL 镜像虽然 SIZE 之和约 969MB，但它们共享 Debian 基础层、共享部分依赖层（相同 SHA256 摘要的层只存一份）（1.5 分）。
    • 实际磁盘占用通过 docker system df 查看，通常小于 SIZE 之和（如约 723MB），这就是层共享的效果（0.5 分）。

评分要点：三部分各自独立给分；要点齐全即可满分；学生能用"层共享""SHA256 摘要""逻辑大小 vs 实际占用"等关键词解释即可。

03-论述-004（★★ 知识点：K3-6 删除与清理，8 分） 请说明 docker rmi、docker image prune、docker image prune -a、docker system prune 四个命令的区别，并说明在什么场景下使用哪个命令。

参考答案与评分标准（8 分，按要点给分）：

  1. 四个命令的区别（4 分，每个 1 分）：
    • docker rmi 镜像：删除指定的镜像（按标签或 ID）。如果镜像有容器依赖会报错，需先删容器或用 -f 强删。
    • docker image prune：清理悬空镜像（dangling，<none>:<none>），即失去标签的中间层镜像。风险低。
    • docker image prune -a：清理所有未被任何容器使用的镜像（含已打标签的）。风险中等，可能删掉"打算用但还没用"的镜像。
    • docker system prune：清理所有未使用的资源（含镜像、容器、网络、构建缓存）。加 -a 更彻底，加 --volumes 还清理卷。风险高。
  2. 使用场景（4 分，每个 1 分）：
    • 删除某个具体镜像：用 docker rmi 镜像:标签。如删 hello-world 镜像。
    • 日常清理悬空镜像（推荐定期执行）：用 docker image prune。安全，只清无用中间层。
    • 磁盘紧张，清理所有未使用镜像：用 docker image prune -a。会删掉未使用的已打标签镜像，谨慎使用。
    • 彻底清理所有无用资源（如重置环境）：用 docker system prune -a。核弹级清理，仅在确定要彻底清理时使用。

评分要点：两部分独立给分；命令区别要说清"清理范围"和"风险等级"；场景要对应命令。

03-阅读-002（★★ 知识点：K3-4 inspect 字段解读，12 分） 阅读以下 docker image inspect mysql:8.0 的部分 JSON 输出，回答问题（每问 3 分，共 12 分）。

{
  "Id": "sha256:d1dc36f8e78f3e5bf7a8e6f4c5b6a7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4",
  "RepoTags": ["mysql:8.0"],
  "Created": "2024-01-15T08:30:00.123456789Z",
  "Config": {
    "Cmd": ["mysqld"],
    "Entrypoint": ["docker-entrypoint.sh"],

      "...（共13层）"
    ]
  }
}

问题：

  1. 该镜像的默认启动命令是什么？入口点（Entrypoint）是什么？（3 分）
  2. 该镜像声明暴露了哪些端口？是否意味着这些端口自动映射到宿主机？（3 分）
  3. 该镜像声明了哪个匿名卷？这暗示了什么？（3 分）
  4. 该镜像有几层？层数信息在哪个字段？（3 分）

参考答案：

  1. 默认启动命令（Cmd）是 ["mysqld"]，即启动 MySQL 服务进程。入口点（Entrypoint）是 ["docker-entrypoint.sh"]，即先执行 docker-entrypoint.sh 脚本，再执行 Cmd。（3 分）

03-编程-002（★★★ 知识点：K3-3/K3-4/K3-6 综合应用，20 分） 镜像管理与清理综合题：某团队 Docker 主机磁盘告警，运维工程师小李需要排查和清理。请回答问题：

# 命令1：查看磁盘占用
docker system df
# 输出：
# TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
# Images          8         2         2.1GB     1.8GB (85%)
# Containers      3         1         50MB      30MB (60%)
# Local Volumes   2         1         500MB     400MB (80%)
# Build Cache     0         0         0B        0B

# 命令2：查看本地镜像
docker images
# 输出（部分）：
# REPOSITORY    TAG       IMAGE ID       CREATED        SIZE
# mysql         8.0       d1dc36f8e78f   2 weeks ago    521MB
# mysql         5.7       7faa3c53e6d1   1 month ago    448MB
# nginx         1.25      605c77e624dd   3 weeks ago    142MB
# hello-world   latest    feb5d9fea6a5   6 months ago   13.3kB
# <none>        <none>    a1b2c3d4e5f6   1 day ago      380MB
# ctts-api      v1        b2c3d4e5f6a7   2 days ago     350MB
# ctts-api      v2        c3d4e5f6a7b8   1 day ago      360MB

问题：

  1. 命令1 输出中 RECLAIMABLE 列 1.8GB (85%) 表示什么？这说明什么问题？（4分）
  2. 命令2 输出中 <none>:<none> 镜像是什么？是怎么产生的？应该用什么命令清理？（4分）
  3. 假设 ctts-api:v1 已不再使用（v2 是最新版），hello-world 也只是测试用，如何安全删除这两个镜像？给出命令（4分）
  4. 如果想一次性清理所有未被容器使用的镜像（保留 mysql:8.0 和 ctts-api:v2，因为它们正在被容器使用），应该用什么命令？该命令会删除哪些镜像？（4分）
  5. 小李想确认 mysql:8.0 和 mysql:5.7 是否共享层，应该用什么命令验证？给出命令和判断依据（4分）

参考答案与评分标准（20 分）：

1. RECLAIMABLE 1.8GB (85%) 的含义（4分）：

  • RECLAIMABLE 表示"可回收空间"——即未被任何容器使用、可被清理的镜像大小（2 分）。
  • 1.8GB (85%) 表示 2.1GB 镜像总占用中有 1.8GB（85%）可被回收，说明磁盘上有大量未使用的镜像，应该清理（2 分）。

2. <none>:<none> 镜像（4分）：

  • 这是悬空镜像（dangling image），即有层但无标签的镜像（1 分）。
  • 产生原因：通常是用相同标签重新构建镜像时，新镜像占用该标签，旧镜像失去标签变成 <none>:<none>。如本题中 ctts-api 从 v1 升级到 v2 时可能产生（2 分）。
  • 清理命令：docker image prune（或 docker image prune -f 跳过确认）（1 分）。

3. 安全删除 ctts-api:v1 和 hello-world（4分）：

# 先确认没有容器依赖（如有先 docker rm）
docker rmi ctts-api:v1
docker rmi hello-world:latest
  • 注意：如果 ctts-api:v1 有容器依赖会报错，需先 docker rm 容器 再 docker rmi（2 分）。
  • 不用 -f 强删，避免误删运行中的容器（2 分）。

4. 一次性清理所有未被容器使用的镜像（4分）：

docker image prune -a
  • 该命令会清理所有未被任何容器使用的镜像（含已打标签的）（2 分）。
  • 会删除的镜像：mysql:5.7、nginx:1.25、hello-world、<none>:<none>、ctts-api:v1（即所有未被容器使用的）（1.5 分）。
  • 保留的镜像：mysql:8.0 和 ctts-api:v2（因为它们正在被容器使用）（0.5 分）。

5. 验证两个 MySQL 镜像是否共享层（4分）：

# 方法1：查看两个镜像的层摘要列表
docker image inspect -f '{{.RootFS.Layers}}' mysql:8.0
docker image inspect -f '{{.RootFS.Layers}}' mysql:5.7
# 对比两个列表，相同的 SHA256 摘要就是共享的层

# 方法2：查看实际磁盘占用
docker system df
# 如果两个 MySQL 镜像 SIZE 之和（521+448=969MB）大于实际 Images SIZE（如 700MB），说明共享了层
  • 判断依据：相同的 SHA256 摘要 = 共享层（2 分）；实际占用小于 SIZE 之和 = 层共享（2 分）。

评分要点：五部分独立给分；命令必须可执行；第 4 问必须明确指出"会删哪些、保留哪些"才给满分；第 5 问两种方法答出一种即可，但需说明判断依据。
