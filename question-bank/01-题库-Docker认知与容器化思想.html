1.1 单项选择题（30 题）

01-选择-001（★ 知识点：K1-1 容器化动机） "在我电脑上能跑，到服务器上就报错"这一现象的根本原因是？

  • A服务器性能太差
  • B开发与运行环境不一致
  • C代码写得不够规范
  • D网络带宽不足

答案：B 解析：这是软件交付的经典痛点"Works on my machine"，根源是开发环境与运行环境不一致（JDK 版本、依赖库版本、系统配置等）。容器化正是为解决此问题而生。A、C、D 都不是"在我电脑上能跑"到"服务器报错"的根本原因。

01-选择-002（★ 知识点：K1-2 Docker 定义） 关于 Docker，下列说法正确的是？

  • ADocker 是一种虚拟机技术
  • BDocker 是一个开源的容器化平台
  • CDocker 只能在 Windows 上运行
  • DDocker 只能运行 Web 应用

答案：B 解析：Docker 是开源的容器化平台，让应用及其依赖打包成容器镜像并一致运行。A 错，Docker 不是虚拟机；C 错，Docker 基于 Linux 内核特性，主要在 Linux 上运行；D 错，任何 Linux 应用都能容器化。

01-选择-003（★ 知识点：K1-3 容器vs虚拟机） 关于容器与虚拟机的区别，下列说法正确的是？

  • A容器和虚拟机都需要为每个实例运行完整的客户机操作系统
  • B容器共享宿主机内核，虚拟机每个实例有独立的客户机操作系统
  • C容器的隔离强度高于虚拟机
  • D虚拟机的启动速度比容器快

答案：B 解析：容器共享宿主机内核（进程级隔离），虚拟机每个实例运行完整 Guest OS（硬件级隔离）。A 错，容器不需要 Guest OS；C 错，虚拟机的硬件级隔离更强；D 错，容器秒级启动，虚拟机分钟级启动，容器更快。

01-选择-004（★ 知识点：K1-4 Docker 架构） Docker 采用的架构模式是？

  • A单体架构
  • BP2P 对等架构
  • CC/S（客户端/服务器）架构
  • D微服务架构

答案：C 解析：Docker 是 C/S 架构：docker CLI（客户端）通过 REST API 与 dockerd（守护进程/服务器）通信，由守护进程管理镜像和容器。A、B、D 都不正确。

01-选择-005（★ 知识点：K1-5 核心概念） 下列关于 Docker 镜像的描述，正确的是？

  • A镜像是可读写的运行实例
  • B镜像是只读的模板
  • C镜像就是容器
  • D镜像删除后容器一定不存在

答案：B 解析：镜像是只读的模板，包含应用及依赖。A 错，可读写的是容器；C 错，镜像是模板、容器是运行实例，二者不同；D 错，删除镜像前需先删除基于它的容器，但"镜像删除后容器一定不存在"逻辑反了，应先有容器才能用镜像，删除镜像要求先删容器。

01-选择-006（★ 知识点：K1-5 核心概念） Docker 中，"镜像运行起来的实例"指的是？

  • A镜像
  • B容器
  • C仓库
  • D守护进程

答案：B 解析：容器是镜像运行起来的实例，可读写。镜像是只读模板；仓库用于存放镜像；守护进程是管理服务。容器才是"运行实例"。

01-选择-007（★ 知识点：K1-5 核心概念） 存放和分发 Docker 镜像的服务称为？

  • A守护进程
  • B仓库（Registry）
  • C客户端
  • D运行时

答案：B 解析：仓库（Registry）是存放和分发镜像的地方，如 Docker Hub。守护进程是管理服务；客户端是命令行工具；运行时是执行容器的组件。

01-选择-008（★ 知识点：K1-3 容器vs虚拟机） 下列关于容器启动速度的描述，正确的是？

  • A容器启动需要数分钟，与虚拟机相当
  • B容器秒级启动，因为只启动进程而非整个操作系统
  • C容器启动比虚拟机慢
  • D容器启动需要先安装客户机操作系统

答案：B 解析：容器共享宿主内核，启动时只启动应用进程，所以秒级启动。虚拟机要启动整个 Guest OS，需分钟级。A、C、D 都错。

01-选择-009（★ 知识点：K1-2 Docker 思想） Docker 的核心思想可以概括为？

  • A一次编写，处处编译
  • B一次构建，到处运行（Build once, run anywhere）
  • C一个容器只跑一个操作系统
  • D所有应用都必须微服务化

答案：B 解析：Docker 核心思想是"把应用和依赖打包成镜像，一次构建到处运行"。A 是 Java 的口号变体；C 错，容器不跑操作系统；D 错，容器化不要求微服务化。

01-选择-010（★ 知识点：K1-4 Docker 架构） 用户在终端敲 docker run 命令后，命令首先发送给？

  • A容器
  • B镜像仓库
  • CDocker 守护进程（通过 REST API）
  • D操作系统内核

答案：C 解析：docker CLI 是客户端，命令通过 REST API 发送给 dockerd 守护进程，由守护进程执行。A、B、D 都不是命令的直接接收方。

01-选择-011（★ 知识点：K1-1 容器化动机） 下列哪一项不是容器化技术带来的价值？

  • A环境一致性
  • B标准化交付
  • C完全取代虚拟机
  • D弹性扩容基础

答案：C 解析：容器与虚拟机是互补关系，不会完全取代虚拟机，强隔离和异构 OS 场景仍需虚拟机。A、B、D 都是容器化的真实价值。

01-选择-012（★★ 知识点：K1-3 容器vs虚拟机） 关于容器与虚拟机的隔离机制，下列说法正确的是？

  • A容器使用 Hypervisor 实现硬件级隔离
  • B虚拟机使用 namespaces 和 cgroups 实现进程级隔离
  • C容器使用 Linux 内核的 namespaces 和 cgroups 实现进程级隔离
  • D容器和虚拟机使用相同的隔离机制

答案：C 解析：容器基于 Linux 内核的 namespaces（隔离）和 cgroups（资源限制）实现进程级隔离。虚拟机用 Hypervisor 虚拟硬件实现硬件级隔离。A、B、D 均错误。

01-选择-013（★ 知识点：K1-4 Docker 架构） Docker 守护进程（dockerd）的主要职责是？

  • A接收用户敲的命令
  • B管理镜像、容器、网络、存储
  • C存放镜像供分发
  • D提供 Web 界面

答案：B 解析：dockerd 是后台常驻进程，负责构建/运行/分发镜像和容器，管理网络和存储。A 是 docker CLI 的职责；C 是仓库的职责；D 不是 dockerd 的职责。

01-选择-014（★ 知识点：K1-5 核心概念） 关于 Docker 镜像的标签（tag），下列说法正确的是？

  • A标签是镜像的唯一标识，不可重复
  • Bmysql:8.0 中的 8.0 是标签，表示版本
  • C不写标签时默认使用 :stable
  • D一个镜像只能有一个标签

答案：B 解析：标签用于标识镜像版本，mysql:8.0 中 8.0 是标签。不写标签默认 :latest（不是 stable）。一个镜像可以打多个标签。A 错，不同镜像可以打相同标签（会覆盖）。

01-选择-015（★★ 知识点：K1-5 核心概念） 关于 :latest 标签，下列说法正确的是？

  • A:latest 一定指向最新最稳定的版本
  • B生产环境推荐使用 :latest 标签
  • C:latest 只是默认标签名，可能指向任意版本，生产环境应指定明确版本
  • D不写标签时镜像会报错

答案：C 解析：:latest 只是默认标签名，不保证最新最稳定，可能指向任意版本，生产环境应指定明确版本号（如 mysql:8.0.35）以保证可复现。A、B 错误；D 错，不写标签默认 latest 不会报错。

01-选择-016（★ 知识点：K1-6 云原生） 关于云原生（Cloud Native），下列说法正确的是？

  • A云原生就是把应用部署到云服务器上
  • B云原生是一套构建和运行应用的方法论，以容器、微服务、声明式 API 为核心技术
  • C云原生必须使用某个特定厂商的云
  • D云原生等同于容器化

答案：B 解析：云原生是一套方法论，核心技术包括容器、微服务、不可变基础设施、声明式 API。A 错，上云≠云原生；C 错，云原生不绑定厂商；D 错，容器化只是云原生的基础之一。

01-选择-017（★ 知识点：K1-6 Docker与K8s关系） 关于 Docker 与 Kubernetes 的关系，下列说法正确的是？

  • A二者是竞争关系，选其一即可
  • BDocker 负责把应用容器化，Kubernetes 负责编排管理集群中的容器
  • CKubernetes 可以完全取代 Docker
  • DDocker 是 Kubernetes 的底层内核

答案：B 解析：Docker 负责容器化（装箱），K8s 负责集群编排（调度），二者是上下游关系。A 错，不是竞争；C 错，K8s 建立在容器之上；D 错，Docker 不是内核。

01-选择-018（★ 知识点：K1-4 Docker 架构） Docker 客户端与守护进程之间通信的方式是？

  • A共享内存
  • BREST API（通过 Unix socket 或网络端口）
  • C消息队列
  • D文件锁

答案：B 解析：docker CLI 通过 REST API 与 dockerd 通信，默认走 Unix socket（/var/run/docker.sock），也可配置走 TCP 网络端口实现远程管理。A、C、D 都不是。

01-选择-019（★ 知识点：K1-3 容器vs虚拟机） 下列场景中，最适合使用虚拟机而非容器的是？

  • A个人电脑跑多个不同版本的 MySQL
  • B微服务快速弹性扩容
  • C在 Linux 上运行 Windows 应用程序
  • D教学实验环境秒级启动

答案：C 解析：容器共享宿主内核，不能在 Linux 上跑 Windows 容器，跨 OS 需虚拟机。A、B、D 都适合用容器。

01-选择-020（★★ 知识点：K1-3 容器vs虚拟机） 下列关于容器与虚拟机资源占用的对比，正确的是？

  • A虚拟机实例通常 MB 级，容器实例通常 GB 级
  • B容器实例通常 MB 级，虚拟机实例通常 GB 级
  • C二者资源占用相当
  • D容器比虚拟机占用更多内存

答案：B 解析：容器没有 Guest OS，实例通常 MB 级；虚拟机有完整 Guest OS，通常 GB 级。所以一台机器能跑成百上千个容器，但通常只能跑几十个虚拟机。

01-选择-021（★ 知识点：K1-2 Docker 历史） Docker 技术最初是基于下列哪项 Linux 内核特性实现的？

  • A文件系统与网络协议栈
  • Bnamespaces 和 cgroups
  • C用户权限与进程调度
  • D内存管理与设备驱动

答案：B 解析：Docker 容器隔离基于 Linux 的 namespaces（隔离视图：PID/NET/MNT 等）和 cgroups（资源限制：CPU/内存等）。其他选项不是容器隔离的底层机制。

01-选择-022（★★ 知识点：K1-4 运行时层次） 在 Docker 的运行时层次中，真正创建并运行容器进程的低级运行时是？

  • Adockerd
  • Bcontainerd
  • CrunC
  • Ddocker CLI

答案：C 解析：层次为 docker CLI → dockerd → containerd → runC。runC 是低级运行时，遵循 OCI 标准，真正创建和运行容器进程。dockerd 是守护进程，containerd 是高级运行时管理生命周期。

01-选择-023（★ 知识点：K1-5 镜像仓库） Docker Hub 是什么？

  • ADocker 的官方公共镜像仓库
  • BDocker 的客户端工具
  • CDocker 的守护进程
  • DDocker 的配置文件

答案：A 解析：Docker Hub（hub.docker.com）是 Docker 官方公共镜像仓库，存放大量官方镜像（mysql、nginx、openjdk 等）。其他选项都不对。

01-选择-024（★ 知识点：K1-5 容器特性） 关于容器，下列说法正确的是？

  • A一个镜像只能运行一个容器实例
  • B一个镜像可以同时运行多个容器实例，互不干扰
  • C容器停止后所有数据永久丢失
  • D容器必须一直运行不能停止

答案：B 解析：一个镜像可以同时启动多个容器实例，每个容器有自己的可写层，互不干扰。C 错，容器停止后可写层仍在，可再次启动；除非删除容器，数据不会丢。D 错，容器可随时启停。

01-选择-025（★ 知识点：K1-1 传统部署痛点） 传统软件交付方式（交付代码+部署文档）的主要问题是？

  • A代码不能运行
  • B环境由目标机器提供，易不一致，文档易过时
  • C必须用 Java 语言
  • D不能部署到云上

答案：B 解析：传统交付把环境配置交给目标机器，依赖人工按文档配置，易不一致、文档易过时。容器化把环境打包进镜像解决此问题。A、C、D 都不是传统交付的问题。

01-选择-026（★★ 知识点：K1-4 C/S架构优势） Docker 采用 C/S 架构的好处不包括？

  • A客户端和守护进程可以分离，支持远程管理
  • B一个守护进程可被多个客户端操作
  • C客户端无需运行在宿主机上即可管理远端 Docker
  • D客户端直接操作容器，速度更快

答案：D 解析：客户端不直接操作容器，是通过 REST API 请求守护进程执行，不存在"直接操作更快"。A、B、C 都是 C/S 架构的真实好处（可远程、多客户端、客户端解耦）。

01-选择-027（★ 知识点：K1-6 CNCF） CNCF 的全称是？

  • ACloud Native Computing Foundation（云原生计算基金会）
  • BContainer Network Control Framework
  • CCloud Native Container Federation
  • DCommon Network Container Format

答案：A 解析：CNCF = Cloud Native Computing Foundation，是 Linux 基金会下的子基金会，托管 Kubernetes、containerd、Prometheus 等云原生核心项目。

01-选择-028（★ 知识点：K1-5 镜像特性） 关于 Docker 镜像的分层结构，下列说法正确的是？

  • A镜像是一个整体的不可分割的文件
  • B镜像由多层（Layer）组成，每层可共享和缓存
  • C镜像的每一层都是可写的
  • D镜像分层会增大存储占用

答案：B 解析：镜像是分层的只读结构，每条 Dockerfile 指令生成一层，多层可共享和缓存，节省存储和传输。A 错，是分层的；C 错，镜像层只读，容器才有可写层；D 错，分层是为了节省存储。

01-选择-029（★★ 知识点：K1-2 容器与Docker关系） 关于"容器"和"Docker"的关系，下列说法正确的是？

  • A容器和 Docker 是同一个概念
  • B容器是一种技术概念，Docker 是实现容器技术的一个工具/平台
  • CDocker 是技术概念，容器是工具
  • D只有 Docker 能实现容器技术

答案：B 解析：容器是技术概念（隔离的运行环境），Docker 是实现该概念的工具之一。类比：容器是"汽车"概念，Docker 是某款"汽车品牌"。还有 Podman、containerd 等其他容器工具。

01-选择-030（★★ 知识点：K1-6 课程项目） 本课程的贯穿项目是"多服务容器化部署项目"，其中需要容器化的三个服务是？

  • A前端（Vue3）+ 后端（SpringBoot）+ MySQL
  • B前端（Vue3）+ 后端（SpringBoot）+ Redis
  • C前端（React）+ 后端（Node.js）+ MySQL
  • D前端（Vue3）+ 后端（Django）+ MongoDB

答案：A 解析：贯穿项目将 JavaWeb 课程的 CTTS 后端（SpringBoot）+ Vue3 课程的 CTTS-Frontend + MySQL 三服务容器化，与已学课程联动。B、C、D 的技术栈不符。

1.2 多项选择题（10 题）

01-选择-031（★★ 知识点：K1-1 容器化价值） 容器化技术带来的价值包括？（多选）

  • A环境一致性
  • B标准化交付
  • C完全取代数据库
  • D弹性扩容基础 E. 快速启动

答案：A、B、D、E 解析：容器化带来环境一致性、标准化交付、弹性扩容基础、快速启动。C 错，容器化不会取代数据库，反而数据库也可以容器化。

01-选择-032（★★ 知识点：K1-3 容器vs虚拟机） 与虚拟机相比，容器的特点包括？（多选）

  • A共享宿主机内核
  • B秒级启动
  • C每个实例运行完整客户机操作系统
  • D资源占用小（MB 级） E. 进程级隔离

答案：A、B、D、E 解析：容器共享内核（A）、秒级启动（B）、资源占用小（D）、进程级隔离（E）。C 是虚拟机的特点，不是容器的。

01-选择-033（★★ 知识点：K1-4 Docker 架构） Docker 引擎的组成部分包括？（多选）

  • ADocker 客户端（docker CLI）
  • BDocker 守护进程（dockerd）
  • CREST API
  • DHypervisor 虚拟化层 E. 镜像仓库（Registry）

01-编程-002（★★★ 知识点：K1-4/K1-5 综合应用，20 分） Docker 架构与命令流程综合题：某团队要将一个 Java Web 应用容器化部署，团队成员小王在终端执行了以下命令序列。请回答问题：

# 命令1
docker pull openjdk:17
# 命令2
docker images
# 命令3
docker build -t ctts-backend:v1 .
# 命令4
docker run -d -p 8080:8080 --name ctts-api ctts-backend:v1
# 命令5
docker ps

问题：

  1. 说明命令1~5每条命令的作用，并指出每条命令在 Docker C/S 架构中是客户端发请求还是守护进程执行（10分）
  2. 命令3中的 . 表示什么？为什么需要它？（3分）
  3. 命令4中 -d、-p 8080:8080、--name ctts-api 三个参数分别是什么含义？（3分）
  4. 如果命令4执行后 docker ps 没看到 ctts-api 容器，可能的原因有哪些？（写出至少2种）（4分）

参考答案与评分标准（20 分）：

1. 各命令作用与架构归属（10分，每条2分）：

  • 命令1 docker pull openjdk:17：从仓库拉取 openjdk:17 镜像到本地。客户端发请求，守护进程执行（执行实际的拉取）。
  • 命令2 docker images：列出本地所有镜像。客户端发请求，守护进程查询并返回。
  • 命令3 docker build -t ctts-backend:v1 .：根据当前目录的 Dockerfile 构建镜像并打标签 ctts-backend:v1。客户端发请求，守护进程执行构建。
  • 命令4 docker run -d -p 8080:8080 --name ctts-api ctts-backend:v1：用 ctts-backend:v1 镜像启动一个名为 ctts-api 的容器，后台运行，端口映射8080。客户端发请求，守护进程创建并运行容器。
  • 命令5 docker ps：列出正在运行的容器。客户端发请求，守护进程查询返回。 （每条命令：作用1分 + 架构归属1分）

2. 命令3中的 .（3分）： . 表示构建上下文（build context）为当前目录。Docker 构建时会把这个目录下的所有文件发送给守护进程，Dockerfile 中的 COPY/ADD 指令会从这个上下文里复制文件到镜像中。所以需要 . 是为了让 Dockerfile 能找到要打包进镜像的应用文件（如 jar 包）。

3. 命令4参数含义（3分，每个1分）：

  • -d：后台运行容器（detached 模式）
  • -p 8080:8080：端口映射，宿主机8080端口映射到容器8080端口
  • --name ctts-api：给容器命名为 ctts-api

4. docker ps 看不到容器的可能原因（4分，每种2分，答出2种即满分）：

  • 容器启动后立即崩溃退出了（如应用启动报错）。可用 docker ps -a（含已停止的）和 docker logs ctts-api 查看日志。
  • 镜像构建有问题，容器内应用无法启动（如 jar 包路径错误、JDK 版本不符）。
  • 端口 8080 被宿主机其他进程占用，导致容器启动失败。
  • 容器启动正常但很快退出（如前台进程没阻塞，容器生命周期结束）。

评分要点：各小题独立给分；原因部分答出任意2种合理原因即给满分；专有名词理解正确即可。
