1.1 单项选择题（30 题）

02-选择-001（★ 知识点：K2-1 系统要求） 本课程推荐的 Docker 安装操作系统是？

  • AWindows 10
  • BmacOS
  • CUbuntu 22.04 LTS
  • DCentOS 6

答案：C 解析：本课程统一用 Ubuntu 22.04 LTS，内核 5.15+ 满足 Docker 要求，社区活跃、官方源支持完善。Windows/macOS 用 Docker Desktop 与生产环境有差异；CentOS 6 内核过旧、CentOS 8 已 EOL。

02-选择-002（★ 知识点：K2-1 内核要求） Docker 对 Linux 内核版本的最低要求是？

  • A2.6
  • B3.10
  • C4.15
  • D5.0

答案：B 解析：Docker 要求内核 ≥ 3.10（建议 3.10+）。Ubuntu 22.04 自带 5.15 内核，完全满足。内核过低会导致 namespaces/cgroups 特性不全。

02-选择-003（★ 知识点：K2-2 卸载旧版本） 安装 Docker 前建议先卸载旧版本，主要原因是？

  • A旧版本无法启动
  • B避免新旧版本冲突
  • C旧版本占用内存
  • D卸载是必须步骤，不卸载无法安装

答案：B 解析：防御性卸载旧版本（如 docker.io、docker-engine）是为避免与官方 docker-ce 冲突。没装过旧版执行卸载命令也不会报错。D 错，不卸载技术上也能装，但有冲突风险。

02-选择-004（★ 知识点：K2-2 GPG 密钥） 添加 Docker 官方 apt 源时，GPG 密钥的作用是？

  • A加速软件下载
  • B验证软件包来源真实性，防止被篡改
  • C压缩软件包体积
  • D自动安装依赖

答案：B 解析：apt 通过 GPG 密钥验证软件包签名，确保包来自 Docker 官方未被篡改。没有 GPG 密钥 apt 会警告 NO_PUBKEY 并拒绝安装。

02-选择-005（★ 知识点：K2-2 apt 源配置） 在 Ubuntu 22.04 上，Docker 官方 apt 源配置文件应放在？

  • A/etc/apt/sources.list
  • B/etc/docker/daemon.json
  • C/etc/apt/sources.list.d/docker.list
  • D/etc/docker/sources.list

答案：C 解析：第三方源统一放在 /etc/apt/sources.list.d/ 目录下，Docker 源文件名为 docker.list。/etc/apt/sources.list 是系统主源文件，不建议直接改。daemon.json 是 Docker 运行配置，不是 apt 源。

02-选择-006（★ 知识点：K2-2 安装包名） 通过 Docker 官方源安装 Docker 引擎主体使用的包名是？

  • Adocker.io
  • Bdocker
  • Cdocker-ce
  • Ddocker-engine

答案：C 解析：官方源提供 docker-ce（Community Edition 社区版）。docker.io 是 Ubuntu 发行版自己打包的旧版本，不推荐。docker-engine 是更早的旧包名。

02-选择-007（★ 知识点：K2-2 包组成） 下列哪个包是 Docker 的命令行客户端？

  • Adocker-ce
  • Bdocker-ce-cli
  • Ccontainerd.io
  • Ddocker-buildx-plugin

答案：B 解析：docker-ce-cli 是 docker 命令行客户端；docker-ce 是引擎主体（含 dockerd）；containerd.io 是容器运行时；docker-buildx-plugin 是构建增强插件。

02-选择-008（★ 知识点：K2-2 验证安装） 安装 Docker 后，查看 Docker 版本号的命令是？

  • Adocker version --all
  • Bdocker --version
  • Cdocker info --version
  • Dsystemctl status docker

答案：B 解析：docker --version 查看客户端版本号（精简）。docker version（不带 --）查看 Client + Server 详细信息。docker info 看系统详情。systemctl status 看服务状态。

02-选择-009（★ 知识点：K2-3 服务管理） 启动 Docker 服务的命令是？

  • Asudo systemctl start docker
  • Bsudo systemctl enable docker
  • Csudo systemctl status docker
  • Dsudo systemctl restart docker

答案：A 解析：start 启动服务；enable 是设置开机自启；status 是查看状态；restart 是重启。启动当前服务用 start。

02-选择-010（★ 知识点：K2-3 开机自启） 设置 Docker 开机自启的命令是？

  • Asudo systemctl start docker
  • Bsudo systemctl enable docker
  • Csudo systemctl status docker
  • Dsudo systemctl restart docker

答案：B 解析：enable 是设置开机自启（持久化）；start 是当前启动。生产环境两者都要执行，或用 enable --now 一步到位。

02-选择-011（★ 知识点：K2-3 服务状态） systemctl status docker 输出中，表示服务正常运行的字段是？

  • ALoaded: loaded
  • BActive: active (running)
  • CMain PID: 12345
  • DTasks: 10

答案：B 解析：Active: active (running) 表示服务正在运行（关键判断）。Loaded 表示单元文件已加载；Main PID 是主进程号；Tasks 是任务数。看到 active (running) 才算服务正常。

02-选择-012（★ 知识点：K2-3 重启生效） 修改 /etc/docker/daemon.json 后，使其生效需要执行？

  • Asystemctl reload docker
  • Bsystemctl restart docker
  • Csystemctl daemon-reload
  • Dsource /etc/docker/daemon.json

答案：B 解析：dockerd 只在启动时读取 daemon.json，运行中改了配置必须 systemctl restart docker 重新加载。reload 对 docker 服务无效；daemon-reload 是让 systemd 重载单元文件（不是配置）；source 不能用于 JSON 文件。

02-选择-013（★ 知识点：K2-4 配置文件） Docker 镜像加速器的配置文件路径是？

  • A/etc/docker/config.json
  • B/etc/docker/daemon.json
  • C/etc/docker/mirror.json
  • D/etc/docker/registry.json

答案：B 解析：Docker 守护进程配置文件固定为 /etc/docker/daemon.json。镜像加速器在其中 registry-mirrors 字段配置。其他文件名都不对。

02-选择-014（★ 知识点：K2-4 配置字段） daemon.json 中配置镜像加速器的字段名是？

  • Amirrors
  • Bregistry-mirrors
  • Cimage-mirrors
  • Ddocker-mirrors

答案：B 解析：字段名是 registry-mirrors，值是地址数组。字段名必须严格一致，写错不报错但不生效。

02-选择-015（★ 知识点：K2-4 加速器作用） 配置镜像加速器的主要目的是？

  • A加快镜像拉取速度
  • B减小镜像体积
  • C提高容器运行性能
  • D自动清理无用镜像

答案：A 解析：镜像加速器是国内镜像站缓存，加速从 Docker Hub 拉取镜像的速度。不影响镜像体积、容器性能或清理。

02-选择-016（★ 知识点：K2-4 生效方式） 配置镜像加速器后，使其生效的正确操作是？

  • A重新登录系统
  • B重启 Docker 服务
  • C重新打开终端
  • D等待自动生效

答案：B 解析：dockerd 启动时读取 daemon.json，改配置后必须 systemctl restart docker 重新加载。重新登录/重开终端/等待都不会让 dockerd 重新读取配置。

02-选择-017（★ 知识点：K2-4 验证生效） 验证镜像加速器是否生效的命令是？

  • Adocker version
  • Bdocker images
  • Cdocker info
  • Ddocker ps

答案：C 解析：docker info 输出中的 Registry Mirrors 字段会列出已生效的加速器地址。docker version 看版本；docker images 看本地镜像；docker ps 看运行中容器。

02-选择-018（★ 知识点：K2-5 docker run 原理） docker run hello-world 第一次执行时，dockerd 会？

  • A直接报错，因为本地没有镜像
  • B自动从仓库拉取 hello-world 镜像再运行
  • C需要先手动 docker pull 才能运行
  • D从本地缓存创建容器

答案：B 解析：docker run 时若本地没有指定镜像，dockerd 会自动从仓库 pull 再运行，不需要手动 pull。第一次看到 "Unable to find image locally" + "Pulling from"。

02-选择-019（★ 知识点：K2-5 输出含义） docker run hello-world 输出 "Unable to find image 'hello-world:latest' locally" 表示？

  • A镜像拉取失败
  • B本地没有该镜像，准备拉取
  • CDocker 安装失败
  • D网络不通

答案：B 解析：这句话表示本地没有 hello-world:latest 镜像，dockerd 接下来会从仓库拉取。是正常流程的第一步，不是报错。

02-选择-020（★ 知识点：K2-5 容器状态） hello-world 容器运行后的状态是？

  • AUp（运行中）
  • BExited (0)（正常退出）
  • CExited (1)（异常退出）
  • DRestarting（重启中）

答案：B 解析：hello-world 程序打印完说明文字就结束，容器正常退出，状态是 Exited (0)（退出码 0 表示正常）。nginx 等守护进程容器才会持续 Up。

02-选择-021（★ 知识点：K2-5 第二次运行） 第二次执行 docker run hello-world 时，与第一次的区别是？

  • A不再显示 "Pulling from" 拉取过程
  • B报错说镜像已存在
  • C需要重新拉取镜像
  • D容器无法运行

答案：A 解析：第一次已把 hello-world:latest 拉到本地，第二次直接用本地镜像创建容器，不再 pull，所以没有 "Unable to find image locally" 和 "Pulling from" 输出。

02-选择-022（★ 知识点：K2-6 命令区别） docker version 和 docker info 的主要区别是？

  • Aversion 看版本，info 看运行状态详情
  • Bversion 看客户端，info 看服务端
  • C两个命令完全相同
  • Dversion 是旧命令，info 是新命令

答案：A 解析：docker version 查看客户端与服务端版本（版本号、API 版本等）；docker info 查看系统级运行详情（容器数、存储驱动、镜像加速器、内核等）。用途不同。

02-选择-023（★ 知识点：K2-6 排查） docker version 输出只显示 Client 段，没有 Server 段，最可能的原因是？

  • ADocker 未安装
  • Bdockerd 守护进程未启动
  • C网络不通
  • D镜像加速器未配置

答案：B 解析：Client 段有说明 docker 命令装了；Server 段空说明连不上 dockerd，最可能是 dockerd 未启动（用 systemctl start docker 启动）。也可能是用户无权限（加入 docker 组）。

02-选择-024（★ 知识点：K2-6 存储驱动） Ubuntu 22.04 上 Docker 推荐的存储驱动是？

  • Aaufs
  • Bdevicemapper
  • Coverlay2
  • Dvfs

答案：C 解析：overlay2 性能最好，是 Ubuntu 22.04 默认推荐。aufs 已不推荐；devicemapper 是老方案；vfs 性能最差（仅兼容用）。

02-选择-025（★ 知识点：K2-6 数据目录） Docker 默认的数据目录（存放镜像、容器、卷）是？

  • A/etc/docker
  • B/var/lib/docker
  • C/var/run/docker
  • D/usr/lib/docker

答案：B 解析：docker info 中 Docker Root Dir: /var/lib/docker 是 Docker 数据目录，镜像、容器、卷都存这里。/etc/docker 是配置目录。

02-选择-026（★ 知识点：K2-2 免 sudo） 让普通用户免 sudo 运行 docker 命令的操作是？

  • Achmod 777 /var/run/docker.sock
  • B把用户加入 docker 组：usermod -aG docker 用户名
  • C修改 daemon.json
  • D用 root 用户登录

答案：B 解析：把用户加入 docker 组后，该用户有权限访问 /var/run/docker.sock，可免 sudo。chmod 777 不安全；daemon.json 不控制权限；用 root 不推荐。

02-选择-027（★★ 知识点：K2-2 安装流程顺序） 下列 Docker 安装步骤的正确顺序是？ ①apt install docker-ce ②添加 GPG 密钥 ③apt update ④添加 apt 仓库 ⑤卸载旧版本

  • A⑤②④③①
  • B⑤④②③①
  • C②④⑤③①
  • D⑤②③④①

答案：A 解析：正确顺序：先卸载旧版本(⑤)→添加 GPG 密钥(②)→添加 apt 仓库(④)→apt update(③)→apt install(①)。GPG 密钥要在仓库之前，apt update 要在 install 之前。

02-选择-028（★★ 知识点：K2-2 GPG 密钥路径） 本课推荐的 GPG 密钥存放路径是？

  • A/etc/apt/trusted.gpg
  • B/etc/apt/keyrings/docker.gpg
  • C/root/docker.gpg
  • D/etc/docker/gpg

答案：B 解析：Ubuntu 22.04 推荐用 keyring 方式，密钥放 /etc/apt/keyrings/docker.gpg，并在 sources.list 中用 signed-by= 指定路径。旧的 trusted.gpg 方式已不推荐。

02-选择-029（★★ 知识点：K2-3 enable --now） sudo systemctl enable --now docker 命令的作用是？

  • A仅设置开机自启
  • B仅立即启动
  • C同时设置开机自启并立即启动
  • D重启 Docker 服务

答案：C 解析：--now 参数等同于 enable + start 一步到位：既设置开机自启，又立即启动服务。是实际运维常用写法。

02-选择-030（★★ 知识点：K2-4 daemon.json 格式） 下列 daemon.json 内容中，格式错误的是？

  • A{"registry-mirrors": ["https://a.com"]}
  • B{"registry-mirrors": ["https://a.com",]}
  • C{"registry-mirrors": ["https://a.com","https://b.com"]}
  • D{"log-driver": "json-file"}

答案：B 解析：B 选项数组最后一项多了逗号（trailing comma），JSON 标准不允许末尾逗号，会导致 dockerd 启动失败。A、C、D 格式正确。

02-选择-038（★★ 知识点：K2-2 旧版本包名） 安装 Docker 前建议卸载的旧版本包名包括？（多选）

  • Bdocker-engine
  • Cdocker.io

02-选择-039（★★ 知识点：K2-3 服务状态判断） 下列情况中，表示 Docker 服务可能未正常运行的有？（多选）

  • Asystemctl status 显示 Active: inactive (dead)
  • Bsystemctl status 显示 Active: failed

02-编程-001（★★ 知识点：K2-2/K2-3/K2-4 综合安装脚本，15 分） 编写 Docker 安装脚本：请为 CTTS 项目环境准备编写一个完整的 Docker 安装 Bash 脚本 install-docker.sh，要求：

  1. 包含环境检查（操作系统是否为 Ubuntu 22.04，1分）
  2. 包含卸载旧版本步骤（2分）
  3. 包含添加 GPG 密钥与 apt 仓库步骤（3分）
  4. 包含 apt update 与安装 docker-ce 全套包步骤（3分）
  5. 包含设置开机自启并立即启动（2分）
  6. 包含配置镜像加速器 daemon.json（2分）
  7. 包含把当前用户加入 docker 组（1分）
  8. 脚本末尾运行 docker run hello-world 验证（1分）

参考答案与评分标准（15 分）：

#!/bin/bash
# install-docker.sh - CTTS 项目 Docker 安装脚本
# 用法：sudo bash install-docker.sh

set -e  # 任一步骤失败即退出

echo "==== 1. 环境检查 ===="
if ! grep -q "Ubuntu 22.04" /etc/os-release; then
    echo "错误：本脚本仅支持 Ubuntu 22.04"
    exit 1
fi
echo "操作系统检查通过"

echo "==== 2. 卸载旧版本 ===="
apt remove -y docker docker-engine docker.io containerd runc 2>/dev/null || true

echo "==== 3. 安装依赖 ===="
apt update
apt install -y ca-certificates curl gnupg lsb-release

echo "==== 4. 添加 GPG 密钥 ===="
mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg

echo "==== 5. 添加 apt 仓库 ===="
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null

echo "==== 6. 安装 Docker ===="
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

echo "==== 7. 设置开机自启并立即启动 ===="
systemctl enable --now docker

echo "==== 8. 配置镜像加速器 ===="
mkdir -p /etc/docker
tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com",
    "https://docker.mirrors.baidubce.com"
  ],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
EOF

echo "==== 9. 重启 Docker 让加速器生效 ===="
systemctl daemon-reload
systemctl restart docker

echo "==== 10. 把当前用户加入 docker 组 ===="
CURRENT_USER=${SUDO_USER:-$USER}
usermod -aG docker "$CURRENT_USER"
echo "用户 $CURRENT_USER 已加入 docker 组，重新登录后免 sudo"

echo "==== 11. 验证安装 ===="
docker run hello-world

echo "==== Docker 安装完成 ===="

评分要点：

  • 8 个要求每项对应分值，全部实现给满分
  • 脚本可执行、逻辑顺序正确给基础分
  • 加分项：set -e 容错、SUDO_USER 处理、友好 echo 提示
  • 减分项：缺少 #!/bin/bash、命令顺序错乱、JSON 格式错

3. 一键诊断脚本 docker-doctor.sh（5分）：

#!/bin/bash
# docker-doctor.sh - Docker 安装健康诊断

echo "===== Docker 诊断报告 ====="
echo "时间: $(date)"
echo ""

echo "【1. 检查 docker 命令是否存在】"
if command -v docker &> /dev/null; then
    echo "  ✓ docker 命令已安装: $(docker --version)"
else
    echo "  ✗ docker 命令未安装，请先安装 Docker"
    exit 1
fi
echo ""

echo "【2. 检查 dockerd 服务状态】"
if systemctl is-active --quiet docker; then
    echo "  ✓ docker 服务运行中 (active)"
else
    echo "  ✗ docker 服务未运行，尝试启动..."
    sudo systemctl start docker
    if systemctl is-active --quiet docker; then
        echo "  ✓ 启动成功"
    else
        echo "  ✗ 启动失败，查看日志: journalctl -u docker.service"
        exit 1
    fi
fi
echo ""

echo "【3. 检查 docker version 通信】"
SERVER_VER=$(docker version --format '{{.Server.Version}}' 2>/dev/null)
if [ -n "$SERVER_VER" ]; then
    echo "  ✓ Client 与 Server 通信正常，Server 版本: $SERVER_VER"
else
    echo "  ✗ 无法连接 dockerd，可能权限不足"
    echo "    解决: sudo usermod -aG docker \$USER && newgrp docker"
    exit 1
fi
echo ""

echo "【4. 检查当前用户是否在 docker 组】"
if groups | grep -qw docker; then
    echo "  ✓ 当前用户在 docker 组（可免 sudo）"
else
    echo "  ! 当前用户不在 docker 组，需加 sudo 或加入组"
    echo "    解决: sudo usermod -aG docker \$USER && newgrp docker"
fi
echo ""

echo "【5. 检查开机自启】"
if systemctl is-enabled --quiet docker; then
    echo "  ✓ docker 已设为开机自启"
else
    echo "  ! docker 未设为开机自启"
    echo "    解决: sudo systemctl enable docker"
fi
echo ""

echo "【6. 检查镜像加速器配置】"
MIRRORS=$(docker info --format '{{json .RegistryConfig.Mirrors}}' 2>/dev/null)
if [ "$MIRRORS" != "[]" ] && [ -n "$MIRRORS" ]; then
    echo "  ✓ 镜像加速器已配置: $MIRRORS"
else
    echo "  ! 未配置镜像加速器，建议编辑 /etc/docker/daemon.json"
fi
echo ""

echo "【7. 检查存储驱动】"
DRIVER=$(docker info --format '{{.Driver}}' 2>/dev/null)
if [ "$DRIVER" = "overlay2" ]; then
    echo "  ✓ 存储驱动: overlay2（推荐）"
else
    echo "  ! 存储驱动: $DRIVER（推荐 overlay2）"
fi
echo ""

echo "===== 诊断完成 ====="

评分要点：

  • 三个原因各 2 分，合理即可（答出 3 种即满分）
  • 排查命令与解决方法各 3 分，命令正确、能解决问题给满分
  • 诊断脚本 5 分：能检查至少 4 项（命令存在/服务状态/通信/用户组/自启/加速器/存储驱动）给满分；脚本结构清晰、有友好输出加分
  • 脚本不要求完全可运行，逻辑正确即可
