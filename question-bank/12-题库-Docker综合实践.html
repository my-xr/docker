一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

12-选择-001（★ 知识点：K12-1 项目架构） CTTS 三服务的正确依赖顺序是？

  • Afrontend → backend → mysql
  • Bmysql → backend → frontend
  • Cbackend → mysql → frontend
  • Dmysql → frontend → backend

答案：B 解析：CTTS 三服务的依赖顺序为：mysql（数据库，最先启动）→ backend（依赖数据库）→ frontend（依赖后端 API）。前端调后端、后端连数据库，故 mysql 必须先就绪。

12-选择-002（★ 知识点：K12-2 MySQL 容器化） MySQL 容器的初始化 SQL 脚本应挂载到容器内的哪个目录？

  • A/var/lib/mysql
  • B/etc/mysql/conf.d
  • C/docker-entrypoint-initdb.d
  • D/usr/local/mysql/init

答案：C 解析：MySQL 官方镜像启动时会扫描 /docker-entrypoint-initdb.d/ 目录，按文件名顺序执行其中的 .sql 或 .sh 文件，仅在首次启动（数据目录为空）时执行。A 是数据目录，B 是配置目录，D 不存在。

12-选择-003（★ 知识点：K12-2 init.sql 执行时机） 关于 MySQL 容器的 init.sql，下列说法正确的是？

  • A每次容器启动都会执行
  • B仅在首次启动（数据目录为空）时执行
  • C仅在容器停止时执行
  • D需要手动 docker exec 执行

答案：B 解析：init.sql 仅在 MySQL 首次启动（/var/lib/mysql 为空）时执行。若数据卷已有数据，再次启动会跳过初始化。修改 init.sql 后需 docker compose down -v 删卷才能重新执行。

12-选择-004（★ 知识点：K12-2 MySQL 环境变量） 设置 MySQL root 用户密码的环境变量是？

  • AMYSQL_PASSWORD
  • BMYSQL_ROOT_PASSWORD
  • CMYSQL_ROOT_USER
  • DROOT_PASSWORD

答案：B 解析：MYSQL_ROOT_PASSWORD 设置 root 密码（必需），MYSQL_USER/MYSQL_PASSWORD 创建普通用户，MYSQL_DATABASE 创建初始数据库。A 是普通用户密码，C/D 不存在。

12-选择-005（★ 知识点：K12-2 数据卷） MySQL 容器化时，数据持久化应挂载哪个容器路径？

  • A/etc/mysql
  • B/var/lib/mysql
  • C/usr/local/mysql
  • D/data/mysql

答案：B 解析：MySQL 数据文件默认存储在 /var/lib/mysql，用具名卷挂载此路径可持久化数据。A 是配置目录，C/D 不是 MySQL 默认路径。

12-选择-006（★★ 知识点：K12-3 多阶段构建） 后端 Dockerfile 多阶段构建中，第一阶段（builder）使用的基础镜像是？

  • Aopenjdk:17
  • Beclipse-temurin:17-jre
  • Cmaven:3.9-eclipse-temurin-17
  • Dnginx:alpine

答案：C 解析：第一阶段需要 Maven 打包，故用 maven:3.9-eclipse-temurin-17（含 Maven + JDK17）。第二阶段用 eclipse-temurin:17-jre（只含 JRE）运行 jar。A 不是推荐镜像，B 是运行阶段镜像，D 是前端镜像。

12-选择-007（★ 知识点：K12-3 多阶段构建价值） 后端 Dockerfile 采用多阶段构建的核心价值是？

  • A加快 Maven 打包速度
  • B减小最终镜像体积
  • C增加镜像层数
  • D简化 Dockerfile 语法

答案：B 解析：多阶段构建把"构建工具（Maven+JDK）"与"运行时（JRE）"分离，最终镜像只含 JRE + jar，体积从约 800MB 减到约 320MB。A 不是核心价值，C 是副作用（不利），D 不正确。

12-选择-008（★ 知识点：K12-3 Dockerfile 缓存优化） 后端 Dockerfile 中先 COPY pom.xml 再 COPY src/ 的目的是？

  • A减少镜像层数
  • B利用 Docker 层缓存，加速重复构建
  • C避免源码泄露
  • D让 Maven 能找到 pom.xml

答案：B 解析：先把 pom.xml 单独 COPY 并 mvn dependency:go-offline 下载依赖（缓存层）。pom.xml 不变时这一层命中缓存，后续只重新 COPY src/ 并打包，大幅加速重复构建。

12-选择-009（★★ 知识点：K12-3 ENTRYPOINT） 后端 Dockerfile 用 ENTRYPOINT ["java", "-jar", "/app/app.jar"] 而不是 CMD 的原因是？

  • ACMD 不能执行 java
  • BENTRYPOINT 不会被 docker run 后的参数覆盖，更固定
  • CENTRYPOINT 比 CMD 速度快
  • DCMD 已被废弃

答案：B 解析：ENTRYPOINT 的启动命令不会被 docker run <镜像> <参数> 的参数覆盖，适合"容器就是跑这个命令"的场景。CMD 可以被覆盖。A 错，CMD 也能执行 java；C 错，性能无差异；D 错，CMD 仍在使用。

12-选择-010（★ 知识点：K12-4 前端多阶段） 前端 Dockerfile 多阶段构建中，第二阶段（runtime）使用的基础镜像是？

  • Anode:20-alpine
  • Bnginx:alpine
  • Chttpd:alpine
  • Dcaddy:alpine

答案：B 解析：前端第二阶段用 nginx:alpine 托管 dist/ 静态文件。A 是第一阶段构建镜像，C/D 是其他 Web 服务器（不是本课方案）。

12-选择-011（★★ 知识点：K12-4 Nginx 反代） 前端 Nginx 反向代理 /api/ 到 http://backend:8080/，proxy_pass 末尾的 / 作用是？

  • A表示路径分隔符，无实际意义
  • B去掉 /api 前缀，把 /api/users 转发为 /users
  • C保留 /api 前缀，把 /api/users 转发为 /api/users
  • D让 Nginx 缓存响应

答案：B 解析：proxy_pass http://backend:8080/; 末尾有 / 表示替换 location 匹配的部分：/api/users → /users（去掉 /api）。末尾无 / 则保留完整路径：/api/users → /api/users。

12-选择-012（★ 知识点：K12-4 SPA fallback） 前端 Nginx 配置中 try_files $uri $uri/ /index.html; 的作用是？

  • A压缩静态文件
  • B实现 SPA 路由 fallback，让 Vue Router 处理前端路由
  • C缓存 index.html
  • D重定向到首页

答案：B 解析：try_files 让所有找不到的文件路径都返回 index.html，由 Vue Router 在前端处理路由（如 /users、/courses/123）。否则刷新 Vue Router 路由会 404。

12-选择-013（★★ 知识点：K12-4 跨域解决） 前端 Nginx 反向代理如何解决跨域问题？

  • A后端配置 CORS
  • B让浏览器只与前端 Nginx 通信，由 Nginx 与后端通信
  • C关闭浏览器同源策略
  • D用 HTTPS 代替 HTTP

答案：B 解析：浏览器访问前端 Nginx（80 端口），调 /api/users 也是 80 端口（同源），由 Nginx 内部转发到 backend:8080。浏览器只与前端通信，避免跨域。A 是另一种方案但复杂，C 不可行，D 与跨域无关。

12-选择-014（★ 知识点：K12-5 depends_on） 关于 docker-compose.yml 中 backend 服务的 depends_on: mysql: condition: service_healthy，下列说法正确的是？

  • A等 mysql 容器启动后立即启动 backend
  • B等 mysql 健康检查通过后才启动 backend
  • C等 backend 健康后才启动 mysql
  • D等 mysql 停止后才启动 backend

答案：B 解析：condition: service_healthy 表示等依赖服务的 healthcheck 通过后才启动。这能避免 backend 启动时 MySQL 还未就绪导致连接失败。A 是默认的 service_started 行为，C/D 逻辑错误。

12-选择-015（★★ 知识点：K12-5 depends_on 局限） depends_on: - mysql（不带 condition）与 depends_on: mysql: condition: service_healthy 的区别是？

  • A没有区别
  • B前者只控制启动顺序，不保证 mysql 就绪；后者等 mysql 健康检查通过
  • C前者等 mysql 健康检查通过；后者只控制启动顺序
  • D前者用于生产，后者用于开发

答案：B 解析：默认 depends_on: - mysql 等价于 service_started，只等容器启动不等服务就绪。service_healthy 会等 healthcheck 通过，确保服务真正可用。生产环境应该用 service_healthy。

12-选择-016（★ 知识点：K12-5 healthcheck） MySQL 容器 healthcheck 的 test 命令应该用什么？

  • Aping localhost
  • Bcurl http://localhost:3306
  • Cmysqladmin ping -h localhost -uroot -p密码
  • Dmysql -e "SELECT 1"

答案：C 解析：MySQL 健康检查推荐用 mysqladmin ping，它能准确反映 MySQL 服务是否就绪。A 检测的是网络，B 不能用 curl 检测 MySQL 端口，D 需要交互式认证不便于 healthcheck。

12-选择-017（★ 知识点：K12-5 一键部署） CTTS 三服务一键构建并启动的命令是？

  • Adocker compose up
  • Bdocker compose up -d --build
  • Cdocker compose start
  • Ddocker run -d ctts

答案：B 解析：docker compose up -d --build 后台启动并强制重新构建镜像。A 是前台启动（会阻塞终端），C 只启动已停止的容器不重建镜像，D 是单容器命令。

12-选择-018（★ 知识点：K12-5 停止与清理） docker compose down 默认会删除哪些资源？

  • A容器 + 网络 + 数据卷
  • B容器 + 网络，保留数据卷
  • C仅容器
  • D容器 + 网络 + 镜像

答案：B 解析：docker compose down 默认删除容器和网络，保留数据卷（保护数据）。要删卷需加 -v：docker compose down -v。要删镜像加 --rmi all。

12-选择-019（★★ 知识点：K12-5 修改文件后生效） 修改了 docker-compose.yml 后，应该用哪个命令让修改生效？

  • Adocker compose restart
  • Bdocker compose start
  • Cdocker compose up -d
  • Ddocker compose down

答案：C 解析：up -d 是声明式对齐，会对比当前状态与 YAML，重建有变化的服务。restart/start 不会重建容器，修改不生效。down 只是停止清理。

12-选择-020（★★ 知识点：K12-5 修改 Dockerfile 后） 修改了 backend/Dockerfile 后，如何让修改生效？

  • Adocker compose up -d
  • Bdocker compose up -d --build
  • Cdocker compose restart backend
  • Ddocker compose start backend

答案：B 解析：修改 Dockerfile 后必须重新构建镜像，--build 强制重建。up -d 不带 --build 会复用旧镜像，restart/start 只重启容器不重建镜像。

12-选择-021（★ 知识点：K12-5 网络） CTTS 三服务能通过服务名互访，是因为它们？

  • A都暴露了端口
  • B都接入同一个自定义 bridge 网络
  • C都用 same host 网络
  • D都在同一个容器内

答案：B 解析：自定义 bridge 网络提供 DNS 解析，同网络内的容器可以用服务名互相访问。A 端口映射是宿主机访问用的，C 本课不用 host 网络，D 三服务是三个独立容器。

12-选择-022（★★ 知识点：K12-6 排障） 后端启动报 Communications link failure，最可能的原因是？

  • A后端代码有 bug
  • BMySQL 还没就绪，后端就启动了
  • C前端 Nginx 配置错误
  • D端口 80 被占用

答案：B 解析：Communications link failure 是 SpringBoot 连不上 MySQL 的典型错误。最常见原因是 depends_on 没用 service_healthy，MySQL 还在初始化时后端就启动了。A/C/D 与此错误无关。

12-选择-023（★★ 知识点：K12-6 排障） 前端访问 /api/users 返回 502 Bad Gateway，最可能的原因是？

  • A前端代码有 bug
  • Bbackend 容器未启动或 nginx.conf 的 proxy_pass 写错
  • CMySQL 数据库连不上
  • D浏览器缓存问题

答案：B 解析：502 Bad Gateway 表示 Nginx 反代时连不上后端。可能是 backend 容器没启动，或 nginx.conf 的 proxy_pass 地址写错（如写成 localhost 而非 backend）。A/C/D 不会导致 502。

12-选择-024（★★ 知识点：K12-6 跨域排障） 浏览器访问前端页面白屏，控制台报 CORS 错误，最可能的原因是？

  • A前端代码直接调 http://localhost:8080/api/users（不同端口）
  • BNginx 配置错误
  • C后端 API 返回 500
  • D网络不通

答案：A 解析：浏览器认为 80（前端）和 8080（后端）是不同源，触发跨域限制。解决方案是前端代码改调相对路径 /api/users，让 Nginx 反代处理。B/C/D 与 CORS 错误无关。

12-选择-025（★★ 知识点：K12-6 init.sql 不生效） 修改了 init.sql 后重新 docker compose up -d，发现数据库没变化，原因是？

  • Ainit.sql 语法错误
  • Binit.sql 只在首次启动执行，数据卷已有数据，跳过执行
  • CMySQL 容器没启动
  • Dinit.sql 挂载路径错误

答案：B 解析：init.sql 仅在 MySQL 首次启动（数据目录为空）时执行。docker compose up -d 默认保留数据卷，卷中已有数据，MySQL 跳过初始化。要让修改生效需 docker compose down -v 删卷后重启。

12-选择-026（★ 知识点：K12-6 排障方法） Docker 部署排障的"三步法"正确顺序是？

  • A进容器 → 看日志 → 看状态
  • B看日志 → 进容器 → 看状态
  • C看状态 → 看日志 → 进容器
  • D看状态 → 进容器 → 看日志

答案：C 解析：排障三步法：①docker compose ps 看哪个服务异常 ②docker compose logs <服务名> 看错误信息 ③docker compose exec <服务名> sh 进容器检查环境。从外到内、从粗到细。

12-选择-027（★★ 知识点：K12-3 JVM 容器支持） 后端 Dockerfile 的 ENTRYPOINT 中 -XX:+UseContainerSupport 的作用是？

  • A让 JVM 支持容器化部署
  • B让 JVM 感知容器内存限制，避免 OOM
  • C加速 JVM 启动
  • D让 JVM 支持 Docker 网络

答案：B 解析：-XX:+UseContainerSupport 让 JVM 感知容器的 cgroup 内存限制，按容器内存（而非宿主机内存）计算堆大小，避免 OOM。JDK 17 默认开启，显式加上更安全。

12-选择-028（★ 知识点：K12-5 重启策略） 生产环境推荐的 Docker 容器重启策略是？

  • Ano
  • Balways
  • Con-failure
  • Dunless-stopped

答案：D 解析：unless-stopped 除非手动 stop，否则总是重启；宿主机重启后也会自启（除非之前手动停过）。always 类似但行为略有差异。生产推荐 unless-stopped。

12-选择-029（★★ 知识点：K12-5 配置注入） 后端 Dockerfile 中不写死数据库配置，而是用 ${MYSQL_HOST:mysql} 形式的好处是？

  • A加快启动速度
  • B同一镜像可连不同环境的数据库，由环境变量注入
  • C减小镜像体积
  • D避免 MySQL 连接

答案：B 解析：用环境变量注入配置，同一个镜像可在开发/测试/生产环境复用，只需改 docker-compose.yml 的 environment。这是 12-Factor App 的"配置分离"原则。

12-选择-030（★★ 知识点：K12-6 Docker 部分总结） Docker 部分学完后，下一步 Kubernetes 要解决的核心问题是？

  • A怎么编写 Dockerfile
  • B怎么在多台机器上调度管理成百上千个容器，支持高可用与弹性
  • C怎么用 Docker Compose 编排多服务
  • D怎么用 Docker 安装 MySQL

答案：B 解析：Docker 解决"单机容器化"，Compose 解决"单机多容器编排"，K8s 解决"集群容器调度与高可用"。A/C 是 Docker 部分已学内容，D 是基础操作。

1.2 多项选择题（10 题）

12-选择-031（★★ 知识点：K12-2 MySQL 容器化） MySQL 容器化需要配置的内容包括？（多选）

  • A环境变量（MYSQL_ROOT_PASSWORD 等）
  • B数据卷持久化 /var/lib/mysql
  • Cinit.sql 挂载到 /docker-entrypoint-initdb.d/
  • Dhealthcheck 健康检查 E. 反向代理配置

答案：A、B、C、D 解析：MySQL 容器化需要：A 配置密码与数据库、B 持久化数据、C 自动建表、D 健康检查供其他服务依赖。E 反向代理是前端 Nginx 的配置，与 MySQL 无关。

12-选择-032（★★ 知识点：K12-3 多阶段构建） 后端 Dockerfile 多阶段构建的好处包括？（多选）

  • A减小最终镜像体积
  • B最终镜像不包含构建工具（Maven/编译器）
  • C加快镜像拉取与推送
  • D减少攻击面，提升安全性 E. 让 Dockerfile 语法更简洁

答案：A、B、C、D 解析：多阶段构建把构建工具与运行时分离，A/B/C/D 都是好处。E 错，多阶段反而让 Dockerfile 更长（多一段 FROM），不是为了简化语法。

12-选择-033（★★ 知识点：K12-4 前端 Nginx） 前端 Nginx 配置的核心功能包括？（多选）

  • A静态资源托管（root 指令）
  • BSPA 路由 fallback（try_files）
  • C反向代理后端 API（location /api/ + proxy_pass）
  • Dgzip 压缩 E. 数据库连接池

答案：A、B、C、D 解析：前端 Nginx 负责：A 托管 dist 静态文件、B 处理 Vue Router 路由、C 反代后端 API、D 压缩响应。E 数据库连接池是后端的事，Nginx 不连数据库。

12-选择-034（★★ 知识点：K12-5 Compose 编排） 完整的 docker-compose.yml 应包含哪些顶层段？（多选）

  • Aservices
  • Bnetworks
  • Cvolumes
  • Dimages E. version（v2 可省）

答案：A、B、C、E 解析：Compose 顶层段：services（必需）、networks（可选）、volumes（可选）、version（v2 可省）。D 错，images 不是顶层段，镜像在 services 下用 image 字段指定。

12-选择-035（★★ 知识点：K12-5 depends_on） 关于 docker-compose.yml 中的 depends_on，下列说法正确的有？（多选）

12-判断-001（★ 知识点：K12-1 架构） CTTS 三服务的依赖顺序是 mysql → backend → frontend。

答案：正确（✓） 解析：mysql 最先启动，backend 依赖 mysql，frontend 依赖 backend。这是 CTTS 的标准部署顺序。

答案：正确（✓） 解析：pom.xml 不变时，依赖下载层命中缓存，只需重新 COPY src/ 并打包。这是 Dockerfile 缓存优化的经典模式。

答案：错误（✗） 解析：应该用 ENTRYPOINT，因为它不会被 docker run <镜像> <参数> 覆盖，适合"容器就是跑这个 jar"的场景。CMD 可以被覆盖，不够固定。

12-判断-009（★ 知识点：K12-4 SPA fallback） 前端 Nginx 配置 try_files $uri $uri/ /index.html; 是为了实现 SPA 路由 fallback。

答案：正确（✓） 解析：让所有找不到的路径都返回 index.html，由 Vue Router 在前端处理路由。否则刷新 Vue Router 路由会 404。

答案：正确（✓） 解析：mysqladmin ping 能准确检测 MySQL 服务是否就绪。需要带用户名和密码，否则会因权限失败。

12-论述-002（★★ 知识点：K12-4 Nginx 反代，8 分） 请说明前端 Nginx 反向代理如何解决跨域问题，并写出完整的 nginx.conf 中关于 /api/ 反代的配置片段，解释 proxy_pass 末尾 / 的作用。

参考答案与评分标准（8 分，按要点给分）：

  1. 跨域问题成因（2 分）：

    • 浏览器访问前端 http://localhost/（80 端口），前端代码直接调 http://localhost:8080/api/users（8080 端口）（1 分）
    • 浏览器认为 80 和 8080 是不同源，触发 CORS 限制，请求被拦截（1 分）

  2. Nginx 反代解决原理（2 分）：

    • 前端代码改调相对路径 /api/users，仍访问 80 端口（同源，无跨域）（1 分）
    • Nginx 把 /api/ 请求内部转发到 backend:8080，浏览器只与前端 Nginx 通信（1 分）

  3. nginx.conf 配置片段（2 分）：

    location /api/ {
    proxy_pass http://backend:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

    （写出 location + proxy_pass 给 1 分，写出 proxy_set_header 给 1 分）

  4. proxy_pass 末尾 / 的作用（2 分）：

    • 末尾有 / 表示替换 location 匹配的部分：/api/users → /users（去掉 /api 前缀）（1 分）
    • 末尾无 / 则保留完整路径：/api/users → /api/users（1 分）
    • 根据后端接口设计选择，本课用末尾 / 让后端接口去掉 /api 前缀

评分要点：每部分独立给分；配置片段不要求字字一致，关键指令正确即可。

12-论述-003（★★ 知识点：K12-5 depends_on 与 healthcheck，10 分） 请说明 depends_on: - mysql 与 depends_on: mysql: condition: service_healthy 的区别，并说明为什么 CTTS 部署中 backend 要用 service_healthy，而 frontend 用默认 service_started 即可。

参考答案与评分标准（10 分，按要点给分）：

  1. 两种 depends_on 的区别（4 分）：

    • depends_on: - mysql（默认）：等价于 service_started，只等 mysql 容器启动，不等服务就绪（2 分）
    • depends_on: mysql: condition: service_healthy：等 mysql 的 healthcheck 通过后才启动，确保服务真正可用（2 分）

  2. 为什么 backend 要用 service_healthy（3 分）：

    • SpringBoot 启动时会建立数据库连接池（HikariCP），如果 MySQL 未就绪会启动失败或反复重试（1 分）
    • MySQL 容器启动 ≠ MySQL 服务能接受连接，初始化需要 10~30 秒（1 分）
    • 等 MySQL 真正就绪后再启动 backend，能避免启动期连接失败（1 分）

  3. 为什么 frontend 用默认 service_started（3 分）：

    • 前端是 Nginx 托管的静态资源，能独立启动，不依赖后端启动（1 分）
    • 前端调后端是运行时行为（用户点按钮时才发请求），不是启动时依赖（1 分）
    • 即使后端没启动，前端页面也能打开（只是请求会失败），所以用默认 service_started 即可（1 分）

评分要点：每部分独立给分；要点完整给满分；意思对即可，不要求字字一致。

12-编程-002（★★★ 知识点：K12-5 完整 docker-compose.yml，20 分） 完整 docker-compose.yml 编写：请为 CTTS 项目编写完整的 docker-compose.yml，要求：

  4. frontend 配置：端口 80、depends_on backend（2 分）

  6. 具名卷 mysql-data 声明（2 分）

services:
  mysql:
    image: mysql:8.0
    container_name: ctts-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: "123456"
      MYSQL_DATABASE: ctts
      MYSQL_USER: ctts
      MYSQL_PASSWORD: "ctts123"
      TZ: Asia/Shanghai
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql
      - ./init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    networks:
      - ctts-net
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-p123456"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s

  backend:
    build: ./backend
    image: ctts-backend:v1
    container_name: ctts-backend
    restart: unless-stopped
    environment:
      MYSQL_HOST: mysql
      MYSQL_PORT: "3306"
      MYSQL_USER: ctts
      MYSQL_PASSWORD: "ctts123"
      MYSQL_DATABASE: ctts
    ports:
      - "8080:8080"
    networks:
      - ctts-net
    depends_on:
      mysql:
        condition: service_healthy

  frontend:
    build: ./frontend
    image: ctts-frontend:v1
    container_name: ctts-frontend
    restart: unless-stopped
    ports:
      - "80:80"
    networks:
      - ctts-net
    depends_on:
      - backend

networks:
  ctts-net:
    driver: bridge

volumes:
  mysql-data:
    driver: local
