1.1 单项选择题（30 题）

08-选择-001（★ 知识点：K8-1 后端 Dockerfile） CTTS 后端采用多阶段构建，第一阶段用 Maven 镜像的主要目的是？

  • A运行 jar 包
  • B编译打包源码产出 jar
  • C提供生产运行环境
  • D托管静态文件

答案：B 解析：多阶段构建第一阶段（builder）用 Maven 镜像执行 mvn package 编译打包源码产出 jar。运行 jar 是第二阶段（JRE 镜像）的职责；提供生产运行环境是第二阶段；托管静态文件是前端 Nginx 的职责。

08-选择-002（★ 知识点：K8-2 前端 Dockerfile） CTTS 前端多阶段构建中，第二阶段运行镜像选择的是？

  • Anode:alpine
  • Bnginx:alpine
  • Copenjdk:17
  • Dhttpd:alpine

答案：B 解析：前端构建产物 dist 是静态文件，用 Nginx 托管。nginx:alpine 体积小（~40MB）且是高性能静态服务器。node 用于构建阶段；openjdk 用于后端；httpd 是 Apache，不如 Nginx 常用。

08-选择-003（★ 知识点：K8-3 构建命令） docker build -t ctts-backend:v1 . 命令中，末尾的 . 表示？

  • ADockerfile 的文件名
  • B当前用户主目录
  • C构建上下文（build context）为当前目录
  • D镜像标签的分隔符

答案：C 解析：. 表示构建上下文为当前目录，Docker 会把该目录下所有文件发送给守护进程，Dockerfile 中的 COPY/ADD 从该上下文复制文件。Dockerfile 默认从上下文根目录查找。

08-选择-004（★ 知识点：K8-3 构建日志） 构建日志中出现 CACHED 字样表示？

  • A构建失败，需要清除缓存
  • B该层命中缓存，复用旧层未重新执行
  • C该层被跳过不执行
  • D镜像已推送到缓存服务器

答案：B 解析：CACHED 表示该层命中缓存（指令相同 + 上传文件未变），Docker 直接复用上次构建的层，加速构建。这是构建缓存机制的核心体现。

08-选择-005（★ 知识点：K8-4 容器运行） 要让前端容器和后端容器通过容器名互相通信，正确做法是？

  • A都用默认 bridge 网络
  • B创建自定义网络，把两个容器都加入该网络
  • C用 host 网络模式
  • D端口映射即可，无需关心网络

答案：B 解析：默认 bridge 网络不支持容器名 DNS 解析；自定义网络支持容器名解析，前端容器可通过 http://ctts-api:8080 访问后端容器。host 模式不隔离端口不推荐；端口映射只解决宿主机访问容器，不解决容器间通信。

08-选择-006（★ 知识点：K8-1 多阶段构建） 后端 Dockerfile 中 COPY --from=builder /build/target/ctts-backend-1.0.0.jar app.jar 的作用是？

  • A从本地文件系统复制 jar
  • B从名为 builder 的构建阶段复制 jar 到当前阶段
  • C从镜像仓库拉取 jar
  • D从宿主机复制 jar

答案：B 解析：COPY --from=<阶段名> 是多阶段构建的关键指令，从前一个构建阶段复制产物到当前阶段。builder 是阶段1 的命名（FROM maven AS builder）。

08-选择-007（★ 知识点：K8-2 前端构建） 前端 Dockerfile 中 npm run build 产出的静态文件目录是？

  • Apublic
  • Bstatic
  • Cdist
  • Dbuild

答案：C 解析：Vite/Vue CLI 默认构建输出目录是 dist。public 是源码中的静态资源目录；static 不是 Vite 默认目录；build 是部分框架（如 Next.js）的输出目录。

08-选择-008（★ 知识点：K8-2 Nginx 部署） 前端 Dockerfile 中，应把 dist 内容 COPY 到 Nginx 镜像的哪个路径？

  • A/var/www/html
  • B/usr/share/nginx/html
  • C/etc/nginx/html
  • D/home/nginx/html

答案：B 解析：Nginx 官方镜像默认静态文件目录是 /usr/share/nginx/html。/var/www/html 是 Apache 的默认目录；其他选项都不是 Nginx 默认目录。

08-选择-009（★ 知识点：K8-4 端口映射） 运行后端容器 docker run -d -p 8080:8080 ctts-backend:v1 中，两个 8080 分别是？

  • A容器端口、宿主机端口
  • B宿主机端口、容器端口
  • C内部端口、外部端口
  • D都是容器端口

答案：B 解析：-p 参数格式是 宿主机端口:容器端口，即 -p 8080:8080 表示宿主机 8080 映射到容器 8080。访问宿主机 8080 端口会被转发到容器的 8080。

08-选择-010（★ 知识点：K8-3 标签管理） 给已有镜像 ctts-backend:v1 再打一个 latest 标签，正确的命令是？

  • Adocker rename ctts-backend:v1 ctts-backend:latest
  • Bdocker tag ctts-backend:v1 ctts-backend:latest
  • Cdocker label ctts-backend:v1 ctts-backend:latest
  • Ddocker build -t ctts-backend:latest ctts-backend:v1

答案：B 解析：docker tag <源镜像> <新标签> 给已有镜像打新标签，两个标签指向同一个 IMAGE ID。docker rename 是重命名容器；docker label 不存在；docker build 是构建不是打标签。

08-选择-011（★★ 知识点：K8-5 层缓存） 后端 Dockerfile 中"先 COPY pom.xml 再 COPY src"的主要目的是？

  • A减小镜像体积
  • B利用层缓存，源码变动时不重新下载依赖
  • C避免编译错误
  • D让 Dockerfile 更易读

答案：B 解析：先 COPY pom.xml 并下载依赖（耗时最久），这层只依赖 pom.xml。修改源码时 pom.xml 没变，依赖层命中缓存跳过，只重新执行 COPY src + mvn package。这是利用层缓存加速构建的经典技巧。

08-选择-012（★ 知识点：K8-5 .dockerignore） .dockerignore 文件的作用是？

  • A让 Dockerfile 忽略某些指令
  • B排除构建上下文中的特定文件，不发送给守护进程
  • C让容器运行时忽略某些环境变量
  • D让 docker 命令忽略某些错误

答案：B 解析：.dockerignore 类似 .gitignore，列出要排除的文件，让构建上下文更小、构建更快、避免敏感信息被打包进镜像。它影响的是构建上下文，不影响 Dockerfile 指令或容器运行。

08-选择-013（★ 知识点：K8-1 基础镜像选型） 后端运行阶段应选择哪个基础镜像最合适（兼顾体积与功能）？

  • Amaven:3.9-eclipse-temurin-17
  • Beclipse-temurin:17
  • Ceclipse-temurin:17-jre-alpine
  • Dubuntu:22.04

答案：C 解析：运行阶段只需 JRE 运行 jar，不需要 JDK 和 Maven。eclipse-temurin:17-jre-alpine 含 JRE 且基于 alpine（体积最小，~170MB）。A 含 Maven+JDK 太大；B 含完整 JDK 体积大；D 需要自己装 Java 太麻烦。

08-选择-014（★ 知识点：K8-4 容器验证） 运行后端容器后，最快的健康验证方式是？

  • Adocker exec 进入容器查看进程
  • Bcurl http://localhost:8080/actuator/health
  • Cdocker inspect 查看容器详情
  • Ddocker top 查看容器进程

答案：B 解析：SpringBoot Actuator 提供 /actuator/health 健康检查接口，curl 访问返回 {"status":"UP"} 即健康。这是最直接的应用层验证。其他方法只能看容器/进程在跑，不能确认应用就绪。

08-选择-015（★ 知识点：K8-6 问题排查） 构建日志出现 COPY failed: no such file or directory，最可能的原因是？

  • A网络不通
  • BCOPY 源路径在构建上下文中不存在
  • CDocker daemon 未启动
  • D镜像仓库不可达

答案：B 解析：COPY failed: no such file or directory 表示 COPY 指令的源文件/目录在构建上下文中不存在，通常是路径写错（如 COPY srcc ./src 多打了一个 c）。需核对路径。

08-选择-016（★★ 知识点：K8-6 跨域问题） 前端容器（端口 80）调用后端容器（端口 8080）报 CORS 错误，最干净的解决方案是？

  • A后端加 @CrossOrigin 注解
  • B把前端和后端合并到一个容器
  • CNginx 配置 /api/ 反向代理到后端，前端用相对路径调用
  • D关闭浏览器 CORS 检查

答案：C 解析：用 Nginx 反向代理 /api/ 到后端，前端用相对路径 /api/hello 调用，浏览器视为同源，无跨域问题。这是最干净的方案。A 也能解决但侵入后端代码；B 违反单容器单进程原则；D 是 hack 不可行。

08-选择-017（★ 知识点：K8-3 构建上下文） 构建上下文过大会导致？

  • A镜像体积变大
  • B构建变慢，因为上下文要传给守护进程
  • CDockerfile 语法错误
  • D容器无法运行

答案：B 解析：构建时整个上下文目录会打包发给 dockerd，上下文越大传输越慢。需用 .dockerignore 排除 node_modules、target、.git 等。上下文不影响最终镜像体积（COPY 哪些由 Dockerfile 决定）。

08-选择-018（★ 知识点：K8-2 npm ci） 前端 Dockerfile 中推荐用 npm ci 而不是 npm install 的原因是？

  • Anpm ci 速度更快、严格按 lock 文件安装、可复现性强
  • Bnpm ci 不需要 package.json
  • Cnpm ci 能装更多包
  • Dnpm install 已被废弃

答案：A 解析：npm ci 严格按 package-lock.json 安装，速度更快、可复现性更强，适合 CI/CD 和 Docker 构建。它要求有 lock 文件，先删除 node_modules 再安装。npm install 仍可用，但不如 ci 严格。

08-选择-019（★★ 知识点：K8-5 镜像大小对比） 对比单阶段构建（FROM maven）与多阶段构建（FROM maven + FROM jre-alpine），多阶段镜像体积大约能减少？

  • A10%
  • B30%
  • C76%（如 820MB → 198MB）
  • D100%

答案：C 解析：单阶段含 Maven+JDK+源码+jar（~820MB），多阶段只含 JRE+jar（~198MB），减少约 76%。多阶段把构建工具链（Maven、JDK）剔除出最终镜像，是减小体积的关键手段。

08-选择-020（★ 知识点：K8-4 容器退出） docker run -d 后 docker ps 看不到容器，应如何排查？

  • A重新运行 docker run
  • Bdocker ps -a 查看已停止容器，docker logs 看错误
  • C重启 Docker 服务
  • D重装 Docker

答案：B 解析：容器可能启动失败立即退出。docker ps 只显示运行中的，docker ps -a 显示所有（含已停止）。看到 Exited 状态后用 docker logs <容器名> 看错误日志定位原因。

08-选择-021（★ 知识点：K8-6 端口占用） docker run -p 80:80 报错 bind: address already in use，原因是？

  • A镜像不存在
  • B宿主机 80 端口被其他进程占用
  • C容器内 80 端口被占用
  • DDocker 网络配置错误

答案：B 解析：端口映射时如果宿主机端口已被占用（如本机装了 Nginx/Apache），会报此错误。解决：换端口（如 -p 8081:80）或停掉占用进程。

08-选择-022（★★ 知识点：K8-1 多阶段命名） 后端 Dockerfile 中 FROM maven:3.9-eclipse-temurin-17 AS builder 的 AS builder 作用是？

  • A指定镜像别名
  • B给构建阶段命名，后续可用 COPY --from=builder 引用
  • C指定构建者
  • D设置镜像标签

答案：B 解析：AS <名字> 给构建阶段命名，后续阶段可用 COPY --from=<名字> 引用该阶段的产物。比用数字序号（COPY --from=0）更清晰、更易维护。

08-选择-023（★ 知识点：K8-3 构建日志） 构建日志中 => [builder 4/5] RUN mvn dependency:go-offline -B 的 4/5 表示？

  • A构建阶段 4，共 5 个阶段
  • Bbuilder 阶段第 4 步，该阶段共 5 步
  • C第 4 次构建，共构建 5 次
  • D镜像第 4 层，共 5 层

答案：B 解析：[builder 4/5] 表示在 builder 阶段的第 4 步指令，该阶段共 5 步。这是 BuildKit 日志的格式，便于定位构建进度和失败位置。

08-选择-024（★ 知识点：K8-5 强制无缓存） 要强制 Docker 构建时不使用缓存，应加哪个参数？

  • A--no-cache
  • B--force
  • C--fresh
  • D--rebuild

答案：A 解析：docker build --no-cache -t <镜像> . 强制不使用缓存，每层都重新执行。用于排查缓存导致的问题或确保完全重新构建。

08-选择-025（★★ 知识点：K8-2 Nginx 配置） Vue Router 用 history 模式时，刷新 /about 页面 404，正确的 Nginx 配置是？

  • Alocation / { return 200; }
  • Blocation / { try_files $uri $uri/ /index.html; }
  • Clocation / { proxy_pass http://backend; }
  • Dlocation / { deny all; }

答案：B 解析：history 模式刷新时浏览器请求真实路径（如 /about），Nginx 找不到对应文件返回 404。try_files $uri $uri/ /index.html 先找文件，找不到就返回 index.html，让 Vue Router 在前端处理路由。

08-选择-026（★ 知识点：K8-1 EXPOSE） Dockerfile 中 EXPOSE 8080 的作用是？

  • A自动映射宿主机端口
  • B声明容器监听端口（仅文档作用，运行时仍需 -p 映射）
  • C开放防火墙端口
  • D让容器必须用 8080 端口

答案：B 解析：EXPOSE 是声明性指令，仅说明容器打算监听该端口，不会自动映射。运行时仍需 docker run -p 8080:8080 才能从宿主机访问。它的作用类似注释，便于使用者了解端口需求。

08-选择-027（★ 知识点：K8-4 容器日志） 实时跟踪容器日志的命令是？

  • Adocker logs --tail ctts-api
  • Bdocker logs -f ctts-api
  • Cdocker logs --follow ctts-api
  • Ddocker logs --realtime ctts-api

答案：B 解析：docker logs -f <容器名> 实时跟踪日志输出（类似 tail -f）。--tail 只显示最后几行不跟踪；--follow 不是有效参数；--realtime 不存在。

08-选择-028（★★ 知识点：K8-5 镜像分析） 查看镜像每层大小的命令是？

  • Adocker image ls
  • Bdocker image history <镜像名>
  • Cdocker image inspect <镜像名>
  • Ddocker image size <镜像名>

答案：B 解析：docker image history <镜像名> 显示镜像每一层的创建命令和大小，便于定位哪层最大、优化哪层。docker image ls 只看总大小；inspect 看元数据；size 不存在。

08-选择-029（★ 知识点：K8-6 DNS 失败） 前端容器日志报 ctts-api could not be resolved，原因是？

  • A后端容器没启动
  • B前后端容器不在同一网络，无法 DNS 解析容器名
  • CNginx 配置错误
  • D后端端口不对

答案：B 解析：容器间通过容器名通信要求在同一个自定义网络中。默认 bridge 网络不支持容器名解析。把两个容器都加入同一自定义网络（--network ctts-net）即可解析。

08-选择-030（★★ 知识点：K8-3 标签规范） 关于生产环境镜像标签，下列做法最规范的是？

  • A用 :latest 标签
  • B不指定标签
  • C用明确版本号如 :v1.0.0 或 :1.0.0-20260722
  • D用 :dev 标签

答案：C 解析：生产环境应指定明确版本号，便于版本追踪、回滚和复现。:latest 不可控（不知具体版本）；不指定标签默认 latest 同样不可控；:dev 是开发环境标签。

1.2 多项选择题（10 题）

08-选择-031（★★ 知识点：K8-5 .dockerignore） .dockerignore 应排除的文件包括？（多选）

  • Anode_modules
  • Btarget
  • C.git
  • Dpackage.json E. .env

答案：A、B、C、E 解析：node_modules（容器内重装）、target（容器内重构建）、.git（版本元数据不需要进镜像）、.env（可能含密码）都应排除。package.json 是构建必需文件，不能排除。

08-选择-032（★★ 知识点：K8-1 多阶段构建） 多阶段构建的好处包括？（多选）

  • A减小最终镜像体积
  • B把构建工具链剔除出运行镜像
  • C提高镜像安全性（攻击面小）
  • D让构建过程不可复现 E. 让 Dockerfile 完整描述构建流程

答案：A、B、C、E 解析：多阶段构建减小体积（A）、剔除构建工具链（B）、提高安全性（C）、完整描述构建流程保证可复现（E）。D 错，多阶段反而让构建更可复现。

08-选择-033（★★ 知识点：K8-6 构建失败原因） 构建镜像失败的可能原因有？（多选）

  • ACOPY 源路径不存在
  • B网络问题导致依赖下载失败
  • C基础镜像名拼错
  • D.dockerignore 排除了必要文件 E. Dockerfile 语法错误

答案：A、B、C、D、E 解析：五个都是常见构建失败原因。COPY 路径错（A）、网络问题（B）、镜像名错（C）、.dockerignore 误排（D）、Dockerfile 语法错（E）都会导致构建失败。

参考答案与评分标准（10 分，按要点给分）：

  1. 多阶段构建定义（2 分）：在一个 Dockerfile 中使用多个 FROM 指令，每个 FROM 开始一个新阶段，前一阶段的产物可以通过 COPY --from=<阶段名> 复制到后一阶段，最终镜像只包含最后一个阶段的内容。

  2. 为什么要用多阶段构建（3 分）：

    • 减小最终镜像体积：构建工具链（Maven、Node、JDK）不进入最终镜像（1 分）
    • 提高安全性：镜像越小攻击面越小，且不含构建工具减少潜在风险（1 分）
    • 让构建过程可复现：Dockerfile 完整描述构建流程，任何机器构建结果一致（1 分）

  3. CTTS 后端两个阶段（3 分）：

    • 阶段1（builder）：FROM maven:3.9-eclipse-temurin-17 AS builder，COPY pom.xml + 源码，执行 mvn package 产出 jar（1.5 分）
    • 阶段2（runtime）：FROM eclipse-temurin:17-jre-alpine，用 COPY --from=builder 复制 jar，CMD 启动 java -jar（1.5 分）

  4. 优势对比（2 分）：

    • 单阶段构建（FROM maven）：最终镜像约 820MB，含 Maven+JDK+源码+jar
    • 多阶段构建：最终镜像约 198MB，仅含 JRE+jar，体积减少约 76%
    • 体积小意味着拉取快、启动快、攻击面小
