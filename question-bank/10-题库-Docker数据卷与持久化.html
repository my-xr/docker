一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

10-选择-001（★ 知识点：K10-1 持久化需求） 容器删除后，容器可写层中的数据会怎样？

  • A自动迁移到宿主机
  • B自动保存为新镜像
  • C随容器删除而消失
  • D自动转存到新容器

答案：C 解析：容器的可写层是临时的，docker rm 删除容器时可写层随之删除，所有写入的数据全部消失。这正是需要持久化的原因。A、B、D 都不会自动发生。

10-选择-002（★ 知识点：K10-1 持久化需求） 关于"为什么不能把数据存在容器里"，下列说法不正确的是？

  • A容器是临时的，随时可能被删除重建
  • B可写层性能差，不如直接写宿主磁盘
  • Cdocker commit 是持久化数据的推荐方式
  • D数据与计算分离是云原生架构的基本原则

答案：C 解析：docker commit 把可写层固化成镜像层，会把数据混进镜像，不便于独立管理、备份、迁移，是反模式，不推荐。A、B、D 都是"不能把数据存容器里"的合理理由。

10-选择-003（★ 知识点：K10-1 持久化需求） 容器停止（docker stop）后，容器可写层中的数据会怎样？

  • A立即丢失
  • B保留，docker start 后可恢复
  • C自动转存到数据卷
  • D自动提交为新镜像

答案：B 解析：docker stop 只是暂停容器进程，可写层仍然保留。docker start 可以恢复运行，数据还在。只有 docker rm 删除容器，可写层才会消失。

10-选择-004（★ 知识点：K10-2 数据卷） Docker 数据卷（Volume）默认存储在宿主机的哪个目录？

  • A/var/lib/docker/containers/
  • B/var/lib/docker/volumes/
  • C/var/lib/docker/images/
  • D/home/docker/volumes/

答案：B 解析：Linux 下 Docker 数据卷默认存储在 /var/lib/docker/volumes/<卷名>/_data/ 目录下，由 Docker 引擎管理。可以通过 docker volume inspect 查看 Mountpoint 字段确认。

10-选择-005（★ 知识点：K10-2 数据卷） 下列哪条命令是用数据卷挂载 MySQL 数据目录的正确写法？

  • Adocker run -v /var/lib/mysql mysql:8.0
  • Bdocker run -v mysql_data:/var/lib/mysql mysql:8.0
  • Cdocker run -v mysql_data mysql:8.0
  • Ddocker run -v /var/lib/mysql:mysql_data mysql:8.0

答案：B 解析：-v 卷名:容器路径 是正确的卷挂载语法，卷名在前，容器路径在后。A 只写容器路径会创建匿名卷；C 缺少容器路径；D 路径顺序写反了（前面的 mysql_data 是卷名不是路径）。

10-选择-006（★ 知识点：K10-2 数据卷） 关于数据卷（Volume），下列说法正确的是？

  • A数据卷的生命周期与容器相同
  • B删除容器时数据卷会被自动删除
  • C数据卷由 Docker 引擎管理，独立于容器生命周期
  • D数据卷只能在创建容器时挂载，不能后续添加

答案：C 解析：数据卷由 Docker 引擎管理，独立于容器生命周期，容器删除卷仍保留。A、B 错，卷的生命周期独立于容器；D 错，可以用 docker run 时挂载，也可以用 --volumes-from 继承。

10-选择-007（★ 知识点：K10-3 绑定挂载） 绑定挂载（Bind Mount）的宿主机路径要求是？

  • A相对路径
  • B绝对路径
  • C可以是任意路径
  • D必须在 /home 下

答案：B 解析：Bind Mount 的宿主机路径必须是绝对路径（如 /home/user/config）。如果写相对路径（如 ./config），Docker 会把它当作卷名处理，而不是绑定挂载。

10-选择-008（★ 知识点：K10-3 绑定挂载） 下列哪条命令是绑定挂载宿主机 /home/user/config 到容器 /etc/app/config 的正确写法？

  • Adocker run -v config:/etc/app/config myapp
  • Bdocker run -v /etc/app/config:/home/user/config myapp
  • Cdocker run -v /home/user/config:/etc/app/config myapp
  • Ddocker run -v /home/user/config myapp

答案：C 解析：-v 宿主路径:容器路径，宿主路径在前，容器路径在后。C 正确。A 是卷挂载（config 是卷名）；B 路径顺序写反了；D 缺少容器路径。

10-选择-009（★★ 知识点：K10-3 对比） 下列场景中，最适合使用 Bind Mount 而非 Volume 的是？

  • A生产环境 MySQL 数据持久化
  • B生产环境 Redis 数据持久化
  • C开发环境 Vue3 代码热加载
  • D生产环境应用日志持久化

答案：C 解析：开发环境代码热加载需要宿主机改代码容器立即生效，Bind Mount 的双向同步特性适合此场景。A、B、D 都是生产环境数据，应该用 Volume（可移植、可备份、Docker 管理）。

10-选择-010（★★ 知识点：K10-3 对比） 关于 Volume 和 Bind Mount 的对比，下列说法正确的是？

  • AVolume 依赖宿主机路径，Bind Mount 由 Docker 管理
  • BBind Mount 可移植性高于 Volume
  • CVolume 由 Docker 管理，可移植性高；Bind Mount 依赖宿主路径，可移植性差
  • D两者在可移植性上没有区别

答案：C 解析：Volume 由 Docker 管理，不依赖宿主路径，可移植性高；Bind Mount 强依赖宿主机绝对路径，换机器路径可能不存在，可移植性差。A、B 说反了；D 错，可移植性有明显区别。

10-选择-011（★ 知识点：K10-4 管理命令） 创建一个名为 mysql_data 的数据卷的命令是？

  • Adocker volume new mysql_data
  • Bdocker volume create mysql_data
  • Cdocker volume make mysql_data
  • Ddocker volume add mysql_data

答案：B 解析：创建数据卷用 docker volume create <卷名>。A、C、D 都不是有效的 docker volume 子命令。

10-选择-012（★ 知识点：K10-4 管理命令） 列出所有数据卷的命令是？

  • Adocker volume list
  • Bdocker volume ls
  • Cdocker volume show
  • Ddocker volume all

答案：B 解析：列出数据卷用 docker volume ls。ls 是 list 的缩写，Docker 命令体系沿用 Unix 风格。A、C、D 都不是有效子命令。

10-选择-013（★ 知识点：K10-4 管理命令） 查看数据卷 mysql_data 详细信息（如 Mountpoint）的命令是？

  • Adocker volume info mysql_data
  • Bdocker volume show mysql_data
  • Cdocker volume inspect mysql_data
  • Ddocker volume describe mysql_data

答案：C 解析：查看数据卷详细信息用 docker volume inspect <卷名>，会显示 Name、Mountpoint、CreatedAt、Driver 等字段。A、B、D 都不是有效子命令。

10-选择-014（★ 知识点：K10-4 管理命令） 删除数据卷 mysql_data 的命令是？

  • Adocker volume delete mysql_data
  • Bdocker volume rm mysql_data
  • Cdocker volume remove mysql_data
  • Ddocker volume drop mysql_data

答案：B 解析：删除数据卷用 docker volume rm <卷名>。rm 是 remove 的缩写。A、C、D 都不是有效子命令。

10-选择-015（★★ 知识点：K10-4 管理命令） docker volume prune 命令的作用是？

  • A删除所有数据卷
  • B删除所有未被容器使用的卷
  • C删除所有命名卷
  • D删除所有匿名卷

答案：B 解析：docker volume prune 删除所有未被任何容器引用的卷，正在被使用的卷会被跳过，安全。A 错，不会删除正在使用的卷；C、D 错，prune 不区分命名卷和匿名卷，只看是否被使用。

10-选择-016（★★ 知识点：K10-4 管理命令） 关于命名卷和匿名卷，下列说法正确的是？

  • A命名卷由 Docker 自动生成随机名字
  • B匿名卷有可读的名字，便于管理
  • C命名卷有可读名字（如 mysql_data），匿名卷是随机哈希名
  • D命名卷和匿名卷在功能上有本质区别

答案：C 解析：命名卷有可读的名字（如 mysql_data），便于识别和管理；匿名卷是随机哈希名（如 a1b2c3d4...），难以识别，容易遗留。两者功能上没有本质区别，只是命名方式不同，但生产环境推荐命名卷。

10-选择-017（★ 知识点：K10-5 卷共享） --volumes-from 参数的作用是？

  • A从镜像中继承卷配置
  • B从另一个容器继承卷挂载配置
  • C从宿主机继承目录
  • D从仓库拉取卷

答案：B 解析：--volumes-from <容器名> 让一个容器继承另一个容器的所有卷挂载配置，实现卷共享。不是从镜像、宿主机或仓库继承。

10-选择-018（★★ 知识点：K10-5 卷共享） 使用 --volumes-from provider 启动的容器，与 provider 容器之间的关系是？

  • A两个容器各自有独立的数据副本
  • B两个容器共享同一个卷，数据互通
  • Cprovider 容器的数据会复制到新容器
  • D新容器只能读不能写

答案：B 解析：--volumes-from 是共享挂载配置，两个容器挂载同一个卷，数据互通，双向可见。不是复制数据，也不是只读（除非显式指定 :ro）。

10-选择-019（★★ 知识点：K10-5 备份） 数据卷备份的经典模式是？

  • A直接拷贝 /var/lib/docker/volumes/ 目录
  • B用 docker commit 提交容器为镜像
  • C用临时容器挂载卷和宿主目录，执行 tar 打包
  • D用 docker export 导出容器

答案：C 解析：数据卷备份的经典模式是"临时容器 + 卷挂载 + 宿主目录绑定 + tar 打包"，即 docker run --rm -v 卷名:/data -v 宿主备份目录:/backup alpine tar cvf /backup/bak.tar /data。A 直接拷贝 Docker 内部目录可能权限不足且不安全；B、D 是针对容器不是卷。

10-选择-020（★★ 知识点：K10-5 备份） 下列哪条命令能正确备份 mysql_data 卷到宿主机 /home/user/backup/ 目录？

  • Adocker run --rm -v mysql_data:/data -v /home/user/backup:/backup alpine tar cvf /backup/bak.tar /data
  • Bdocker run --rm -v mysql_data:/backup alpine tar cvf /backup/bak.tar /data
  • Cdocker run --rm -v /home/user/backup:/data alpine tar cvf /backup/bak.tar /data
  • Ddocker run --rm mysql_data alpine tar cvf bak.tar /data

答案：A 解析：备份需要同时挂载卷（mysql_data:/data）和宿主备份目录（/home/user/backup:/backup），然后 tar cvf /backup/bak.tar /data 把卷数据打包到宿主目录。B 缺少宿主目录挂载；C 缺少卷挂载；D 卷名不能这样用。

10-选择-021（★★ 知识点：K10-5 恢复） 数据卷恢复时，tar xvf /backup/bak.tar -C / 中的 -C / 作用是？

  • A解压到 /backup 目录
  • B解压到根目录，还原打包时的路径结构
  • C创建一个新目录
  • D压缩到根目录

答案：B 解析：-C / 表示切换到根目录再解压，因为打包时用的是 /data（绝对路径），解压时要从根开始还原路径结构，这样数据会正确解到 /data（即卷挂载路径）。不加 -C / 会解压到当前目录，路径错乱。

10-选择-022（★ 知识点：K10-6 MySQL 持久化） MySQL 容器中需要持久化的核心数据目录是？

  • A/etc/mysql
  • B/var/lib/mysql
  • C/var/log/mysql
  • D/usr/share/mysql

答案：B 解析：/var/lib/mysql 是 MySQL 的数据目录，存放数据库表、索引等核心数据，必须持久化。/etc/mysql 是配置目录（可选持久化）；/var/log/mysql 是日志目录（可选）；/usr/share/mysql 是程序文件（在镜像里）。

10-选择-023（★★ 知识点：K10-6 MySQL 持久化） 启动 MySQL 容器并持久化数据的正确命令是？

  • Adocker run -d -v /var/lib/mysql mysql:8.0
  • Bdocker run -d -v mysql_data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0
  • Cdocker run -d -v mysql_data mysql:8.0
  • Ddocker run -d --volume mysql_data mysql:8.0

答案：B 解析：B 正确，-v mysql_data:/var/lib/mysql 把数据卷挂载到 MySQL 数据目录，同时设置 root 密码（必需）。A 只写容器路径会创建匿名卷且没设密码；C 缺少容器路径；D --volume 不是有效参数（应为 -v 或 --mount）。

10-选择-024（★★ 知识点：K10-6 MySQL 持久化） MySQL 容器挂载已有数据的卷重新启动时，MYSQL_DATABASE 环境变量指定的数据库会被重新创建吗？

  • A会，每次启动都会重新创建
  • B不会，数据目录非空时初始化脚本跳过
  • C会，但只创建不存在的数据库
  • D会，且会覆盖已有数据

答案：B 解析：MySQL 官方镜像的初始化脚本（创建 MYSQL_DATABASE、MYSQL_USER 等）只在数据目录为空时执行。挂载已有数据的卷后，数据目录非空，初始化脚本跳过，直接加载已有数据。这正是持久化的体现。

10-选择-025（★★ 知识点：K10-6 MySQL 持久化） 验证 MySQL 数据持久化是否生效的标准流程是？

  • A启动容器→写入数据→重启容器→查看数据
  • B启动容器→写入数据→停止删除容器→重建容器挂载同一卷→查看数据
  • C启动容器→写入数据→docker commit→查看数据
  • D启动容器→写入数据→导出镜像→查看数据

答案：B 解析：验证持久化的标准流程是"写入数据→删除容器→重建容器挂载同一卷→验证数据还在"。A 只重启容器没删容器，不能证明持久化；C、D 是针对镜像不是卷。只有删除容器重建后数据还在，才能证明持久化生效。

10-选择-026（★★ 知识点：K10-2 挂载语法） 关于 -v 和 --mount 两种挂载语法，下列说法正确的是？

  • A-v 是官方推荐语法，--mount 已废弃
  • B--mount 是官方推荐语法，更清晰，字段写错会报错
  • C两者功能完全不同，不能互换
  • D--mount 只能用于 Volume，不能用于 Bind Mount

答案：B 解析：--mount 是 Docker 17.06+ 推荐的语法，参数明确（type/source/target），字段写错会报错，更安全。-v 是简短语法，老版本沿用，简单场景可用。两者功能等价，都能用于 Volume 和 Bind Mount。

10-选择-027（★★ 知识点：K10-2 只读挂载） 将数据卷 config_data 以只读方式挂载到容器 /etc/app/config 的命令是？

  • Adocker run -v config_data:/etc/app/config:ro myapp
  • Bdocker run -v config_data:/etc/app/config:rw myapp
  • Cdocker run -v config_data:/etc/app/config myapp
  • Ddocker run -v config_data:/etc/app/config:readonly myapp

答案：A 解析：:ro（read-only）表示只读挂载，容器内不能修改该路径。:rw 是读写（默认）；不写默认是读写；readonly 不是有效选项（应为 ro）。

10-选择-028（★★ 知识点：K10-4 管理命令） 删除一个正在被容器使用的卷会发生什么？

  • A卷被删除，容器数据丢失
  • B卷被删除，但容器数据保留
  • C报错，提示卷正在使用，无法删除
  • D卷被标记为待删除，容器停止后自动删除

答案：C 解析：正在被容器使用的卷无法删除，Docker 会报错"volume is in use and cannot be removed"。需要先 docker stop 并 docker rm 使用该卷的容器，才能删除卷。这是 Docker 的保护机制。

10-选择-029（★★ 知识点：K10-3 双向同步） 关于 Bind Mount 的双向同步特性，下列说法正确的是？

  • A宿主机修改文件，容器内立即生效；容器内修改，宿主机也能看到
  • B宿主机修改文件，容器内不生效
  • C容器内修改文件，宿主机看不到
  • D只能宿主机向容器同步，不能反向

答案：A 解析：Bind Mount 是双向同步的，宿主机和容器挂载的是同一个目录，任意一方修改，另一方立即可见。这正是开发环境热加载的基础。B、C、D 都错。

10-选择-030（★★ 知识点：K10-6 升级场景） 升级 MySQL 镜像版本（如 8.0 升 8.1）时，如何保证数据不丢？

  • A先 docker commit 旧容器，再用新镜像启动
  • B删除旧容器，用新镜像启动新容器，挂载同一卷
  • C先导出容器为 tar 包，再导入
  • D无法保证，必须重新录入数据

答案：B 解析：升级镜像时，删除旧容器（卷保留），用新镜像启动新容器并挂载同一卷，数据自动加载。A、C 是针对容器/镜像不是数据；D 错，持久化卷就是为了这种场景。注意跨大版本升级需先备份。

1.2 多项选择题（10 题）

10-选择-031（★★ 知识点：K10-1 持久化需求） 容器可写层存在的问题包括？（多选）

  • A容器删除数据丢失
  • B可写层性能差于直接写宿主磁盘
  • C不便于数据共享和迁移
  • D不便于备份 E. 可写层会自动同步到宿主机

答案：A、B、C、D 解析：可写层的问题包括：容器删除数据丢失（A）、性能差（B）、不便于共享迁移（C）、不便于备份（D）。E 错，可写层不会自动同步到宿主机，是容器专属的临时层。

10-选择-032（★★ 知识点：K10-1 持久化需求） 下列数据中，通常需要持久化的有？（多选）

  • AMySQL 数据库数据
  • B应用配置文件
  • C用户上传的图片
  • D容器内的 /tmp 临时文件 E. 应用日志

二、判断题（共 20 题，每题 1 分）

10-判断-001（★ 知识点：K10-1 持久化需求） 容器的可写层在容器删除后仍然保留。

答案：错误（✗） 解析：容器删除（docker rm）时，可写层随之删除，所有写入的数据全部消失。只有 docker stop 暂停容器，可写层才保留。

10-判断-002（★ 知识点：K10-1 持久化需求） docker stop 停止容器后，容器内的数据会丢失。

答案：错误（✗） 解析：docker stop 只是暂停容器进程，可写层仍然保留。docker start 恢复运行后数据还在。只有 docker rm 才会删除可写层。

10-判断-003（★ 知识点：K10-1 持久化需求） docker commit 是持久化容器数据的推荐方式。

答案：错误（✗） 解析：docker commit 把可写层固化成镜像层，会把数据混进镜像，不便于独立管理、备份、迁移，是反模式。推荐用数据卷持久化。

10-判断-004（★ 知识点：K10-2 数据卷） 数据卷由 Docker 引擎管理，存储在 /var/lib/docker/volumes/ 目录下。

答案：正确（✓） 解析：Linux 下 Docker 数据卷默认存储在 /var/lib/docker/volumes/<卷名>/_data/，由 Docker 引擎统一管理。

10-判断-005（★ 知识点：K10-2 数据卷） 删除容器时，容器挂载的数据卷会被自动删除。

答案：错误（✗） 解析：删除容器不会删除数据卷，数据卷独立于容器生命周期。需要用 docker volume rm 显式删除卷。

10-判断-006（★ 知识点：K10-3 绑定挂载） 绑定挂载的宿主机路径必须是绝对路径。

答案：正确（✓） 解析：Bind Mount 的宿主机路径必须是绝对路径（如 /home/user/config）。相对路径会被识别为卷名，变成 Volume 挂载。

10-判断-007（★ 知识点：K10-3 绑定挂载） 绑定挂载实现了宿主机和容器之间的双向同步。

答案：正确（✓） 解析：Bind Mount 把宿主机目录直接映射到容器，任意一方修改，另一方立即可见，是双向同步。这正是开发环境热加载的基础。

10-判断-008（★★ 知识点：K10-3 对比） 生产环境推荐使用 Bind Mount 来持久化 MySQL 数据。

答案：错误（✗） 解析：生产环境推荐用 Volume 持久化 MySQL 数据（可移植、可备份、Docker 管理）。Bind Mount 强依赖宿主路径，可移植性差且有安全风险，不推荐生产使用。

10-判断-009（★ 知识点：K10-4 管理命令） docker volume create 命令可以创建一个命名卷。

答案：正确（✓） 解析：docker volume create <卷名> 创建一个有可读名字的命名卷，如 docker volume create mysql_data。

10-判断-010（★ 知识点：K10-4 管理命令） docker volume ls 命令可以列出所有数据卷。

答案：正确（✓） 解析：docker volume ls 列出本地所有数据卷，包括命名卷和匿名卷。

10-判断-011（★★ 知识点：K10-4 管理命令） docker volume prune 会删除正在被容器使用的卷。

答案：错误（✗） 解析：docker volume prune 只删除未被任何容器引用的卷，正在被使用的卷会被跳过，安全。

10-判断-012（★★ 知识点：K10-4 管理命令） 删除正在被容器使用的卷时，Docker 会报错并拒绝删除。

答案：正确（✓） 解析：正在被容器使用的卷无法删除，Docker 会报错"volume is in use and cannot be removed"，需先删除使用该卷的容器。

10-判断-013（★ 知识点：K10-4 命名卷与匿名卷） 使用 -v /var/lib/mysql（只写容器路径）会创建一个匿名卷。

答案：错误（✗） 解析：--volumes-from 只是共享挂载配置，两个容器指向同一个卷，数据互通，不是复制数据。

10-判断-016（★★ 知识点：K10-5 备份） 数据卷备份的经典模式是用临时容器挂载卷和宿主目录，执行 tar 打包。

10-判断-018（★★ 知识点：K10-6 MySQL 持久化） MySQL 容器挂载已有数据的卷重新启动时，MYSQL_DATABASE 指定的数据库会被重新创建。

答案：错误（✗） 解析：MySQL 初始化脚本只在数据目录为空时执行。挂载已有数据的卷后，数据目录非空，初始化脚本跳过，不会重新创建数据库，直接加载已有数据。

10-判断-019（★★ 知识点：K10-6 MySQL 升级） 升级 MySQL 镜像版本时，用新镜像启动新容器并挂载原卷，数据会保留。

10-判断-020（★★ 知识点：K10-2 只读挂载） 使用 :ro 可以将数据卷以只读方式挂载到容器。

10-论述-002（★★ 知识点：K10-2/K10-3 对比，10 分） 请从存储位置、管理方式、可移植性、适用场景、安全性五个方面，对比 Volume 和 Bind Mount 的区别，并给出生产环境和开发环境的选择建议。

参考答案与评分标准（10 分，按要点给分）：

  1. 存储位置（2 分）：Volume 存储在 Docker 管理的 /var/lib/docker/volumes/；Bind Mount 存储在宿主机用户指定的任意绝对路径。
  2. 管理方式（2 分）：Volume 用 docker volume 系列命令统一管理；Bind Mount 直接由宿主机文件系统管理，无专门命令。
  3. 可移植性（2 分）：Volume 由 Docker 管理，不依赖宿主路径，可移植性高；Bind Mount 强依赖宿主机绝对路径，换机器路径可能不存在，可移植性差。
  4. 适用场景（2 分）：Volume 适合生产环境数据持久化（数据库、应用数据、日志）；Bind Mount 适合开发环境代码热加载、配置文件挂载、CI/CD 构建产物输出。
  5. 安全性（1 分）：Volume 由 Docker 隔离管理，安全性较好；Bind Mount 暴露宿主路径，有安全风险，生产环境慎用。
  6. 选择建议（1 分）：生产环境优先 Volume（可移植、可备份、安全）；开发环境需要热加载时用 Bind Mount；不要在生产环境用 Bind Mount 暴露宿主路径。

评分要点：五个方面各 2 分（存储/管理/可移植/适用），安全性和建议共 2 分；要点齐全即可满分。

    docker run --rm -v mysql_data:/data -v /home/user/backup:/backup alpine tar cvf /backup/bak.tar /data
    • --rm：容器执行完自动删除，临时容器（0.5 分）
    • -v mysql_data:/data：把要备份的卷挂载到容器的 /data（0.5 分）
    • -v /home/user/backup:/backup：把宿主机备份目录绑定挂载到容器的 /backup（0.5 分）

1. 数据卷设计方案（6 分）：

  • 数据目录 /var/lib/mysql：使用 Volume（命名卷 mysql_data）持久化（2 分）
    • 理由：数据是核心资产，Volume 由 Docker 管理，可移植、可备份、独立于容器生命周期，适合生产环境数据（1 分）
  • 配置目录 /etc/mysql/conf.d：使用 Bind Mount 挂载宿主机配置目录（2 分）
