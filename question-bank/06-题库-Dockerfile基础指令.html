一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

06-选择-001（★ 知识点：K6-1 Dockerfile 概念） 关于 Dockerfile，下列说法正确的是？

  • ADockerfile 是一个二进制文件，包含镜像的所有内容
  • BDockerfile 是一个文本文件，包含一条条描述镜像构建过程的指令
  • CDockerfile 必须用专门的 IDE 才能编辑
  • DDockerfile 是容器运行时的配置文件

答案：B 解析：Dockerfile 是文本文件，由一条条指令组成，描述镜像如何构建。A 错，是文本不是二进制；C 错，任何文本编辑器都能编辑；D 错，Dockerfile 是构建时的，不是运行时的配置。

06-选择-002（★ 知识点：K6-1 Dockerfile vs commit） 相比 docker commit，使用 Dockerfile 制作镜像的主要优势不包括？

  • A可复现——任何人照着 Dockerfile 都能 build 出同样的镜像
  • B可版本管理——Dockerfile 可提交到 Git
  • C可审计——每行修改都可 Code Review
  • D镜像体积更小——Dockerfile 构建的镜像天然比 commit 小

答案：D 解析：Dockerfile 的优势是可复现（A）、可版本管理（B）、可审计（C）。D 错，镜像体积取决于内容，不取决于用哪种方式构建；用 commit 和 Dockerfile 都可能做出大或小的镜像。

06-选择-003（★ 知识点：K6-1 Dockerfile 命名） Dockerfile 的默认文件名是？

  • Adockerfile.txt
  • BDockerfile（无扩展名，首字母大写）
  • CDockerfile.cfg
  • Ddocker.conf

答案：B 解析：默认文件名是 Dockerfile，首字母大写、无扩展名。用其他名字时需 docker build -f 文件名。A、C 带扩展名不符合默认；D 是完全不同的命名。

06-选择-004（★ 知识点：K6-1 Dockerfile 语法） 关于 Dockerfile 的语法，下列说法正确的是？

  • A指令必须小写
  • B指令通常大写，注释以 # 开头
  • C指令必须以分号结尾
  • D第一条指令必须是 RUN

答案：B 解析：规范是指令大写（FROM、RUN 等），注释以 # 开头。A 错，小写能跑但不规范；C 错，不需要分号；D 错，第一条指令通常是 FROM，不是 RUN。

06-选择-005（★ 知识点：K6-2 FROM 指令） Dockerfile 中通常的第一条指令是？

  • ARUN
  • BCOPY
  • CFROM
  • DCMD

答案：C 解析：FROM 指定基础镜像，通常是 Dockerfile 的第一条指令（除 ARG、解析器指令等少数例外）。RUN、COPY、CMD 都在 FROM 之后。

06-选择-006（★ 知识点：K6-2 基础镜像选择） 关于基础镜像选择，下列做法正确的是？

  • A用 FROM ubuntu:latest 保证最新
  • B用 FROM openjdk:17 因为 openjdk 是官方维护
  • C用 FROM eclipse-temurin:17-jre 固定版本
  • D用 FROM myjdk:latest 从不知名仓库拉

答案：C 解析：C 正确：eclipse-temurin 是官方维护的 OpenJDK 镜像，固定 17-jre 版本。A 错，:latest 不固定版本不可复现；B 错，openjdk 镜像已被弃用；D 错，不用不知名第三方镜像。

06-选择-007（★★ 知识点：K6-2 scratch 镜像） 关于 FROM scratch，下列说法正确的是？

  • Ascratch 是一个最小 Linux 系统
  • Bscratch 是一个特殊的"空镜像"，什么内容都不包含
  • Cscratch 是 Docker Hub 的官方镜像
  • D所有应用都推荐用 scratch 作为基础

答案：B 解析：scratch 是空镜像，不包含任何内容。A 错，scratch 不是 Linux 系统；C 错，scratch 是保留名，不在 Docker Hub；D 错，scratch 仅适合静态编译的程序（如 Go），99% 应用不用 scratch。

06-选择-008（★★ 知识点：K6-2 镜像变体） 关于 alpine、slim、普通版镜像变体的对比，正确的是？

  • Aalpine 最大，普通版最小
  • Balpine 基于 Debian，slim 基于 Alpine
  • Calpine 体积最小（约 5MB），slim 适中（约 50MB），普通版最大
  • D三者体积相同，只是名字不同

答案：C 解析：alpine 基于 Alpine Linux，体积最小（~5MB）；slim 基于 Debian 去除非必要文件（~50MB）；普通版完整 Debian（~几百MB）。A、B、D 都错。

06-选择-009（★ 知识点：K6-3 RUN 指令） 关于 RUN 指令，下列说法正确的是？

  • ARUN 在容器启动时执行
  • BRUN 在构建时执行，每条 RUN 生成一个新的镜像层
  • CRUN 不会生成镜像层
  • DRUN 和 CMD 完全等价

答案：B 解析：RUN 在构建时执行，每条 RUN 生成一层。A 错，启动时执行的是 CMD/ENTRYPOINT；C 错，RUN 会生成层；D 错，RUN 是构建时，CMD 是启动时。

06-选择-010（★★ 知识点：K6-3 层缓存） 关于 Docker 构建的层缓存，下列说法正确的是？

  • A任何指令变了，所有层都重新构建
  • B某条指令变了，只重新构建该层，前后层不受影响
  • C某条指令变了，该层及之后的所有层重新构建，之前的层可复用缓存
  • D缓存完全无法控制，每次都全部重建

答案：C 解析：Docker 按指令顺序检查，某条指令变了，该层及之后的所有层缓存失效并重新构建；之前的层仍可复用缓存。这就是"不常变的放前面、常变的放后面"的原理。

06-选择-011（★★ 知识点：K6-3 合并 RUN） 下列哪种 Dockerfile 写法是工程推荐的？

  • A每条命令单独写一个 RUN
  • B用 && 合并相关命令到一个 RUN
  • C用 ; 分隔命令到一个 RUN
  • D不用 RUN，全用 CMD

答案：B 解析：用 && 合并相关命令到一个 RUN 是推荐做法，可减少层数且 && 保证前一条失败则整体失败。A 错，层数过多；C 错，; 即使前一条失败也会执行下一条，不安全；D 错，CMD 是启动时执行，不能装软件。

06-选择-012（★★ 知识点：K6-3 apt update+install） 为什么 apt-get update 和 apt-get install 必须用 && 连起来写？

  • A不连起来语法报错
  • B分开写会导致两层都用同一个包索引，缓存可能过期导致 install 找不到包
  • C连起来写得更快
  • D没有区别，怎么写都行

答案：B 解析：如果分开写，apt-get update 单独一层，apt-get install 用的是缓存中的包索引。缓存可能过期，导致 install 时找不到包或版本错。用 && 连起来保证 update 和 install 在同一层执行，索引一定最新。

06-选择-013（★ 知识点：K6-4 COPY 指令） COPY 指令的源路径是相对于什么？

  • A镜像内的根目录
  • B构建上下文（build context）
  • CDocker 守护进程的工作目录
  • D用户的 home 目录

答案：B 解析：COPY 源路径相对于构建上下文（docker build 命令最后的路径参数）。不能写构建上下文之外的路径，这是安全设计。

06-选择-014（★★ 知识点：K6-4 COPY vs ADD） 关于 COPY 和 ADD 的区别，下列说法正确的是？

  • ACOPY 和 ADD 功能完全相同
  • BADD 比 COPY 多了自动解压 tar 包和从 URL 下载的功能
  • CCOPY 比 ADD 多了解压功能
  • DADD 只能复制本地文件，COPY 才能下载 URL

答案：B 解析：ADD 在 COPY 基础上多了：①自动解压 tar 包；②从 URL 下载。COPY 只能复制本地文件。所以 ADD 功能更多，但因为行为不可预测，官方推荐优先用 COPY。

06-选择-015（★★ 知识点：K6-4 选择建议） 你需要把本地一个 tar.gz 包复制到镜像并解压，下列哪种做法最合适？

  • A用 COPY file.tar.gz /app/ 然后用 RUN 解压
  • B用 ADD file.tar.gz /app/，让 ADD 自动解压
  • C用 ADD https://example.com/file.tar.gz /app/
  • D用 COPY file.tar.gz /app/file.tar.gz

答案：B 解析：需要解压 tar 包时，ADD 是合适的选择（这是 ADD 唯一被推荐使用的场景）。A 也可以但更繁琐；C 错，不推荐用 ADD 下载 URL（用 RUN wget 更可控）；D 不解压，不符合需求。

06-选择-016（★★ 知识点：K6-4 选择建议） 你需要把本地一个普通 jar 文件复制到镜像，下列哪种做法最合适？

  • A用 ADD app.jar /app/
  • B用 COPY app.jar /app/
  • C用 RUN cp app.jar /app/
  • D用 RUN mv app.jar /app/

答案：B 解析：复制本地普通文件应该用 COPY，行为明确。A 错，复制普通文件不需要 ADD 的额外功能，行为不如 COPY 可预测；C、D 错，RUN cp/mv 是在容器内执行，源文件不在镜像里，会失败。

06-选择-017（★ 知识点：K6-5 WORKDIR 指令） 关于 WORKDIR 指令，下列说法正确的是？

  • AWORKDIR 只对下一条指令生效
  • BWORKDIR 设置的工作目录对后续所有指令（RUN/COPY/CMD 等）持续生效
  • CWORKDIR 必须在 FROM 之前
  • DWORKDIR 创建的目录如果不存在会报错

答案：B 解析：WORKDIR 设置后，对后续所有指令持续生效（直到下一条 WORKDIR）。A 错，不是只对下一条；C 错，WORKDIR 在 FROM 之后；D 错，目录不存在 Docker 会自动创建。

06-选择-018（★★ 知识点：K6-5 WORKDIR vs cd） 为什么 Dockerfile 中应该用 WORKDIR 而不是 RUN cd？

  • AWORKDIR 比 cd 速度快
  • BRUN cd 只在那条 RUN 执行时生效，下一条 RUN 又回到原目录；WORKDIR 持续生效
  • Ccd 不是有效的 shell 命令
  • DWORKDIR 不需要参数

答案：B 解析：每条 RUN 是独立的 shell，RUN cd /app 只在那条 RUN 生效，下一条 RUN 又回到默认目录。WORKDIR 设置后对所有后续指令持续生效。

06-选择-019（★ 知识点：K6-5 USER 指令） USER 指令的作用是？

  • A创建新用户
  • B切换后续指令和容器的运行用户
  • C删除用户
  • D修改用户密码

答案：B 解析：USER 切换后续指令和容器启动时的运行用户。A 错，创建用户要用 RUN useradd/adduser；USER 本身不创建用户。C、D 都不是 USER 的作用。

06-选择-020（★★ 知识点：K6-5 安全最佳实践） 生产镜像中的应用应该以什么用户运行？

  • Aroot 用户（默认）
  • B非 root 用户（如 appuser）
  • Cnobody 用户
  • D任意用户都行

答案：B 解析：生产镜像应用应非 root 运行（最小权限原则）。容器内 root 虽被 namespace 隔离，但仍是特权用户，被攻击后可能内核逃逸。A 错，root 不安全；C nobody 太受限，很多操作做不了；D 错，要明确用非 root。

06-选择-021（★★ 知识点：K6-5 USER 用法） USER 指令切换用户前，应该先做什么？

  • A重启 Docker 守护进程
  • B创建该用户（如 RUN useradd）并创建所需目录、设置权限
  • C安装 sudo
  • D切换到 root 用户

答案：B 解析：USER 切换前，必须先在 root 阶段用 RUN 创建该用户，并创建所需目录、chown 设置权限。否则切换后无权限操作。A、C、D 都不需要。

06-选择-022（★ 知识点：K6-6 docker build 命令） docker build -t ctts-backend:v0.6 . 命令中，最后的 . 表示？

  • ADockerfile 的文件名
  • B构建上下文路径（当前目录）
  • C镜像标签
  • D容器名

答案：B 解析：docker build 最后的参数是构建上下文路径，. 表示当前目录。Dockerfile 默认在该路径下查找。不是文件名（A）、不是标签（C）、不是容器名（D）。

06-选择-023（★ 知识点：K6-6 构建上下文） 关于构建上下文，下列说法正确的是？

  • A构建上下文是 Dockerfile 里的内容
  • B构建上下文是构建时发送给 Docker 守护进程的所有文件
  • C构建上下文只能是当前目录
  • D构建上下文不影响构建速度

答案：B 解析：构建上下文是 docker build 最后路径参数指定的目录下的所有文件，构建时全部发送给守护进程。A 错，上下文是文件不是 Dockerfile 内容；C 错，可以是任意路径；D 错，上下文大则发送慢。

06-选择-024（★★ 知识点：K6-6 .dockerignore） .dockerignore 文件的作用是？

  • A让 Dockerfile 忽略某些指令
  • B让构建上下文不发送某些文件给守护进程
  • C让容器运行时忽略某些文件
  • D让 Git 忽略某些文件

答案：B 解析：.dockerignore 列出不发送给守护进程的文件模式，作用：①减小上下文加快构建；②避免敏感文件（.git、.env）进入上下文；③避免无关文件改动触发缓存失效。

06-选择-025（★★ 知识点：K6-6 .dockerignore 内容） 下列哪一项最不应该出现在 .dockerignore 中？

  • A.git/
  • B*.log
  • Cctts-backend.jar（应用需要打包进镜像的 jar）
  • Dtarget/

答案：C 解析：.dockerignore 应该排除不需要进镜像的文件。jar 是镜像必需的，不能排除。A（.git）、B（日志）、D（构建产物目录）都不该进镜像，应排除。

06-选择-026（★★ 知识点：K6-6 docker build 参数） 下列哪个 docker build 参数可以强制不使用层缓存？

  • A--no-cache
  • B--cache=off
  • C--disable-cache
  • D--fresh

答案：A 解析：--no-cache 让 Docker 不使用层缓存，全部重新构建。其他选项不存在。

06-选择-027（★ 知识点：K6-6 -f 参数） 如果 Dockerfile 文件名为 MyDockerfile，构建命令应该是？

  • Adocker build -t myapp:v1 .
  • Bdocker build -f MyDockerfile -t myapp:v1 .
  • Cdocker build -t myapp:v1 MyDockerfile
  • Ddocker build --file MyDockerfile myapp:v1 .

答案：B 解析：用 -f 指定 Dockerfile 路径：docker build -f MyDockerfile -t myapp:v1 .。A 错，默认找 Dockerfile 找不到会报错；C、D 语法错。

06-选择-028（★★ 知识点：K6-3 RUN 形式） 关于 RUN 的 shell 形式和 exec 形式，下列说法正确的是？

  • Ashell 形式不经过 shell 执行
  • Bexec 形式支持变量替换（如 $NAME）
  • Cshell 形式通过 /bin/sh -c 执行，支持变量替换和管道
  • Dexec 形式比 shell 形式更常用

答案：C 解析：shell 形式 RUN cmd 通过 /bin/sh -c 执行，支持变量替换和管道。A 错；B 错，exec 形式不经过 shell 不解析变量；D 错，大多数情况用 shell 形式。

06-选择-029（★★ 知识点：K6-2 openjdk 弃用） 为什么 Java 应用不再推荐使用 FROM openjdk:17？

  • Aopenjdk 镜像体积太大
  • Bopenjdk 官方镜像已被声明弃用，不再更新
  • Copenjdk 不是开源的
  • Dopenjdk 不支持 Java 17

答案：B 解析：Docker 官方已声明 openjdk 镜像不再更新（已弃用）。推荐用 eclipse-temurin、amazoncorretto 等替代。A 错，体积问题不是弃用原因；C 错，openjdk 是开源的；D 错，openjdk 支持 17 但镜像弃用了。

06-选择-030（★★★ 知识点：K6-3/K6-6 综合） 你的 Dockerfile 构建时间突然从 10 秒变成 60 秒，最不可能的原因是？

  • A构建上下文里多了大文件（如 100MB 日志）
  • B改了 Dockerfile 靠前的 RUN 指令，导致后续层缓存全部失效
  • C基础镜像更新了，FROM 这层缓存失效
  • D镜像名变了

答案：D 解析：A（上下文变大）、B（缓存失效）、C（基础镜像更新导致 FROM 失效）都会让构建变慢。D 错，镜像名（-t 参数）不影响构建速度，只影响最终标签。

1.2 多项选择题（10 题）

06-选择-031（★★ 知识点：K6-1 Dockerfile 优势） 相比 docker commit，使用 Dockerfile 制作镜像的优势包括？（多选）

  • A可复现——任何人照着 Dockerfile 都能 build 出同样的镜像
  • B可版本管理——Dockerfile 可提交到 Git
  • C可审计——每行修改都可 Code Review
  • D镜像自动优化体积 E. 完全取代 docker commit，commit 严禁使用

答案：A、B、C 解析：Dockerfile 优势是可复现（A）、可版本管理（B）、可审计（C）。D 错，Dockerfile 不会自动优化体积，要靠编写规范；E 错，commit 在临时调试场景仍有用（如保留故障现场），生产镜像才必须用 Dockerfile。

06-选择-032（★★ 知识点：K6-2 基础镜像选择原则） 基础镜像选择的原则包括？（多选）

  • A优先用官方镜像
  • B固定版本号，不用 :latest
  • C优先 slim/alpine 变体减小体积
  • D优先用运行时镜像而非自己装 E. 总是用 scratch 最安全

答案：A、B、C、D 解析：A（官方镜像安全）、B（固定版本可复现）、C（slim/alpine 体积小）、D（用现成运行时镜像如 eclipse-temurin:17-jre）都是正确原则。E 错，scratch 仅适合静态编译程序，99% 应用不适用。

06-选择-033（★★ 知识点：K6-3 RUN 优化） 关于 RUN 指令的工程优化，下列做法正确的有？（多选）

  • A用 && 合并相关命令减少层数
  • Bapt update 和 apt install 用 && 连起来
  • C装完软件后用 rm -rf /var/lib/apt/lists/* 清理包索引

06-论述-001（★★ 知识点：K6-1 Dockerfile vs commit，10 分） 请阐述使用 Dockerfile 制作镜像相比 docker commit 的优势，并说明为什么"Dockerfile 是镜像的源代码"。

06-论述-002（★★ 知识点：K6-3 RUN 分层与缓存，8 分） 请解释 Dockerfile 中"每条 RUN 生成一层"的机制，说明层缓存的工作原理，并举例说明如何利用层缓存优化构建。

参考答案与评分标准（8 分，按要点给分）：

  1. 分层机制（2 分）：Docker 镜像是分层的，Dockerfile 中每条 RUN/COPY/ADD 指令都会创建一个新的层。每层只读，叠加在上一层之上。多层可共享、缓存、增量传输。
  2. 层缓存原理（3 分）：
    • Docker 构建时按指令顺序检查缓存（1 分）。
    • 某条指令没变则复用上次的层（缓存命中，秒过）；变了则该层及之后所有层重新构建（缓存失效）（1 分）。
    • 之前的层不受影响，仍可复用缓存（1 分）。
  3. 优化示例（3 分）：
    • 把不常变的指令（如 FROM、apt install）放前面，常变的（如 COPY 应用代码）放后面（1 分）。

RUN apt-get install -y curl          # 不变，缓存
WORKDIR /app                          # 不变，缓存
COPY app.jar /app/                    # 常变，这层失效
CMD ["java", "-jar", "/app/app.jar"]  # 跟着失效
      改 jar 后只有最后两层重新构建（2 分）。

06-论述-004（★★ 知识点：K6-5 安全最佳实践，8 分） 请说明为什么生产镜像应该用非 root 用户运行应用，并写出一个"创建非 root 用户并切换"的标准 Dockerfile 片段。

参考答案与评分标准（8 分，按要点给分）：

  1. 非 root 运行的原因（4 分）：
    • 容器内的 root 虽然被 namespace 隔离，但仍然是特权用户（2 分）。
    • 如果应用有漏洞被攻击，攻击者拿到容器内的 root，可能通过内核漏洞逃逸到宿主机 root，造成灾难（2 分）。
    • 最小权限原则：应用能用普通用户跑就用普通用户跑，限制攻击影响范围。
  2. 标准 Dockerfile 片段（4 分）： 
    FROM eclipse-temurin:17-jre
# 1. root 阶段：创建用户、目录并 chown
RUN useradd -m -d /app -u 1000 appuser \
    && mkdir -p /app \
    && chown -R appuser:appuser /app
WORKDIR /app
COPY app.jar /app/app.jar
# 2. 切换到非 root 用户
USER appuser
CMD ["java", "-jar", "/app/app.jar"]
    • root 阶段创建用户和目录（1 分）
    • chown 设置权限（1 分）

06-编程-002（★★★ 知识点：K6-1~K6-6 综合，20 分） Dockerfile 反例诊断与改写：以下是一个学生写的"反面教材"Dockerfile，存在多处问题。

FROM openjdk
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y vim
ADD ctts-backend.jar /app.jar
RUN cd /app && echo "ready"
CMD java -jar /app.jar

问题：

  1. 找出该 Dockerfile 中至少 5 处问题，并说明每处问题为什么是问题、应该怎么改（10 分）
  2. 写出改写后的"正面"Dockerfile（6 分）
  3. 写出对应的 .dockerignore 文件（4 分）

参考答案与评分标准（20 分）：

1. 找出问题（10 分，每处 2 分，答出 5 处给满分）：

问题 为什么是问题 怎么改
① FROM openjdk（不固定版本，且 openjdk 已弃用） :latest 不可复现；openjdk 弃用 改 FROM eclipse-temurin:17-jre
② RUN apt-get update 和两条 install 分三行写 层数多（3 层）；update 和 install 分开会导致包索引过期 用 && 合并成一条 RUN
③ 用 ADD ctts-backend.jar 复制普通文件 jar 不是 tar，应用 COPY 行为更明确 改 COPY
④ RUN cd /app（且 /app 不存在） cd 只在该 RUN 生效，下条又回默认；且 /app 不存在会失败 用 WORKDIR /app
⑤ 没有设置非 root 用户，默认 root 运行 不安全，违反最小权限原则 创建 appuser + USER 切换
⑥ 装完软件没清理 apt 缓存 镜像体积大 同层 rm -rf /var/lib/apt/lists/*
⑦ CMD java -jar /app/app.jar（shell 形式） shell 形式通过 /bin/sh 执行，信号传递有问题 改 exec 形式 CMD ["java","-jar","/app/app.jar"]

（每处问题 2 分：找出 1 分 + 改法 1 分。答出任意 5 处即满分。）

2. 改写后的 Dockerfile（6 分）：

FROM eclipse-temurin:17-jre

    && mkdir -p /app \
    && chown -R appuser:appuser /app

RUN apt-get update \
    && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*

COPY ctts-backend.jar /app/app.jar

USER appuser

CMD ["java", "-jar", "/app/app.jar"]
