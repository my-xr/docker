一、选择题（共 40 题，每题 2 分）

1.1 单项选择题（30 题）

16-选择-001（★ 知识点：K16-1 Deployment 作用） 关于 Deployment，下列说法正确的是？

  • ADeployment 是 K8s 中能够创建和部署的最小单元，类似于 Pod
  • BDeployment 是 K8s 中管理无状态应用的工作负载控制器
  • CDeployment 只能管理一个 Pod 副本
  • DDeployment 不能滚动更新

答案：B 解析：Deployment 是 K8s 中管理无状态应用的工作负载控制器，通过 ReplicaSet 管理 Pod，提供自愈、扩缩容、滚动更新、回滚能力。A 错，Deployment 不是最小单元，Pod 才是；C 错，Deployment 可管理多副本；D 错，Deployment 默认支持滚动更新。

16-选择-002（★ 知识点：K16-1 裸 Pod 痛点） 裸 Pod 在生产环境不推荐使用的主要原因是？

  • A裸 Pod 启动速度太慢
  • B裸 Pod 不能指定 namespace
  • C裸 Pod 无自愈、不能扩缩容、不能滚动更新
  • D裸 Pod 不支持容器

答案：C 解析：裸 Pod 是临时性的，无自愈能力（节点宕机 Pod 消失无人重建）、不能扩缩容、不能滚动更新与回滚。生产环境要求"挂了自动补、按需扩缩容、不停机更新可回滚"，这些都靠 Deployment 实现。A、B、D 都不是裸 Pod 的痛点。

16-选择-003（★ 知识点：K16-2 三层关系） Deployment、ReplicaSet、Pod 三者的层级关系是？

  • APod 管理 ReplicaSet，ReplicaSet 管理 Deployment
  • BReplicaSet 管理 Deployment，Deployment 管理 Pod
  • CDeployment 管理 ReplicaSet，ReplicaSet 管理 Pod
  • D三者是平级关系，互不管理

答案：C 解析：层级关系是 Deployment → ReplicaSet → Pod。Deployment 管理 ReplicaSet（可管理多个版本用于滚动更新/回滚），ReplicaSet 管理 Pod（维持副本数），Pod 是实际运行的实例。

16-选择-004（★ 知识点：K16-3 apiVersion） Deployment 资源的 apiVersion 是？

  • Av1
  • Bapps/v1
  • Cextensions/v1beta1
  • Dbatch/v1

答案：B 解析：Deployment 属于 apps API 组，版本是 apps/v1（稳定版）。A 错，v1 是 Pod/Service/ConfigMap 等核心资源的 apiVersion；C 错，extensions/v1beta1 是旧版本已废弃；D 错，batch/v1 是 Job/CronJob 的 apiVersion。

16-选择-005（★ 知识点：K16-3 YAML 结构） Deployment YAML 中 spec 的三要素是？

  • AapiVersion、kind、metadata
  • Breplicas、selector、template
  • Ccontainers、volumes、restartPolicy
  • Dname、namespace、labels

答案：B 解析：Deployment 的 spec 三要素：replicas（期望副本数）、selector（标签选择器）、template（Pod 模板）。A 是 YAML 的顶层四要素中的三个；C 是 Pod spec 的字段；D 是 metadata 的字段。

16-选择-006（★ 知识点：K16-3 selector 匹配） 关于 Deployment 的 selector 和 template.labels 的关系，下列说法正确的是？

  • Aselector.matchLabels 必须与 template.metadata.labels 完全相同
  • Bselector.matchLabels 必须是 template.metadata.labels 的子集
  • Ctemplate.metadata.labels 必须是 selector.matchLabels 的子集
  • D二者可以完全不匹配

答案：B 解析：selector.matchLabels 必须是 template.metadata.labels 的子集，即 template.labels 要包含 selector.matchLabels 的所有键值对。template 可以有额外标签，但 selector 里的标签必须在 template 里都有。不匹配会导致 Deployment 找不到自己创建的 Pod。

16-选择-007（★ 知识点：K16-4 滚动更新命令） 触发 Deployment 滚动更新的命令是？

  • Akubectl scale deployment xxx --replicas=5
  • Bkubectl rollout status deployment xxx
  • Ckubectl set image deployment xxx container=image:v2
  • Dkubectl rollout undo deployment xxx

答案：C 解析：kubectl set image 用于更新容器镜像，触发滚动更新。A 是扩缩容；B 是查看滚动更新状态；D 是回滚。

16-选择-008（★ 知识点：K16-4 回滚命令） 将 Deployment 回滚到上一版本的命令是？

  • Akubectl rollout history deployment xxx
  • Bkubectl rollout status deployment xxx
  • Ckubectl rollout undo deployment xxx
  • Dkubectl rollout restart deployment xxx

答案：C 解析：kubectl rollout undo 回滚到上一版本（可用 --to-revision=N 回滚到指定版本）。A 是查看历史；B 是查看状态；D 是重启（强制重新创建 Pod）。

16-选择-009（★ 知识点：K16-5 扩缩容命令） 将 Deployment 副本数调整为 5 的命令是？

  • Akubectl scale deployment xxx --replicas=5
  • Bkubectl set replicas deployment xxx 5
  • Ckubectl resize deployment xxx 5
  • Dkubectl expand deployment xxx --to=5

答案：A 解析：kubectl scale deployment xxx --replicas=5 是扩缩容的标准命令。其他选项都不是有效的 kubectl 命令。

16-选择-010（★ 知识点：K16-2 ReplicaSet 作用） ReplicaSet 的核心职责是？

  • A管理多个 Deployment 版本
  • B维持指定数量的 Pod 副本运行
  • C提供 Service 服务发现
  • D管理集群存储

答案：B 解析：ReplicaSet 是副本控制器，核心职责是维持指定数量的 Pod 副本运行——少了就创建，多了就删除。A 是 Deployment 的职责；C 是 Service 的职责；D 是 PV/PVC 的职责。

16-选择-011（★ 知识点：K16-4 滚动更新原理） Deployment 滚动更新时，旧版本的 ReplicaSet 会怎样？

  • A立即删除
  • B副本数降到 0 但保留 RS 对象
  • C副本数保持不变
  • D自动转换为 StatefulSet

答案：B 解析：滚动更新时，旧 ReplicaSet 的副本数逐步降到 0，但 RS 对象保留（用于回滚）。Deployment 默认保留 10 个历史版本（revisionHistoryLimit: 10）。

16-选择-012（★ 知识点：K16-1 声明式） 关于 Deployment 的声明式管理，下列说法正确的是？

  • A用户告诉 K8s"做什么动作"，如 scale 到 5
  • B用户描述"期望状态"，K8s 维持这个状态
  • C声明式不可版本化
  • D声明式比命令式更慢

答案：B 解析：声明式是用户描述"期望状态"（如 replicas: 3），K8s 维持这个状态。声明式可版本化（YAML 提交 Git）、可复现、自愈。A 是命令式；C、D 错。

16-选择-013（★★ 知识点：K16-4 maxSurge） RollingUpdate 策略中，maxSurge 参数的含义是？

  • A滚动更新时最多低于期望副本数的值
  • B滚动更新时最多超出期望副本数的值
  • C滚动更新的最大重试次数
  • D滚动更新的最大超时时间

答案：B 解析：maxSurge 是滚动更新时最多超出期望副本数的值（向上浮动），控制新 Pod 启动速率。maxUnavailable 才是最多低于期望副本数的值（向下浮动）。

16-选择-014（★★ 知识点：K16-4 maxUnavailable） RollingUpdate 策略中，maxUnavailable 参数的含义是？

  • A滚动更新时最多超出期望副本数的值
  • B滚动更新时最多低于期望副本数的值
  • C不可用 Pod 的最大总数
  • D滚动更新失败的最大次数

答案：B 解析：maxUnavailable 是滚动更新时最多低于期望副本数的值（向下浮动），控制旧 Pod 终止速率。maxSurge 才是最多超出期望副本数的值。

16-选择-015（★★ 知识点：K16-4 参数计算） 某 Deployment replicas=3，maxSurge=25%，maxUnavailable=25%，滚动更新时最多同时存在几个 Pod？

  • A3
  • B4
  • C5
  • D6

答案：B 解析：maxSurge=25% 表示最多超出期望 25%，3 + 3×25% = 3.75，向上取整 = 4。所以最多同时 4 个 Pod（3 期望 + 1 超出）。

16-选择-016（★★ 知识点：K16-4 参数计算） 某 Deployment replicas=3，maxSurge=25%，maxUnavailable=25%，滚动更新时最少有几个 Pod 可用？

  • A1
  • B2
  • C3
  • D0

答案：B 解析：maxUnavailable=25% 表示最多低于期望 25%，3 - 3×25% = 2.25，向下取整 = 2。所以最少保持 2 个 Pod 可用。

16-选择-017（★ 知识点：K16-4 历史版本） 查看 Deployment 版本历史的命令是？

  • Akubectl history deployment xxx
  • Bkubectl rollout history deployment xxx
  • Ckubectl get history deployment xxx
  • Dkubectl describe deployment xxx --history

答案：B 解析：kubectl rollout history deployment xxx 查看版本历史。可以用 --revision=N 查看指定版本详情。

16-选择-018（★ 知识点：K16-4 指定版本回滚） 将 Deployment 回滚到指定版本（如 revision 2）的命令是？

  • Akubectl rollout undo deployment xxx --revision=2
  • Bkubectl rollout undo deployment xxx --to-revision=2
  • Ckubectl rollout undo deployment xxx --version=2
  • Dkubectl rollout undo deployment xxx -r 2

答案：B 解析：kubectl rollout undo deployment xxx --to-revision=2 回滚到指定版本。参数是 --to-revision，不是 --revision 或 --version。

16-选择-019（★ 知识点：K16-5 标签命令） 给 Pod 打标签的命令是？

  • Akubectl label pod xxx key=value
  • Bkubectl tag pod xxx key=value
  • Ckubectl set label pod xxx key=value
  • Dkubectl mark pod xxx key=value

答案：A 解析：kubectl label pod xxx key=value 给 Pod 打标签。修改已有标签需加 --overwrite，删除标签是 key-（键后加 -）。

16-选择-020（★ 知识点：K16-5 标签筛选） 按标签筛选 Pod 的命令是？

  • Akubectl get pods --filter app=backend
  • Bkubectl get pods -l app=backend
  • Ckubectl get pods --label app=backend
  • Dkubectl get pods --selector app=backend

答案：B 解析：kubectl get pods -l app=backend 按标签筛选（-l 是 --selector 的简写）。其他选项语法错误。

16-选择-021（★ 知识点：K16-3 replicas 字段） 关于 Deployment 的 replicas 字段，下列说法正确的是？

  • Areplicas 必须是正整数
  • Breplicas 可以是小数，如 1.5
  • Creplicas 默认值是 0
  • Dreplicas 最大值是 100

答案：A 解析：replicas 必须是正整数（1、3、5 等），不能是小数或负数。默认值是 1（不是 0）；没有固定最大值（受集群资源限制）。

16-选择-022（★ 知识点：K16-2 自愈机制） 手动删除 Deployment 管理的一个 Pod，会发生什么？

  • APod 被删除，不会重建
  • BPod 被删除，ReplicaSet 立即创建新 Pod 补齐
  • CPod 删除失败
  • D整个 Deployment 被删除

答案：B 解析：ReplicaSet 持续监控 Pod 数量，发现 Pod 少于期望值就立即创建新 Pod 补齐。这就是 Deployment 的自愈能力。要真正删除 Pod 必须删除 Deployment。

16-选择-023（★★ 知识点：K16-3 更新策略） Deployment 默认的更新策略是？

  • ARecreate
  • BRollingUpdate
  • CBlueGreen
  • DCanary

答案：B 解析：Deployment 默认策略是 RollingUpdate（滚动更新）。Recreate 是先删旧再建新（服务会中断）。BlueGreen 和 Canary 不是 K8s 原生策略（需要额外工具如 Argo Rollouts）。

16-选择-024（★ 知识点：K16-4 查看状态） 查看 Deployment 滚动更新状态的命令是？

  • Akubectl status deployment xxx
  • Bkubectl rollout status deployment xxx
  • Ckubectl get status deployment xxx
  • Dkubectl describe rollout deployment xxx

答案：B 解析：kubectl rollout status deployment xxx 查看滚动更新状态，会持续输出进度直到完成或失败。

16-选择-025（★ 知识点：K16-5 修改标签） 修改 Pod 已有标签的值，需要加哪个参数？

  • A--force
  • B--update
  • C--overwrite
  • D--replace

答案：C 解析：修改已有标签必须加 --overwrite，否则 kubectl 会报错提示标签已存在。如 kubectl label pod xxx env=prod --overwrite。

16-选择-026（★ 知识点：K16-5 删除标签） 删除 Pod 上的某个标签，正确的命令是？

  • Akubectl label pod xxx key=
  • Bkubectl label pod xxx key-
  • Ckubectl label pod xxx --delete key
  • Dkubectl label pod xxx --remove key

答案：B 解析：删除标签是在键后加 -，如 kubectl label pod xxx env- 删除 env 标签。注意不是 key=（这是设空值）。

16-选择-027（★★ 知识点：K16-4 错误配置） 某 Deployment 配置 maxSurge=0 且 maxUnavailable=0，滚动更新时会怎样？

  • A正常滚动更新
  • B无法滚动更新（卡死）
  • C立即完成更新
  • D删除所有 Pod

答案：B 解析：maxSurge=0 表示不能多出 Pod（不能先启新），maxUnavailable=0 表示不能少于 Pod（不能先停旧），二者矛盾，K8s 无法执行任何操作，滚动更新卡死。这是错误配置，禁止使用。

16-选择-028（★ 知识点：K16-3 历史版本数） Deployment 默认保留多少个历史版本（revisionHistoryLimit）？

  • A0
  • B1
  • C10
  • D100

答案：C 解析：revisionHistoryLimit 默认 10，表示保留 10 个历史 ReplicaSet 版本用于回滚。设为 0 表示不保留历史（无法回滚，不推荐）。

16-选择-029（★★ 知识点：K16-2 为什么用 Deployment） 相比直接用 ReplicaSet，用 Deployment 的主要优势是？

  • ADeployment 启动速度更快
  • BDeployment 支持滚动更新与回滚的版本管理
  • CDeployment 占用资源更少
  • DDeployment 可以跨命名空间

答案：B 解析：Deployment 在 ReplicaSet 之上增加了版本管理能力——每次更新镜像创建新 ReplicaSet，保留旧的用于回滚。ReplicaSet 只能维持副本数，不能滚动更新与回滚。实际工作中都用 Deployment，不直接用 ReplicaSet。

16-选择-030（★★ 知识点：K16-6 CTTS 部署） 部署 CTTS 后端 Deployment 时，imagePullPolicy 应该设成什么（镜像在 Minikube Docker daemon 本地构建）？

  • AAlways
  • BNever 或 IfNotPresent
  • CForever
  • DOnce

答案：B 解析：本地构建的镜像不存在于远程仓库，设 Always 会去仓库拉取导致 ImagePullBackOff。应该用 Never（从不拉取，只用本地）或 IfNotPresent（本地没有才拉取）。

1.2 多项选择题（10 题）

16-选择-031（★★ 知识点：K16-1 Deployment 能力） Deployment 提供的核心能力包括？（多选）

  • A自愈（Pod 挂了自动重建）
  • B扩缩容
  • C滚动更新
  • D回滚 E. 声明式管理

答案：A、B、C、D、E 解析：Deployment 五大能力：自愈、扩缩容、滚动更新、回滚、声明式管理。全部属于 Deployment 的核心能力。

16-选择-032（★★ 知识点：K16-1 裸 Pod 痛点） 裸 Pod 在生产环境的痛点包括？（多选）

  • A不自愈（节点宕机 Pod 消失无人重建）
  • B不能扩缩容
  • C不能滚动更新
  • D不能回滚 E. 不能指定 namespace

答案：A、B、C、D 解析：裸 Pod 四大痛点：不自愈、不能扩缩容、不能滚动更新、不能回滚。E 错，裸 Pod 可以指定 namespace（metadata.namespace）。

16-选择-033（★★ 知识点：K16-3 Deployment YAML） Deployment YAML 中 spec 必填的三要素是？（多选）

  • Areplicas
  • Bselector
  • Ctemplate
  • Dstrategy E. revisionHistoryLimit

答案：A、B、C 解析：spec 三要素：replicas（期望副本数）、selector（标签选择器）、template（Pod 模板）。D、E 是可选字段（有默认值）。

16-选择-034（★★ 知识点：K16-4 滚动更新命令） 下列命令与滚动更新相关的有？（多选）

  • Akubectl set image
  • Bkubectl rollout status
  • Ckubectl rollout history
  • Dkubectl rollout undo E. kubectl scale

答案：A、B、C、D 解析：A 触发滚动更新，B 查看状态，C 查看历史，D 回滚。E 是扩缩容，不直接与滚动更新相关（虽然修改 replicas 也会触发 Pod 创建/删除，但不叫滚动更新）。

16-选择-035（★★ 知识点：K16-4 RollingUpdate 参数） 关于 RollingUpdate 策略的 maxSurge 和 maxUnavailable，下列说法正确的有？（多选）

  • AmaxSurge 控制新 Pod 启动速率
  • BmaxUnavailable 控制旧 Pod 终止速率
  • C二者都可以是百分比或整数
  • DmaxSurge=0 且 maxUnavailable=0 是合法配置 E. 默认值都是 25%

答案：A、B、C、E 解析：A、B、C、E 都正确。D 错，maxSurge=0 且 maxUnavailable=0 会导致无法滚动更新（卡死），是错误配置，禁止使用。

16-选择-036（★★ 知识点：K16-5 标签管理） 关于 K8s 标签（labels），下列说法正确的有？（多选）

  • A标签是键值对
  • B标签用于标识和筛选资源
  • C一个资源可以有多个标签
  • D标签可以被 selector 选择 E. 标签和注解（annotations）是同一个概念

答案：A、B、C、D 解析：A、B、C、D 都正确。E 错，标签用于"选择"和"筛选"（selector 能用），注解用于"附加元数据"（不能被 selector 选择），二者不同。

16-选择-037（★★ 知识点：K16-5 选择器写法） K8s 标签选择器（selector）的两种写法是？（多选）

  • AmatchLabels
  • BmatchExpressions
  • CmatchTags
  • DmatchFields E. matchAnnotations

答案：A、B 解析：selector 两种写法：matchLabels（精确匹配键值对）和 matchExpressions（表达式匹配，支持 In/NotIn/Exists/DoesNotExist 操作符）。matchLabels 是 matchExpressions 的简化形式。

16-选择-038（★★ 知识点：K16-2 三层关系） 关于 Deployment、ReplicaSet、Pod 三者关系，下列说法正确的有？（多选）

  • ADeployment 管理 ReplicaSet
  • BReplicaSet 管理 Pod
  • CDeployment 直接管 Pod

  1. 裸 Pod 的痛点（3 分）：

    • ReplicaSet：副本控制器，维持指定数量的 Pod 副本运行（少了建、多了删），通过 selector 匹配 Pod（1 分）
    • Pod：实际运行的实例，K8s 最小调度单元（1 分）

16-论述-002（★★ 知识点：K16-4 滚动更新原理，10 分） 请详细说明 Deployment 滚动更新的完整流程，并解释 maxSurge 和 maxUnavailable 参数的含义。以 replicas=3、maxSurge=25%、maxUnavailable=25% 为例，计算滚动更新时最多和最少同时有几个 Pod。

参考答案与评分标准（10 分，按要点给分）：

  1. 滚动更新流程（4 分）：

    • kubectl set image 触发更新，Deployment 创建新 ReplicaSet（RS-new，副本数=0）（1 分）
    • RS-new 副本数逐步增加（启动新 Pod），旧 ReplicaSet（RS-old）副本数逐步减少（终止旧 Pod）（1 分）
    • 按 maxSurge 和 maxUnavailable 控制速率，先启新再停旧（1 分）
    • 最终 RS-new 副本数=期望值，RS-old 副本数=0（但保留 RS 对象用于回滚）（1 分）

  2. 参数含义（3 分）：

    • maxSurge：滚动更新时最多超出期望副本数的值（向上浮动），控制新 Pod 启动速率（1.5 分）
    • maxUnavailable：滚动更新时最多低于期望副本数的值（向下浮动），控制旧 Pod 终止速率（1.5 分）

  3. 计算（3 分）：

    • replicas=3，maxSurge=25%：最多超出 3×25%=0.75→向上取整=1，最多同时 3+1=4 个 Pod（1.5 分）
    • replicas=3，maxUnavailable=25%：最多低于 3×25%=0.75→向下取整=1，最少保持 3-1=2 个 Pod（1.5 分）

评分要点：三部分各自独立给分；计算过程要清晰；参数含义要答全"控制什么速率"。

  • (e) --to-revision=N 指定回滚版本
  • (f) kubectl scale 扩缩容

评分标准：每空 2 分，共 12 分。命令拼写要准确（连字符、大小写）；(e) 答 to-revision 给满分，答 revision 或 version 不给分。

六、编程/接口设计题（共 2 题）

16-编程-001（★★ 知识点：K16-3/K16-6 Deployment YAML 编写，15 分） 编写 CTTS 后端 Deployment YAML：请为 CTTS 后端编写一份完整的 Deployment YAML，要求：

  1. 3 副本，命名空间为 ctts（3 分）
  2. 镜像为 ctts-backend:v1，imagePullPolicy 为 IfNotPresent（3 分）
  3. 暴露 8080 端口（2 分）
  4. 设置环境变量 SPRING_PROFILES_ACTIVE=prod 和 DB_HOST=mysql.ctts.svc.cluster.local（3 分）
  5. 资源限制：requests cpu=250m/memory=256Mi，limits cpu=500m/memory=512Mi（2 分）
  6. selector.matchLabels 与 template.metadata.labels 必须匹配（2 分）

参考答案与评分标准（15 分）：

apiVersion: apps/v1                    # 0.5 分
kind: Deployment                       # 0.5 分
metadata:                              # 0.5 分
  name: ctts-backend                   # 0.5 分
  namespace: ctts                      # 1 分（命名空间）
  labels:
    app: ctts-backend
spec:                                  # 0.5 分
  replicas: 3                          # 1.5 分（3 副本）
  selector:                            # 1 分
    matchLabels:
      app: ctts-backend
  template:                            # 0.5 分
    metadata:
      labels:
        app: ctts-backend              # 1 分（必须与 selector 匹配）
    spec:
      containers:
      - name: backend
        image: ctts-backend:v1         # 1 分
        imagePullPolicy: IfNotPresent  # 1 分
        ports:                         # 1 分
        - containerPort: 8080
        env:                           # 1.5 分（每个环境变量 0.75 分）
        - name: SPRING_PROFILES_ACTIVE
          value: prod
        - name: DB_HOST
          value: mysql.ctts.svc.cluster.local
        resources:                     # 1 分
          requests:
            cpu: "250m"
            memory: "256Mi"
          limits:
            cpu: "500m"
            memory: "512Mi"

评分要点：按字段给分；关键字段（apiVersion、kind、replicas、selector、template、image、ports、env、resources）齐全即可；selector 与 template.labels 匹配是硬性要求，不匹配扣 2 分；imagePullPolicy 必须是 IfNotPresent（或 Never），用 Always 扣 1 分。

16-编程-002（★★★ 知识点：K16-4/K16-5/K16-6 综合应用，20 分） Deployment 运维综合题：某团队已部署 CTTS 后端 Deployment（3 副本，镜像 ctts-backend:v1），现在需要进行一系列运维操作。请回答：

  1. 写出查看当前 Deployment 状态和 Pod 列表的命令（4分）
  2. 写出扩容到 5 副本的命令，并说明扩容后如何验证（4分）
  3. 假设已构建 ctts-backend:v2 镜像，写出滚动更新到 v2 的完整命令序列（触发更新 + 查看状态 + 查看历史）（6分）
  4. 如果 v2 有问题需要回滚到 v1，写出回滚命令，并说明如何确认回滚成功（3分）
  5. 写出给某个 Pod 打标签 env=prod 的命令，以及按标签筛选 Pod 的命令（3分）

参考答案与评分标准（20 分）：

1. 查看 Deployment 状态和 Pod 列表（4分，每条2分）：

# 查看 Deployment 状态
kubectl get deployment ctts-backend -n ctts
# 预期输出：
# NAME           READY   UP-TO-DATE   AVAILABLE   AGE
# ctts-backend   3/3     3            3           5m

# 查看 Pod 列表
kubectl get pods -n ctts -l app=ctts-backend
# 预期输出：
# NAME                            READY   STATUS    RESTARTS   AGE
# ctts-backend-7b6f8c9d4-abc12   1/1     Running   0          5m
# ctts-backend-7b6f8c9d4-def34   1/1     Running   0          5m
# ctts-backend-7b6f8c9d4-ghi56   1/1     Running   0          5m

（每条命令 1 分 + 预期输出/说明 1 分）

2. 扩容到 5 副本并验证（4分）：

# 扩容命令
kubectl scale deployment ctts-backend --replicas=5 -n ctts
#（2分）

# 验证：查看 Deployment，READY 应该是 5/5
kubectl get deployment ctts-backend -n ctts
# 预期输出：
# NAME           READY   UP-TO-DATE   AVAILABLE   AGE
# ctts-backend   5/5     5            5           6m
#（2分）

3. 滚动更新到 v2 的完整命令序列（6分，每条2分）：

# 触发滚动更新
kubectl set image deployment/ctts-backend backend=ctts-backend:v2 -n ctts --record
# deployment.apps/ctts-backend image updated

# 查看滚动更新状态
kubectl rollout status deployment/ctts-backend -n ctts

# deployment "ctts-backend" successfully rolled out

# 查看版本历史
kubectl rollout history deployment/ctts-backend -n ctts

# 2         kubectl set image deployment/ctts-backend backend=ctts-backend:v2 ...

（每条命令 2 分；--record 可选，加不加都给分；必须指定容器名 backend）

4. 回滚到 v1 并确认（3分）：

# 回滚命令
kubectl rollout undo deployment/ctts-backend -n ctts
# deployment.apps/ctts-backend rolled back
#（1.5分）

# 确认回滚成功：查看 Pod 镜像版本，应该都是 v1
kubectl get pods -n ctts -l app=ctts-backend -o jsonpath='{range .items[*]}{.spec.containers[0].image}{"\n"}{end}'
# 预期输出：
# ctts-backend:v1
# ctts-backend:v1
# ctts-backend:v1
#（1.5分；也可以用 kubectl rollout status 或 kubectl describe deployment 确认）

5. 打标签与筛选（3分）：

# 给某个 Pod 打标签 env=prod
kubectl label pod ctts-backend-7b6f8c9d4-abc12 env=prod -n ctts
#（1.5分）

# 按标签筛选 Pod
kubectl get pods -n ctts -l env=prod
#（1.5分）

评分要点：各小题独立给分；命令必须包含 -n ctts（不包含扣 0.5 分）；命令拼写要准确；set image 必须指定容器名 backend；预期输出/说明意思对即可。
