二、知识点详解

知识点 K2-1：Linux 环境准备

定义

Linux 环境准备 是指在安装 Docker 之前，确保操作系统版本、内核、软件包管理工具、网络、用户权限等满足 Docker 引擎运行要求的准备工作。

原理

Docker 引擎基于 Linux 内核的 namespaces 和 cgroups 特性运行，因此对操作系统版本和内核版本有最低要求：

要求项 最低要求 推荐
操作系统 Ubuntu 20.04 LTS Ubuntu 22.04 LTS
内核版本 3.10+ 5.15+（Ubuntu 22.04 自带）
架构 x86_64 / arm64 x86_64（amd64）
apt 包管理 已安装 已安装
网络 能访问外网 能访问外网
用户权限 sudo 权限 sudo 权限

Ubuntu 22.04 LTS 自带内核 5.15，完全满足 Docker 要求，是本课程推荐环境。

问题 / 场景

问：为什么用 Ubuntu 22.04 而不是 CentOS？

  • Ubuntu 22.04 是当前主流 LTS（长期支持版），社区活跃、Docker 官方源支持完善。CentOS 8 已停止维护，CentOS Stream 7 也已 EOL，故本课程统一用 Ubuntu 22.04。企业环境中 Ubuntu/Debian 系也是 Docker 部署的主流选择。

问：可以用 Windows 或 macOS 吗？

  • 可以用 Docker Desktop，但本课程以 Linux 服务器环境为主（生产环境基本都是 Linux）。Windows/macOS 上的 Docker Desktop 是通过轻量级 Linux 虚拟机实现的，与生产环境有差异。建议用虚拟机装 Ubuntu 22.04 学习。

问：为什么需要 sudo 权限？

  • 安装软件、配置 apt 源、管理 systemd 服务都需要 root 权限。普通用户通过 sudo 临时获取 root 权限执行这些操作。

易错点

  1. ❌ 直接在 root 用户下操作，不写 sudo。✅ 本课程统一用普通用户 + sudo，培养规范习惯（生产环境禁止直接用 root）。
  2. ❌ 系统版本过低（如 Ubuntu 18.04）仍强行装新版 Docker。✅ 升级到 22.04 LTS 再装。
  3. ❌ 跳过 apt update 直接装依赖，可能拉到旧索引。✅ 先 update 再 install。
  4. ❌ 忘记装 ca-certificates/curl/gnupg，导致后续添加 GPG 密钥失败。✅ 按步骤先装依赖。

小结

环境准备是安装 Docker 的前置步骤：确认 Ubuntu 22.04 + 内核 5.15+ + x86_64 + sudo 权限 + 联网，并安装 ca-certificates/curl/gnupg/lsb-release 依赖。环境就绪后才能进入正式安装。

知识点 K2-2：Docker 安装

定义

Docker 安装 是指通过 apt 官方源在 Ubuntu 22.04 上安装 Docker 引擎（Docker Engine）的完整流程，包括：卸载旧版本 → 配置 Docker 官方 apt 源（GPG 密钥 + 仓库地址）→ apt 安装 docker-ce → 验证安装。

原理

Ubuntu 默认软件源里的 docker.io 包是 Ubuntu 自己打包的旧版本，不是 Docker 官方维护的。官方推荐使用 Docker 自己维护的 apt 源（download.docker.com）安装 docker-ce（Community Edition，社区版），版本最新、维护及时。

安装流程的核心原理：

  1. 卸载旧版本：避免新旧版本冲突。
  2. 添加 GPG 密钥：apt 通过 GPG 密钥验证软件包来源真实性，防止被篡改。
  3. 添加 apt 仓库：告诉 apt "从 download.docker.com 这个源拉 docker-ce"。
  4. apt install：从配置好的官方源安装 docker-ce、docker-ce-cli、containerd.io 等组件。

Docker 引擎的组成包：

包名 作用
docker-ce Docker 引擎主体（含 dockerd 守护进程）
docker-ce-cli Docker 命令行客户端（docker 命令）
containerd.io containerd 运行时（容器生命周期管理）
docker-buildx-plugin Buildx 构建插件（增强构建能力）
docker-compose-plugin Docker Compose v2 插件（多容器编排）

问题 / 场景

问：为什么要卸载旧版本？系统没装过也要卸载吗？

  • 防御性操作。Ubuntu 源里有 docker.io、docker-engine、docker-containerd 等旧包名，若之前装过会与官方 docker-ce 冲突。即使没装过，执行卸载命令也不会报错（只是提示未安装），所以统一执行一遍更安全。

问：docker-ce 和 docker.io 有什么区别？

  • docker-ce 是 Docker 官方维护的社区版，版本新、更新快；docker.io 是 Ubuntu 发行版自己打包的，版本旧、更新慢。生产环境一律用 docker-ce。

问：为什么不用一键脚本 curl -fsSL https://get.docker.com | sh？

  • 官方提供了一键脚本，确实方便。但课堂学习要理解每一步，所以本课讲手动配置 apt 源的完整流程。理解后实际工作中可以用一键脚本提速。脚本本质也是执行这些步骤。

完整示例

步骤 1：卸载旧版本（防御性操作，没装过也不会报错）

sudo apt remove -y docker docker-engine docker.io containerd runc

预期输出（若系统未装过，显示如下）：

Reading package lists... Done

Reading state information... Done

Package 'runc' is not installed, so not removed
0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.

步骤 2：添加 Docker 官方 GPG 密钥

# 创建密钥存放目录（Ubuntu 22.04 推荐 keyring 方式）
sudo mkdir -p /etc/apt/keyrings

# 下载 Docker 官方 GPG 密钥并放到 keyring 目录
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

预期输出：无输出（命令成功执行即表示密钥已写入 /etc/apt/keyrings/docker.gpg）。

验证密钥文件已生成：

ls -l /etc/apt/keyrings/docker.gpg

预期输出：

步骤 3：添加 Docker apt 仓库

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

预期输出：无输出（命令成功即表示仓库配置已写入 /etc/apt/sources.list.d/docker.list）。

验证仓库文件内容：

cat /etc/apt/sources.list.d/docker.list

预期输出：

易错点

  1. ❌ 跳过 GPG 密钥直接配置源，apt 会警告 "NO_PUBKEY" 并拒绝安装。✅ 必须先添加 GPG 密钥再添加源。
  2. ❌ GPG 密钥路径与 sources.list 中 signed-by= 路径不一致。✅ 两者必须完全一致（本资料统一用 /etc/apt/keyrings/docker.gpg）。
  3. ❌ 用 lsb_release -cs 拼写源地址时，Ubuntu 22.04 输出是 jammy，不要手写错成 bionic 或 focal。✅ 用命令自动获取。
  4. ❌ 忘记 apt update 就直接 install，apt 找不到 docker-ce 包。✅ 添加源后必须 update。
  5. ❌ 安装后直接运行 docker 命令报 "permission denied"。✅ 要么加 sudo，要么把用户加入 docker 组后重新登录。
  6. ❌ 用 apt install docker.io 装了 Ubuntu 源的旧版。✅ 必须用官方源装 docker-ce。

小结

Docker 安装核心流程：卸载旧版本 → 添加 GPG 密钥 → 添加 apt 仓库 → apt update → apt install docker-ce 全套包 → 验证。装完把用户加入 docker 组可免 sudo 操作。看到 docker run hello-world 输出 Hello from Docker! 即安装成功。

知识点 K2-3：Docker 服务管理

定义

Docker 服务管理 是指使用 systemd 的 systemctl 命令对 Docker 守护进程（dockerd）进行启动、停止、重启、状态查看和开机自启配置的操作。

原理

Ubuntu 22.04 使用 systemd 作为初始化系统（init system），所有系统服务由 systemd 管理。Docker 安装后会注册为 systemd 服务（服务名 docker），服务单元文件位于 /lib/systemd/system/docker.service。

systemctl 是 systemd 的命令行工具，用于管理服务。Docker 守护进程（dockerd）作为一个后台服务运行，必须启动 dockerd 才能执行 docker 命令。

常用 systemctl 命令：

命令 作用
sudo systemctl start docker 启动 Docker 服务
sudo systemctl stop docker 停止 Docker 服务
sudo systemctl restart docker 重启 Docker 服务（改配置后生效）
sudo systemctl status docker 查看 Docker 服务状态
sudo systemctl enable docker 设置 Docker 开机自启
sudo systemctl disable docker 取消开机自启
sudo systemctl is-enabled docker 查看是否已设为开机自启

问题 / 场景

问：为什么改了 daemon.json 要 restart docker？

  • dockerd 启动时读取 /etc/docker/daemon.json 配置文件，运行中不会自动重新读取。改配置后必须 restart 让 dockerd 重新加载配置才能生效。

问：开机自启为什么重要？

  • 生产环境服务器重启后，Docker 服务必须自动启动，否则所有容器都不会运行，导致业务中断。systemctl enable docker 就是配置开机自启。

问：stop docker 后正在运行的容器会怎样？

  • stop docker 会停止 dockerd 守护进程，所有正在运行的容器也会被停止（但容器配置仍在，下次 start docker 后可用 docker start 重新启动容器）。

完整示例

1. 查看 Docker 服务状态：

sudo systemctl status docker

预期输出：

● docker.service - Docker Application Container Engine
     Loaded: loaded (/lib/systemd/system/docker.service; enabled; vendor preset: enabled)
     Active: active (running) since Sun 2024-01-01 10:00:00 UTC; 30min ago
TriggeredBy: ● docker.socket
       Docs: https://docs.docker.com
   Main PID: 12345 (dockerd)
      Tasks: 10
     Memory: 120.5M
        CPU: 2.5s
     CGroup: /system.slice/docker.service
             └─12345 /usr/bin/dockerd -H fd:// --containerd=/run/containerd/containerd.sock

Jan 01 10:00:00 server systemd[1]: Started Docker Application Container Engine.

关键字段含义：

  • Loaded: loaded (...; enabled)：服务单元已加载，且已设为开机自启（enabled）
  • Active: active (running)：服务当前正在运行（关键！看到这个才算正常）
  • Main PID: 12345 (dockerd)：主进程 PID 与进程名
  • 若显示 inactive (dead) 或 failed，说明服务未启动或启动失败

2. 启动 Docker 服务：

sudo systemctl start docker

预期输出：无输出（命令成功即表示已启动）。可用 status 验证。

3. 停止 Docker 服务：

sudo systemctl stop docker

预期输出：无输出。此时 docker ps 等命令会报错 "Cannot connect to the Docker daemon"。

4. 重启 Docker 服务（改完 daemon.json 后必做）：

sudo systemctl restart docker

预期输出：无输出。重启会重新加载配置文件。

5. 设置开机自启：

sudo systemctl enable docker

预期输出：

Synchronizing state of docker.service with SysV service script with /lib/systemd/systemd-sysv-install.
Executing: /lib/systemd/systemd-sysv-install enable docker

6. 查看是否已设为开机自启：

systemctl is-enabled docker

预期输出：

enabled

若输出 disabled 则表示未设为开机自启，需执行 enable。

7. 同时设置开机自启并立即启动：

sudo systemctl enable --now docker

💡 --now 参数等同于 enable + start 一步到位，实际工作中常用。

图示

Docker 服务生命周期：

   ┌─────────┐ enable  ┌──────────┐
   │ disabled│────────▶│ enabled  │
   │ (未自启) │◀────────│ (开机自启)│
   └────┬────┘ disable └────┬─────┘
        │                    │
        │ start              │ start
        ▼                    ▼
   ┌─────────┐  stop   ┌──────────┐
   │ inactive│◀────────│ active   │
   │ (未运行) │────────▶│ (running)│
   └─────────┘  start  └──────────┘
                     │
                     │ restart（改配置后执行）
                     ▼
                 重新加载配置并运行

关键：
- enable/disable 控制开机是否自启
- start/stop 控制当前是否运行
- restart 用于配置变更后重新加载

易错点

  1. ❌ 改了 daemon.json 不 restart docker，配置不生效。✅ 任何 daemon.json 修改后必须 systemctl restart docker。
  2. ❌ 混淆 enable 和 start。✅ enable 是设开机自启（持久化），start 是当前启动（即时）。enable --now 才是两者都做。
  3. ❌ stop docker 后直接运行 docker 命令，报 "Cannot connect to the Docker daemon"。✅ stop 后必须先 start 才能用 docker 命令。
  4. ❌ 忘记设置开机自启，服务器重启后容器全没跑。✅ 生产环境必须 systemctl enable docker。
  5. ❌ 用 service docker start 旧命令。✅ Ubuntu 22.04 用 systemd，统一用 systemctl（service 命令虽兼容但不推荐）。

小结

Docker 服务用 systemctl 管理：start/stop/restart 控制运行，enable 控制开机自启，status 查看状态。改 daemon.json 后必须 restart。生产环境务必 enable 开机自启。看到 Active: active (running) 即服务正常。

知识点 K2-4：镜像加速器配置

定义

镜像加速器（Image Registry Mirror） 是指在国内搭建的 Docker Hub 镜像副本站点，通过配置 /etc/docker/daemon.json 让 dockerd 从国内镜像站拉取镜像，从而加速拉取速度、解决网络不通的问题。

原理

Docker Hub（hub.docker.com）服务器在国外，国内拉取镜像经常很慢甚至超时。镜像加速器是国内厂商搭建的 Docker Hub 镜像缓存站点，定期同步 Docker Hub 上的镜像。配置镜像加速器后，dockerd 拉取镜像时会优先从加速器地址拉取，速度大幅提升。

配置原理：dockerd 启动时读取 /etc/docker/daemon.json 配置文件，其中的 registry-mirrors 字段指定镜像加速器地址列表。dockerd 拉取镜像时按列表顺序尝试，第一个不通自动切换下一个。

国内常用镜像加速器：

加速器名称 地址 提供方
阿里云 https://<你的ID>.mirror.aliyuncs.com 阿里云（需登录获取专属地址）
中科大 https://docker.mirrors.ustc.edu.cn 中国科学技术大学
网易 https://hub-mirror.c.163.com 网易
腾讯云 https://mirror.ccs.tencentyun.com 腾讯云（内网）
百度云 https://docker.mirrors.baidubce.com 百度云
DaoCloud https://docker.m.daocloud.io DaoCloud

⚠️ 镜像加速器地址可能随时间变化，若某个地址失效，换一个即可。本课以阿里云 + 中科大 + 网易三个为例。

问题 / 场景

问：为什么要配置镜像加速器？

  • Docker Hub 在国外，国内直拉经常超时（pull 一个 mysql 镜像可能要 10 分钟甚至失败）。配置国内加速器后，拉取速度可提升到 MB/s 级，几秒到几十秒完成。

问：配置多个镜像加速器有意义吗？

  • 有。dockerd 会按顺序尝试，第一个不通自动用下一个，提高可用性。建议配 2~3 个备份。

问：配置后不重启会生效吗？

  • 不会。dockerd 只在启动时读取 daemon.json，运行中改了配置必须 systemctl restart docker 重新加载才生效。

问：阿里云加速器为什么地址里有"你的ID"？

  • 阿里云为每个账号提供专属加速器地址，需登录阿里云容器镜像服务控制台（cr.console.aliyun.com）查看自己的专属地址。专属地址比公共地址更稳定、有带宽保障。

完整示例

1. 创建或编辑 /etc/docker/daemon.json：

    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com",

  ],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
EOF

看到 Registry Mirrors 下面列出了配置的加速器地址，即表示配置生效。

sudo systemctl restart docker

将 abcdef12 替换为你阿里云控制台显示的专属 ID。

易错点

  1. ❌ daemon.json 格式错误（JSON 多逗号、少引号、用单引号）。✅ JSON 必须用双引号，最后一项不能有逗号。可用 python3 -m json.tool 校验。

镜像加速器解决国内拉取 Docker Hub 镜像慢的问题。配置方法是编辑 /etc/docker/daemon.json 的 registry-mirrors 字段，写入 1~3 个国内镜像地址，然后 systemctl restart docker 生效。用 docker info 查看 Registry Mirrors 字段确认配置成功。

知识点 K2-5：运行首个容器

定义

运行首个容器 是指通过 docker run hello-world 命令运行 Docker 官方入门镜像 hello-world，验证 Docker 安装是否成功，并理解 docker run 背后的 pull 原理。

原理

docker run hello-world 的执行流程（对应第 1 次课讲的 C/S 架构）：

图示 3：用户敲 docker run hello-world

输入命令

用户执行 docker run hello-world。

查找本地镜像

Docker 先检查本机是否已有 hello-world 镜像。

拉取镜像

本地没有时，从镜像仓库下载 hello-world。

创建并启动容器

Docker 用镜像创建容器，执行默认命令。

输出结果后退出

容器打印 hello 信息，进程结束，容器进入 Exited。

pull 原理关键点：

  • docker run 时若本地没有指定镜像，dockerd 会自动 pull（拉取），不需要手动 docker pull。
  • 第一次运行 hello-world 会拉取镜像（看到 "Unable to find image locally" + "Pulling from library/hello-world"）。
  • 第二次运行 hello-world 时本地已有镜像，不再 pull，直接创建容器运行。
  • hello-world 程序打印完说明文字就退出，所以容器状态是 Exited (0)（正常退出）。

问题 / 场景

问：docker run 和 docker pull 有什么区别？

  • docker pull 只拉取镜像到本地，不运行；docker run 是"拉取（若本地没有）+ 运行容器"二合一。第一次 docker run hello-world 会自动 pull。

问：为什么 hello-world 容器运行完就退出了？

  • hello-world 镜像里的程序就是打印一段文字，打印完程序就结束了。容器是"运行进程"的载体，进程结束容器就退出。这不是报错，是正常退出（Exited (0)）。像 nginx、mysql 这类守护进程镜像会持续运行不会退出。

问：第二次运行 hello-world 为什么没有 "Pulling from" 那段输出？

  • 因为第一次已经把 hello-world:latest 拉到本地了，第二次直接用本地镜像创建容器，不再 pull。可以用 docker images 看到本地已有 hello-world 镜像。

知识点 K2-6：Docker 基本信息查看

定义

Docker 基本信息查看 是指使用 docker version 和 docker info 命令查看 Docker 引擎的版本信息、运行状态、配置详情，用于验证安装与排查问题。

原理

两个命令都能查看 Docker 信息，但侧重点不同：

命令 作用 输出重点
docker version 查看客户端与服务端版本 版本号、API 版本、Go 版本、Git commit、OS/Arch
docker info 查看系统级详细信息 服务状态、容器数、镜像数、存储驱动、网络、镜像加速器、运行时

为什么有两个命令？

  • docker version 快速确认"客户端和服务端是否都能连上、版本是否匹配"。若服务端部分为空，说明 dockerd 没启动或权限不足。
  • docker info 用于全面诊断，看存储驱动、镜像加速器、容器数量等运行时信息。

问题 / 场景

问：docker version 只显示 Client 部分，没有 Server 部分，怎么回事？

  • 三种可能：①dockerd 没启动（用 systemctl start docker 启动）；②当前用户无权限访问 docker.sock（把用户加入 docker 组或用 sudo）；③dockerd 启动失败（用 systemctl status docker 查日志）。

问：docker info 里的 Storage Driver 是什么？

  • 存储驱动，决定镜像和容器在磁盘上如何存储。Ubuntu 22.04 默认是 overlay2（推荐，性能最好）。老版本可能是 aufs（已不推荐）。若显示 vfs 说明用了最慢的兼容驱动，需排查。

问：docker info 看不到 Registry Mirrors，配置没生效？

  • 说明 daemon.json 没配置或没 restart docker。检查 /etc/docker/daemon.json 是否存在、格式是否正确、是否 restart 过。

4. 排查"Server 部分为空"问题：

若 docker version 只显示 Client 没有 Server，按以下步骤排查：

# 1. 检查 dockerd 是否运行
sudo systemctl status docker
# 若 inactive/dead，启动：
sudo systemctl start docker

# 2. 检查当前用户是否在 docker 组
groups
# 若输出中没有 docker，添加：
sudo usermod -aG docker $USER
newgrp docker

# 3. 检查 docker.sock 权限
ls -l /var/run/docker.sock
# 应显示 srw-rw---- 1 root docker

# 4. 查看 dockerd 启动日志
sudo journalctl -u docker.service --no-pager | tail -50

排查思路：
docker version 只显示 Client？
   ↓
1. systemctl status docker（服务是否运行）
2. groups（用户是否在 docker 组）
3. journalctl -u docker（看启动日志）

易错点

  1. ❌ 只看 docker --version 就以为安装没问题。✅ docker --version 只看客户端版本，不能确认服务端是否运行。要用 docker version（不带 --）看 Client + Server 两段。
  2. ❌ docker version 只显示 Client 段没在意。✅ Server 段为空说明 dockerd 没启动或权限不足，必须排查。
  3. ❌ 不看 docker info 的 Storage Driver。✅ 若不是 overlay2（如 vfs）性能会差很多，需排查。
  4. ❌ 配置了镜像加速器却不用 docker info 验证。✅ 用 docker info 看 Registry Mirrors 字段确认配置生效。
  5. ❌ 把 docker version 和 docker info 混为一谈。✅ version 看版本，info 看运行状态，用途不同。

小结

docker version 看客户端与服务端版本（快速验证通信），docker info 看系统级运行详情（容器数、存储驱动、镜像加速器、内核等）。安装后必跑这两个命令确认：Client 和 Server 都有版本、Storage Driver 是 overlay2、Registry Mirrors 显示配置的加速器。若 Server 段为空，按"服务状态→用户组→日志"顺序排查。

三、综合示例：从零安装 Docker 到跑通 hello-world

把前面所有知识点串起来，形成一份完整的"Docker 安装与验证"操作清单（学生可直接照做）：

# ============================================================
# Docker 安装与验证完整流程（Ubuntu 22.04）
# 对应 CTTS 项目环境准备第一步
# ============================================================

# ---- K2-1：环境准备 ----
# 1. 确认系统版本
cat /etc/os-release | grep PRETTY_NAME
# 预期：Ubuntu 22.04.x LTS

# 2. 确认内核
uname -r
# 预期：5.15.x

# 3. 更新 apt 并装依赖
sudo apt update
sudo apt install -y ca-certificates curl gnupg lsb-release

# ---- K2-2：安装 Docker ----
# 4. 卸载旧版本（防御性，无旧版也不报错）
sudo apt remove -y docker docker-engine docker.io containerd runc

# 5. 添加 GPG 密钥
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# 6. 添加 apt 仓库
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 7. 更新 apt 索引
sudo apt update

# 8. 安装 Docker 引擎全套
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 9. 把当前用户加入 docker 组（免 sudo）
sudo usermod -aG docker $USER
newgrp docker

# ---- K2-3：服务管理 ----
# 10. 设置开机自启并立即启动
sudo systemctl enable --now docker

# 11. 查看服务状态（确认 active running）
sudo systemctl status docker

# ---- K2-4：镜像加速器配置 ----
# 12. 写入 daemon.json
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com",
    "https://docker.mirrors.baidubce.com"
  ],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
EOF

# 13. 校验 JSON 格式
sudo cat /etc/docker/daemon.json | python3 -m json.tool

# 14. 重启 Docker 让配置生效
sudo systemctl daemon-reload
sudo systemctl restart docker

# ---- K2-5：运行首个容器 ----
# 15. 运行 hello-world（第一次会自动 pull）
docker run hello-world
# 预期看到 "Hello from Docker!"

# 16. 查看本地镜像
docker images
# 预期看到 hello-world 镜像

# 17. 查看所有容器（含已退出）
docker ps -a
# 预期看到一个 Exited (0) 的 hello-world 容器

# ---- K2-6：信息查看 ----
# 18. 查看版本（确认 Client + Server 都有）
docker version

# 19. 查看系统信息（确认镜像加速器生效）
docker info
# 预期在 Registry Mirrors 下看到配置的三个加速器地址

# ============================================================
# 至此 Docker 安装完成，CTTS 项目环境准备第一步就绪
# 后续课程将在此环境上拉取镜像、构建镜像、编排部署
# ============================================================

这个流程是后续所有 Docker 实操的基础。学生必须在自己的机器上完整跑通一遍，遇到报错记录并排查。

四、拓展阅读（选学）
