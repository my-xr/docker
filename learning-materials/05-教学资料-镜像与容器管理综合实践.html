二、知识点详解

知识点 K5-1：实践任务总览与 CTTS 三服务镜像准备

定义

CTTS 三服务容器化 是把课程贯穿项目 CTTS 的三个服务（MySQL 数据库、Nginx 前端 Web 服务器、Java 后端运行环境）分别用官方镜像运行成容器的过程。这是 CTTS 容器化部署项目阶段 2 的核心任务。

镜像选型原则：

  1. 优先使用官方镜像（Docker Hub 上 library/ 命名空间的镜像）。
  2. 标签明确版本号，不使用 :latest（不可控，不可复现）。
  3. 生产环境优先选 alpine/slim 变体（体积小、攻击面小），学习阶段可用完整版。

原理

CTTS 三服务的镜像选型对照表：

服务 官方镜像 推荐标签 镜像大小 说明
MySQL mysql 8.0 ~520MB 官方 MySQL 8.0，含完整服务端
Nginx nginx stable 或 1.25 ~140MB 官方 Nginx 稳定版，托管静态页面
Java openjdk 17-jdk-slim ~400MB OpenJDK 17，含完整 JDK

📌 openjdk 官方镜像已标记为 deprecated（弃用），生产环境推荐用 eclipse-temurin:17-jre。本课程学习阶段仍使用 openjdk:17-jdk-slim，便于理解。

问题 / 场景

问：为什么不用 :latest 标签？

  • :latest 不保证是最新最稳定版本，可能指向任意版本。今天 pull 的 :latest 和明天 pull 的可能不同，导致环境不一致。生产环境必须指定明确版本号，保证可复现。

问：MySQL 为什么不选 8.0.35 这种更精确的版本？

  • 学习阶段用 8.0 大版本即可，方便记忆。生产环境建议用 8.0.35 这种精确到补丁号的版本，避免小版本升级引入兼容性问题。

问：为什么 Nginx 不选 alpine 变体？

  • nginx:alpine 体积更小（~40MB），但基于 musl libc，部分依赖 glibc 的模块不兼容。学习阶段用 nginx:stable（基于 Debian）兼容性更好。生产环境推荐 nginx:alpine 减小攻击面。

常见报错排查

报错 1：拉取镜像超时

Error response from daemon: Get "https://registry-1.docker.io/v2/": net/http: request canceled

原因：网络无法访问 Docker Hub。 解决：配置国内镜像加速器（参考第 2 次课内容），编辑 /etc/docker/daemon.json：

{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}

重启 Docker：sudo systemctl restart docker。

报错 2：磁盘空间不足

failed to register layer: Error processing tar file(exit status 1): write /usr/lib/...: no space left on device

原因：磁盘空间不足。 解决：用 docker system prune -a 清理无用镜像和容器（注意会删除所有停止的容器和未使用的镜像）。

易错点

  1. ❌ 使用 :latest 标签。✅ 明确指定版本号，如 mysql:8.0、nginx:stable。
  2. ❌ 拉取镜像后不查看镜像列表确认。✅ 用 docker images 确认镜像已拉取成功。
  3. ❌ 不区分 openjdk:17-jdk-slim 和 openjdk:17-jre-slim。✅ JDK 包含编译工具，JRE 只能运行；运行 jar 用 JRE 即可，体积更小。

小结

K5-1 完成了 CTTS 三服务镜像的准备。镜像选型要遵循"官方镜像 + 明确版本 + 学习用完整版/生产用 slim"的原则。拉取后用 docker images 确认，用 docker inspect 查看详细信息，为后续运行容器打下基础。

知识点 K5-2：MySQL 容器运行与数据库初始化

定义

MySQL 容器化运行 是用 mysql:8.0 镜像启动一个 MySQL 数据库容器，并通过环境变量配置 root 密码、通过 docker exec 进入容器执行 SQL 完成数据库初始化的过程。

原理

MySQL 官方镜像的关键设计：

  1. 必需环境变量：MYSQL_ROOT_PASSWORD（root 密码，必填，不填容器启动失败）。
  2. 可选环境变量：MYSQL_DATABASE（自动创建数据库）、MYSQL_USER/MYSQL_PASSWORD（自动创建用户）。
  3. 暴露端口：3306（MySQL 服务端口）、33060（X Protocol 端口）。
  4. 数据目录：/var/lib/mysql（数据持久化目录，需挂载到宿主机或数据卷）。
  5. 入口命令：docker-entrypoint.sh，负责初始化数据库、创建用户、启动 mysqld。

问题 / 场景

问：为什么必须设置 MYSQL_ROOT_PASSWORD？

  • MySQL 官方镜像设计上要求必须设置 root 密码，否则容器启动时会报错退出。这是出于安全考虑，避免无意中暴露无密码的数据库。

问：如何自动创建数据库和用户？

  • 用环境变量 MYSQL_DATABASE=ctts 自动创建 ctts 数据库；用 MYSQL_USER=ctts + MYSQL_PASSWORD=ctts123 自动创建用户 ctts 并授予 ctts 数据库的所有权限。

问：容器删除后数据还在吗？

  • 不在。本次课为了简化操作不配置数据卷，容器删除后数据丢失。第 10 次课会学习数据卷持久化。本次课的操作可重复执行，但每次重启容器数据会丢失（除非用 docker stop/docker start 而非 docker rm）。

完整示例

操作步骤 1：运行 MySQL 容器

# 运行 MySQL 容器
# 参数说明：
#   -d                  后台运行
#   --name ctts-mysql   容器命名为 ctts-mysql
#   -p 3306:3306        宿主机 3306 端口映射到容器 3306 端口
#   -e MYSQL_ROOT_PASSWORD=123456  设置 root 密码（必填）
#   -e MYSQL_DATABASE=ctts         自动创建 ctts 数据库
#   mysql:8.0           使用的镜像
docker run -d \
  --name ctts-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -e MYSQL_DATABASE=ctts \
  mysql:8.0

# 预期输出（容器 ID，64 位十六进制）：
# 7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a

操作步骤 2：检查容器运行状态

# 查看运行中的容器
docker ps
# 预期输出：
# CONTAINER ID   IMAGE       COMMAND                  STATUS              PORTS                              NAMES
# 7f8a9b0c1d2e   mysql:8.0   "docker-entrypoint.s…"   Up 10 seconds       0.0.0.0:3306->3306/tcp, 33060/tcp  ctts-mysql

# 查看 MySQL 容器日志（确认 MySQL 已启动）
docker logs ctts-mysql

将以下 SQL 保存为宿主机文件 ctts-init.sql（用任意文本编辑器创建）：

-- CTTS 数据库初始化脚本
USE ctts;

-- 用户表
CREATE TABLE IF NOT EXISTS `t_user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `username` VARCHAR(50) NOT NULL COMMENT '用户名',
  `password` VARCHAR(100) NOT NULL COMMENT '密码',
  `real_name` VARCHAR(50) DEFAULT NULL COMMENT '真实姓名',
  `role` VARCHAR(20) NOT NULL DEFAULT 'student' COMMENT '角色：admin/teacher/student',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='CTTS 用户表';

-- 试题表
CREATE TABLE IF NOT EXISTS `t_question` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '试题ID',
  `title` VARCHAR(200) NOT NULL COMMENT '题目标题',
  `content` TEXT COMMENT '题目内容',
  `type` VARCHAR(20) NOT NULL COMMENT '题型：single/multiple/judge',
  `difficulty` TINYINT NOT NULL DEFAULT 1 COMMENT '难度：1-5',
  `answer` VARCHAR(500) COMMENT '答案',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`)

常见报错排查

报错 1：容器启动后立即退出

docker ps -a   # 看到 ctts-mysql 状态是 Exited (1)
docker logs ctts-mysql
# 报错：[ERROR] [Entrypoint]: MYSQL_ROOT_PASSWORD not set

原因：未设置 MYSQL_ROOT_PASSWORD 环境变量。 解决：删除容器重新运行，加上 -e MYSQL_ROOT_PASSWORD=123456。

docker rm ctts-mysql
docker run -d --name ctts-mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 -e MYSQL_DATABASE=ctts mysql:8.0

报错 2：端口 3306 被占用

docker: Error response from daemon: driver failed programming external connectivity on endpoint ctts-mysql: Bind for 0.0.0.0:3306 failed: port is already allocated.

原因：宿主机 3306 端口已被占用（可能是宿主机本地装的 MySQL）。 解决：换一个宿主机端口，如 -p 3307:3306（宿主机 3307 → 容器 3306）。

docker rm ctts-mysql
docker run -d --name ctts-mysql -p 3307:3306 -e MYSQL_ROOT_PASSWORD=123456 -e MYSQL_DATABASE=ctts mysql:8.0
# 连接时用 mysql -h127.0.0.1 -P3307 -uroot -p123456

报错 3：连接 MySQL 报 "Access denied"

ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: YES)

原因：密码输入错误，或 MySQL 还没完全启动。 解决：

  1. 确认密码与 MYSQL_ROOT_PASSWORD 一致。
  2. 用 docker logs ctts-mysql 查看 MySQL 是否已 "ready for connections"。
  3. 等待 10~20 秒后重试。

报错 4：执行 SQL 时中文乱码

ERROR 1366 (HY000): Incorrect string value: '\xE5\xBC\xA0\xE8\x80\x81...' for column 'real_name'

原因：表字符集不是 utf8mb4。 解决：建表时指定 DEFAULT CHARSET=utf8mb4（本脚本的 CREATE TABLE 已包含）。已建的表可手动修改：

ALTER DATABASE ctts CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE t_user CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

易错点

  1. ❌ 忘记设置 MYSQL_ROOT_PASSWORD，容器启动失败。✅ 必须设置该环境变量。
  2. ❌ 容器刚启动就连接，报 "Can't connect to MySQL server"。✅ 等待 10~20 秒，看日志 "ready for connections" 后再连。
  3. ❌ 用 docker exec -it 配合 < 重定向。✅ 重定向用 docker exec -i（不带 -t），否则会报错。
  4. ❌ 删除容器后想找回数据。✅ 本次课未配置数据卷，容器删除数据即丢失；如需保留，用 docker stop/docker start 而非 docker rm。

小结

K5-2 完成了 MySQL 容器的运行与 CTTS 数据库初始化。核心命令是 docker run 配合环境变量启动 MySQL，用 docker exec -i < ctts-init.sql 执行 SQL 脚本。注意：必须设置 root 密码、等待启动完成、用 -i 而非 -it 配合重定向。

知识点 K5-3：Nginx 容器运行与静态页面部署

定义

Nginx 容器部署静态页面 是用 nginx:stable 镜像启动 Nginx 容器，通过 -v 挂载宿主机的 HTML 文件到容器的默认 Web 根目录 /usr/share/nginx/html，从而部署 CTTS 前端简易首页的过程。

原理

Nginx 官方镜像的关键设计：

  1. 默认 Web 根目录：/usr/share/nginx/html，Nginx 默认从这里提供静态文件服务。
  2. 默认配置文件：/etc/nginx/conf.d/default.conf，定义了监听 80 端口、根目录指向 /usr/share/nginx/html、默认首页 index.html。
  3. 暴露端口：80（HTTP）。
  4. 入口命令：nginx -g 'daemon off;'，以前台模式运行 Nginx（容器需要前台进程才能保持运行）。

数据挂载（Volume Mount）原理：

  • -v 宿主机路径:容器路径 将宿主机的文件/目录挂载到容器内对应位置。
  • 挂载后，容器内看到的就是宿主机的文件，修改宿主机文件容器内立即生效。
  • 这是容器与宿主机共享文件的核心机制（第 10 次课详讲）。

问题 / 场景

问：为什么要用 -v 挂载，不直接把 HTML 文件构建进镜像？

  • 学习阶段用挂载便于修改：改宿主机 HTML 文件，容器内立即生效，刷新浏览器就能看到变化。生产环境通常把 HTML 构建进自定义镜像（第 8 次课 Dockerfile 实践会做）。

问：为什么挂载到 /usr/share/nginx/html 而不是别的路径？

  • 这是 Nginx 官方镜像的默认 Web 根目录，由 /etc/nginx/conf.d/default.conf 配置。挂载到这里，Nginx 自动提供文件服务，无需改配置。

问：挂载后访问 403 Forbidden 是怎么回事？

  • 通常是宿主机的 HTML 文件权限不足，或挂载路径错误（宿主机文件不存在）。检查：宿主机文件是否存在、文件权限是否可读。

知识点 K5-4：Java/OpenJDK 镜像与简单 Java 应用运行

定义

OpenJDK 容器运行 Java 应用 是用 openjdk:17-jdk-slim 镜像启动 Java 容器，运行简单 jar 包或验证 Java 环境的过程。CTTS 后端（SpringBoot）就是基于 Java 运行的，本次课先验证 Java 容器环境，第 8 次课再构建完整的 CTTS 后端镜像。

原理

OpenJDK 官方镜像的关键设计：

  1. JDK vs JRE：JDK 含编译工具（javac），体积大；JRE 只能运行，体积小。运行 jar 用 JRE 即可，开发调试用 JDK。
  2. slim 变体：基于 Debian slim，体积比完整版小（~400MB vs ~600MB）。
  3. Java 命令路径：/usr/local/openjdk-17/bin/java。
  4. 工作目录：默认 /，通常通过 -w 参数或 Dockerfile 的 WORKDIR 指定。

问题 / 场景

问：为什么用 openjdk:17-jdk-slim 而不是 openjdk:17？

  • slim 版本去除了不必要的文档和工具，体积小约 200MB，下载快、攻击面小。学习阶段 JDK 便于编译调试。

问：如何把 jar 包运行到容器里？

  • 两种方式：
    1. 挂载方式（学习阶段）：docker run -v ~/ctts/app.jar:/app/app.jar openjdk:17-jdk-slim java -jar /app/app.jar
    2. 构建镜像方式（生产环境，第 8 次课）：写 Dockerfile，COPY app.jar，CMD ["java", "-jar", "app.jar"]。

问：openjdk 官方镜像为什么被弃用？

  • Docker Hub 官方说明 openjdk 镜像不再更新到最新版本（停在 18），推荐使用 eclipse-temurin、amazoncorretto、azul/zulu-openjdk 等替代镜像。本课程学习用 openjdk:17 仍可用，生产建议迁移。

知识点 K5-5：容器间通信验证

定义

容器间通信 是指多个 Docker 容器之间通过网络进行互相访问的能力。本次课使用 --link 实现简单通信验证，并理解其局限性，为第 9 次课的 Docker 网络专题埋下伏笔。

原理

--link 机制：

  • docker run --link <目标容器名>:<别名> 让新容器能通过"别名"访问目标容器。
  • 原理：Docker 在新容器的 /etc/hosts 中添加一条记录，把目标容器的 IP 映射到别名。
  • 这是 Docker 早期的容器通信方案，已被官方标记为 legacy（过时），现代做法是用自定义网络（第 9 次课详讲）。

容器间通信的三种方式（概览）：

  1. 默认 bridge 网络：容器间只能通过 IP 通信，不能用容器名（每次重启 IP 可能变）。
  2. --link：通过容器名通信，但只能单向、已过时。
  3. 自定义网络（推荐）：创建一个自定义 bridge 网络，加入该网络的所有容器都能用容器名互相通信，双向、稳定。

问题 / 场景

问：为什么 --link 是过时的？

  • --link 是单向的（A link B，A 能访问 B，但 B 不能访问 A）；重启容器后可能失效；不支持容器别名动态更新。官方推荐用自定义网络替代。

问：那本次课为什么还要学 --link？

  • --link 机制简单，便于初学者理解"容器间如何通过名字通信"的概念。理解了 --link，再学自定义网络就更容易。同时，一些老旧文档和教程仍用 --link，了解它有助于阅读历史资料。

问：容器间能直接 ping 通吗？

  • 默认 bridge 网络下，容器间可以 ping 通 IP，但不能 ping 通容器名（除非用 --link 或自定义网络）。

  --link ctts-mysql:mysql \

常见报错排查

报错 1：--link 找不到目标容器

docker: Error response from daemon: Cannot link to /ctts-mysql, as it does not belong to the default network.

原因：目标容器不存在，或不在默认网络中。 解决：先确认目标容器在运行：docker ps，确保 ctts-mysql 存在。

报错 2：容器内 ping 命令找不到

bash: ping: command not found

原因：精简镜像默认不含 ping 工具。 解决：在容器内安装：apt-get update && apt-get install -y iputils-ping。

易错点

  1. ❌ 误以为 --link 是双向的。✅ --link 是单向的，A link B，只有 A 能找 B，B 找不到 A。
  2. ❌ 误以为 --link 是现代做法。✅ --link 已被官方标记为 legacy，现代做法是自定义网络（第 9 次课）。
  3. ❌ 在容器内 ping 不通容器名，以为是网络问题。✅ 默认 bridge 网络不支持容器名解析，需要 --link 或自定义网络。

小结

K5-5 用 --link 实现了容器间的基本通信验证。--link 是 Docker 早期的单向通信方案，已过时，理解它有助于学习自定义网络。第 9 次课会学习自定义 bridge 网络，实现容器的双向、稳定通信。

知识点 K5-6：综合实践复盘与常见问题排查

定义

容器踩坑复盘 是对本次实践课操作中遇到的问题进行汇总、分析、总结的过程。容器化运维的核心能力之一就是故障排查——遇到问题先看日志、查状态、定位原因，而非盲目重装。

原理

容器故障排查的标准流程：

图示 5：容器故障排查五步法

docker ps -a 查看容器状态（是否 Exited、Exit Code 是多少）

docker logs 查看容器日志（应用报错信息）

docker inspect 查看容器详细信息（网络、挂载、状态）

docker exec -it bash 进入容器排查（文件是否存在、命令能否执行）

定位原因 → 修复 → 重新运行

常见问题分类与解决：

问题类型 典型表现 排查方法 解决方案
容器无法启动 docker ps 看不到，docker ps -a 显示 Exited docker logs <容器名> 看报错 根据报错修复（环境变量、配置等）
端口冲突 Bind for 0.0.0.0:80 failed: port is already allocated netstat -tlnp | grep :80 查占用进程 换宿主机端口，或停止占用进程
数据丢失 容器删除后数据没了 确认是否用了数据卷 用 -v 挂载数据卷（第 10 次课）
容器间通信失败 ping 不通、连接超时 检查是否在同一网络、是否用 --link 用自定义网络（第 9 次课）
中文乱码 SQL 插入中文报错、页面显示乱码 检查字符集设置 建表用 utf8mb4，连接加 ?characterEncoding=utf8
命令找不到 bash: xxx: command not found 容器是精简镜像，不含该命令 apt-get install 安装，或换完整版镜像
挂载路径错误 容器内文件不存在、403 docker exec 进容器 ls 检查 用绝对路径，确认宿主机文件存在

问题 / 场景

问：容器启动后立即退出，怎么排查？

  • 三步：
    1. docker ps -a 看 Exit Code（0 是正常退出，非 0 是异常）。
    2. docker logs <容器名> 看应用报错。
    3. 根据报错定位：环境变量缺失、配置文件错误、依赖服务连不上等。

问：MySQL 容器为什么总是启动很慢？

  • MySQL 首次启动要初始化数据库（创建系统表、ctts 库等），约 10~20 秒。看日志出现 "ready for connections" 才算就绪。

问：如何避免端口冲突？

  • 用 netstat -tlnp | grep :端口号 检查端口占用，或换一个不常用的端口（如 3307、8080、8888）。

完整示例

复盘案例 1：MySQL 容器忘记设密码

# 学生操作：忘记加 -e MYSQL_ROOT_PASSWORD
docker run -d --name ctts-mysql -p 3306:3306 mysql:8.0

# 检查状态
docker ps -a
# 看到 ctts-mysql 状态是 Exited (1)

# 查看日志
docker logs ctts-mysql
# 报错：[ERROR] [Entrypoint]: MYSQL_ROOT_PASSWORD not set
#        [ERROR] [Entrypoint]: A password is needed for user 'root'

# 解决：删除容器，重新运行（加密码）
docker rm ctts-mysql
docker run -d --name ctts-mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 -e MYSQL_DATABASE=ctts mysql:8.0

复盘案例 2：Nginx 端口 80 被占用

# 学生操作：80 端口被宿主机 Apache 占用
docker run -d --name ctts-nginx -p 80:80 -v ~/ctts/nginx-html:/usr/share/nginx/html nginx:stable
# 报错：Bind for 0.0.0.0:80 failed: port is already allocated

# 排查：检查 80 端口占用
sudo netstat -tlnp | grep :80
# 输出：tcp6 0 0 :::80 :::* LISTEN 1234/apache2

# 解决：换宿主机端口 8080
docker rm -f ctts-nginx
docker run -d --name ctts-nginx -p 8080:80 -v ~/ctts/nginx-html:/usr/share/nginx/html nginx:stable
# 访问 http://localhost:8080

复盘案例 3：MySQL 数据丢失

# 学生操作：删除 MySQL 容器后重建，发现 ctts 库没了
docker rm -f ctts-mysql
docker run -d --name ctts-mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=123456 -e MYSQL_DATABASE=ctts mysql:8.0

docker exec ctts-mysql mysql -uroot -p123456 -e "SHOW DATABASES;"
# ctts 库还在（因为是新建的），但里面的 t_user、t_question 表没了！

# 原因：未配置数据卷，容器删除后 /var/lib/mysql 的数据丢失
# 解决（第 10 次课详讲）：用 -v 挂载数据卷
docker rm -f ctts-mysql
mkdir -p ~/ctts/mysql-data
docker run -d --name ctts-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -e MYSQL_DATABASE=ctts \
  -v ~/ctts/mysql-data:/var/lib/mysql \
  mysql:8.0
# 这样即使容器删除，数据还在 ~/ctts/mysql-data 目录

复盘案例 4：容器间通信失败

# 学生操作：Nginx 容器想访问 MySQL，但没加 --link
docker exec -it ctts-nginx bash
# 在容器内：
ping ctts-mysql
# ping: ctts-mysql: Name or service not known

# 原因：默认 bridge 网络不支持容器名解析
# 解决 1：加 --link（单向，legacy）
docker rm -f ctts-nginx
docker run -d --name ctts-nginx -p 80:80 -v ~/ctts/nginx-html:/usr/share/nginx/html --link ctts-mysql:mysql nginx:stable

# 解决 2（推荐，第 9 次课）：用自定义网络
docker network create ctts-net
docker network connect ctts-net ctts-mysql
docker network connect ctts-net ctts-nginx
# 这样两个容器都能用名字互相访问

三、综合示例：CTTS 三服务容器化完整操作流程

把 K5-1 到 K5-6 串起来，CTTS 三服务容器化的完整操作流程：

# === 步骤 1：准备工作目录 ===
mkdir -p ~/ctts/nginx-html ~/ctts/java-app ~/ctts/mysql-data
cd ~/ctts

# === 步骤 2：拉取三个镜像（K5-1） ===
docker pull mysql:8.0
docker pull nginx:stable
docker pull openjdk:17-jdk-slim
docker images  # 确认三个镜像已拉取

# === 步骤 3：运行 MySQL 容器并初始化数据库（K5-2） ===
docker run -d \
  --name ctts-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -e MYSQL_DATABASE=ctts \
  -v ~/ctts/mysql-data:/var/lib/mysql \
  mysql:8.0

# 等待 MySQL 启动
for i in $(seq 1 30); do
  docker exec ctts-mysql mysqladmin ping -uroot -p123456 --silent 2>/dev/null && break
  echo "Waiting for MySQL... ($i)"
  sleep 2
done

# 初始化 CTTS 数据库表（ctts-init.sql 见 K5-2）
docker exec -i ctts-mysql mysql -uroot -p123456 < ctts-init.sql
docker exec ctts-mysql mysql -uroot -p123456 -e "USE ctts; SHOW TABLES;"

# === 步骤 4：运行 Nginx 容器部署静态页面（K5-3） ===
# 确保 ~/ctts/nginx-html/index.html 已创建（见 K5-3）
docker run -d \
  --name ctts-nginx \
  -p 80:80 \
  -v ~/ctts/nginx-html:/usr/share/nginx/html \
  --link ctts-mysql:mysql \
  nginx:stable

# 验证 Nginx
curl http://localhost

# === 步骤 5：运行 Java 容器验证环境（K5-4） ===
# 确保 ~/ctts/java-app/HelloCTTS.java 已创建（见 K5-4）
docker run --rm -v ~/ctts/java-app:/app -w /app openjdk:17-jdk-slim javac HelloCTTS.java
docker run --rm -v ~/ctts/java-app:/app -w /app openjdk:17-jdk-slim java HelloCTTS

# === 步骤 6：容器间通信验证（K5-5） ===
docker exec -it ctts-nginx bash
# 在容器内：
getent hosts mysql
exit

# === 步骤 7：检查所有容器状态 ===
docker ps
# 预期：看到 ctts-mysql 和 ctts-nginx 两个运行中的容器

# === 清理（可选，课后练习） ===
# docker stop ctts-mysql ctts-nginx
# docker rm ctts-mysql ctts-nginx

这个完整流程体现了 CTTS 三服务容器化的操作链：镜像准备 → MySQL 容器+初始化 → Nginx 容器+静态页面 → Java 容器+环境验证 → 容器通信。每个步骤都有明确的预期输出和排查方法。
