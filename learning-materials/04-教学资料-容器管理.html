二、知识点详解

知识点 K4-1：容器生命周期概述

定义

容器生命周期（Container Lifecycle） 指容器从创建到删除的完整过程，包含若干状态：created（已创建）、running（运行中）、paused（已暂停）、exited（已退出）、dead（死亡）。

容器生命周期的核心命令：

命令 作用 状态变化
docker create 创建容器但不启动 → created
docker run 创建并启动容器 → running
docker start 启动已停止的容器 exited → running
docker stop 优雅停止容器（发 SIGTERM，超时后 SIGKILL） running → exited
docker restart 重启容器（先 stop 再 start） running → exited → running
docker pause 暂停容器（冻结进程，不释放内存） running → paused
docker unpause 恢复暂停的容器 paused → running
docker kill 强制终止容器（直接发 SIGKILL） running → exited
docker rm 删除容器（必须先停止） exited → 删除

原理

容器状态流转图：

                    docker create
                         │
                         ▼
                    ┌─────────┐
       docker start │ created │  (创建后未启动)
        ┌──────────▶│         │
        │           └─────────┘
        │                │ docker run (create+start)
        │                ▼
        │           ┌─────────┐
        │           │ running │  (运行中)
        │  ┌───────▶│         │◀───────┐
        │  │        └─────────┘        │
        │  │ docker     │    ▲         │ docker unpause
        │  │ start      │    │ docker  │
        │  │            │    │ pause   │
        │  │     ┌──────▼────┴───┐     │
        │  │     │    paused      │─────┘
        │  │     │  (进程冻结)    │
        │  │     └────────────────┘
        │  │
        │  │ docker stop / kill (主进程退出)
        │  │
        │  ▼
        │ ┌─────────┐
        └─│ exited  │  (已退出但容器仍在)
          │         │
          └─────────┘
                │ docker rm
                ▼
             [容器删除]

注：docker restart = docker stop + docker start

关键状态说明：

状态 含义 是否占用内存 是否能再次启动
created 已创建未启动 否 是（docker start）
running 运行中 是 —
paused 进程被冻结 是（内存保留） 是（docker unpause）
exited 已停止（主进程退出） 否 是（docker start）
dead 异常状态（极少出现） 否 通常需 rm 后重建

问题 / 场景

问：docker stop 和 docker kill 有什么区别？

  • docker stop 先发 SIGTERM 信号，让主进程优雅退出（如保存数据、关闭连接），10 秒后仍未退出才发 SIGKILL 强制终止。生产中推荐用 stop。
  • docker kill 直接发 SIGKILL，立即强制终止，主进程没有机会做清理工作。可能导致数据丢失，仅在 stop 无效时使用。

问：docker pause 和 docker stop 有什么区别？

  • pause 冻结进程（cgroups freezer），内存保留，恢复后继续运行，适合临时挂起；stop 完全停止进程，内存释放，恢复时相当于重新启动。pause 比 stop 更快恢复。

问：容器 exited 后还能再启动吗？

  • 能。docker start 容器名 即可重新启动。exited 只是主进程退出了，容器的文件系统、配置等仍在。除非 docker rm 删除容器，否则可以反复启停。

问：能不能直接 rm 一个运行中的容器？

  • 不能。会报错 Error: cannot remove a running container。需要先 docker stop 再 docker rm，或加 -f 参数强制删除（docker rm -f，等价于 kill + rm，生产慎用）。

完整示例

# 1. 创建一个容器（不启动）
docker create --name mynginx nginx
# 输出：a1b2c3d4e5f6...（容器 ID）

# 2. 查看所有容器（包括未启动的）
docker ps -a
# CONTAINER ID   IMAGE   STATUS        NAMES
# a1b2c3d4e5f6   nginx   Created       mynginx

# 3. 启动容器
docker start mynginx
# mynginx

# 4. 查看运行中的容器
docker ps
# CONTAINER ID   IMAGE   STATUS         NAMES
# a1b2c3d4e5f6   nginx   Up 5 seconds   mynginx

# 5. 停止容器（优雅停止）
docker stop mynginx
# mynginx

# 6. 再次启动
docker start mynginx

# 7. 重启
docker restart mynginx

# 8. 删除容器（先停止）
docker stop mynginx
docker rm mynginx
# mynginx

基于镜像生成容器配置和可写层，但主进程尚未运行。

docker restart = stop + start，用于重启主进程。
docker rm -f = kill + rm，适合强制清理异常容器。

易错点

  1. ❌ 误认为"容器 exited 就是删除了"。✅ exited 只是停止，容器仍存在（docker ps -a 可见），需 docker rm 才真正删除。
  2. ❌ 误认为"docker kill 和 docker stop 等价"。✅ stop 优雅退出，kill 强制终止，可能丢数据。
  3. ❌ 误认为"运行中的容器可以直接 rm"。✅ 不能，必须先 stop 或加 -f 强制。
  4. ❌ 误认为"docker run 和 docker start 相同"。✅ run 是 create+start（新容器），start 是启动已存在的停止容器。
  5. ❌ 误认为"pause 后内存会释放"。✅ pause 冻结进程但保留内存，stop 才释放内存。

小结

容器生命周期包括创建、运行、暂停、停止、删除等状态，每一步都有对应命令。重点掌握：docker run（创建并启动）、docker stop（优雅停止）、docker start（重启已停止的）、docker rm（删除）。理解 stop 与 kill、pause 与 stop 的区别是运维必备知识。

知识点 K4-2：docker run 核心参数

定义

docker run 是 Docker 最核心的命令之一，用于基于镜像创建并启动一个新容器。其完整语法：

docker run [OPTIONS] IMAGE [COMMAND] [ARG...]

常用参数：

参数 全称 作用 示例
-d --detach 后台运行容器 docker run -d nginx
--name — 给容器命名 docker run --name myweb nginx
-p --publish 端口映射 hostPort:containerPort docker run -p 8080:80 nginx
-P --publish-all 随机映射所有暴露端口 docker run -P nginx
-e --env 设置环境变量 docker run -e MYSQL_ROOT_PASSWORD=123456 mysql
-v --volume 挂载数据卷或绑定挂载 docker run -v /data:/var/lib/mysql mysql
--rm — 容器退出后自动删除 docker run --rm alpine echo hi
-it -i + -t 交互式终端（常用于进入容器） docker run -it alpine sh
--restart — 重启策略 docker run --restart=always nginx
-w --workdir 设置工作目录 docker run -w /app nginx

原理

docker run 的执行过程（K1-4 中讲过的架构，这里细化）：

docker run nginx
    │
    ▼
1. docker CLI 把命令通过 REST API 发给 dockerd
2. dockerd 检查本地是否有 nginx 镜像
   ├── 有 → 直接用
   └── 无 → docker pull 自动拉取
3. dockerd 在镜像之上创建一个可写层（容器层）
4. dockerd 准备命名空间、cgroups 等隔离环境
5. dockerd 调用 containerd → runC 真正启动容器进程
6. 容器主进程启动（如 nginx 的 master process）
7. 返回容器 ID 给客户端

前台运行 vs 后台运行（-d）：

图示 2：前台运行与后台运行的差异
不加 -d

前台运行

  • docker run nginx
  • 终端被 nginx 日志占据。
  • Ctrl+C 会把中断信号发给主进程。
  • 主进程退出后，容器随之退出。
加 -d

后台运行

  • docker run -d nginx
  • 命令立即返回容器 ID。
  • 终端可继续执行其它命令。
  • 容器在后台持续运行，日志用 docker logs 查看。

端口映射（-p）原理：

docker run -p 8080:80 nginx

宿主机                  Docker 进程               容器
┌──────────┐         ┌──────────────┐         ┌──────────┐
│ 客户端    │         │ docker-proxy │         │ nginx    │
│ 浏览器    │ ──────▶ │ 监听 0.0.0.0:│ ──────▶ │ 监听 :80 │
│ 访问      │ :8080   │ 8080         │ 转发     │          │
│ localhost │         │              │         │          │
│ :8080     │         └──────────────┘         └──────────┘
└──────────┘

含义：宿主机的 8080 端口 → 容器的 80 端口
访问 http://宿主机IP:8080 即可访问容器内的 nginx

-p 的四种写法：

# 1. 指定 hostPort:containerPort（最常用）
docker run -p 8080:80 nginx
# 宿主机 8080 → 容器 80

# 2. 指定 IP:hostPort:containerPort
docker run -p 127.0.0.1:8080:80 nginx
# 只允许本机访问

# 3. 指定 hostPort:containerPort/protocol
docker run -p 8080:80/tcp nginx
# 显式指定 TCP（默认）

# 4. 只指定 containerPort，hostPort 随机分配
docker run -p 80 nginx
# 宿主机随机选一个高位端口（如 32768）映射到容器 80

-e 环境变量原理：

docker run -e MYSQL_ROOT_PASSWORD=123456 mysql:8.0

容器内：
   主进程（mysqld）
   └── 可以通过环境变量读取：
       MYSQL_ROOT_PASSWORD=123456

很多官方镜像（mysql、postgres、redis）都通过 -e 接收初始化配置：
   -e MYSQL_ROOT_PASSWORD=...    MySQL root 密码
   -e MYSQL_DATABASE=...         自动创建的数据库
   -e MYSQL_USER=...             自动创建的用户
   -e POSTGRES_PASSWORD=...      PostgreSQL 密码
   -e REDIS_PASSWORD=...         Redis 密码

问题 / 场景

问：为什么 -p 是"宿主端口:容器端口"而不是反过来？

  • Docker 的约定是"宿主:容器"（host:container），所有映射类参数（-p、-v）都是这个方向。记忆口诀："外:内"——外部（宿主机）的端口映射到内部（容器）的端口。

问：-d 后台运行后，怎么查看容器的输出日志？

  • 用 docker logs 容器名 查看（详见 K4-4）。后台运行的容器，stdout/stderr 会被 Docker 接管并存储，可通过 logs 命令查看。

问：--rm 什么时候用？

  • 适合"一次性任务"容器，如运行测试、执行脚本、临时调试。容器退出后自动删除，避免堆积无用容器。例如：docker run --rm alpine echo hello，输出 hello 后容器自动删除。

问：-it 和 -d 可以一起用吗？

  • 一般不一起用。-it 是交互式前台，-d 是后台，语义冲突。进入容器调试用 docker exec -it（详见 K4-4）。

完整示例

# 示例 1：运行 hello-world（一次性）
docker run hello-world
# 输出：
# Hello from Docker!
# This message shows that your installation appears to be working correctly.
# ...

# 示例 2：后台运行 nginx 并命名
docker run -d --name myweb nginx
# 输出容器 ID：a1b2c3d4e5f6...

# 示例 3：端口映射运行 nginx
docker run -d --name myweb -p 8080:80 nginx
# 访问 http://localhost:8080 可以看到 nginx 默认页面
# 输出：a1b2c3d4e5f6...

# 示例 4：环境变量运行 MySQL
docker run -d --name mydb \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  mysql:8.0
# 输出：b2c3d4e5f6a1...

# 示例 5：数据卷 + 环境变量运行 MySQL（生产推荐）
docker run -d --name mydb \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v /data/mysql:/var/lib/mysql \
  mysql:8.0
# /data/mysql 是宿主机目录，/var/lib/mysql 是容器内 MySQL 数据目录

# 示例 6：--rm 一次性容器
docker run --rm alpine echo "Hello Docker"
# 输出：Hello Docker
# 容器退出后自动删除（docker ps -a 看不到）

# 示例 7：-it 交互式进入 alpine
docker run -it alpine sh
# 进入 alpine 容器的 sh 终端
# / # ls
# bin    etc    lib    mnt    proc   run    srv    tmp    var
# dev    home   media  opt    root   sbin   sys    usr
# / # exit  ← 退出后容器自动停止

# 示例 8：覆盖默认命令
docker run -it alpine echo "Hello"
# 不进入 sh，直接执行 echo 后退出

# 示例 9：重启策略
docker run -d --name myweb --restart=always nginx
# 容器退出或宿主机重启后自动重启容器
# 重启策略：no（默认）/ on-failure / always / unless-stopped

参数方向记忆：所有映射都是"外:内"（host:container）
   -p 8080:80    → 宿主 8080 → 容器 80
   -v /h:/c      → 宿主 /h   → 容器 /c

易错点

  1. ❌ 误认为 -p 8080:80 是"容器 8080 → 宿主 80"。✅ 是"宿主 8080 → 容器 80"，方向是 host:container。
  2. ❌ 误认为 -d 后容器日志会显示在终端。✅ -d 后终端只返回容器 ID，日志要用 docker logs 查看。
  3. ❌ 忘记 --name，导致容器名随机生成（如 nostalgic_einstein）。✅ 生产中应规范命名（如 ctts-mysql），便于管理。
  4. ❌ 误认为 -e 设置的环境变量在容器外可见。✅ 环境变量只在容器内可见，宿主机看不到。
  5. ❌ 误认为 --rm 会清理所有数据。✅ --rm 只删容器本身，挂载的数据卷不会被删。
  6. ❌ 多次执行同一条带 --name 的 docker run 报"容器名冲突"。✅ 同名容器只能有一个，需先 docker rm 旧的。

小结

docker run 是创建并启动容器的核心命令，常用参数：-d（后台）、--name（命名）、-p（端口映射 host:container）、-e（环境变量）、-v（数据卷）、--rm（退出自动清理）、-it（交互式）。所有映射类参数方向都是"外:内"。生产中推荐组合使用：docker run -d --name <name> -p <host>:<container> -e <KEY>=<VAL> -v <host>:<container> <image>。

知识点 K4-3：容器查看与管理

定义

容器查看与管理命令用于监控和操作已存在的容器：

命令 作用
docker ps 列出运行中的容器
docker ps -a 列出所有容器（包括已停止）
docker stats 实时显示容器资源占用（CPU/内存/网络/IO）
docker top <容器> 查看容器内的进程列表

原理

docker ps 输出字段：

$ docker ps
CONTAINER ID   IMAGE   COMMAND                  CREATED        STATUS        PORTS                  NAMES
a1b2c3d4e5f6   nginx   "/docker-entrypoint.…"   5 minutes ago  Up 5 minutes  0.0.0.0:8080->80/tcp   myweb

字段说明：
- CONTAINER ID：容器唯一 ID（前 12 位）
- IMAGE：所用镜像
- COMMAND：容器主进程启动命令
- CREATED：创建时间
- STATUS：状态（Up X minutes 表示运行中；Exited X minutes ago 表示已停止）
- PORTS：端口映射
- NAMES：容器名（未指定则随机生成）

docker ps 常用选项：

docker ps              # 运行中的容器
docker ps -a           # 所有容器（含已停止）
docker ps -q           # 只显示容器 ID（脚本用）
docker ps -n 5         # 显示最近 5 个容器
docker ps --filter "name=web"     # 按名字过滤
docker ps --filter "status=exited" # 按状态过滤
docker ps --format "table {{.Names}}\t{{.Status}}"  # 自定义格式

docker stats 资源监控：

$ docker stats
CONTAINER ID   NAME    CPU %   MEM USAGE / LIMIT   MEM %   NET I/O         BLOCK I/O
a1b2c3d4e5f6   myweb   0.50%   20MiB / 1.95GiB     1.00%   5kB / 3kB       8kB / 0B
b2c3d4e5f6a1   mydb    2.30%   350MiB / 1.95GiB    17.50%  1.2kB / 850B    45MB / 12MB

按 Ctrl+C 退出实时监控

docker top 查看进程：

$ docker top myweb

- PID：宿主机视角的进程 ID
- PPID：父进程 ID

问题 / 场景

问：docker ps 和 docker ps -a 的区别？

  • docker ps 只显示运行中的容器（status 为 Up）；docker ps -a 显示所有容器，包括已停止的（Exited）。排查问题时常用 -a 看历史容器。

问：容器 ID 和容器名有什么区别？

  • 每个 Docker 会自动给容器分配一个 64 位十六进制 ID（如 a1b2c3...），并用 docker ps 显示前 12 位。容器名是用户可读的（如 myweb），用 --name 指定或自动生成。两者都能唯一标识容器，命令中可互换使用。

问：docker stats 显示的内存限制是什么？

  • 默认是宿主机总内存。可通过 docker run -m 512m 给容器设置内存限制。生产中建议每个容器都设置内存限制，防止一个容器吃光宿主机内存。

问：docker top 显示的 PID 是容器内的还是宿主机的？

  • 是宿主机视角的 PID。因为容器本质是宿主机的进程，只是在 namespace 中隔离。这就是"容器是进程级隔离"的体现。

知识点 K4-4：容器日志与进入

定义

容器日志查看和进入容器是日常排障的两大核心能力：

命令 作用
docker logs <容器> 查看容器主进程的 stdout/stderr 输出
docker logs -f <容器> 实时跟踪日志（类似 tail -f）

docker exec -it <容器> <命令> 在运行中的容器内执行新命令（开新进程）

exec 会话

进入容器后得到的是新的 shell，不会替代主进程。

问题 / 场景

问：为什么生产中几乎都用 exec 不用 attach？

  • attach 直接连接主进程，Ctrl+c 或 exit 会导致容器停止，风险大；exec 开新进程，退出不影响容器。生产排障几乎都用 docker exec -it <容器> bash。

问：docker logs 看不到日志怎么办？

  • 检查：① 容器是否在运行（docker ps）；② 应用是否把日志输出到 stdout/stderr（如果只写文件，logs 看不到，需进入容器看文件）；③ 日志驱动是否是 json-file（默认是）。

问：进入容器后想退出但不停止容器，怎么做？

  • 如果是 exec 进入的，直接 exit 即可，容器继续运行。如果是 attach 进入的，按 Ctrl+p 然后 Ctrl+q（detach keys）脱离，容器继续运行。

问：如何查看容器某个时间段的日志？

  • docker logs --since 30m <容器>（最近 30 分钟）；docker logs --since 2026-07-22T10:00:00 <容器>（指定时间起）；docker logs --until 2026-07-22T11:00:00 <容器>（指定时间止）。

易错点

问题 / 场景

问：为什么 docker inspect 输出是数组？

  • 因为 inspect 可以传多个参数（多个容器/镜像），输出对应数组。即使只查一个，也是数组的第一个元素。

问：端口映射为什么需要 docker-proxy？

  • docker-proxy 是用户态进程，监听宿主机端口并转发到容器。这是为了在 iptables 规则未生效时也能工作。实际生产中主要靠 iptables NAT 规则转发（性能更好），docker-proxy 是兜底方案。

问：-p 8080:8080 和 -p 8080:80 有什么区别？

  • 前者宿主 8080 → 容器 8080（端口号相同）；后者宿主 8080 → 容器 80（端口号不同）。端口号可以相同也可以不同，看应用监听什么端口。如 nginx 默认监听 80，mysql 默认监听 3306。

问：宿主机 80 端口被占用，怎么映射？

  • 换一个宿主机端口，如 -p 8080:80。如果宿主机 8080 也被占用，就再换一个（如 8888）。容器端口不变（必须与应用监听端口一致）。

问：-P 随机端口有什么用？

  • 用于快速测试、不关心具体端口映射的场景。生产中通常用 -p 指定明确端口，便于客户端访问。

  •         docker- ▶ nginx:80

  • docker inspect 核心字段：
  • Id 容器完整 ID
  • State.Status 容器状态（running/exited/...）
  • State.Pid 容器主进程在宿主机的 PID

  • HostConfig.PortBindings 端口映射配置
  • Config.Env 环境变量
  • Config.Cmd 启动命令

易错点

  1. ❌ 把端口映射方向记反。✅ -p hostPort:containerPort，方向是宿主→容器（外→内）。
  2. ❌ 端口冲突时不知所措。✅ 报错 port is already allocated 表示宿主机端口被占，换一个端口即可。
  3. ❌ 用 -P 后不知道访问哪个端口。✅ 用 docker port <容器> 或 docker ps 查看随机分配的端口。
  4. ❌ docker inspect 输出太长看不懂。✅ 用 -f '{{.字段}}' 提取需要的字段，常用 .State.Status、.NetworkSettings.IPAddress。
  5. ❌ 误认为 -p 127.0.0.1:8080:80 外部能访问。✅ 绑定到 127.0.0.1 表示仅本机能访问，外部访问不了。

小结

docker inspect 查看容器完整元数据（JSON 格式），用 -f 模板提取特定字段。端口映射 -p hostPort:containerPort 让外部通过宿主机端口访问容器服务，方向是"外:内"；-P 大写随机分配宿主机端口。端口冲突时换宿主机端口。docker port 命令查看容器的端口映射。

知识点 K4-6：运行 MySQL 容器实践

定义

本知识点将前 5 个知识点综合应用到 CTTS 项目场景——运行 MySQL 容器作为 CTTS 项目的数据库。

完整命令：

docker run -d \
  --name ctts-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -e MYSQL_DATABASE=ctts \
  -e MYSQL_USER=ctts \
  -e MYSQL_PASSWORD=ctts123 \
  -v /data/ctts/mysql:/var/lib/mysql \
  --restart=unless-stopped \
  mysql:8.0

原理

MySQL 官方镜像的环境变量：

环境变量 作用 必填
MYSQL_ROOT_PASSWORD root 用户密码 必填（不填会启动失败）
MYSQL_DATABASE 启动时自动创建的数据库 可选
MYSQL_USER 自动创建的普通用户 可选
MYSQL_PASSWORD 普通用户密码 与 MYSQL_USER 配套
MYSQL_ALLOW_EMPTY_PASSWORD 允许空密码（不安全，仅测试用） 可选
MYSQL_RANDOM_ROOT_PASSWORD 随机生成 root 密码 可选

为什么挂载数据卷 -v：

图示 7：是否挂载数据卷对数据保留的影响
不挂载数据卷

数据跟着容器走

MySQL 数据写在容器可写层里；容器删除后，/var/lib/mysql 中的数据也随之消失。

挂载数据卷

数据落在宿主机

-v /data/ctts/mysql:/var/lib/mysql 把数据目录映射到宿主机；容器删除后，数据仍可被新容器复用。

--restart=unless-stopped 的意义：

  • 容器意外退出（如崩溃）或宿主机重启后，Docker 自动重启该容器。
  • 除非用户手动 docker stop，否则会一直尝试重启。
  • 生产数据库容器必加此参数。

MySQL 容器启动流程：

图示 8：Docker 拉取/使用 mysql:8.0 镜像

拉取镜像

docker pull mysql:8.0，获得官方 MySQL 镜像。

准备参数

设置 MYSQL_ROOT_PASSWORD、端口映射、容器名和数据目录。

启动容器

docker run 创建并启动 MySQL 进程。

验证连接

使用 docker ps、logs 或 mysql 客户端确认 3306 可用。

处理持久化

生产或长期练习必须挂载 volume，避免容器删除导致数据丢失。

问题 / 场景

问：为什么 MYSQL_ROOT_PASSWORD 是必填的？

  • MySQL 官方镜像的入口脚本要求必须设置 root 密码，否则启动失败（出于安全考虑）。如果测试场景想用空密码，需显式设置 MYSQL_ALLOW_EMPTY_PASSWORD=yes。

问：第一次启动很慢，正常吗？

  • 正常。MySQL 首次启动要初始化数据目录、创建系统表、创建用户和数据库，通常 10~30 秒。用 docker logs -f ctts-mysql 看到 ready for connections 就表示就绪。

问：如何验证 MySQL 容器正常工作？

  • 三种方式：
    1. docker exec -it ctts-mysql mysql -uroot -p123456 -e "SELECT 1;"（容器内执行）
    2. 宿主机装了 mysql 客户端：mysql -h 127.0.0.1 -P 3306 -uroot -p123456
    3. 用 Navicat / DBeaver 等图形工具连接 宿主机IP:3306

问：数据卷目录 /data/ctts/mysql 需要提前创建吗？

  • 不需要。Docker 会自动创建。但要注意目录权限，如果 SELinux 开启可能需要 :Z 选项（-v /data/ctts/mysql:/var/lib/mysql:Z）。

问：第二次启动容器时数据还在吗？

  • 在。因为挂载了数据卷，MySQL 数据写到了宿主机 /data/ctts/mysql。即使 docker rm 删了容器，只要数据卷在，重新 docker run 挂载同一目录，数据就恢复。

四、拓展阅读（选学）

  1. Docker 日志驱动：默认 json-file，还支持 syslog、journald、fluentd、gelf 等。生产中常配合 ELK/EFK 收集日志。配置：/etc/docker/daemon.json 中 "log-driver": "json-file", "log-opts": {"max-size": "10m", "max-file": "3"}。
  2. docker run 的 --restart 策略：no（默认，不重启）、on-failure（非 0 退出码重启，可加最大重试次数 on-failure:5）、always（总是重启，包括 daemon 重启）、unless-stopped（除非手动 stop，否则总是重启，推荐）。
  3. 容器资源限制：docker run -m 512m --cpus 1.5 限制内存 512MB、CPU 1.5 核。生产中每个容器都应设置资源限制。
  4. docker exec 原理：通过 setns() 系统调用进入已有容器的命名空间，然后 fork() 一个新进程。所以 exec 能进入运行中的容器而不影响主进程。
  5. 端口暴露与端口映射的区别：EXPOSE 是 Dockerfile 中的声明（文档性质），-p 是 docker run 时的实际映射（真正生效）。EXPOSE 80 只是说"这个镜像暴露 80 端口"，要让外部访问还需 -p。
